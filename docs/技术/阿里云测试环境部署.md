# 阿里云线上测试环境部署

> 适用范围：RICSE 线上测试、演示和用户验收环境。
> 当前方案：单台 ECS + Docker Compose。正式生产环境应逐步迁移到 RDS、云数据库 Redis 和 OSS。

## 1. 部署架构

```text
浏览器
  │ 80 / 443
  ▼
Nginx
  ├── /                    → Next.js Web:3001
  ├── /api/*               → NestJS API:3000
  └── /ricse-attachments/* → MinIO:9000（仅预签名链接可访问）

内部 Docker 网络
  ├── PostgreSQL:5432
  ├── Redis:6379
  └── MinIO Console:9001
```

数据库、Redis、MinIO、API 和 Web 端口均不向公网暴露。公网只开放 Nginx 的 80/443。

## 2. ECS 与安全组

测试环境建议从以下规格开始：

- 4 vCPU、8 GB 内存；
- Alibaba Cloud Linux 或 Ubuntu；
- 系统盘和数据盘应开启快照；
- ECS 绑定公网 IP 或 EIP。

安全组规则：

| 端口 | 来源 | 用途 |
|---|---|---|
| 22 | 固定办公 IP | SSH |
| 80 | 互联网；启用 HTTPS 后仅用于跳转 | HTTP |
| 443 | 互联网 | HTTPS |

不要向公网开放 3000、3001、5432、6379、9000、9001。

中国内地 ECS 使用域名对外提供服务前，需要完成 ICP 备案。未备案且需要快速验证时，可以先使用香港节点，或仅通过安全组白名单限制的公网 IP 做内部测试。

## 3. ECS 初始化

安装 Git、Docker 和 Docker Compose，并启动 Docker：

```bash
sudo systemctl enable --now docker
docker --version
docker compose version
```

创建部署目录并从云效 Codeup 拉取代码：

```bash
sudo mkdir -p /opt/ricse
sudo chown "$USER":"$USER" /opt/ricse
git clone https://codeup.aliyun.com/690b019af9c52e7d8c273f40/ricse.git /opt/ricse
cd /opt/ricse
```

建议为 ECS 配置 Codeup SSH Deploy Key，避免长期保存个人账号密码。

## 4. 环境变量

```bash
cd /opt/ricse
cp deploy/.env.staging.example deploy/.env.staging
```

编辑 `deploy/.env.staging`，替换所有 `CHANGE_ME` 与访问地址。可以生成随机密钥：

```bash
openssl rand -hex 32
openssl rand -hex 32
openssl rand -hex 24
```

首次通过公网 IP、HTTP 验证时：

```dotenv
PUBLIC_HOST=ECS公网IP
PUBLIC_URL=http://ECS公网IP
MINIO_PUBLIC_PORT=80
MINIO_PUBLIC_USE_SSL=false
```

该方式只能用于安全组限制到可信测试人员 IP 的短时验证。登录和附件访问正式开放前必须启用 HTTPS。

## 5. 首次启动

为脚本添加执行权限：

```bash
chmod +x deploy/deploy.sh
```

首次部署并初始化测试数据：

```bash
./deploy/deploy.sh --seed
```

脚本会依次执行：

1. 校验 Compose 配置；
2. 构建 API 和 Web 镜像；
3. 启动 PostgreSQL、Redis 和 MinIO；
4. 执行 `prisma migrate deploy`；
5. 按需初始化测试数据；
6. 启动 API、Web 和 Nginx。

系统必需配置与演示数据分开管理。采购、销售和双边合同默认审批流由数据库迁移自动、幂等初始化，常规流水线发布即可生效；`--seed` 只用于首次创建演示企业、合作伙伴、物料和测试账号，不应为修复审批流程而重复执行。

种子账号密码由以下环境变量决定，不再使用代码中的开发默认密码：

```dotenv
SEED_ADMIN_PASSWORD=
SEED_APPROVER_PASSWORD=
SEED_USER_PASSWORD=
```

线上环境默认关闭公开注册：`ALLOW_PUBLIC_REGISTRATION=false`。

## 6. 配置 HTTPS

域名解析到 ECS 公网 IP 后，将证书文件放置为：

```text
deploy/certs/fullchain.pem
deploy/certs/privkey.pem
```

修改环境变量：

```dotenv
PUBLIC_HOST=test.example.com
PUBLIC_URL=https://test.example.com
MINIO_PUBLIC_PORT=443
MINIO_PUBLIC_USE_SSL=true
ENABLE_HTTPS=true
```

重新部署：

```bash
./deploy/deploy.sh --https
```

HTTPS 配置会把 80 端口请求重定向到 443。阿里云证书续期后，需要替换证书文件并重新加载 Nginx：

```bash
docker compose \
  --env-file deploy/.env.staging \
  -f deploy/docker-compose.staging.yml \
  -f deploy/docker-compose.https.yml \
  restart nginx
```

## 7. 日常发布

在 ECS 上执行：

```bash
cd /opt/ricse
git pull --ff-only origin main
./deploy/deploy.sh --https
```

不需要测试数据时不要使用 `--seed`。

查看运行状态和日志：

```bash
docker compose \
  --env-file deploy/.env.staging \
  -f deploy/docker-compose.staging.yml \
  ps

docker compose \
  --env-file deploy/.env.staging \
  -f deploy/docker-compose.staging.yml \
  logs -f --tail=200 api web nginx
```

健康检查：

```text
https://测试域名/login
https://测试域名/api/v1/health
https://测试域名/api/docs
```

Swagger 文档只建议对管理员 IP 开放，或在 Nginx 中增加认证保护。

## 8. 云效 Flow

第一次手工部署验收通过后，创建云效流水线。当前账号未开通 ACR 时，先使用
源码制品发布：

```text
Codeup main 分支
  → 安装依赖
  → API 单元测试
  → TypeScript 类型检查
  → 生成源码制品
  → ECS 主机部署
  → deploy/deploy.sh
  → /api/v1/health 健康检查
```

开通 ACR 后，推荐升级为：

```text
Codeup main 分支
  → deploy/ci-verify.sh
  → 构建 API/Web 镜像并推送 ACR
  → 生成镜像发布清单
  → ECS 主机部署
  → deploy/release.sh
  → /api/v1/health 和 /login 健康检查
```

云效 ECS 服务连接和环境密钥应保存在云效凭据或 ECS 的 `deploy/.env.staging` 中，禁止写入代码仓库。

## 9. 备份与恢复

线上测试数据也应至少执行：

- PostgreSQL 每日逻辑备份或 ECS 云盘快照；
- MinIO 数据卷快照；
- 发布前数据库备份；
- 定期验证备份能否恢复。

数据库迁移使用 `prisma migrate deploy`，不会自动回滚。涉及数据结构变更时，应在发布前完成备份并准备对应恢复方案。
