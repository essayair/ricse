# 采购付款与质量结算联动开发备注

## 范围

采购货款及双边合同采购侧：合同/批次提前付款、实际采购结算、质量扣款、付款申请与分次付款、预付款用途指定及核销、小程序付款审批。销售收款和客户退款继续使用既有路径，物流运费独立结算。

已确认产品口径：结算制单人或付款申请发起人明确确认扣款接收；磅单和报告事实不在资金环节重选或修改；质保金按尾款处理。详见[产品方案](../../产品/采购付款与质量结算联动产品及开发方案.md)。

## 实现

- `payment-balance.ts`：Decimal计算与申请剩余占用，覆盖部分付款、待财务确认和作废状态。
- `purchase-settlement-basis.ts`：运单货物来源、已复核结算磅单、最终质检报告、质量处置及版本签名；同车多物料和未映射历史重复应付显式阻断自动计算。
- `purchase-payment-context.ts`：合同及结算可申请额、已付未核销、预付款比例、用途指定、付款条件与来源版本校验。
- `FinancialSettlementService`：写入时合同级事务锁、资金行锁、请求幂等、实际货物结算、审批前后重检、用途消耗和核销撤销；修正资金确认的目标操作数据范围。
- 付款申请独立新建/编辑、货物结算新建、双方筛选、质量依据、资金抵扣及A4打印快照。
- 2026-10-21：付款申请新建/编辑页移除独立“查找合同”输入框，保留双方下拉筛选、合同下拉选择及上游单据快捷带入；不改变列表搜索、合同必选及权限校验。
- 2026-10-21：新增「资金结算 → 采购结算单」独立二级菜单，沿用`settlement.view`可见权限；顶部保留“采购结算单／付款申请单／付款单”切换，结算列表及新建页面包屑不再挂在付款申请之下。
- `settlement.quality.accept`独立控制商务接收，保存确认人、时间、原因和判定版本；不授予`quality.manage`。
- 小程序审批中心区分合同与付款申请，付款详情展示金额、质量扣款、账户、预付款、附件及审批，继续由相同后端服务流转；订阅通知复用审批模板。

## 数据迁移及发布顺序

迁移：`20261017100000_quality_payment_linkage`。只新增字段、外键、用途表和专项权限，不重算或删除旧合同、旧结算和旧付款。旧付款申请标记为`LEGACY`，保持历史人工依据；新申请使用明确依据类型。

本地开发库迁移已执行。发布时先运行RICSE数据库迁移、生成Prisma Client并发布后端和Web，再重新构建/上传小程序；旧缓存页面若在扣款接收时提示版本不符，刷新并重新登录后操作。已有普通岗位账号应重新登录以刷新前端权限缓存。

本轮未执行Git提交、推送或线上部署。

## 验证和回归

- RICSE API全量单元测试通过：46个测试套件、405项测试（后续补测以最终运行结果为准）。
- Web生产构建、API/Web类型检查通过；小程序类型检查及微信目标构建通过，修改文件按工程ESLint规范检查。
- 本地新页面HTTP 200；新增资金和移动审批接口未登录时HTTP 401。
- 真实本地PostgreSQL事务冒烟脚本：`apps/api/scripts/smoke-quality-payment.ts`。运行方式：在`apps/api`目录执行`pnpm exec tsx --env-file=.env scripts/smoke-quality-payment.ts`，需要支持`--env-file`的Node版本。
- 冒烟覆盖预付30%、请求幂等、审批、商务接收版本校验、100吨×2,000元/吨扣40元/吨得到196,000元应付、60,000元预付抵扣、136,000元尾款分次付款、重复申请阻断、质检依据变化阻断、最终核销结清。
- 所有模拟单据在一个事务中创建并强制回滚，不写入真实文件，不发送银行转账；脚本只允许localhost及dev/test库。
- 当前计算机浏览器控制服务不可用，未执行可视化浏览器交互验收；手机真机和纸质打印效果仍需业务测试。

## 人工测试入口

1. 登录Web，进入“资金结算 → 应付管理 → 付款申请单”，点击“新建付款申请”。先测试无磅单、无质检的合同预付款。
2. 完成到货、磅单复核与选用、质检最终报告。扣款待确认时，由有专项权限的结算/申请人员确认接收。
3. 进入「资金结算 → 采购结算单」（也可用应付管理顶部标签切换），新建实际货物结算，选择车辆、数量，查看质量计算后保存并确认应付。
4. 从结算详情“按本结算申请付款”。财务处理已有预付款核销或保留用途后提交审批，测试分次付款和核销。
5. 小程序重新编译`dist-weapp`，将业务API指向同版本后端，进入工作台“业务审批 → 付款申请”核对待办、金额、附件及同意/驳回。

## 边界

本次不实现网银直接打款、发票验真、独立质保金释放引擎、跨合同合并付款、复杂混装检测或自动把历史阶段应付映射成逐车应付。已有质量价格扣款之外的特殊扣水扣重须按合同明确口径复核，不能在其他加减项再次重复扣款。

完整混装或历史来源不明确时保留提示和人工复核，不推断每项物料的重量与质量。付款申请创建草稿允许资料未齐，正式业务确认/财务提交、审批和付款登记按相应节点重新校验。
