# 修复双侧水分导致总干基协商误拦截

## 问题与原因

线上首佳—诺龙13车结算测试中，我方净重和水分折干1040.477吨，供应商发货净重和水分折干1049.389吨，双方拟协商1044.88吨，却被“调整后干基数量不能超过可结算数量”拦截。

原协商上限对发货、收货磅单都使用当前选中的报告水分，忽略另一侧报告的水分。这组数据沿用我方报告时，上限误算为1040.684吨。不是输入1044.88为零，也不是合同1000吨硬性拦截。

## 修复范围

- 采购和销售复用 `negotiableGoodsQuantity`：两侧有有效采信磅单时，分别用各侧已确认报告水分折干，综合当前选用数量得到可协商上限；不组合另一侧最低水分与最大净重虚增上限。
- 排除草稿、作废、删除及未分类报告对另一侧上限的扩充；无有效本侧水分时保留沿用当前有效报告的历史兼容行为；缺水分不推定为0。
- 单侧磅单、多张未采信磅单、结算占用、重复来源、互斥调整、说明及审批校验保持不变。实物计价不折干。
- 预览快照带回 `quantityCeiling`，页面在总干基输入下显示协商上限；区分非正数/精度错误与超限错误，超限提示具体吨数。
- 确认及审批重新核验当前双方依据上限，防止另一侧报告撤销或变更后继续使用旧上限。
- 无数据库迁移，不改已过账库存、合同及原始磅单、检测报告；不替用户保存结算单或提交审批。

## 回归场景

13车逐车三位小数折干合计1040.477吨；供应商侧上限1049.389吨。调整总干基1044.88吨，含税单价2920元/吨，应形成最终金额3051049.60元，逐车明细与库存保持原值；超过1049.389吨继续拦截。

同时覆盖采购与销售来源、正数/精度校验、双方不同水分、净重与水分同侧配对、无报告/无水分、单侧计量、多报告状态、整单与逐车调整互斥、快照及当前依据核验。

验证结果：结算模块13个测试套件、153项测试通过；前后端类型检查及 `git diff --check` 通过。另直接读取本次线上重建结果的13车快照，在本地运行修复后的计算及保存快照校验，得到上限1049.389吨、最终数量1044.88吨、含税金额3051049.60元；原始快照未变，未写入线上单据。本地前端服务未运行，未开展本次浏览器联调。

## 上线

本改动须按用户授权提交、推送并完成应用部署后才在线上生效；本地完成不代表已更新生产。不通过直接修改业务数据绕过校验。

## 调整字段就地校验与文案

- 新增前端纯函数 `settlement-adjustment-validation.ts`，按数量、金额、原因分别返回错误；采购和销售共用结算编辑器。
- 常驻提示：`可协商上限：1049.389 吨，按双方有效磅单及质检报告计算。`（数值动态取当前所选车辆）。
- 超限提示：`协商干基数量不能超过 1049.389 吨，请核对双方单据或修改数量。`
- 空值或非正数：`请填写大于 0 的协商干基数量。`
- 精度提示：`干基数量最多保留 3 位小数。`
- 缺少原因：`请填写双方协商调整的原因。`
- 金额调整同样将正数及小数位要求分别显示在金额输入处。
- 错误位置标红并配置 `aria-invalid`、`aria-describedby`；复用平台 `focusInvalidField`，在系统居中提示关闭后滚动、聚焦首个错误处。保留原输入，不关闭编辑页，不重置数量。输入正确后清除错误并恢复实时试算。
- 预览及保存前均校验；客户端有错不继续请求，按钮提示统一为`请检查标红的填写项。`。服务器并发校验异常映射回对应字段，非调整错误仍保留原业务提示。
- 未填写完整时显示“待完善调整信息”，不将正常填写过程称为“试算失败”；无实际数量或金额变化时不强迫填写额外原因，与原有后端快照兼容。

验证：后端结算模块153项测试、前端字段校验/选择/合计19项测试、前后端类型检查通过。新增测试包含空白、零、负数、非法数值、数量三位/金额两位精度、协商上限等值、超限、缺少原因、恢复原数量、错误来源定位和保留输入。尝试本地隔离浏览器验证时用户正在使用浏览器、独立浏览器宿主不可用，未完成本次视觉联调；临时测试服务已停止，不影响已有开发服务，未连接线上写入接口。
