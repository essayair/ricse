# 业务影像归档与附件互通

日期：2026-11-14。仅本地开发、迁移与测试，未提交、推送或部署线上。

## 1. 数据结构

- `BusinessImage` / `business_images` 是归档元数据，与 `Attachment` 共用主键，一对一。
- 元数据记录归档合同、可选通知、类型、来源文件名、原大小、压缩标识、文件哈希、客户端幂等请求、名称确认人/时间（确认人为上传人）、创建人/时间。
- `Attachment` 仍是文件及具体业务外键的唯一来源。关联只写原业务外键和原类别，不复制文件。删除 Attachment 会级联删除归档元数据，原单据生命周期未被重写。
- `(createdBy, clientRequestId)` 防重试重复，`(contractId, fileHash)` 防同合同内容重复。仅归档不自动填 `Attachment.contractId`，避免尚未关联的资料被算作正式合同附件。
- 迁移：`20261114100000_business_image_archive`。无历史文件搬迁，无合同/库存/结算数据回填。
- 增补迁移 `20261114230000_business_image_unique_name`：`(contractId, nameKey)` 唯一索引，nameKey为最终附件名去首尾空格后转小写；触发器在归档和原单据改名时同步，防止并发或其他入口绕过。既有归档如果已重名则停止迁移，不能自动替用户改名。历史未归档原单据附件不批量纳入约束。
- 新文件类型初始为空，顶部预选只影响之后新增文件；前端逐行必填校验、批次同名标红、服务端DTO类型校验及上传/改名重名提示均已加入。

## 2. API 与权限

- `/api/v1/business-images`：列表、逐文件上传、编辑、删除。
- `/contracts`、`/notices`、`/targets`：有范围的关联选择器；`/:id/view-url`、`/:id/preview-url`：授权原件/缩略图；`/:id/link`、`/:id/unlink`：附件互通。
- `business_image.view`、`business_image.manage` 独立权限。迁移给已有合同查看角色补充查看；按已有业务维护权限补充归档维护。管理员沿用系统管理员权限。
- 服务端要求内部账号及 `contract.view`。归档合同同时取影像权限范围与合同查看范围的交集；既有 `getContractScope` 继续约束顶层事业部归属。
- 原单据附件另按模块查看权限及原模块范围过滤。没有原模块权限的文件不能走“仅归档”分支绕过：此分支明确要求所有业务外键为空。
- 物流结算共享附件仅在所有关联贸易合同均可见时集中显示，避免一份多合同文件泄露其他事业部数据。
- 关联要求原模块操作权限，资金单按收/付款方向切换权限，付款申请按状态切换申请/提交权限。
- 关联事务使用合同咨询锁、目标单据行锁、附件行锁，并在锁内重检状态；不能向已审批合同或已锁定凭证变相添加/移走附件。
- 已选执行通知时，车次类目标与报告有效任务关联必须匹配该通知；合同、汇总结算和资金单不按单通知截断。
- 管理员详情返回 `BUSINESS_IMAGE` 操作轨迹；普通用户不返回。关联/解除同时记录原单据业务操作日志。

## 3. 文件、缩略图与资源保护

- Multer 和服务端均限制20MB；前端先校验。检测文件签名，支持PNG/JPEG/WEBP/PDF。
- 图片预览使用 lazy import 的 `sharp@0.35.5`，最大4000万像素输入，长边1200px，JPEG82，10秒超时；原件不覆盖。
- PDF 使用 `pdftoppm` 无 shell 调用，仅首页，长边1200px，12秒超时，临时文件 finally 清理。
- 派生文件私有存于 `business-previews/<原存储key的SHA256>.jpg`，原件删除时一并清理；签名地址1小时。
- 缩略图按需生成、同文件 single-flight、进程最多2份并发；繁忙时前端延迟重试，异常回退查看原件。预览依赖不可用不导致交易API启动失败。
- 普通车辆/现场照片可在浏览器适度压缩；其他类型与PDF不进入压缩。照片原件是否压缩、压缩前后大小留在元数据。这里的“原件保留”特指单据/PDF及未选压缩的照片。
- 文件尚无杀毒沙箱或不可篡改档案保障，不将业务影像称作监管级存证。

## 4. 部署要求

1. 正常安装锁文件依赖并重新构建 API/Web，不能只热替换页面。
2. 运行数据库迁移并重新生成 Prisma Client，禁止对生产执行 reset。
3. API Dockerfile 的构建/运行镜像已加入 `poppler-utils`。裸机部署需自行安装 Poppler，确认 `pdftoppm` 在 PATH 中；缺失仅影响PDF缩略图，不影响原件。
4. `sharp` 要求 Node.js 20.9 或更高，现有API镜像使用Node22；目标架构可选依赖必须正常安装，不要使用 `--no-optional`。启动时不主动加载该原生库。
5. 沿用现有 MinIO 私有桶及鉴权配置，无新增密钥。现有Nginx请求上限100m可承载20MB单文件及multipart开销，业务接口仍执行20MB限制。
6. 检查角色配置中的业务影像权限；新增自定义角色需按岗位授予，不以视频监控权限替代。
