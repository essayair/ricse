# 官网公开写入与合作意向防护

## 范围与边界

本次保护官网匿名“提交合作意向”：`GET /api/v1/public/content/contacts/submission-token` 和 `POST /api/v1/public/content/contacts`。资讯、行情读取与后台跟进流程不变，不调整数据库结构。

供需发布仍要求有效微信用户身份、每日限额及后台审核，本次将该写入的 Redis 故障策略改为拒绝提交。AI、微信登录等既有限流接口保留原故障策略，不表示所有公开接口已经完成安全加固。

这是应用层基础防刷，不是验证码，也不是抗 DDoS 方案。自动化程序仍可模拟取凭证和等待；持续分布式攻击需配合云 WAF、边缘限流及必要的人机验证。CORS、隐藏字段、前端按钮禁用都不能独立作为鉴权措施。

## 合作意向提交过程

1. 官网加载表单时取签名凭证，有效期15分钟，绑定客户端 IP 与 User-Agent，最短等待2秒。
2. 前端校验字段、锁定提交按钮；服务端再次校验 JSON、字段白名单、长度及联系方式格式。
3. 服务端检查隐藏防刷字段、签名、有效期和一次性凭证；原子计数限制提交频率。
4. 相同姓名、企业、联系方式、邮箱及留言24小时内不重复入库。并发使用 Redis 排他锁；入库后缓存接受标记，数据库查询作为 Redis 标记丢失后的补充核对。
5. 成功仅返回成功标志和提示，不回传咨询主键、IP、个人资料。官网清空表单并换取新凭证；失败保留填写内容并显示错误。

24小时去重不是永久唯一约束；锁有效期60秒，不是数据库跨系统事务。若数据库操作长时间阻塞超过锁期，仍需进一步数据库唯一约束/事务设计，不能宣称“绝不重复”。

## 默认限制

| 维度 | 限制 |
| --- | --- |
| 取凭证/IP | 每分钟10次、每小时40次 |
| 提交尝试/IP（包含失败请求） | 每分钟3次、每小时5次 |
| 联系方式（有效新内容） | 每24小时3次 |
| 全局（有效新内容） | 每分钟20次、每24小时200次 |
| 正文 | 仅 JSON，最大24KB |
| 字段 | 姓名50字、企业200字、联系方式30字、留言5000字、来源路径500字 |

计数窗口从该维度第一次请求起算，不是自然整点。限制存在代码中，后续按实际流量调整；共用出口 IP 的访客会共享 IP 限额。重复内容仍受 IP 尝试频率限制，不重复消耗有效新内容的联系方式和全局额度。

防护存储异常时返回503，不绕过防护写入；限频429、内容过长413、格式错误400、不支持类型415、同内容处理中409。Redis键中散列IP、联系方式；日志不输出凭证、联系方式及留言内容。后台留言沿用 React 文本节点渲染，不作为 HTML 执行。

## 配置与上线

- 不增加新第三方付费服务，复用现有 Redis。
- `PUBLIC_FORM_SECRET` 可配置独立随机密钥，留空回退 `JWT_SECRET`；两者均无则拒绝取凭证。真实密钥只在本机/服务器密钥配置，不能放 Git。
- 内容服务的 `CONTENT_TRUST_PROXY` 优先，其次 `TRUST_PROXY`，最后默认信任本机和内网代理。不要配置为 `true` 无条件信任任意转发头；入口代理须正确处理转发头，内容 API 不直接暴露公网。新增代理/CDN时需重新核验真实 IP。
- RICSE 与 website 需要配套发布。旧官网不带凭证会被新接口拒绝，不能只升级后端；发布后刷新官网以获取新资源。轮换密钥会使在填凭证失效，用户需重试刷新表单。
- 发布后的验收使用测试意向并人工标记无效，不能通过批量灌库测试生产服务。正常提交、连续点击、伪造/过期/重放凭证、超限、超长正文、Redis异常均需验证。
- 此次仅本地实现与自动测试，不包含云 WAF配置、线上部署和生产数据变更。
