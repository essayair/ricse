# 销售结算列表未关联收款兼容修复

## 现象与原因

点击“应收管理 / 销售结算单”报错。开发环境只读复现中，结算列表、销售资金流水、合同候选三个接口均返回 200；其中销售资金流水 3 条记录的 `contract` 为 `null`，这是先登记收款、后认领业务的合法数据，不是缺失合同必须补录的数据。

`SettlementWorkbench` 将资金的 `contract` 错误声明为必有对象。页面在每次渲染时计算退款候选，直接读取 `item.contract.id`，因此即使没有打开资金操作也会崩溃。核销候选、打开核销时的可用流水筛选，以及旧资金列表的合同展示有同类问题。

## 修复

- 资金合同和交易对手类型允许为空，不修改原收款记录。
- 核销候选、可用流水、退款候选统一使用空值安全的合同匹配逻辑；未选合同或资金未关联合同时，不匹配任何合同。
- 资金列表无合同显示“未关联合同”，不读取空对象。
- 保留原有状态、支付阶段、方向、余额和服务端权限校验，不自动认领收款，不改变核销规则。
- 无数据库迁移，无线上数据修改。

## 验证

- 本地销售与采购方向各 3 个真实查询接口均返回 200。
- 增加 3 项回归：空合同安全、同合同匹配、混合流水筛选；全部 Web 辅助测试共 82 项通过。
- Web 类型检查和 `git diff --check` 通过。
- 浏览器访问销售结算入口跳转到登录页，当前浏览器没有有效登录会话，未将 HTTP 成功当作登录后页面验收；需用户现有登录页面刷新复测。
