# 司机车辆统一建档

## 实现

- 新增`/dashboard/master-data/transport-resources/new`，上司机下车辆，支持新建/已有/留空组合；列表和承运商创建入口统一。原车辆新建路由重定向，司机、车辆编辑逻辑继续保留。
- `VehicleForm`支持受控值、隐藏独立按钮和重复司机区块，原独立编辑不变；新增司机详情，两个档案均可查看、补传和替换资料。
- `POST /transport-resources`：multipart，`payload`为JSON，文件分为`driverAttachments`和`vehicleAttachments`。嵌套DTO白名单验证、基础必填和附件必传、身份唯一、车辆归属验证均在服务端执行。
- 主数据仍为`Driver`、`Vehicle`、`VehicleDriver`，不引入一体化身份。新档案和关联、资料元数据统一事务，已有车辆关联加行锁，已有主驾保留；错误补偿删除已传文件。
- `Attachment`增量增加`driverId/vehicleId`关系和索引，记录上传人、时间与SHA256。迁移`20261022160000_transport_resource_attachments`已仅在本地开发库应用；历史档案不强制补录。
- `POST /transport-resources/recognize`使用本地规则；个人证件和联系方式不会发送到第三方模型/OCR。多值歧义提示、不覆盖已有档案，识别后仍须核对。
- 资料路由为`/transport-resources/:kind/:id/attachments…`，按主数据权限及档案归属校验；最后一份附件保护，替换先传后删。
- `MasterDataModule`显式导入`AccessControlModule`，浏览器联调发现并修复模块注入遗漏，核心API已恢复健康。

## 验证

- 后端完整测试49组433项通过；前后端类型检查、Web生产构建通过，修改页面定向ESLint通过。
- `apps/api/scripts/smoke-transport-resources.ts`：真实本地数据库，子事务使用保存点，覆盖单建、联合建、两个已有/新建组合、保留主驾、重复关联及失败无半套档案；真实MinIO上传、下载、替换、跨档案拒绝访问和最后附件保护。数据库整体回滚，全部测试文件清理。
- 浏览器检查新入口、中文面包屑、司机在上/车辆在下、文字识别7项回填及缺附件居中拦截；未保存浏览器模拟档案。
- 本轮不提交、不推送、不操作线上数据。真实设备/定位接入、图片证件OCR、车队重新归属不在本轮范围。

## 测试建议

1. 只填司机姓名/手机号和附件，车辆留空或暂不填写，保存后进入司机详情。
2. 只填车辆，司机暂不填写，保存后进入车辆详情；车牌拼音省份输入不应被打断。
3. 新司机+新车辆、新司机+已有车辆、已有司机+新车辆分别保存，核对两个列表及主/副驾关系。
4. 用已有手机号/车牌的文字识别，确认自动引用原档案，不重复创建或覆盖原信息。
5. 故意缺附件、填不完整、重复手机号/车牌，确认提示明确且不留下部分新档案。
6. 从司机/车辆详情预览资料、追加新文件后删除旧文件，最后一份应不能删除。
