# 合同基准水分与扣水结算

## 范围与实现

- 在分档价格 JSON 中新增 `moistureDeductionMode: ACTUAL | EXCESS` 与 `moistureBasePct`。未声明模式仍走旧的全水分折干，旧的质量水分上限不自动转换为免扣基准。
- 新建分档规则默认提供超基准扣水，基准由用户填写；原质量水分上限改名并独立配置。没有新模式的旧合同仍保留原校验。
- 共享规则位于 `packages/shared-types/moisture-pricing.js` 与同名声明文件，采用可直接被 Node 和 Web 使用的 CommonJS 子路径，不引入生产 API 直接加载未编译 TypeScript 的问题。
- API 用 Decimal 计算三位数量；Web 用共享规则计算选磅单/报告后的实时数量，回归覆盖前后端精度一致性。
- 常规采购、销售的结算来源及双侧协商上限均接入新规则；`dryQuantity` 仍是实际全折干值，不冒充免扣结算量，不回写仓库数量。
- 直拨交付以新合同的下游规则计算两向共同辅助数量；直拨采购的数量及其扣水说明跟随销售快照，自己的价格规则仍用于核价。
- 合同详情/打印、结算编辑/详情/预览/打印、Web与小程序直拨数量展示区分实际干基和扣水后计价量。
- 新字段随交付和结算证据快照保留；仅新模式追加字段，原来源签名不因新空字段变化。无 Prisma 迁移，不修改历史合同、交付、库存或结算。

## 验证

- 后端81套893项测试通过，包括基准0、低于/等于/超过基准、缺失/非法水分、质量上限独立、采销结算来源、实际干基不变和真实直拨准备逻辑。
- Web辅助85项、API/Web/小程序类型检查通过；API与Web生产构建通过，生产API模块可直接加载共享计算并算出98.2吨。
- 完整HTTP联调三轮通过，每轮82项：
  - 同基准超额扣水：`E2E-ZB-1113072738`。
  - 不带新字段的历史全折干：`E2E-ZB-1113072913`。
  - 采购基准4%、销售基准3%，数量及说明仍跟随销售：`E2E-ZB-1113073117`。
- 新模式HTTP关键值：净重19.8吨、水分4.5%、基准3%，交付计价量19.503吨；改用20吨发货磅单后19.700吨；最终采购合计38吨与销售19.7＋18.3吨一致。
- 初轮HTTP `E2E-ZB-1113072614` 被当前模板新增碳酸钙指标拦截，原因是模拟报告缺该指标；补齐模拟报告实测0.8后重跑通过，没有放宽业务质量校验。
