# 独立质检报告与品位分档计价（2026-10-28）

## 本轮已落地

- 机构检测报告可独立创建、上传附件，然后与车辆质检任务建立多对多关联；原有从任务录入的单车报告保留，迁移补写关联记录。
- 首次关联锁定报告的合同、供方、业务单元和物料；关联时检查范围，全部解除后才释放归属。关联和解除留时间、操作人，已作为任务最终依据或入库引用的报告不能直接解绑。
- 质检任务列表和详情合并展示旧直接报告及新关联报告；任务可从多份已确认报告选一份形成最终判定。共享报告用于多车时，每车入库依其自身运单和磅单，不复制混样重量。
- 合同明细可保存采购/双边销售方向的 CaF₂ 品位分档价格快照；Web 新建、编辑、详情、打印均可查看规则。固定价合同维持原路径。
- 采购结算读取最终报告的 CaF₂、水分，按已确认的“百分数数值即度数”命中档位。经办人每次输入税率，系统计算税前价、税额及含税金额，存入来源快照。表外品位、水分超限、缺报告或与质量扣价叠加时不自动形成正式金额。
- 已有合同不自动迁移为分档价；现有固定价结算和库存数量口径不改。

## 迁移与验证

迁移为 `20261028130000_shared_quality_reports` 和 `20261028140000_backfill_quality_report_material`，只新增字段/关联表并回填旧报告关联、原运单物料；不删除报告、磅单、合同或历史结果。部署需先应用迁移，再启动新版 API。Prisma schema 校验、API/Web TypeScript 类型检查与单元测试应全部通过后，再在有数据库的环境做单车/多车、解绑、入库与结算联调。

本轮已在本机 `ricse_dev`（PostgreSQL `localhost:5433`）应用迁移；12 份原有质检报告对应回填 12 条任务关联，未回填数量为 0；有原磅单而无物料 ID 的旧报告数量为 0。API/Web 类型检查、API 单元测试和 lint 已通过。浏览器端完整业务操作仍需按下述场景联调，不能把这些检查等同于生产验收。

## 仍需开发

当前采购货款来源仍是我方入库过账数量和任务最终报告；销售应收仍为原批次结算。发货侧/收货侧磅单与质检报告分别选择作为商业结算依据、与库存过账依据独立，以及销售采用客户收货证据的端到端处理仍需完成。该部分应新增正式证据选择与版本快照，不能改写已过账库存或让混样报告将总重复制给多车。

产品口径见[双侧计量质检与萤石矿品位结算方案](../../产品/2026-10-28_双侧计量质检与萤石矿品位结算方案.md)。

## 2026-11-05 价格税率与折干增量

- 合同行新增可空字段 `unitPriceExTax`、`salesUnitPriceExTax`、`taxRatePct`；新页面默认 13% 并支持含税/不含税双向换算。历史合同字段为空时不假设税率或重写原价。
- 品位分档快照新增可选 `quantityBasis`：新合同默认 `DRY_MATTER`（所选磅单净重折干），旧快照没有字段时为 `PHYSICAL`。采购、销售结算来源均按合同快照决定商业计价吨数，不改变库存过账事实。
- 品位档位的原始 `rates` 仍是不含税元/度，界面显示其含税换算值；结算引用合同行税率。存量合同没有税率时允许在结算单上人工确认。
- 付款 85%/15% 和发票 95%/5% 未自动联动。回收率扣价见下节。
- 迁移 `20261105120000_contract_dual_tax_prices` 仅增加可空列；上线前须应用迁移。针对新分档合同净重折干的单元测试已增补，完整真实单据联调仍需进行。

## 2026-11-05 物料质检模板显示与新合同带入修正

- 物料品类列表“质检模板”列优先显示结构化关联 `qualityTemplate`，仅对历史未关联物料回退到旧文本字段 `qcTemplate`。
- 新合同的质量规则读取物料当前启用模板。原先精粉 97 的硬编码扣款/拒收预设被错误套到块矿模板；现只对 `QT-FLUORITE-97` 保留该专用预设，其他模板按各自指标标准及 `fuseValue` 初始化，未配置的商务扣款由合同经办人确认。拒收条件不再依赖是否配置扣款才显示。
- 合同草稿可重新选择物料以重新带入模板；已审批合同与既有质检任务仍沿用各自创建时的快照，不自动覆盖。

## 2026-11-05 选矿回收率扣价与结算行计价事实

- 品位分档快照新增可选 `recoveryAdjustment { baselinePct, deductionPerPointPerDegree, stepMode: PROPORTIONAL | FULL_POINT, note }`，合同提交时由 `parseGradePriceRules` 校验。未配置时 `evaluateGradePrice` 不输出任何回收率字段，存量结算依据签名保持不变，已有草稿不会因本次上线变为“待复核”。
- `readMeasuredPct` 新增 `RECOVERY` 类型，识别编码 `RECOVERY` 或名称含“回收率”的指标；品位识别排除回收率指标，避免“CaF₂回收率”被误读为品位。
- `evaluateGradePrice` 的 `unitPrice` 仍为档位原价，另返回 `recovery`（差额点数、每度扣价、每吨扣价）与 `netUnitPrice`；扣价不低于档位单价时转人工。采购、销售结算来源新增 `recoveryDeductionPerTon`，与质量扣款规则的 `deductionPerTon` 分开，不触发“分档价与质量扣价叠加”拦截。
- 含税金额由 `settlement-pricing.ts` 的 `gradeTierAmounts` 统一计算：税额按扣价后不含税货款计，扣价含税后写入 `qualityDeductionAmount`，保证 `grossAmount − qualityDeductionAmount = amountExTax + taxAmount`。销售结算头新增 `qualityDeductionAmount` 合计。
- 销售侧：仅“选矿回收率”指标未达标导致报告结论为扣款、且合同已配置回收率条款时，不再以“报告不合格”或任务“待复核”拦截；其他指标不合格仍按原规则处理。
- 迁移 `20261105210000_settlement_line_pricing_facts` 为 `financial_settlement_lines` 新增可空列 `pricingMethod`、`pricingQuantityBasis`、`measuredGradePct`、`measuredMoisturePct`、`measuredRecoveryPct`、`gradeBandLower`、`gradeBandUpper`、`gradeRateExTax`、`recoveryDeductionPerTonExTax`、`taxRatePct`、`amountExTax`、`taxAmount` 及索引 `(pricingMethod, measuredGradePct)`，并从既有来源快照回填分档行与固定价行。合同条款原文仍以合同行快照为准。
- 验证：API/Web 类型检查通过；合同与资金结算单元测试 156 项通过（新增回收率计价、金额取整、结算行事实、采购来源读取回收率等用例）；本机接口验证合同草稿保存回收率条款、提交时拒绝无效扣价。含回收率的分档合同端到端结算（磅单、混样报告、结算审批）仍需在测试环境按真实单据联调。
