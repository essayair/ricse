# 服务生态独立名称

## 业务规则

- 物流承运商、质检机构、仓储与港口、加工服务商具有独立的“服务商名称”；可与关联合作伙伴名称一致，也可不同。
- 新建页面名称必填，最长200字符。选择合作伙伴时，名称为空或仍为前一个伙伴自动带入值时自动带入；人工自定义名称不被再次选择覆盖。
- 服务商名称可编辑，不修改关联合作伙伴名称；伙伴以后更名，也不联动覆盖服务名称。
- 合作伙伴ID、供应商角色、主体权限和同一伙伴同一服务类型的唯一规则保持不变。
- 服务商业务名称不替代合同签约、开票或收付款的法定主体。历史物流、质检等单据名称快照不回写；新建质检报告快照采用服务机构名称并保留合作伙伴ID。

## 实现

- 数据库 `service_organizations.name` 必填、非空；新增迁移 `20261111150000_service_organization_name`。
- 迁移一次性用合作伙伴名称填充已有档案（包括停用档案），只补新增字段，不修改伙伴和业务数据；极少数伙伴名为空时以服务档案编码兜底。
- 创建/编辑DTO增加name，后端拒绝显式空白/空值及超长名称。旧客户端省略名称时创建默认采用伙伴名；更新未传名称保留原服务名。
- 服务生态列表分别展示服务名称、关联伙伴；搜索同时覆盖名称、伙伴名称和编码。
- Web质检、仓储、加工、运力及司机车队选择和详情优先展示服务名；与伙伴不同名时可标注关联伙伴。原接口未返回名称时保留兼容回退。
- 小程序承运商/质检机构专用候选返回服务名，并额外提供partnerName。ID仍为既有伙伴ID，不改移动端选用及权限逻辑。
