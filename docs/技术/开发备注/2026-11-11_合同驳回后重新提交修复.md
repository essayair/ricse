# 合同驳回后重新提交修复

## 原因

前端和权限计算允许已驳回合同编辑、再次提交，后端提交预检也接受已驳回状态，但最终状态机只允许 `REJECTED → DRAFT/VOIDED`。编辑保存不自动改为草稿，最终提交被“不能从REJECTED变更为PENDING_APPROVAL”阻断。

## 修复

- 增加 `REJECTED → PENDING_APPROVAL` 合法流转，采购、销售及双边合同共用；无需创建新合同，也不要求先转草稿。
- 详情按钮按状态显示“重新提交审批”。编辑与附件权限保持既有规则，不扩大任何账号的数据范围。
- 复用事务内必填资料、附件、启用流程和有效审批人校验；新审批任务和状态同步提交。
- 沿用审批轮次递增逻辑，新轮首节点待处理，后续节点等待；旧轮驳回意见等记录保留。
- 编辑保存仍维持已驳回状态，只有明确点击重新提交才启动审批。

## 回归范围

采购/销售/双边合同各从草稿及已驳回提交；缺附件的已驳回合同保持拦截；原ID编辑保存、不生成新合同；第2轮驳回后创建第3轮首节点待办，不删除旧轮审批记录。另复用已有附件锁定测试。

本次仅本地代码与测试，不修改现有合同状态或审批记录，未提交、推送或部署。

验证结果：API全套74组、797项测试通过；API/Web TypeScript检查通过。新增回归涵盖三种合同的驳回后再提交、旧记录保留和新轮节点状态；不通过重置线上合同规避状态机问题。
