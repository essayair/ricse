# 付款申请过滤已付清合同

- 新采购货款申请根据合同选项 `remainingPaymentAmount` 过滤，余额为零不显示；主体与对手筛选同步收口。草稿不占用，业务确认、审批及执行中未付部分按原 `requestCommitment` 规则占用；银行待确认付款仍占额度，部分付款不重复计入。
- 反向处理不靠前端缓存标记，重新读取有效付款及申请实时计算。驳回、退回业务草稿、作废或退款释放余额后可再申请；付款作废但原申请仍有效时，释放额回到原申请，不允许重复申请。
- `confirmedFinalSettlementAmount` 从已确认、部分结清、已结清的最终结算取累计正式货款；最终标识来自 `CONTRACT_FINAL` 或明细快照 `settlementQuantityReview.finalSettlement`。草稿、待审批、驳回、作废不能确定最终付款上限。合同选项与采购付款校验共用此口径，避免已按质量扣款付清后仍展示合同预计金额尾差。
- `paymentContractSelectable` 统一前端合同、主体、交易对手的候选范围。已有草稿或驳回单保留本单合同，销售退款和保证金等反向场景不误用采购货款余额。深链指向不可申请合同时提示重新选择，不静默保存新申请。
- 不删除或隐藏历史付款申请，不改变角色和数据权限，不增加数据库迁移。正式提交和执行付款沿用后端余额、依据与事务锁校验。
- 回归：全付、部分付、申请全额占用、驳回/退回/作废释放、退款、部分付款不重复计数、最终质量扣价付清、最终结算作废、原草稿编辑、销售退款和履约保证金。
