# 物流结算组合筛选

## 实现边界

- 列表与新建页使用 `logistics-settlement-filters.ts` 统一关键词、日期及维度筛选。沿用现有接口返回的完整授权结果做即时筛选，不扩大数据范围、不修改业务状态、不新增数据库迁移。现有日期和状态查询 API 保持兼容。
- 列表 API 只针对已授权结果中的 `ownerPartnerId`、`carrierPartnerId`、`businessUnitId` 批量查询名称，不返回其他企业或事业部作为筛选项。历史未记录维度显示“历史未记录”，不伪造归属。新建候选补充贸易合同与执行批次引用。
- 结算周期使用交集判断；签收日期使用北京时间的自然日，支持仅开始或仅结束日期。多关键词采用 AND 匹配，匹配大小写不敏感。
- 新建筛选状态与已选行状态分离。`retainCandidateSelection` 仅在刷新时移除已不在可结算范围的行，其余已填信息保留；移除有显式提示。筛选日期不作为创建请求的周期参数，由后端根据全部已选运单生成。
- 选用分组键为货主、事业部、承运方三者组合。批量只选当前组的有效已绑定运单；未选定分组且存在多组时不擅自选第一组；待绑定运单走原确认接口。原后端跨组、重复结算、磅单版本及运价校验继续生效。
- 合计口径区分当前筛选已选与全部已选。筛选外的已选运单仍参与最终保存，并在底部显示数量，提供“查看全部已选”。

## 表头批量操作补充

- 重点入口位于可结算运单表头操作行，不以增加筛选条件替代批量选用。左侧为全选与全部取消，发货、收货净重列各有统一选用按钮，选中态由当前实际已选行计算，手工确认重量或混合口径不误显示统一成功。筛选面板默认折叠。
- 全选仅作用当前范围内同一结算分组的可选行；全部取消清空所有已选（含筛选外）及待绑定状态。重量统一切换作用当前范围已选行，不新增未选行或修改筛选外选择。缺目标侧有效磅单保留原值、明确提示。
- `freightWeightSelectionStage`、`switchFreightWeightStage` 复用逐车有效磅单规则；保留明确选用的同侧旧磅单及原业务说明。手工重量改回磅单时清空手工值并重新填写依据；偏离合同默认依据只弹一次共同原因窗口，取消无副作用。合同运价、单价及库存、货款选用不修改。
- 单选、统一选用及下方磅单框共享 `lines` 状态。两侧合计同样传入所选磅单 ID，避免已明确使用同侧旧磅单时页脚却统计另一张重量。

## 回归

组合维度、多关键词、北京日期边界、跨周期结果、待绑定、仅已选、筛选不丢填写、刷新剔除占用、不同结算组、列表权限、历史缺字段及空结果。
