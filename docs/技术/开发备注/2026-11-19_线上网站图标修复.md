# 线上网站图标修复

## 原因

- RICSE页面Metadata已更新，但Standalone生产镜像只复制了standalone与.next/static，未复制public目录，ICO和PNG均返回404。
- 官网线上仍为旧入口和旧图标，推送未在静态目录生效；数字大屏已是新图标。
- 本地资源存在和构建成功不能证明生产镜像含有public资源。

## 修复及验证

- Web Dockerfile增加从构建阶段复制public到运行时的apps/web/public。
- 增加生产运行时资源复制回归检查，覆盖standalone、static和public。
- 线上应急将当前已部署发布目录中的已批准图标补入Web容器，只重启Web，未改API、数据库或业务数据。容器内补文件仅用于恢复当前服务；持久修复依赖后续提交并部署新Dockerfile，容器重建前应包含该修复。
- 官网只备份并替换图标及入口图标引用，不替换原JS/CSS。官网构建/发布脚本新增图标完整性检查及实际入口、ICO字节比对。
- 官网云效存在未保存且未完成配置的草稿，本次保留，不覆盖；自动发布配置尚未恢复，不能把应急图标更新当作流水线修复完成。

源码及测试修复纳入本次用户授权的提交推送；线上图标已按HTTP状态、HTML引用及文件SHA256与本地一致完成核验。后续持久化镜像修复是否已部署，仍以云效流水线结果为准。
