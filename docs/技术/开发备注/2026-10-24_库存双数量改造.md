# 2026-10-24 库存双数量改造

产品口径见[库存双数量与业务单据联动方案](../../产品/库存双数量与业务单据联动方案.md)。

## 本次代码

- 物料 `pricingQuantityBasis` 取 `PHYSICAL` / `DRY_MATTER`；已有库存批次的物料不能直接切换口径。同标准商品可以按两个口径分别建业务物料。
- `InboundReceipt.receivedQuantity` 与 `BusinessInbound.quantity` 保留为实物数量。入库确认时读取当前选定磅单净重；折干计价从最终确认报告中读取唯一“水分”指标。`pricingQuantity`、口径和实测水分快照随入库过账写入。
- 入库详情接口另返回 `reportMeasuredMoisturePct`，直接来自关联报告的唯一有效水分指标，待收货阶段也可展示；按实物计价的确认单同样保留水分快照但不扣减计价数量。迁移 `20261026120000_backfill_inbound_report_moisture` 仅补齐已确认入库单中为空、且报告指标唯一有效的快照，不改写数量。
- `InventoryLot.availableQuantity` 保留实物余额；新增 `pricingAvailableQuantity`。出库、冲销和生产领退料同步变更两列，并写入 `InventoryLedger` 双数量变化。来源批次全部耗尽时取剩余计价尾数。
- 采购货款来源读取 `BusinessInbound.pricingQuantity`，不读取当前库存余额；质量扣价仍与数量换算分开。销售客户收货磅单不回写出库批次。
- Web 和小程序的入出库、库存及合同展示已同步；质检新报告不再把超限扣水/扣杂当作自动库存扣重。

## 迁移与核验

迁移文件：`apps/api/prisma/migrations/20261024120000_inventory_dual_quantity/migration.sql` 与 `20261024130000_legacy_quantity_reconciliation/migration.sql`。第一步沿用旧数，第二步保留原值并标记旧入库单为 `LEGACY_UNVERIFIED`。核对脚本 `apps/api/prisma/reconcile-legacy-inventory.ts` 默认只预演；显式指定目标库的 `DATABASE_URL` 后运行 `pnpm db:reconcile-legacy-inventory` 查看结果，核实无误再运行 `pnpm db:reconcile-legacy-inventory -- --apply`。脚本根据当前选定的入库磅单、最终采用的已确认报告与物料计价口径补全安全的旧单；已有下游出库、领料、冲销、其他库存变动或结算依赖的批次不会自动改账。历史旧值保留在 `legacy*` 字段；无法自动核对的批次继续标记待核对，旧已收货单不能直接过账。**不要对生产库直接跳过预演执行。**

旧采购结算快照增加前版本签名兼容校验：仅事实未变化时允许继续确认，不覆盖已确认金额。端到端测试种子合同已补齐当前必填字段与附件，避免旧用例误报。部署前后仍要核对批次数、各仓库各物料实物余额、采购结算来源和库存台账。迁移不清理业务数据。

迁移和端到端测试使用一次性隔离 PostgreSQL 验证，不触碰现有开发或生产数据。正式环境运行前仍须在测试环境用真实业务数据副本预演，并由业务、仓库和财务共同确认待核对清单。
