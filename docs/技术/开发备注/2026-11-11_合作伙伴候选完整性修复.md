# 合作伙伴及服务生态候选完整性

## 排查结果

- 服务生态新建表单只读供应商列表第一页，最多200条。
- 组织建企两处入口未传分页参数，只能取到默认前20条合作伙伴。
- 生产配方用固定500条合作伙伴，前端再筛内部主体；同样可能漏掉较早创建的内部主体。
- 质检机构、仓储与港口、加工服务商、运力管理的服务商选择只取固定一页。
- Web运力候选中的承运商、内部主体，以及小程序调度候选中的承运商，存在固定200条截断。
- 合同表单专用候选接口、收款登记主体、物流合同及物流结算主体候选无固定伙伴条数截断；保留原权限、角色与状态过滤。

## 调整

1. 新增 `apps/web/src/lib/option-loader.ts`，按服务端实际页码及总页数逐页读取，保留原筛选条件并按ID去重。页码异常、网络失败或总数未加载齐时明确失败，不把部分结果当成完整成功。
2. 接入服务生态新建/编辑、组织建企、生产配方、合作伙伴列表、运力承运商、质检机构、仓储与港口及加工服务商选项。
3. 伙伴、服务档案分页增加ID作为相同创建时间下的稳定排序依据。
4. 专用运力候选接口移除轻量承运商及内部主体查询的固定200条限制；移动调度候选的承运商同样调整。车辆、司机原有关键词查询及条数限制不在本次修改范围。
5. 服务生态新增名称/编码搜索、加载与错误状态；编辑旧档案时保留关联伙伴名称，避免伙伴停用后只显示空选项。

## 业务边界

服务生态仍只允许关联已启用、未删除且具有供应商角色的伙伴；供应商兼客户可选，纯客户不可选。该规则由既有后端校验决定，本次未改为客户也可建服务档案。表单显示此说明；缺少的具体企业还需按其角色、状态核对。

选择框不应直接拿列表第一页充当全部选项；新增同类功能应使用完整候选接口、分页补全或真正支持服务端检索的选择组件，不能只增大固定 `pageSize`。

## 验证与发布

- 回归覆盖超过200条伙伴、服务端缩小每页条数、双角色、末页数据、失败/空页/忽略页码及承运商候选无上限。
- API全套74组、786项测试通过；候选加载前端5项测试通过；API/Web类型检查、Web生产构建及 `git diff --check` 通过。构建仅保留其他页面既有Hook依赖警告，未做本次浏览器视觉验收。
- 本轮只修改本地 RICSE 代码，不改主数据、不推送、不部署；小程序端复用后端候选修复，不需要改变小程序页面代码。
