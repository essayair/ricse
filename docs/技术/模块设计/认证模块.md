# 认证模块设计

> 版本：v1.0 | 日期：2026-07-02

## 概述

认证模块负责用户身份的注册、登录、鉴权和令牌管理。基于 JWT（JSON Web Token）实现无状态认证，配合 Refresh Token 机制提供安全的会话管理。

## API 端点

| 方法 | 路径 | 认证 | 说明 |
|------|------|------|------|
| POST | `/api/v1/auth/login` | ❌ | 用户登录，返回 accessToken + refreshToken |
| POST | `/api/v1/auth/register` | ❌ | 用户注册，自动返回 token |
| POST | `/api/v1/auth/refresh` | ❌ | 使用 refreshToken 刷新 accessToken |
| GET | `/api/v1/auth/profile` | ✅ JWT | 获取当前登录用户信息 |
| POST | `/api/v1/auth/logout` | ✅ JWT | 退出登录，清除 refreshToken |
| POST | `/api/v1/users` | ✅ JWT + ADMIN | 创建用户并同步初始角色授权 |
| PATCH | `/api/v1/users/:id` | ✅ JWT + ADMIN | 修改账号名称、用户名或状态 |
| PATCH | `/api/v1/users/:id/password` | ✅ JWT + ADMIN | 重置密码并使旧 refreshToken 失效 |

## 数据模型

### User 表（`users`）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | String (cuid) | 主键 |
| username | String (unique) | 用户名 |
| password | String | bcrypt 哈希 |
| name | String | 显示名称 |
| role | String | 兼容主角色字段，新鉴权读取用户角色授权 |
| status | String (ACTIVE/DISABLED) | 状态 |
| refreshToken | String? | refreshToken 的 bcrypt 哈希 |
| createdAt/updatedAt | DateTime | 时间戳 |

## 认证流程

```
┌──────────┐     POST /auth/login     ┌──────────────┐
│  客户端   │ ──────────────────────→  │  认证服务     │
│          │ ←──────────────────────  │              │
└──────────┘    { accessToken,         └──────────────┘
                 refreshToken }              │
      │                                       │ bcrypt 比对
      │                                       ▼
      │                                  ┌──────────┐
      │  ┌────────────────────────────── │  User DB │
      │  │ Authorization: Bearer <jwt>    └──────────┘
      │  ▼
  ┌──────────┐     JwtStrategy          ┌──────────────┐
  │  请求    │ ──verify(secret)──────→  │   Passport   │
  └──────────┘                          └──────────────┘
```

## JWT 载荷

```typescript
// AccessToken
{
  sub: string;       // 用户 ID
  username: string;  // 用户名
  role: string;      // 角色
  iat: number;       // 签发时间
  exp: number;       // 过期时间
}

// RefreshToken
{
  sub: string;       // 用户 ID
  type: 'refresh';   // 类型标记
  iat: number;
  exp: number;
}
```

JWT 中的角色信息只用于请求上下文和兼容展示。`JwtStrategy` 每次认证会重新读取数据库中的账号状态和当前有效角色，角色停用、授权过期或账号停用后不能继续依赖旧 Token 获得权限。

## 多角色授权

认证成功只代表用户身份有效，业务授权继续由以下模型计算：

- `Role` / `Permission` / `RolePermission`：角色功能权限；
- `UserRoleAssignment`：用户获得角色、有效期和范围类型；
- `UserRoleScope`：指定企业等范围明细。

功能权限和数据范围必须同时满足。外部企业账号范围强制锁定为所属企业关联业务数据，且不能授予 `ADMIN`。详细实现见[角色权限与数据范围](./角色权限与数据范围.md)。

## 管理员开通账号

管理员可以在“组织数据 → 用户账号”或员工详情页为员工开通登录账号。创建表单必须明确填写以下内容：

- 用户名：3—50 位，以字母或数字开头，可包含字母、数字、点、下划线和短横线；
- 初始密码：至少 6 位，页面必须再次输入确认密码；
- 关联员工：账号与员工主数据关联后，继承对应企业和组织信息；
- 初始角色：默认授予 `USER` 角色，后续通过角色权限配置调整。

前端仅负责输入提示和即时校验，API 服务仍需重复执行用户名、密码和唯一性校验，不能依赖前端校验。密码输入默认隐藏，可由管理员临时切换显示；密码原文不写入日志、不通过查询接口返回。

管理员重置密码时同样要求两次输入一致。重置成功后，服务端清除该账号已有的 refreshToken，用户需要使用新密码重新登录。

## 安全设计

### 密码存储
- 使用 `bcryptjs` 以 10 轮 salt 哈希存储
- `findByUsername()` 返回完整用户记录（含 password 哈希）供登录比对
- `findById()` 和 `profile()` 不暴露 password 字段

### 令牌安全
- AccessToken 有效期：24 小时（配置于 `JWT_EXPIRES_IN`）
- RefreshToken 有效期：7 天，用于无感刷新
- RefreshToken 以 bcrypt 哈希存储在 DB，即使 DB 泄露也无法直接使用
- 退出登录时清除 refreshToken，使旧 refreshToken 失效

### 401 处理（前端）
- `api.ts` 自动拦截 401 响应，清除 localStorage 并重定向到 `/login`
