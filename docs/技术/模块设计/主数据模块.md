# 主数据模块设计

> 版本：v1.0-draft | 日期：2026-07-03

## 整体思路

以 **合作伙伴 (Partner)** 为中心，将原来的 Supplier 表升级为统一的企业主体管理，通过角色区分供应商/客户。所有主数据实体遵循统一规范：编码唯一、软删除、状态管理。

---

## 一、合作伙伴 (Partner)

将原有的 `Supplier` 升级为 `Partner`，一个企业可同时扮演多个角色。

### 合作伙伴编码规则

| 类型 | 位数 | 字符集 | 生成方式 | 示例 |
|------|------|--------|---------|------|
| **内部企业** | 6 位 | 字母+数字 | 手工录入，数据库唯一校验 | `100000`、`200001` |
| **外部企业** | 8 位 | 纯数字 | 系统自动生成（递增序列），可切换为手工输入 | `80000001`、`80000125` |

### Partner 表

| 字段 | 类型 | 说明 |
|------|------|------|
| id | String (cuid) | 主键 |
| code | String (unique) | 合作伙伴编码，编码规则见下方 |
| name | String | 企业全称「唯一校验：name + taxId」 |
| shortName | String? | 简称 |
| taxId | String? | 统一社会信用代码「唯一校验：name + taxId」 |
| legalPerson | String? | 法定代表人 |
| contactPerson | String? | 联系人 |
| contactPhone | String? | 联系电话 |
| address | String? | 注册地址 |
| bizAddress | String? | 经营地址 |
| sourceRegion | String? | 货源地（萤石产地：金华、武义、福建等） |
| creditLimit | Decimal? | 授信额度 |
| roles | String[] | 角色数组，多选：SUPPLIER / CUSTOMER |
| status | String | ACTIVE / INACTIVE / BLACKLIST |
| remark | String? | 备注 |
| createdAt/updatedAt/deletedAt | | |

> 角色是 Partner 的属性（字段），非独立关联表。创建时通过勾选多选确定角色。
> 唯一性校验：`@unique([taxId, name])`，统一社会信用代码 + 企业名称联合唯一。

### 角色类型说明

| 类型 | 说明 | 示例 |
|------|------|------|
| SUPPLIER | 外部供应商 | 萤石矿企、运输公司 |
| CUSTOMER | 外部客户 | 钢厂、氟化工企业 |
| CARRIER | 承运商 | 物流车队 |
| INTERNAL | 内部企业 | 集团子公司、分公司、内部业务部门 |

### 对 Contract 的影响

原有 Contract 的 `supplierId` 改为引用 `Partner`，新增 `buyerId` 也引用 `Partner`。这样一份合同可以做：
- 采购合同：Partner(供应商/SUPPLIER) → 我方内部企业(INTERNAL)
- 销售合同：我方内部企业(INTERNAL) → Partner(客户/CUSTOMER)
- 内部调拨：内部企业A(INTERNAL) → 内部企业B(INTERNAL)
- 双边合同：上下游都是 Partner

## 二、物料 (Material) — 增强

萤石贸易中物料需要区分品级和规格。

### MaterialCategory（物料分类）

| 字段 | 说明 |
|------|------|
| id | |
| name | 分类名称，如"萤石粉"、"萤石块矿" |
| parentId | 父级分类，支持二级分类 |
| sort | 排序 |

### Material（改进字段）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | String | |
| code | String (unique) | 物料编码，如 `MT-000001` |
| name | String | 物料名称 |
| categoryId | String | 关联 MaterialCategory |
| grade | String | 品级/规格描述，如"CaF₂≥97%" |
| unit | String | 单位，默认为 TON |
| spec | String? | 规格参数，如"-200目" |
| sourceRegion | String? | 主要产地 |
| packageType | String? | 包装方式（散装/吨袋/小包装） |
| status | String | ACTIVE / INACTIVE |
| remark | String? | |

示例数据：

| name | category | grade | unit |
|------|----------|-------|------|
| 萤石粉 | 萤石粉 | CaF₂≥97% | TON |
| 萤石粉 | 萤石粉 | CaF₂≥95% | TON |
| 萤石块矿 | 萤石块矿 | CaF₂≥85% | TON |
| 萤石砂 | 萤石砂 | CaF₂≥90% | TON |

| 字段 | 类型 | 说明 |
|------|------|------|
| id | String | |
| plateNo | String (unique) | 车牌号 |
| vehicleType | String | 车型：TRUCK（自卸车）/ TANK（罐车）/ TRAILER（挂车） |

| driverPhone | String? | 驾驶员电话 |
| status | String | ACTIVE / MAINTENANCE / RETIRED |
| remark | String? | |

## 六、设计决策记录

| 决策 | 选项 | 选择 | 理由 |
|------|------|------|------|
| 供应商/客户分表还是统一 | 分表 / 统一 Partner | **统一 Partner** | 一家企业可能同时是供应商和客户，统一管理避免数据冗余 |
| 物料分类用字段还是表 | 字段 / 分类表 | **分类表** | 大宗贸易物料分类层次清晰，分类表便于筛选和日后扩展 |
| 价格信息 | 单独表 | **暂缓，放在后续行情模块** | 价格数据量和分析需求超出现有范围，一期先保证基础 CRUD 可用 |
