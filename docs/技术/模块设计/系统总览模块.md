# 系统总览模块设计

## 1. 定位

系统总览是登录后的实时业务汇总页，不自行产生业务数据，也不保存一套与业务单据重复的统计数据。页面每次打开或用户手动刷新时，由后端基于当前业务表实时聚合。

## 2. API

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/dashboard/overview` | 返回当前账号可见的总览指标、异常和最近动态 |

## 3. 当前统计口径

| 指标 | 数据来源 | 口径 |
|------|---------|------|
| 本月采购入库量 | `BusinessInbound` | 本月已过账且未取消的入库数量 |
| 当前在途车辆 | `Waybill` | 状态为 `IN_TRANSIT` 的有效运单数 |
| 当前账面库存 | `InventoryLot` | 可用数量大于 0 的批次账面余额合计 |
| 待处理异常 | 运单、磅单、质检单 | 在途超过计划到达时间、磅差异常、质检拒收数量之和 |
| 主流程进度 | 执行批次、运单、磅单、质检、入库、出库 | 各业务模块当前待办或执行中数量 |
| 最近业务动态 | 合同、运单、磅单、质检、业务入库 | 各模块最近变更合并排序，可直接跳转单据详情 |

结算与监控模块尚未形成业务数据，系统总览不显示模拟数字。

## 4. 权限与数据范围

- 统计前先判断当前账号是否拥有对应模块查看权限，无权模块不执行业务查询，前端显示“无查看权限”。
- 合同使用 `getContractScope`，执行、通知、运单、磅单、质检和库存通过单据链逐级继承同一数据范围。
- 外部企业账号仅汇总其关联合作伙伴作为卖方、买方或签约主体的合同及下游数据。
- 系统管理员可查看全平台统计。

## 5. 前端交互

- 页面首次进入自动请求真实数据，顶部显示数据生成时间。
- “刷新数据”按钮可重新执行聚合查询。
- 异常、模块卡片和最近动态均可跳转对应业务页面。
