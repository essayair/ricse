# 质检单模块设计

> 版本：v1.0 | 日期：2026-07-21

## 目标与边界

质检单承接已完成磅单，采用“单机构、单报告、单质检单”模型记录取样、检测指标、扣水扣杂和质量结论，为业务入库及结算提供质量依据。第一版支持人工/设备/OCR来源标记和附件留存，不包含真正的 OCR 服务、化验设备直连及质检规范独立配置后台。采购入库作业单已在运单确认发运时提前生成，确认合格质检会补齐其最终验收依据，而不是再创建一张新入库单。

## 单据关系

```text
合同 → 合同执行批次 → 执行通知 → 物流运单 → 磅单 → 质检单
                                                    ├─ 动态质检指标
                                                    └─ 分类附件
```

- 一张完成称重或已复核的磅单可以产生任意多张质检单。
- 每张质检单仅对应一个检测机构和一份报告；不同机构报告通过同一 `weighTicketId` 归组。
- 合作方或第三方检测机构必须从服务生态主数据选择；质检单保存 `institutionPartnerId` 并保留 `institutionName` 名称快照。
- 质检单保存物料、供应商、车牌和基准重量快照，避免上游主数据变化影响历史凭证。

## 数据模型

### QualityInspection

保存质检编号、关联磅单、机构类型、机构名称、报告编号、检测时间、状态、结论、取样/留样、业务快照、扣减结果、熔断处理、确认人和审计时间。

### QualityInspectionIndicator

每行保存指标编码、名称、比较符、标准值、范围上限、熔断值、单位、本机构检测值和判定结果。`inspectionId + code` 唯一。

### Attachment

通过 `qualityInspectionId` 关联质检单，新数据类别为 `REPORT`、`SAMPLE_PHOTO` 或 `OTHER`；接口兼容第一版遗留的机构分类附件值。

## 状态与结论

状态：`DRAFT → TESTING → REPORTED → CONFIRMED`，未确认前可以转为 `VOIDED`。结论独立保存为 `PENDING`、`PASS`、`DEDUCTION` 或 `FUSE`；其中只有 `CONFIRMED + PASS` 可以作为入库依据，`DEDUCTION` 仅表示超标扣款并暂停入库。

判定优先级为熔断 > 超标扣款 > 合格。`GTE` 在实测值低于熔断值时熔断，`LTE` 在实测值高于熔断值时熔断；否则按标准值判断合格或超标。

## API

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/quality-inspections` | 分页及组合检索 |
| GET | `/quality-inspections/eligible-weigh-tickets` | 查询可创建质检单的磅单 |
| POST | `/quality-inspections` | 创建质检单并计算结论 |
| GET | `/quality-inspections/:id` | 查看完整质检单和上游链路 |
| PATCH | `/quality-inspections/:id/status` | 出报告、确认或作废 |
| POST | `/quality-inspections/:id/attachments` | 上传分类附件 |
| GET | `/quality-inspections/attachments/:id/view-url` | 获取附件查看地址 |
| DELETE | `/quality-inspections/attachments/:id` | 删除未锁定附件 |

列表 `search` 同时匹配质检编号、检测机构、报告号、物料、供应商、车牌、磅单、运单及执行批次名称/编号；`status`、`conclusion`、`dateFrom`、`dateTo` 可组合使用。详情接口额外返回同一磅单下的其他质检单摘要。

## 一致性与安全

- 创建时只校验磅单是否完成称重或已复核，不限制同磅单质检单数量。
- 提交报告必须存在至少一个指标，且本机构所有检测值完整。
- 已确认/已作废质检单附件锁定。
- 文件仅接受 JPG、JPEG、PNG、WEBP 和 PDF，限制为 20 MB；存储写入失败不创建附件记录，数据库写入失败会清理对象文件。
- 熔断质检单确认必须填写处理方案并记录确认人、确认时间。
- 采购质检进入 `CONFIRMED + PASS` 后，第一张合格单自动成为既有入库作业单的最终验收依据；仓管可在待入库阶段改选同运单下其他已确认合格单。

## 测试范围

- 指标上下限、扣款与熔断判定。
- 关键词、状态、结论和日期的组合检索条件。
- TypeScript 前后端静态检查。

## 权限与数据范围

- 候选磅单、列表、详情、同车其他报告和附件查看使用 `quality.view`。
- 创建、状态操作和附件增删使用 `quality.manage`。
- `QualityInspection` 通过 `weighTicket.waybill.dispatchNotice.order.contract` 继承合同范围。
- 详情中的同磅单其他质检单天然属于同一合同链，但入口质检单仍必须先通过范围校验。
- 附件查看和删除在附件关系中同时约束质检单范围，不能通过附件 ID 越权。

统一实现见[角色权限与数据范围](./角色权限与数据范围.md)。
