# 到货质检任务模块设计

> 版本：v3.0 | 日期：2026-08-27

## 目标与边界

质检模块采用“到货质检任务 + 机构检测报告 + 最终质检结论”三级口径。一辆物流运单确认到达后，系统幂等生成一条到货质检任务；质检管理人员在任务内录入一份或多份机构检测报告，确认有效报告后形成一次任务级最终结论。当前版本不拆分取样员、送检员和判定员角色，拥有 `quality.manage` 权限的人员可以完成全部线上操作。

## 单据关系

```text
合同 → 执行批次 → 执行通知 → 物流运单（确认到达）
                                  ├─ 运单级磅单信息 → 发货/收货磅单
                                  └─ 到货质检任务（一条）
                                      ├─ 机构检测报告 1 → 指标 + 附件
                                      ├─ 机构检测报告 2 → 指标 + 附件
                                      ├─ 机构检测报告 N → 指标 + 附件
                                      └─ 最终质检结论 → 入库/结算执行口径
```

- `QualityTask.waybillId` 唯一，保证重复确认到达或消息重试不会生成重复任务。
- 计划报告数默认 1，可调整为 2 份、3 份或更多；每份机构检测报告对应一家检测机构、一个样品编号和一套指标结果。
- 列表一行对应一条到货质检任务，不再让每份机构报告占据管理列表一行。
- 最终结论保存参与判定的全部有效报告 ID，并指定一份“执行口径报告”为入库扣重及结算提供数值快照。

## 数据模型

### QualityTask

保存任务编号、物流运单、计划报告数、取样摘要、当前处理人、结构化质检模板及快照、任务状态、最终结论、执行口径报告、参与判定报告、判定原因、版本、判定人和判定时间。

状态为：`PENDING_SAMPLING`（待取样）、`PENDING_SENDING`（待送检）、`INSPECTING`（检测中）、`PENDING_DECISION`（待综合判定）、`COMPLETED`（已完成）、`RECHECK_REQUIRED`（新增结果待复判）、`EXCEPTION`（异常处理中）、`VOIDED`（已作废）。

### QualityInspection（机构检测报告）

保留原表名以兼容既有接口，业务含义调整为“机构检测报告”。保存 `qualityTaskId`、关联磅单、样品编号、机构、报告编号、指标、机构结论、扣水扣杂、附件、确认人和确认时间。

### QualityInspectionIndicator / Attachment

指标行同时保存指标定义 ID、检测方法 ID 及编码/名称快照，防止主数据后续修改影响历史报告。机构报告附件支持 JPG、JPEG、PNG、WEBP、PDF。

任务级现场影像通过 `Attachment.qualityTaskId` 关联，保存 `sourceType`、`evidenceNode`、`capturedAt`、`uploadedBy`、`fileHash` 和 `watermarkText`。文件哈希用于完整性核验，水印文本快照记录任务号、运单号、车辆、物料、计划重量、拍摄节点和时间。

### 质检标准模型

- `QualityIndicatorDefinition`：检测指标字典。
- `QualityMethod`：检测方法与标准号。
- `QualityIndicatorMethod`：指标允许使用的方法及默认方法。
- `QualityTemplate` / `QualityTemplateItem`：场景化模板和指标阈值。
- `QualityMethodPreference`：按“用户 + 物料 + 指标”保存最近检测方法。
- `Material.qualityTemplateId`：物料显式绑定模板；未绑定时按物料分类和业务场景回退解析。

## 自动创建与处理

1. 物流运单从“在途”进入“已到达”时调用 `ensureTaskForWaybill`。
2. 系统按 `waybillId` 查找既有任务；存在则直接返回，不存在才创建 `QT-日期-流水号` 任务。
3. 初始状态为“待取样”，计划报告数为 1；尚未过磅时任务仍可作为待办展示，同时固化质检模板快照。
4. 磅单完成称重后，质检管理人员进入任务追加机构检测报告。
5. 报告确认有效后，任务进入“待综合判定”。至少一份有效报告即可判定；少于计划数量必须填写提前判定原因并二次确认。
6. 最终结论确认后记录版本、报告范围和执行口径报告。新增报告不会静默覆盖既有结论，而是使任务进入“待复判”。

## 入库联动

- 单份机构报告确认不再直接驱动入库。
- 任务最终结论为“合格”时，系统以所选执行口径报告补齐既有入库作业单的质量依据、扣水扣杂及最终数量。
- “超标扣款”“熔断”和“待判定”继续禁止直接形成系统库存。
- 有效磅单决定净重基数；任务级最终质检结论决定质量结果，执行口径报告提供扣水、扣杂和扣款数值。

## API

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/quality-tasks` | 到货质检任务分页及组合检索 |
| GET | `/quality-tasks/:id` | 任务详情、运单磅单和全部机构报告 |
| PATCH | `/quality-tasks/:id/sampling` | 登记取样信息和计划报告数 |
| POST | `/quality-tasks/:id/attachments` | 上传任务级现场影像 |
| GET | `/quality-tasks/attachments/:id/view-url` | 获取任务影像查看地址 |
| PATCH | `/quality-tasks/:id/finalize` | 二次确认形成任务级最终结论 |
| GET/POST/PATCH | `/quality-standards/indicators` | 检测指标查询、创建和维护 |
| GET/POST/PATCH | `/quality-standards/methods` | 检测方法查询、创建和维护 |
| GET/POST/PATCH | `/quality-standards/templates` | 质检模板查询、创建和维护 |
| GET | `/quality-standards/resolve` | 按物料与场景解析模板及用户方法偏好 |
| PUT | `/quality-standards/preferences` | 保存用户最近检测方法 |
| GET | `/quality-inspections/eligible-weigh-tickets` | 查询可关联的完成/复核磅单 |
| POST | `/quality-inspections` | 在指定任务下新增机构检测报告 |
| PATCH | `/quality-inspections/:id/status` | 确认或作废机构检测报告 |
| POST | `/quality-inspections/:id/attachments` | 上传机构报告附件 |
| GET | `/quality-inspections/attachments/:id/view-url` | 获取当前页预览地址 |
| DELETE | `/quality-inspections/attachments/:id` | 删除未锁定附件 |

小程序使用受 `MobileUserGuard` 保护的 `/mobile/quality-tasks/:id/attachments` 上传接口，必须先关联有效后台账号并具备 `quality.manage`。

## 权限与数据范围

- 查看任务、报告和附件使用 `quality.view`；录入、确认、最终判定和附件维护使用 `quality.manage`。
- 当前不增加取样、送检、复核等细分角色，`quality.manage` 是统一质检管理权限。
- `QualityTask` 通过 `waybill.dispatchNotice.order.contract` 继承合同企业范围；机构报告通过任务和磅单继承相同范围。
- 首页“到货质检”待办按未完成任务统计，可直接进入任务详情处理。

统一实现见[角色权限与数据范围](./角色权限与数据范围.md)。
