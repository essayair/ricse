# 业务操作记录

## 1. 目标

RICSE 的核心业务单据必须能够回答三个问题：谁创建、谁操作、何时执行了什么动作。操作轨迹属于单据信息的一部分，用于业务追溯、异常核对和责任界定，不作为业务状态或权限判断的替代数据。

## 2. 覆盖范围

统一操作记录当前覆盖：

- 合同、合同执行批次、执行通知；
- 物流运单、磅单、质检任务；
- 入库单、出库管理单、库存冲销单；
- 生产任务及其领料、耗用、退料、完工、质量确认和过账动作。

后续新增核心业务单据时，应接入同一机制，不再为每个模块单独设计操作日志表。

## 3. 数据模型

`business_operation_logs` 保存：

| 字段 | 说明 |
|---|---|
| `businessType` | 单据类型，如 `CONTRACT`、`WAYBILL` |
| `businessId` | 业务单据 ID |
| `action` | 稳定的动作代码 |
| `actionLabel` | 面向用户展示的中文动作名称 |
| `operatorId` | 实际操作账号 |
| `details` | 状态、原因、备注、结论等必要补充信息 |
| `createdAt` | 操作发生时间 |

操作记录不保存密码、令牌、附件内容、完整请求体或其他无关隐私数据。

## 4. 记录与查询机制

- 认证后的核心业务新增、修改、删除、状态变化及关键动作，由统一拦截器在业务成功后写入记录。
- 子单据动作优先归集到用户实际查看的主单。例如检测报告操作归集到质检任务，出库车次作业归集到出库管理单，生产完工操作归集到生产任务。
- 详情服务先执行原有权限与数据范围检查；校验成功后，统一附加 `operationLogs`，避免通用日志接口绕过单据访问控制。
- 写日志失败不会把已经成功的业务操作返回为失败，防止用户重试造成重复单据；服务端同时输出错误日志供运维处理。
- 数据库迁移为既有核心单据回填“创建”记录；自动生成的新单据若尚无创建日志，详情仍使用单据 `creator/createdBy/createdAt` 形成创建记录。

## 5. 前端展示

主要业务详情页统一展示“操作记录”板块，按时间倒序显示：

- 动作名称；
- 操作人员姓名和登录账号；
- 操作时间；
- 原因或备注（存在时）。

审批任务的会签、或签和处理意见仍由审批记录展示；合同操作记录用于补充提交、撤回、状态变化等单据层动作，两者不互相替代。
