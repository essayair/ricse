# 移动端任务提醒 MVP

## 1. 目标

在不改变合同审批和现场作业状态机的前提下，为微信小程序提供统一任务提醒。业务单据是事实来源，提醒数据仅用于触达、未读展示和页面跳转。

首期覆盖：

- 合同审批；
- 过磅任务；
- 质检任务；
- 入库作业；
- 出库作业。

## 2. 工作方式

API 进程每分钟扫描一次有效待办，并按 `业务类型 + 业务ID + 接收用户` 幂等生成通知。任务完成、取消或失效后，通知自动进入“已完成”。扫描和微信接口异常均不得阻断业务操作。

接收规则：

- 合同审批：使用审批快照中的 `assigneeId`，确保通知人与实际审批人一致；
- 质检任务：已指定处理人时优先通知处理人；
- 其他现场任务：通知同一业务单元中拥有对应管理权限的人员；
- 尚未完成岗位授权或无法解析人员时，回退通知任务创建人；
- 系统管理员不会因为拥有全部权限而默认收到全部现场提醒。

## 3. 小程序交互

- 工作台企业信息卡右上角显示消息入口和未读数量；
- 消息中心分为“待处理”和“已完成”；
- 点击消息先标记已读，再进入对应审批或现场任务详情；
- 用户通过明确点击“开启微信提醒”调用微信订阅授权；
- 用户拒绝授权或模板未配置时，站内消息和工作台待办仍正常使用。

## 4. 微信配置

在微信公众平台为小程序选择“待审批通知”和“工作任务待办通知”两个订阅消息模板，并在服务器部署变量中配置：

```env
WX_SUBSCRIBE_APPROVAL_TEMPLATE_ID=
WX_SUBSCRIBE_TASK_TEMPLATE_ID=
WX_MINIPROGRAM_STATE=formal
```

当前发送参数约定：

| 模板 | 模板字段 | 含义 |
| --- | --- | --- |
| 待审批通知 | `thing2` | 审批类型 |
| 待审批通知 | `time3` | 发送时间 |
| 待审批通知 | `thing4` | 备注 |
| 工作任务待办通知 | `thing1` | 待办类型 |
| 工作任务待办通知 | `thing2` | 待办内容 |
| 工作任务待办通知 | `time3` | 时间 |

如公众平台实际模板字段不同，应同步修改发送字段映射后再启用。模板未配置时服务不会调用微信发送接口。

## 5. 可靠性边界

微信订阅消息取决于用户主动授权，不能作为唯一任务来源。小程序工作台与消息中心始终以 RICSE 数据库中的业务状态为准。发送失败最多自动尝试三次，失败原因保留在通知记录中，便于后续排查。
