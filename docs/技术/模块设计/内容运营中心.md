## 2. 运行架构

代码统一在 RICSE Monorepo，运行时采用三个独立进程/容器：

```text
                         ┌─ core-api
                         │  合同、审批、物流、库存、生产
Nginx ───────────────────┤
                         ├─ content-api
                         │  内容后台、公开内容、行情、微信、实时 AI
                         │
                         └─ content-worker
                            批量 AI、行情采集、Excel 导入

PostgreSQL ─ 业务表 + 内容表（逻辑隔离）
Redis      ─ 缓存 + BullMQ 任务队列
MinIO      ─ ricse-attachments + content-assets
```

三进程可使用同一 Docker 镜像，通过不同启动命令加载不同 Nest Module。内容 API 和 Worker 使用独立数据库连接池，禁止直接修改合同、库存等核心表。

## 4. 数据模型

### 4.1 ContentCategory

- `id`：RICSE 内部 ID。
- `legacyId`：旧系统数字 ID，迁移和历史链接兼容使用。
- `name`、`code`、`sort`、`status`。

### 4.2 ContentArticle

- 基础：`title`、`summary`、`content`、`coverUrl`、`source`、`author`。
- 分类：`categoryId`、`tags`。
- 类型：`NEWS`、`SUPPLY`、`DEMAND`。
- 状态：`DRAFT`、`PENDING_REVIEW`、`PUBLISHED`、`REJECTED`、`OFFLINE`。
- 来源追溯：`dataSourceId`、`externalId`、`sourceUrl`、`sourcePublishedAt`、`collectedAt`、`rawData`。
- 形成方式：`ingestionMode` 区分 `MANUAL`、`AUTO`、`IMPORT`、`MIGRATION`。
- 审核：`reviewedById`、`reviewedAt`、`reviewNote`；用于人工内容和供需审核，生意社自动采集资讯不经过人工审核。
- 供需扩展：商品、规格、数量、价格、地区、交货方式、要求、企业和联系人。
- 发布：`publishAt`、`publishedBy`、浏览量、点赞数。
- 兼容：`legacyId` 保留旧文章地址使用的数字 ID。

### 4.3 ProductType / ProductPrice

- 产品类型维护产品名称、编码、规格和状态。
- 价格记录业务日期、地区、市场、规格、价格、单位、来源及原始数据。
- 唯一约束覆盖“产品 + 市场/地区 + 规格 + 业务日期 + 来源”。

### 4.4 WebsiteContact

- 姓名、电话、企业、邮箱、留言、来源页面、状态、负责人和跟进备注。
- 公开创建接口限流；后台查询和处理必须鉴权。

### 4.5 SupplyDemandPost

- 供应/需求、商品、规格、数量、价格、地区和描述。
- 联系人、手机号、企业和微信 OpenID 仅后台或本人可见。
- 状态、驳回原因、来源、发布时间和审核人完整留痕。

### 4.6 ContentAsset

- 复用 RICSE `FileService` 与 MinIO 客户端，使用 `content/` 对象前缀。
- 记录对象键、原文件名、MIME、大小、用途和关联内容。
- 迁移时扫描并转存旧封面和正文内嵌媒体。

### 4.7 ContentJob

- 类型、业务唯一键、状态、参数、执行次数、下次重试时间。
- 开始/结束时间、成功数量、失败数量、错误摘要和日志引用。
- 支持幂等、人工重试、暂停和取消。

### 4.8 ContentDataSource

- `SUNSIRS_FLUORITE_NEWS`（生意社萤石情报 `pid=318`）是唯一产业资讯来源，以 `ACTIVE/API/PUBLIC_HTML` 登记。列表页、分页参数和详情选择器由原 `spiderworks/NewsSpider` 迁移，采集执行位置改为独立 Content Worker。
- `FLUORSPAR_COM_NEWS`、`GDELT_FLUORITE_NEWS` 与 `SMM_INDUSTRY_RSS` 全部停用并取消调度；其配置和历史任务只为审计保留，不再参与聚合采集。
- 聚合任务只要存在来源失败即标记为 `PARTIAL`，全部失败才标记为 `FAILED`；所有来源正常但无新增内容仍为 `SUCCEEDED`，结果中明确记录 `NO_NEW_DATA`、过滤数和重复数。
- 每个资讯源独立维护状态、Cron、查询表达式或订阅地址、行业关键词、排除词、排除域名和最近成功/异常。
- Worker 启动时为每个已启用资讯源注册独立 BullMQ Scheduler；修改或启停数据源后即时刷新调度器。
- RSS 请求只允许 HTTPS 且域名必须在 `NEWS_SOURCE_ALLOWED_HOSTS` 中；所有重定向逐次复验，禁止访问本机和私网地址，单次响应上限 5MB。

## 6. 任务执行与故障隔离

- Redis + BullMQ 承载可重试队列和周期任务。
- `NEWS_SYNC` 由 `content-worker` 执行：按来源外部 ID、规范化原文 URL 和标题哈希三层去重；生意社新资讯直接创建为 `PUBLISHED`，并以原文发布时间写入 `publishAt`，官网和小程序可立即读取。
- 生意社调度表达式为 `0 8,12,17 * * *`，调度时区固定为 `Asia/Shanghai`。自动发布文章的 `publishAt` 写入 `sourcePublishedAt`；统一查询按 `publishAt DESC, createdAt DESC` 返回，避免同批采集产生倒序。
- 产业资讯只访问生意社固定公开列表和详情路径。请求使用 `RICSE-Content-Collector` 透明标识，不复制旧版伪装 Chrome 的 `Sec-*` 请求头，不复用安全挑战 Cookie；检测到安全检查时立即失败并进入任务异常处理。
- 入库时统一写入来源名称、原文链接、外部编号、发布时间、采集时间与原始响应摘要，并按外部编号、规范化链接、标题哈希三层去重。
- 自动采集某一来源失败时记录该数据源错误并继续处理其他来源；只有全部来源失败时任务标记失败并按指数退避重试。
- 资讯清洗默认并发 1；同一文章内容版本只处理一次。
- 百川同一数据源只允许一个采集任务运行，先写临时结果，完整校验后替换当前有效版本。
- 百川萤石行情默认按 `Asia/Shanghai` 时区每日 06:00 执行；每次读取近 180 天导出数据并按“产品、日期、地区、来源、市场”幂等更新，首次接入或历史缺失时可自动补齐趋势数据。
- 百川登录失效同时兼容 HTTP 401/403 与 HTTP 200 中的业务层失效码；配置专用采集账号后自动续期一次，避免将人工浏览器会话作为后台定时任务的长期凭据。
- 开发、测试或生产环境未配置百川凭据时，Worker 会移除百川定时调度、跳过启动同步并在数据源中记录“自动采集已暂停”，不再生成无意义的重试任务；补齐凭据并重启 Worker 后自动恢复。
- Business Analytiq 采集不绕过付费下载：日常任务只读取页面明确披露的当月区域价格摘要；趋势初始化另使用互联网档案馆中可核验的 Business Analytiq 公开页面历史快照，当前基线为 2023-05、2024-12、2025-03、2025-09、2026-02。不得从趋势缩略图反算价格，也不得把涨跌幅推算点标记为真实历史。任务类型为 `HF_MARKET_SYNC`，默认每天 06:15 检查一次，同月同区域幂等更新。
- fluorspar.com 趋势任务类型为 `FLUORSPAR_TREND_SYNC`，默认每天 06:05 执行；区域映射固定为华中 `cn_vp`、华东 `eu_fv`、北方 `eu_vp`。同日重复点以后返回值覆盖前值，日涨跌绝对值达到 10% 时写入 `LARGE_CHANGE` 质量标记但不修改来源价格。
- 数字大屏通过自身同源 `/ricse-api/**` 代理访问 RICSE HTTPS API，禁止在浏览器端写死 HTTP IP；第三方页面和 Google 图表不直接嵌入大屏。
- 第三方请求必须设置连接和总超时；重试采用指数退避和随机抖动。
- 连续失败触发熔断；查询端降级到最近一次成功数据。
- 超过重试次数的任务进入失败队列，由内容运营人员人工重试。
- `content-worker` 设置 CPU/内存/并发上限，不能挤占 `core-api` 的保留资源。
- `content-worker` 同时加入仅用于第三方访问的 `egress` 网络；交易 API、PostgreSQL、Redis 和 MinIO 继续位于 `backend` 内部网络。禁止为了采集方便取消 `backend` 的内部网络隔离。

## 7. 数据迁移

1. 旧资讯已经迁入 `content_articles` 并标记 `MIGRATION`；`LEGACY_NEWS` 保持停用，不再调用旧后端。
2. RICSE 只保留 `SUNSIRS_FLUORITE_NEWS` 作为产业资讯采集入口；旧来源不再运行，新任务与旧接口无兼容或转发关系。
3. 产品价格和行情统一进入 `content_product_types`、`content_product_prices`，百川采集必须使用 RICSE Worker 的直连凭据，不允许回退旧 `3001` 服务。
4. 萤石进出口快照迁入 `content_industry_datasets`，公开代码为 `FLUORITE_IMPORT_EXPORT`。
5. 封面、正文图片和附件统一存储到 MinIO `content/` 前缀。
6. 历史数据保留 `legacyId` 仅用于追溯，不继续暴露旧路径。

迁移脚本必须幂等，重复执行不得生成重复内容。旧服务停止后若发现缺少数据，应通过 RICSE 导入任务补录，禁止恢复默认转发。

## 8. 上线与回滚

1. 测试环境同时运行 RICSE `core-api`、`content-api` 和 `content-worker`。
2. 官网、小程序、数字大屏全部使用 `/api/v1/**` 并完成回归测试。
3. Nginx 不保留旧接口路由别名，也不设置旧后端兜底。
4. 停止旧 Java `48080` 和小程序 NestJS `3001` 服务；旧数据库和代码仅作离线归档。
5. 异常通过 RICSE 日志、任务记录和新接口修复，不将流量切回旧服务。

## 9. 安全约束

- 原公开 Excel 上传和刷新入口必须收回为后台权限接口。
- 公开资讯详情必须校验已发布状态，禁止草稿泄漏。
- DeepSeek、微信、百川凭据只允许通过环境变量/密钥服务注入。
- 百川优先使用现有 Token；临期或收到 401/403 时，使用服务器密钥变量中的账号密码自动续期，真实凭据不得写入仓库。
- AI、登录、咨询和供需提交分别限流，避免滥用和费用失控。
- 富文本保存前和展示前执行白名单清洗，阻断 XSS。
- 日志不得记录微信密钥、DeepSeek Key、百川密码、完整 Token 或联系人隐私。
- 国际价格响应保留来源 URL、数据月份和采集时间；源站失败时不删除最近一次成功记录。
