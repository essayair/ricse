# 内容运营中心模块设计

> 版本：v1.0
> 日期：2026-08-20
> 状态：开发中

## 1. 现状与迁移来源

| 来源项目 | 当前能力 | 迁移结果 |
|---|---|---|
| `website-admin-dashboard` | 资讯、供需型资讯、官网合作咨询管理 | 改写为 RICSE Next.js 页面 |
| `hgchain-server` | 官网资讯、分类、价格、产品类型、咨询、萤石 Excel 接口 | 数据迁入 PostgreSQL，接口改写为 NestJS |
| `hgchain-server-17` | Java 17 升级分支及区域均价接口 | 不作为独立来源运行，仅补齐必要接口能力 |
| `fyzs-mini-app/server` | 资讯同步、AI 清洗、百川行情、AI 对话、微信登录、供需 JSON | API 和 Worker 迁入 RICSE |
| `sci99` | 已停用行情源 | 不启用，仅归档参考 |

旧若依框架的系统模块、Quartz 示例任务和无关业务模块不迁移。

## 2. 运行架构

代码统一在 RICSE Monorepo，运行时采用三个独立进程/容器：

```text
                         ┌─ core-api
                         │  合同、审批、物流、库存、生产
Nginx ───────────────────┤
                         ├─ content-api
                         │  内容后台、公开内容、行情、微信、实时 AI
                         │
                         └─ content-worker
                            资讯同步、批量 AI、行情采集、Excel 导入

PostgreSQL ─ 业务表 + 内容表（逻辑隔离）
Redis      ─ 缓存 + BullMQ 任务队列
MinIO      ─ ricse-attachments + content-assets
```

三进程可使用同一 Docker 镜像，通过不同启动命令加载不同 Nest Module。内容 API 和 Worker 使用独立数据库连接池，禁止直接修改合同、库存等核心表。

## 3. 当前外部任务清单

| 能力 | 当前触发方式 | 当前运行位置 | 目标位置 |
|---|---|---|---|

| 百川行情下载/Excel 解析 | 用户查询、AI 工具调用触发，24 小时文件缓存 | `fyzs-server` PM2 单进程 | `content-worker` 定时采集 |

## 4. 数据模型

### 4.1 ContentCategory

- `id`：RICSE 内部 ID。
- `legacyId`：旧系统数字 ID，迁移和历史链接兼容使用。
- `name`、`code`、`sort`、`status`。

### 4.2 ContentArticle

- 基础：`title`、`summary`、`content`、`coverUrl`、`source`、`author`。
- 分类：`categoryId`、`tags`。
- 类型：`NEWS`、`SUPPLY`、`DEMAND`。
- 状态：`DRAFT`、`PUBLISHED`、`OFFLINE`。
- 供需扩展：商品、规格、数量、价格、地区、交货方式、要求、企业和联系人。
- 发布：`publishAt`、`publishedBy`、浏览量、点赞数。
- 兼容：`legacyId` 保留旧文章地址使用的数字 ID。

### 4.3 ProductType / ProductPrice

- 产品类型维护产品名称、编码、规格和状态。
- 价格记录业务日期、地区、市场、规格、价格、单位、来源及原始数据。
- 唯一约束覆盖“产品 + 市场/地区 + 规格 + 业务日期 + 来源”。

### 4.4 WebsiteContact

- 姓名、电话、企业、邮箱、留言、来源页面、状态、负责人和跟进备注。
- 公开创建接口限流；后台查询和处理必须鉴权。

### 4.5 SupplyDemandPost

- 供应/需求、商品、规格、数量、价格、地区和描述。
- 联系人、手机号、企业和微信 OpenID 仅后台或本人可见。
- 状态、驳回原因、来源、发布时间和审核人完整留痕。

### 4.6 ContentAsset

- 复用 RICSE `FileService` 与 MinIO 客户端，使用 `content/` 对象前缀。
- 记录对象键、原文件名、MIME、大小、用途和关联内容。
- 迁移时扫描并转存旧封面和正文内嵌媒体。

### 4.7 ContentJob

- 类型、业务唯一键、状态、参数、执行次数、下次重试时间。
- 开始/结束时间、成功数量、失败数量、错误摘要和日志引用。
- 支持幂等、人工重试、暂停和取消。

## 5. API 边界

### 5.1 运营后台

- `/api/v1/content/articles/**`
- `/api/v1/content/categories/**`
- `/api/v1/content/prices/**`
- `/api/v1/content/product-types/**`
- `/api/v1/content/contacts/**`
- `/api/v1/content/supply-demand/**`
- `/api/v1/content/data-sources/**`
- `/api/v1/content/jobs/**`

后台 API 使用 RICSE JWT、`PermissionGuard` 和内容权限字典。

### 5.2 公开接口

- `/api/v1/public/content/articles/**`
- `/api/v1/public/content/prices/**`
- `/api/v1/public/content/contacts`
- `/api/v1/public/content/supply-demand/**`
- `/api/v1/public/content/market/fluorite/regions`
- `/api/v1/public/content/market/fluorite/trend`
- `/api/v1/public/ai/**`
- `/api/v1/public/wechat/login`

公开接口只返回已发布、到达发布时间且未下线的数据。联系方式、OpenID、内部状态和运营备注不允许进入公开响应。

### 5.3 旧接口兼容

兼容入口仅委托正式应用服务，不建立第二套表和第二套业务逻辑。通过访问日志统计调用量并设置下线日期。

当前兼容入口包括 `/api/news/**`、`/api/market/baiinfo/fluorite/**`、`/api/ai/**`、`/api/auth/wx-login`、`/api/supply-demand/**`，以及旧官网资讯、价格和咨询的精确路径。Nginx 不对整个 `/app-api/website/**` 做统配覆盖，避免影响官网仍在使用的其他旧模块。

## 6. 任务执行与故障隔离

- Redis + BullMQ 承载可重试队列和周期任务。
- 资讯清洗默认并发 1；同一文章内容版本只处理一次。
- 百川同一数据源只允许一个采集任务运行，先写临时结果，完整校验后替换当前有效版本。
- 第三方请求必须设置连接和总超时；重试采用指数退避和随机抖动。
- 连续失败触发熔断；查询端降级到最近一次成功数据。
- 超过重试次数的任务进入失败队列，由内容运营人员人工重试。
- `content-worker` 设置 CPU/内存/并发上限，不能挤占 `core-api` 的保留资源。

## 7. 数据迁移

1. 从旧 MySQL 导出资讯、分类、价格、产品类型和咨询。
2. 从 `.cache/news`、`.cache/supply-demand` 和旧 Excel 文件导出文件数据。
3. 复制封面、正文图片和附件到 MinIO `content/` 前缀。
4. 以 `legacyId` 保留历史数字主键并生成 RICSE 内部 ID。
5. 在测试环境校验数量、状态、时间、正文和媒体可用性。
6. 正式切换前停止旧后台写入，执行最后一次增量导入。

`LEGACY_WEBSITE_API_BASE` 在迁移期必须指向仍由旧服务响应的直连地址，不能指向已经切到 RICSE 兼容层的公网地址。兼容层会返回识别响应头，Worker 检测到回环后自动跳过；最终增量导入完成后应在“数据源管理”停用“旧官网资讯”。

迁移脚本必须幂等，重复执行不得生成重复内容。

## 8. 上线与回滚

1. 测试环境并行启动 `content-api` 和 `content-worker`。
2. 官网、小程序切换正式新接口并完成回归测试。
3. Nginx 继续保留旧接口路由别名。
4. 正式切换时冻结旧后台、导入增量数据、切换路由。
5. 旧 Java、MySQL、PM2 服务只读保留 7～14 天。
6. 异常时仅切回 Nginx 上游；新系统变更通过增量导出回补。
7. 旧接口访问归零后停止旧服务并归档数据库和对象文件。

## 9. 安全约束

- 原公开 Excel 上传和刷新入口必须收回为后台权限接口。
- 公开资讯详情必须校验已发布状态，禁止草稿泄漏。
- DeepSeek、微信、百川凭据只允许通过环境变量/密钥服务注入。
- 百川优先使用现有 Token；临期或收到 401/403 时，使用服务器密钥变量中的账号密码自动续期，真实凭据不得写入仓库。
- AI、登录、咨询和供需提交分别限流，避免滥用和费用失控。
- 富文本保存前和展示前执行白名单清洗，阻断 XSS。
- 日志不得记录微信密钥、DeepSeek Key、百川密码、完整 Token 或联系人隐私。
