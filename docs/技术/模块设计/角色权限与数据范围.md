# 角色权限与数据范围设计

## 权限计算口径

RICSE 将账号授权拆分为两部分：

- 角色权限：决定用户可以执行哪些操作；
- 数据范围：决定该角色可以在哪些组织或企业数据上执行操作。

用户可以同时拥有多个角色。数据范围配置在用户的角色授权关系上，而不是固定在角色模板上。

授权通过的必要条件为：

```text
账号有效
  AND 至少一个有效角色包含目标功能权限
  AND 目标单据命中该用户有效授权的数据范围
```

## 数据模型

| 模型 | 作用 |
|---|---|
| `Role` | 角色模板，分系统、管理和业务角色 |
| `Permission` | `资源.操作` 格式的权限字典 |
| `RolePermission` | 角色包含的功能权限 |
| `UserRoleAssignment` | 用户获得某个角色及其数据范围 |
| `UserRoleScope` | 指定企业、部门或仓库等范围明细 |

现有 `User.role` 字段暂时保留为主角色兼容字段，所有新鉴权以有效角色授权为基础；修改用户授权时同步更新主角色，直到旧代码中的固定角色判断全部迁移完成。

## 预置角色与权限

系统预置 `ADMIN`、`APPROVER`、`MANAGER`、`SALESPERSON`、`USER` 五个角色和 24 个基础权限。管理员拥有全部权限；其他预置角色提供默认模板，系统管理员可为用户组合多个角色并配置每项授权的数据范围。

角色权限页同时支持逐项勾选和全局全选。全局全选基于权限字典接口返回的全部权限 ID 生成待保存集合；当全部权限已选中时再次点击会清空待保存集合。`ADMIN` 的全部权限由后端规则保证，前端固定显示为全选并禁止收窄。

### 配置与开发边界

| 事项 | 目标方式 | 当前实现 |
|------|----------|----------|
| 新增、编辑、停用角色 | 管理员页面配置 | API 已支持，前端入口待补 |
| 为角色组合已有权限 | 管理员页面配置 | 已支持逐项、全选、取消全选和保存 |
| 为用户授予角色及数据范围 | 管理员页面配置 | 已支持 |
| 新增权限编码 | 开发并发布 | 需增加权限字典、后端校验点、前端可见性控制和测试 |

权限编码不是普通业务字典。禁止只在数据库增加权限名称而不接入服务端鉴权，否则会形成“页面看似授权、接口实际不受控”的伪权限。

权限编码使用 `资源.操作`：

| 模块 | 查看 | 管理/专项操作 |
|------|------|---------------|
| 合同 | `contract.view` | `contract.create/edit/submit/approve/void/delete` |
| 执行 | `execution.view` | `execution.manage` |
| 物流 | `logistics.view` | `logistics.manage` |
| 磅单质检 | `quality.view` | `quality.manage` |
| 库存 | `inventory.view` | `inventory.manage` |
| 结算 | `settlement.view` | `settlement.manage` |
| 主数据 | `master_data.view` | `master_data.manage` |
| 组织系统 | `organization.view` | `organization.manage`、系统管理专项权限 |

外部企业范围是数据范围，不是角色模板。外部账号是否能创建或修改业务，仍取决于其角色是否包含管理权限。

## 外部企业账号

外部企业账号必须关联 `Company(type=EXTERNAL)`，该企业必须通过 `partnerId` 关联合作伙伴。

外部账号的数据范围固定为本企业全部关联数据，不能在授权页面切换为全平台或其他企业：

- 合同中本企业合作伙伴作为卖方；
- 合同中本企业合作伙伴作为买方；
- 合同中本企业合作伙伴作为签约主体；
- 合同下游执行批次、执行通知、物流、磅单、质检、库存和结算数据沿单据链继承。

这里的“全部”指企业级全部，不是平台级全部；同一外部企业的不同员工看到相同的企业关联数据，不限于本人创建。

外部企业未关联合作伙伴时拒绝访问业务数据，避免因为无法确认企业身份而意外放开权限。

## 范围构造与继承

`AccessControlService` 统一生成 Prisma `WhereInput`，业务 Service 将范围与自身状态、搜索条件组合：

| 目标模型 | 继承路径 |
|----------|----------|
| `Contract` | 卖方/买方/签约主体，或内部企业/部门/创建人范围 |
| `Order` | `contract` |
| `DispatchNotice` | `order.contract` |
| `Waybill` | `dispatchNotice.order.contract` |
| `WeighTicket` | `waybill.dispatchNotice.order.contract` |
| `QualityInspection` | `weighTicket.waybill...contract` |
| `InboundReceipt` | `waybill...contract` |
| `BusinessInbound` | `receipt.waybill...contract` |
| `InventoryLot` | `businessInbound.receipt...contract` |
| `InventoryLedger` | `lot.businessInbound.receipt...contract` |
| `OutboundReceipt` | `waybill...contract` |
| `SalesOutbound` | `receipt.waybill...contract` |
| `InventoryReversal` | 入库来源或出库来源范围的并集 |

附件查询必须在附件所属业务对象关系中附加同一范围，只有校验通过后才可生成对象存储临时查看地址。

## 管理约束

- 外部企业账号授权保存时强制改为 `COMPANY` 及本企业 ID。
- 外部企业不能授予 `ADMIN`。
- 一个外部企业最多 6 个有效账号。
- 系统至少保留一个有效系统管理员。
- 管理员可以处理全部当前合同审批节点；库存冲销审核支持有效 `ADMIN` 或 `APPROVER` 多角色。
- 合同只有作废后才能由管理员软删除。

## 当前接入范围

已完成：

- 角色、权限、用户授权和数据范围表；
- 5 个预置角色和 24 个基础权限；
- 现有用户角色数据迁移；
- 新建账号自动生成角色授权；
- 外部企业最多 6 个有效账号；
- 外部企业角色范围强制锁定到所属企业；
- 合同列表、详情、附件、编辑、提交、审批、作废和删除接入统一鉴权；
- 执行批次和执行通知的列表、详情、创建、修改、状态流转接入统一鉴权；
- 物流运单的列表、详情、调度、状态流转和收货附件接入统一鉴权；
- 磅单和质检单的候选单据、列表、详情、业务操作和附件接入统一鉴权；
- 物流入库、销售出库、库存批次、库存台账和库存冲销接入统一鉴权；
- 库存冲销审核读取多角色授权，系统管理员和审批人均可处理；
- 系统管理“用户与权限”页面。

单据范围继承链为：

`合同 → 执行批次 → 执行通知 → 物流运单 → 磅单 → 质检单 → 出入库 → 库存批次/库存台账/库存冲销`

后续新增结算单、发票、收付款等模块时，必须从合同或对应的出入库来源单继承同一企业范围，不允许仅按创建人过滤外部企业数据。

## 尚待接入

- 角色管理页面需补齐新增、编辑和停用入口，并复用现有 `POST/PATCH /access-control/roles` 接口。
- 合同审批人候选和节点处理需从旧 `User.role` 判断迁移为有效多角色及 `contract.approve` 权限判断。
- 主数据和组织数据目前尚未形成外部企业专属只读视图，外部账号开放前需对合作伙伴、银行账户、企业、部门和员工接口逐项接入权限与字段范围。
- 结算中心、发票、收付款尚无正式业务接口。
- 承运商、质检机构、仓储服务商作为非直接签约参与方的穿透访问需要新增参与方映射和字段级脱敏，不能直接复用合同签约方范围。
- 上述能力完成前，外部账号不得获得 `master_data.manage`、`organization.manage` 或任何系统管理权限。

## 验证基线

- 外部企业合同范围匹配卖方、买方和签约主体三种参与方式。
- 外部企业未绑定合作伙伴时拒绝访问。
- 质检等深层单据生成的 Prisma 范围完整包含合同参与方条件。
- 业务模块单元测试注入范围服务，并验证自身业务状态和数量规则不受破坏。
- 当前回归基线：16 个 API 测试套件、109 项测试通过；前后端 TypeScript 检查和生产构建通过。
