# 合同执行批次模块设计

## 目标与关系

合同执行批次是合同拆分后的具体履约计划，程序内部兼容使用 `Order`：

```text
Contract
  1:N Order
      1:N OrderLineItem
      1:N DispatchNotice
```

采购合同只生成采购执行批次，销售合同只生成销售执行批次；双边合同可分别生成采购和销售执行批次。未取消批次累计数量不得超过对应合同及方向的可执行数量。

## 标识与状态

- `name`：用户填写的业务名称。
- `orderNo`：系统自动生成的唯一编号。
- 状态：`DRAFT → CONFIRMED → DISPATCHED → COMPLETED`，草稿和已确认批次可取消。
- 草稿可修改，草稿或已取消批次可软删除。

## 权限与数据范围

- `execution.view`：列表、合同剩余可执行量、详情。
- `execution.manage`：创建、修改、状态流转和删除。
- `Order` 通过 `contractId` 继承合同数据范围，不使用 `createdBy` 作为企业范围。
- 创建时必须确认来源合同在当前用户范围内；合同候选、列表、详情和操作接口使用同一范围。
- 外部企业员工因此可以查看同企业参与合同下由其他员工创建的执行批次。

统一实现见[角色权限与数据范围](./角色权限与数据范围.md)。

## 事务与校验

- 新建批次重新汇总相同合同、相同方向的有效批次数量。
- 首次从已通过合同创建执行批次时，合同进入执行中。
- 修改批次明细时排除当前批次后重新计算剩余量。
- 状态流转按服务端状态机校验，不能依赖前端按钮限制。
