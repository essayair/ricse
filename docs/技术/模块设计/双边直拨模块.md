# 双边直拨模块

> 更新于2026-11-12；本地实现，未部署。产品口径见《2026-11-10_双边合同业务方案》。本期不含原地交割，不转换存量 DIRECT。

## 1. 数据边界

| 表/字段 | 职责 |
|---|---|
| `DirectExecution` | 一份双边合同下配对采购通知与销售通知；`createdBy + requestId` 唯一，防重复创建 |
| `DirectDelivery` | 单车交付版本、采用磅单/报告、双数量与事实快照、确认/复核/撤销记录 |
| `DirectTradeDocument` | 每版交付各一张采购业务入库和销售出库；方向唯一、数量复制同一计算结果 |
| `FinancialSettlementLine.directDeliveryId` | 商业结算与有效交付版本关联；采购、销售独立占用 |
| `Waybill.directOutcome / replacementWaybillId` | 整车拒收、转常规采购入库及后续运单追溯 |
| 合同销售号、销售签订日、销售收款约定 | 与既有采购方向字段分开保存 |
| 合同行 `pricingQuantityBasis` | 新建/修改草稿时固化物料口径，不批量覆盖已执行合同 |

主运单挂在销售通知；采购通知通过明确的 `DirectExecution` 配对关系读取同一批运单。不能只凭 `mode=DIRECT` 判定新直拨。独立直拨表没有仓库、库存批次关系，不写入 `InventoryLot`、常规仓储入出库和库存台账。

数据库迁移：`20261111090000_bilateral_direct_delivery`、`20261111110000_direct_delivery_exceptions`。本次仅应用到本地 `ricse_dev`。部分唯一索引保证一车同时最多一个待复核/已确认版本；历史版本和被撤销业务单据不删除。

## 2. 状态机与计算

```text
有效签收 + 复核采信磅单 + 任务最终采用报告
  → 预览（无入账）
  → 确认 → CONFIRMED → 两向 POSTED 业务单据
  或 → PENDING_REVIEW → 运营经理通过 → CONFIRMED
                        → 退回 → REJECTED
CONFIRMED / PENDING_REVIEW → 无有效下游引用 → REVERSED → 可生成下一版
```

- 交付取本车所选磅单净重，不取计划重量、毛重或报告中的重量。
- `PHYSICAL`：辅助计价数量等于净重；`DRY_MATTER`：净重 × (1－实测水分/100)。水分为 0 有效；缺失、重复或超范围不能当 0 使用。Decimal 保留三位，两向复制同一结果。
- 一侧一张复核磅单可直接采用；同侧多张必须先确定采信。交付报告必须是质检任务已完成最终判定、已确认且未作废的报告；可来自任意一侧，不要求两侧齐全。
- 质量异常可显式确认接收，必须填写采用及差异处理说明；商业扣款继续由结算流程处理。
- 确认、撤销、取消和异常处理锁定运单，结算读取交付版本时共享锁、撤销时排他锁；事务重试序列化失败/死锁，数据库唯一约束兜底。复核重新核对证据快照，使用稳定 JSON 比较，防止 JSONB 键序导致误报。
- 撤销恢复两向通知/批次执行状态；仅 `COMPLETED` 合同恢复 `EXECUTING`，不自动恢复已关闭、终止、作废合同。更换已交付采信磅单须先撤销。

## 3. 接口与权限

公共前缀 `/api/v1/bilateral-direct`，JWT；权限和范围均由领域服务收口：

| 方法、路径 | 用途 | 主要权限 |
|---|---|---|
| GET `trade-documents` | 分页查询已生成的两向直拨单据，按交付版本成对展示，包含历史撤销记录 | inventory.view + 内部身份，复用对应权限的运单/合同业务单元范围 |
| GET `contracts/:id/execution-options` | 合同三方有效地址、仓库、两向批次及剩余数量 | execution.manage |
| POST `executions` | 幂等、原子创建两向配对执行 | execution.manage |
| GET `waybills/:id` | 内部直拨详情、凭证、交付版本 | logistics.view |
| POST `waybills/:id/preview`、`confirm` | 数量预览、直接确认/提交复核 | inventory.manage |
| POST `waybills/:id/review` | 通过或退回 | contract.approve + BUSINESS_MANAGER 对应范围，管理员兜底 |
| POST `waybills/:id/reverse` | 成对撤销 | inventory.manage |
| POST `waybills/:id/cancel` | 取消未有效交付车次 | logistics.manage |
| POST `waybills/:id/reject-return` | 已到达整车拒收 | inventory.manage |
| POST `waybills/:id/to-warehouse` | 整车转常规采购入库 | inventory.manage |
| GET `contracts/:id/review` | 内部合同、货物、资金、发票补充核对 | contract.view，财务区另需 settlement.view 对应范围 |

小程序前缀 `/api/v1/mobile/bilateral-direct`，由 `MobileUserGuard` 解析关联后台用户，复用同一服务的交付、复核和异常操作，不另写状态机。现阶段配对执行创建页面以 Web 为主。

`trade-documents` 支持 `search`、`contractId`、`status=CONFIRMED/REVERSED`、`startDate/endDate`、`pageNo/pageSize`（默认50，最多100）。按确认时间、ID稳定排序；日期以北京时间自然日计算，结束日期包含当天。列表、总数与有效数量汇总均采用同一权限/筛选范围；汇总不分页且只计有效交付一次，不把采购与销售相加。返回必要凭证快照字段，不下发完整交付快照或两向价格。新入口 `/dashboard/direct-trades` 使用库存查看权限与中文面包屑。

`GET /waybills?directPending=true` 已接通 Controller 的布尔校验。Web 筛选与小程序数量共用 `DIRECT_PENDING_WHERE`：已签收、未确认交付、配对直拨、无拒收/转仓去向且合同仍有效执行。该筛选覆盖通用运单状态，Web 启用时将状态固定展示为已签收。

磅单自动生成、创建及追加时识别 `directSalesExecution`，发货方取上游供应商、收货方取下游客户。直拨磅单默认仅建立 `SHIPPING/RECEIVING` 采信，不建立 `INVENTORY/SETTLEMENT`；人工请求旧用途被阻止并给出正确入口。常规仓储逻辑不变，存量凭证与旧选用不自动改写。

### 双侧快照与编号（2026-11-12）

`DirectDelivery.snapshot.evidenceSides` 冻结发货/收货两侧采信磅单的ID、编号、毛皮净重和更新时间，各侧有效已确认报告的ID、编号、机构、品位、水分、是否最终采用及更新时间，另记录 `weightVariance=收货净重-发货净重`。同侧多张未采信时标记 `selectionRequired`，不取任意一张；缺侧为 null；零水分有效。Web、小程序及直拨进出列表只读展示。确认后的运单发货/客户重量字段分别取对应侧，不把采用的同一磅单冒充双侧事实。

复核通过前重新比对稳定快照，当前资料有变更则要求重新提交；旧待复核记录没有 `evidenceSides` 时仅比较其原有字段，保持兼容。旧已确认快照不按当前凭证回填。

`common/business-number.ts` 在建单事务内通过共享 PostgreSQL advisory lock 和数字后缀最大值生成新编号：`CGDD/XSDDYYYYMMDD0001`、`PI/SD-YYYYMMDD-0001`、`ZBCG/ZBXS-YYYYMMDD-0001`、`WB-YYYYMMDD-0001`。日期用北京时间；普通与直拨建单共用相同编号空间。软删除也占号，旧随机后缀不参与新数字序列；超过9999扩展位数，不改历史编号。批量运单在同一锁下预留连续号段。无新增数据库迁移。

采购结算编辑器识别来源中的 `followAdjustment`：只允许相同完整销售车组，自动同步总干基和原因，禁止手动改选磅单/报告和总量；批量切换跳过跟随行，重置明细仍保留销售协商数量。少选、多选或混入其他整单组时前后端均阻止保存，不估算分摊。

专项脚本：`smoke-direct-domain.ts --http`（21项，清理自建数据）、`smoke-direct-http.mjs`（82项，保留E2E标记模拟单据）、`smoke-direct-adjustment.ts`（8项，清理自建角色/账号/业务数据）。仅允许本机开发库；不输出令牌，不执行真实付款。详见同日《直拨凭证快照机构编号与专项验收》。

直拨内部接口拒绝外部企业身份。双边合同及其附件只允许内部运营维护；即使外部账号误配创建、编辑、提交等权限，后端仍拒绝双边合同写入，也不能将普通合同改成双边合同。外部企业仍可按方向查看必要合同/批次/共享物流，合同详情及列表删除对方方向价格、附件和内部草稿审批信息；附件下载再次检查类别，不依赖前端隐藏。共享运单嵌套订单仅返回白名单基础字段。外部打印/导出专项需随发布验收。

## 4. 结算及异常

- 直拨来源适配为既有逐车货款来源模型（`direct-settlement-sources.ts`），复用固定价/品位价、水分、价税、协商调整和预览。
- 销售默认采用有效交付版本的磅单与报告，可有说明地改选。`settlementRequiresApproval` 对含服务端 `directDeliveryId` 的来源只豁免侧别/报告差异触发条件；数量、单价、逐车金额和整单调整条件不豁免，普通仓储的侧别审批不变。
- 采购跟随同车有效销售结算行：磅单、报告、数量（含协商）取自销售行；候选磅单/报告只返回销售采用的一项；`settlementWeightSource=FOLLOW_SALES`。签名包含跟随的销售行、数量、审批状态和整单数量调整，确认、审批时由 `assertCurrent` 复核。
- 销售行未审批（非 CONFIRMED/PARTIALLY_SETTLED/SETTLED）时来源 `available=false`、`previewOnly=true`；`preview-goods` 返回 `saveBlocked`，创建与保存草稿拦截。
- `assertDirectPurchaseFollowsSales`：拒绝采购改选磅单/报告、不同数量、单独协商与单独整单数量调整；销售有整单数量调整时要求相同车辆与相同最终数量。金额类调整两向独立。
- 销售结算作废前检查是否存在跟随的有效直拨采购结算，须先作废采购结算。
- 交付确认：磅单与报告环节不同（跨侧）时 `crossSideReason` 必填（`NEGOTIATED_TICKET`/`SINGLE_SIDE_REPORT`），仅跨侧时写入快照；预览返回 `crossSide` 标记，不要求原因。
- 撤销/取消/拒收/转仓前检查有效货款结算（包括草稿）和运费结算。须先走原有反向流程解除资金、发票等下游引用，不能删除实物流或资金事实。
- 正常采购付款不能支付给下游客户、正常销售收款不能登记为上游供应商；兼容既有退款/质保金返还方向及第三方处理规则。
- 整车拒收要求到货和拒收附件；取消与拒收保留证据，作废未继续执行的现场任务。
- 整车转仓减少原两向通知该车计划参考量，生成常规采购通知和新待发运运单，保留原车及后续车关联；采购计划不重复。实际到仓复核我方磅单、质检后走原仓储流程，不立即生成库存，不自动完成销售。
- 供应商承运、客户自提的运单不进入我方运费结算候选和创建接口。

## 5. 验证与发布

- 单元/回归涵盖双数量、方向权限、资金对象、版本、防重复、反向占用和既有仓储流程。
- `pnpm --filter @ricse/api exec tsx scripts/smoke-direct-domain.ts --http`：仅允许本地 `ricse_dev`，真实 API/鉴权/数据库验证；建立并清理自有 QA 数据，不修改既有主数据、内容或账号。
- 浏览器自动化当前不可用，不能把类型检查/编译当作视觉验收；上线前需 Web 页面、外部身份、安卓/iOS 真机及多车真实合同复测。
- 未执行生产迁移、历史数据转换、提交或推送。生产发布必须另行授权，并完成存量 DIRECT 核查。
