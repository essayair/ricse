# 个人用户与后台账号关联

## 1. 设计目标

复用已经建成的 `User + Employee + Company + Role + UserRoleScope` 后台账号体系，为微信小程序个人用户建立独立身份档案和受控关联。微信身份只解决“谁从小程序登录”，业务权限仍由后台账号决定。

```text
WechatIdentity（个人微信身份）
  └─ linkedUserId（一对一当前关联）
      └─ User（后台账号）
          ├─ Employee / Company
          └─ Role / Permission / Data Scope
```

## 2. 数据模型

### WechatIdentity

- `openId`：小程序内唯一微信标识；页面默认脱敏。
- `unionId`：满足微信开放平台条件时保存，用于后续跨应用身份归并。
- `nickName/avatarUrl`：用户主动授权的展示资料。
- `phone/phoneVerifiedAt`：通过微信手机号接口换取的已验证手机号，不做自动账号关联。
- `status`：`ACTIVE` 或 `DISABLED`。
- `linkedUserId`：当前后台账号，数据库唯一索引保证一对一。
- `linkedAt`：当前关联时间。

### WechatAccountBinding

保存 `BIND/REBIND/UNBIND` 历史，包括微信身份、目标后台账号、操作人、备注和时间。当前关系以 `WechatIdentity.linkedUserId` 为准，审计表不作为权限判断依据。

## 3. API

### 管理端（核心 API）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v1/platform-users` | 分页检索个人用户 |
| GET | `/api/v1/platform-users/:id` | 用户详情和关联历史 |
| GET | `/api/v1/platform-users/linkable-accounts` | 查询可关联企业账号 |
| PATCH | `/api/v1/platform-users/:id` | 启用/禁用个人用户 |
| PUT | `/api/v1/platform-users/:id/backend-account` | 关联或重新关联后台账号 |
| DELETE | `/api/v1/platform-users/:id/backend-account` | 解除关联 |

全部接口要求 JWT 和 `system.user.manage` 权限。

### 小程序（内容 API）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/v1/public/wechat/login` | `wx.login` code 换取会话并更新个人档案 |
| GET | `/api/v1/public/wechat/me` | 获取个人资料、关联状态和企业账号上下文 |
| PATCH | `/api/v1/public/wechat/profile` | 更新用户主动授权的昵称和头像 |
| POST | `/api/v1/public/wechat/phone` | 一次性 code 换取微信验证手机号 |

### 企业工作台（核心 API）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v1/mobile/workspace` | 企业账号、权限及业务摘要 |
| GET | `/api/v1/mobile/approvals?status=PENDING/DONE` | 待审批或已审批列表 |
| GET | `/api/v1/mobile/approvals/:contractId` | 合同、明细、审批轨迹及当前节点 |
| PATCH | `/api/v1/mobile/approvals/:contractId` | 同意或驳回合同 |
| GET | `/api/v1/mobile/business-modules` | 按实时权限返回移动业务入口 |
| GET | `/api/v1/mobile/business/:module` | 业务模块只读列表及关键字检索 |
| GET | `/api/v1/mobile/business/:module/:id` | 业务模块只读详情 |

移动接口使用微信会话令牌，由 `MobileUserGuard` 映射到当前有效后台账号。合同详情和决策继续调用 `ContractService` 与 `AccessControlService`，因此节点、权限、企业数据范围、管理员全节点审批和并发控制与 Web 后台保持一致。

第二阶段支持的 `module` 为：`contracts`、`orders`、`dispatch-notices`、`waybills`、`weigh-tickets`、`quality-tasks`、`inventory`。其中磅单以物流运单为一条管理档案，详情归集该运单下多份发货/收货称重；库存按库存主体、仓库和库存批次展示实物、预占及可用数量。

### 小程序动态导航

- 小程序使用原生 `custom-tab-bar`，基础导航为首页、资讯、行情和我的。
- `GET /api/v1/public/wechat/me` 返回的 `workspaceEnabled` 是“工作台”Tab 是否出现的唯一业务口径；为 `true` 时插入中间工作台 Tab。
- 客户端将最近一次账号上下文保存为 `workspace_access_snapshot`，用于应用启动时避免导航闪动；应用显示、登录、退出及资料刷新后都会重新同步。
- 自定义 TabBar 只控制入口可见性。工作台页面进入时仍强制刷新账号上下文，所有移动 API 仍由 `MobileUserGuard`、功能权限和数据范围进行服务端校验。
- AI 助手保留普通页面路由，由首页快捷入口打开，不参与企业身份状态判断。

## 4. 权限与失效规则

- 未关联时 `workspaceEnabled=false`，只使用公开内容功能。
- 个人用户、后台账号、员工或企业任一停用，企业工作台均不可用。
- 角色和权限每次获取用户上下文时从后台账号实时读取，不复制到微信身份表。
- 绑定本身不增加权限，解除绑定后立即失去企业工作台身份。
- 外部企业的数据范围继续由现有访问控制服务计算。
- 系统管理员可以处理当前任一审批节点；普通用户只能处理分配给自己的当前节点。
- 管理员待办按“合同 + 审批轮次 + 当前步骤”去重，避免或签/会签多人任务在移动列表重复展示。
- 移动业务入口不等于授权：入口按 `contract.view`、`execution.view`、`logistics.view`、`quality.view`、`inventory.view` 动态显示，每次列表和详情请求仍由对应后台服务再次校验权限和数据范围。
- 外部企业账号只能查看其企业参与合同及沿合同、执行通知、物流等来源链继承的业务数据。

## 5. 部署要求

- 核心 API 与内容 API 使用同一 PostgreSQL 数据库并执行新增迁移。
- 内容 API 配置 `WX_APPID`、`WX_SECRET` 和 `WECHAT_TOKEN_SECRET`。
- 小程序域名白名单包含 `https://api.hgyunlian.com`。
- 发布小程序客户端后，用户需重新完成微信资料/手机号授权才能在管理端看到相应信息。
