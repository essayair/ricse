# 库存冲销模块设计

## 1. 设计原则

- 不删除、不覆盖原业务单和原库存台账。
- 使用原库存批次生成反向库存变动。
- 支持多次部分冲销，累计不得超过原业务数量。
- 待审批、审批通过和已过账数量共同占用可冲销额度。
- 审批通过不直接改变库存，过账时再次进行并发安全校验。

## 2. 数据模型

### InventoryReversal

库存冲销单头：

- `type`：`INBOUND` / `OUTBOUND`
- `status`：`DRAFT` / `PENDING_APPROVAL` / `APPROVED` / `REJECTED` / `POSTED` / `CANCELLED`
- `businessInboundId`：入库冲销原单
- `salesOutboundId`：出库冲销原单
- 冲销原因、申请人、审批人、过账人及对应时间

### InventoryReversalLine

- `inventoryLotId`：必须为原业务涉及的库存批次
- `sourceSalesOutboundLineId`：出库冲销时关联原销售出库明细
- `sourceQuantity`：原业务数量快照
- `quantity`：本次冲销数量
- `balanceAfter`：冲销过账后批次余额

`BusinessInbound.status` 和 `SalesOutbound.status` 增加 `PARTIALLY_REVERSED` 和 `REVERSED`。

## 4. 入库冲销算法

```text
sourceRemaining = 原入库数量 − 活跃冲销数量
reversible = min(sourceRemaining, 当前批次可用数量)
```

过账时条件更新库存批次，同时减少 `initialQuantity` 和 `availableQuantity`，创建 `INBOUND_REVERSAL` 负数台账。累计等于原入库数量时原单变为 `REVERSED`，否则为 `PARTIALLY_REVERSED`。

## 5. 出库冲销算法

```text
lineRemaining = 原销售出库明细数量 − 该明细活跃冲销数量
```

每条冲销明细必须引用原 `SalesOutboundLine`，按其 `inventoryLotId` 增加可用库存并创建 `OUTBOUND_REVERSAL` 正数台账。全部明细冲销完毕时原销售出库变为 `REVERSED`，否则为 `PARTIALLY_REVERSED`。

## 6. 一致性与并发

- 创建、提交审批、审核通过和过账均校验累计上限。
- 活跃额度状态为 `PENDING_APPROVAL`、`APPROVED`、`POSTED`；驳回或取消立即释放额度。
- 过账使用数据库事务处理批次更新、冲销明细余额、台账、原单状态和冲销单状态。
- 入库冲销使用带实时库存条件的原子更新，库存变化后不足则整单回滚。
- 出库冲销按原销售出库明细恢复，禁止跨批次恢复。

## 7. 后续扩展

- 将库存冲销接入可配置审批流程节点。
- 已结算业务自动生成应收/应付调整单。
- 冲销过账的二次纠错单据。
- 销售退货与库存冲销的业务边界联动。
