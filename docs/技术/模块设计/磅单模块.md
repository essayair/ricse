# 磅单模块设计

## 数据关系

```text
Waybill
  1:1 WeighTask
      1:N Attachment（任务现场影像）
  1:N WeighTicket
      1:N WeighRecord
  1:N WaybillWeightSelection
```

一张物流运单按 `weighingStage` 分为 `SHIPPING`（发货称重）和 `RECEIVING`（收货称重）两个节点，每个节点允许维护多张完整磅单。第一张 `sequence = 1`；第二张及以后标记 `isSupplementary = true`，必须填写 `additionReason`，并通过 `previousTicketId` 连接上一张凭证。追加不会覆盖或删除原磅单。

过磅管理以 `WeighTask` 作为显式任务对象，并与 `Waybill` 一对一关联。车辆或车牌确定后幂等生成 `WT-日期-流水号`，状态为待过磅；列表一张物流运单只显示一行，即使尚无 `WeighTicket` 也可跟踪。进入详情后按发货称重、收货称重展示全部 `WeighTicket`。单张 `WeighTicket` 仍是可上传凭证附件、称重、复核和被选用的完整业务凭证。

`WeighTask` 状态为 `PENDING_WEIGHING`、`IN_PROGRESS`、`PENDING_CONFIRMATION`、`COMPLETED`、`EXCEPTION`、`VOIDED`，由下属完整磅单和异常状态同步推进。任务级 `Attachment` 保存现场证据，字段包含来源、拍摄节点、拍摄时间、上传人、SHA-256 和水印文本快照；单张磅单附件仍保存正式磅单图片或 PDF，两类附件不混用。

完整磅单的追加与磅单内部复磅是两层不同概念：前者新增 `WeighTicket`，后者只在同一 `WeighTicket` 下新增 `WeighRecord`。

`WeighTicket` 保存有效毛重、皮重、净重、各结算候选重量、磅差和复核结果。`WeighRecord` 是不可覆盖的称重事实记录，通过 `weighingType` 区分 `GROSS` 和 `TARE`，通过 `sequence` 保证磅单内的记录顺序。

磅单同时保存正式凭证快照字段：`ticketDate`、`plateNo`、`materialName`、`materialSpec`、`shipperName`、`receiverName`、`packageCount`、`driverName`、`weighmasterName` 和 `printedAt`。毛重时间、皮重时间不重复存储，根据有效记录的 `weighedAt` 动态取得。

`Attachment.weighTicketId` 关联磅单，类别固定为 `WEIGH_TICKET`。磅单完成称重前至少需要一份附件；完成后附件锁定不可删除。

## 多次称重规则

- 基础称重为一条毛重和一条皮重，但数据模型不限制记录数量。
- 采购入场的默认录入顺序为 `GROSS → TARE`，销售出场为 `TARE → GROSS`；顺序用于反映车辆进出场作业过程，不影响净重始终按两者差值绝对值计算。
- 前端默认生成两条基础录入行，允许只提交已填写重量的记录；尚缺的基础类型在后续加载时继续展示。
- 每次新增记录分配递增 `sequence`，同时将该记录设为对应类型的有效记录。
- `selectedGrossRecordId` 与 `selectedTareRecordId` 只允许指向本磅单、且类型匹配的记录。
- 净重计算公式为 `abs(grossWeight - tareWeight)`。
- 更换有效记录或调整结算口径后统一重新计算派生字段，不修改历史记录。

## 单张磅单重量与运单选用

`settlementBasis` 可取：

- `RECEIVING`：默认，使用 `receivingWeight`，其值等于当前净重。
- `SHIPPING`：使用 `shippingWeight`。
- `CUSTOMER`：使用 `customerWeight`。
- `THIRD_PARTY`：使用 `thirdPartyWeight`。
- `MANUAL`：使用 `manualWeight`。

非 `RECEIVING` 口径必须填写大于零的对应重量。`settlementWeight` 是单张磅单内部口径的派生快照；运单层最终采用哪一张完整磅单，由 `WaybillWeightSelection` 另行确定，避免把“本张磅单怎么算”和“多张磅单选哪张”混为一谈。

`WaybillWeightSelection.purpose` 保留 `INVENTORY` 和 `SETTLEMENT` 两条下游适配记录，但二者是同一次原子选用产生的技术镜像，当前 `weighTicketId` 和 `quantity` 必须完全一致。产品口径只称“结算入库磅单”：用户从该运单全部已复核完整磅单中选择一次，系统同时同步库存执行和结算；不提供分开选择。更换时必须填写原因，旧记录改为非当前并永久保留；已经完成库存入账或出库批次拣配时禁止更换。

采购和销售均在首张发货称重磅单复核后自动建立默认结算入库磅单。后续收货称重或追加磅单不会自动覆盖当前选择，确需采用时由用户明确改选并留痕。

磅差基于现场收货净重与运单计划数量计算：

```text
varianceWeight = netWeight - plannedQuantity
varianceRate = abs(varianceWeight) / plannedQuantity × 100%
abnormal = varianceRate > toleranceRate
```

## 状态机

```text
PENDING → WEIGHING → COMPLETED → REVIEWED
   └───────────────→ VOIDED
```

- `PENDING`、`WEIGHING` 可以新增称重记录和更换有效记录。
- `COMPLETED` 要求有效毛重、有效皮重、净重和结算重量均存在。
- `COMPLETED`、称重中状态可以调整结算口径；`REVIEWED`、`VOIDED` 禁止调整。
- 异常磅单进入 `REVIEWED` 时必须填写 `reviewRemark`。
- `REVIEWED` 不能直接作废。
- 当前被选为结算入库依据的磅单不能作废；已完成库存入账后不得更换结算入库磅单。

|------|------|------|
| `GET` | `/weigh-tickets` | 查询磅单，支持状态、异常和关键字筛选 |
| `GET` | `/weigh-tickets/management-files` | 按物流运单查询磅单信息聚合列表 |
| `GET` | `/weigh-tickets/management-files/:waybillId` | 查询运单级磅单信息和全部发货/收货子磅单 |
| `POST` | `/weigh-tickets/tasks/:taskId/attachments` | 上传过磅任务现场影像 |

| `POST` | `/weigh-tickets` | 从物流运单创建磅单 |
| `GET` | `/weigh-tickets/:id` | 查询磅单详情和全部称重记录 |

| `POST` | `/weigh-tickets/:id/records/batch` | 按录入顺序批量追加 1 至 20 条称重记录 |

| `PATCH` | `/weigh-tickets/:id/print` | 更新打印时间并返回完整磅单 |

| `DELETE` | `/weigh-tickets/attachments/:id` | 删除未完成磅单附件 |

## 审计要求

称重记录保留数据来源、称重时间、操作人和备注。前端生成基础记录时，第一次称重默认使用系统当前时间，后续记录以上一条已有记录或草稿的时间为基准，随机增加 30–40 分钟且精确到秒；自动生成值允许人工调整。批量保存使用同一事务，数组顺序决定连续的 `sequence`；每种类型最后一条新增记录自动成为该类型的当前有效记录。复磅不更新原记录。复核保留复核人、复核时间和处理意见。小程序接口 `/mobile/weigh-tasks/:id/attachments` 由已绑定后台账号调用，仍校验 `quality.manage` 和运单数据范围。

## 权限与数据范围

- 查看候选运单、磅单列表、详情和附件使用 `quality.view`。
- 创建、称重记录、单张磅单有效记录选择、内部重量口径、复核、作废、信息修改和附件增删使用 `quality.manage`。
- 运单级结算入库磅单由现场质检岗位统一选用，使用 `quality.manage`；下游库存和结算模块只消费选择结果。
- `WeighTicket` 通过 `waybill.dispatchNotice.order.contract` 继承合同范围。
- 附件查询附加所属磅单范围条件，禁止仅凭附件 ID 获取临时地址。
- 外部企业员工共享本企业合同链形成的磅单，不按司磅员或创建人过滤。

统一实现见[角色权限与数据范围](./角色权限与数据范围.md)。
