# 磅单模块设计

## 数据关系

```text
Waybill
  1:N WeighTicket
      1:N WeighRecord
```

业务上同一运单同一时刻只允许一张 `deletedAt = null` 且状态不为 `VOIDED` 的磅单。允许保留已作废磅单，再创建新磅单。

`WeighTicket` 保存有效毛重、皮重、净重、各结算候选重量、磅差和复核结果。`WeighRecord` 是不可覆盖的称重事实记录，通过 `weighingType` 区分 `GROSS` 和 `TARE`，通过 `sequence` 保证磅单内的记录顺序。

磅单同时保存正式凭证快照字段：`ticketDate`、`plateNo`、`materialName`、`materialSpec`、`shipperName`、`receiverName`、`packageCount`、`driverName`、`weighmasterName` 和 `printedAt`。毛重时间、皮重时间不重复存储，根据有效记录的 `weighedAt` 动态取得。

`Attachment.weighTicketId` 关联磅单，类别固定为 `WEIGH_TICKET`。磅单完成称重前至少需要一份附件；完成后附件锁定不可删除。

## 多次称重规则

- 基础称重为一条毛重和一条皮重，但数据模型不限制记录数量。
- 每次新增记录分配递增 `sequence`，同时将该记录设为对应类型的有效记录。
- `selectedGrossRecordId` 与 `selectedTareRecordId` 只允许指向本磅单、且类型匹配的记录。
- 净重计算公式为 `abs(grossWeight - tareWeight)`。
- 更换有效记录或调整结算口径后统一重新计算派生字段，不修改历史记录。

## 结算重量

`settlementBasis` 可取：

- `RECEIVING`：默认，使用 `receivingWeight`，其值等于当前净重。
- `SHIPPING`：使用 `shippingWeight`。
- `CUSTOMER`：使用 `customerWeight`。
- `THIRD_PARTY`：使用 `thirdPartyWeight`。
- `MANUAL`：使用 `manualWeight`。

非 `RECEIVING` 口径必须填写大于零的对应重量。`settlementWeight` 是根据当前口径生成的派生快照，用于下游结算；其他候选重量继续保留。

磅差基于现场收货净重与运单计划数量计算：

```text
varianceWeight = netWeight - plannedQuantity
varianceRate = abs(varianceWeight) / plannedQuantity × 100%
abnormal = varianceRate > toleranceRate
```

## 状态机

```text
PENDING → WEIGHING → COMPLETED → REVIEWED
   └───────────────→ VOIDED
```

- `PENDING`、`WEIGHING` 可以新增称重记录和更换有效记录。
- `COMPLETED` 要求有效毛重、有效皮重、净重和结算重量均存在。
- `COMPLETED`、称重中状态可以调整结算口径；`REVIEWED`、`VOIDED` 禁止调整。
- 异常磅单进入 `REVIEWED` 时必须填写 `reviewRemark`。
- `REVIEWED` 不能直接作废。

## API

| 方法 | 路径 | 说明 |
|------|------|------|
| `GET` | `/weigh-tickets` | 查询磅单，支持状态、异常和关键字筛选 |
| `GET` | `/weigh-tickets/eligible-waybills` | 查询可创建磅单的已到达/已签收运单 |
| `POST` | `/weigh-tickets` | 从物流运单创建磅单 |
| `GET` | `/weigh-tickets/:id` | 查询磅单详情和全部称重记录 |
| `POST` | `/weigh-tickets/:id/records` | 追加毛重或皮重记录 |
| `PATCH` | `/weigh-tickets/:id/effective-records` | 选择有效毛重和皮重记录 |
| `PATCH` | `/weigh-tickets/:id/settlement` | 修改结算重量口径和候选重量 |
| `PATCH` | `/weigh-tickets/:id/status` | 完成、复核或作废磅单 |
| `PATCH` | `/weigh-tickets/:id/print` | 更新打印时间并返回完整磅单 |
| `PATCH` | `/weigh-tickets/:id/info` | 修改未复核磅单的业务快照和备注 |
| `POST` | `/weigh-tickets/:id/attachments` | 上传磅单附件 |
| `GET` | `/weigh-tickets/attachments/:id/view-url` | 获取附件临时查看地址 |
| `DELETE` | `/weigh-tickets/attachments/:id` | 删除未完成磅单附件 |

## 审计要求

称重记录保留数据来源、称重时间、操作人和备注。复磅不更新原记录。复核保留复核人、复核时间和处理意见。设备直连和影像关联将在后续迭代复用现有 `dataSource` 及磅单关联关系扩展。

## 权限与数据范围

- 查看候选运单、磅单列表、详情和附件使用 `quality.view`。
- 创建、称重记录、有效记录选择、结算口径、复核、作废、信息修改和附件增删使用 `quality.manage`。
- `WeighTicket` 通过 `waybill.dispatchNotice.order.contract` 继承合同范围。
- 附件查询附加所属磅单范围条件，禁止仅凭附件 ID 获取临时地址。
- 外部企业员工共享本企业合同链形成的磅单，不按司磅员或创建人过滤。

统一实现见[角色权限与数据范围](./角色权限与数据范围.md)。
