# 合同审批收口设计

## 目标

保证角色会签合同审批链稳定可用：

- 审批配置异常不产生重复草稿；
- 不产生“合同已待审批但没有审批任务”的中间状态；
- 节点按角色和组织范围解析所有有效审批成员；
- 提交时固化本轮审批成员快照；
- 会签节点全部通过后才激活下一级；
- 管理员可以代办所有当前审批节点；
- 待审批合同可安全撤回或作废；
- 合同必须作废后才能由管理员软删除。

## 新建幂等

新建合同页面为一次填写会话生成 `clientRequestId`，服务端以 `createdBy + clientRequestId` 建立唯一约束。

相同请求重复到达时：

1. 服务端优先查询并返回已创建的草稿；
2. 并发请求触发唯一约束时，捕获冲突并返回已经创建的合同；
3. 前端取得合同 ID 后，后续保存、附件上传和提交都更新该合同。

## 提交预检

`GET /contracts/:id/approval-readiness` 检查：

- 合同仍为草稿或已驳回；
- 对应合同类型存在启用的审批流程；
- 当前金额至少匹配一个启用节点；
- 节点绑定角色处于启用状态并拥有 `contract.approve` 权限；
- 合同所属企业和业务部门能够确定；
- 节点角色在合同部门、合同企业或全平台范围内至少存在一名有效成员。

业务部门解析顺序为：合同已保存的 `departmentId` → 合同创建人关联员工的 `departmentId`。采用创建人部门兼容历史草稿时，正式提交会将解析结果补写到合同；仍无法确定时返回可操作提示，要求用户编辑合同选择业务部门。

预检用于提前反馈配置问题，状态提交接口仍会在事务内再次校验，不能把预检结果作为最终授权依据。

## 事务边界

合同状态流转、审批节点处理、下一节点激活和等待节点取消均在同一个 Prisma 事务内执行。

- 提交：确定并固化合同业务部门 → 检查流程 → 按角色及范围解析成员 → 为每位成员创建本轮快照任务 → 合同进入待审批；
- 会签通过：记录当前成员操作；同级全部通过后一次性激活下一节点全部成员；
- 或签通过：记录当前成员操作，将同级其他未处理任务标记为 `OTHERS_APPROVED`（他人已审批），然后激活下一节点；
- 或签驳回：记录当前成员操作，将同级其他未处理任务标记为 `OTHERS_REJECTED`（他人已驳回），取消后续等待节点，合同进入已驳回；
- 会签驳回：记录意见 → 取消同级其他成员和后续等待节点 → 合同进入已驳回；
- 撤回/作废：取消未处理任务 → 更新合同状态。

审批任务使用“状态仍为待处理”作为更新条件，避免多人或重复点击处理同一个节点。合同状态更新也携带原状态条件，发生并发变化时要求用户刷新。

## 权限与状态规则

| 操作 | 规则 |
|---|---|
| 提交审批 | 普通用户、业务员、经理、系统管理员 |
| 节点审批 | 当前节点成员快照中的用户；系统管理员可代办当前节点全部未处理成员 |
| 撤回 | 合同创建人或系统管理员 |
| 作废 | 当前阶段向普通业务角色开放，待审批作废同步取消任务 |
| 删除 | 仅系统管理员，且合同必须已作废 |

删除为软删除，合同业务列表默认过滤 `deletedAt` 不为空的数据。

## 开发备注：配置与开发边界（2026-07-27）

当前审批配置属于“部分可配置”：

| 能力 | 当前状态 |
|------|----------|
| 查询采购、销售、双边合同流程 | 已支持 |
| 启停整条流程 | 已支持 |
| 修改节点绑定审批角色 | 已支持 |
| 配置会签/或签 | 已支持 |
| 配置合同部门/合同企业/全平台范围 | 已支持 |
| 启停已有节点 | 已支持 |
| 修改采购金额门槛 | 已支持 |
| 新建流程 | 未支持，无创建接口 |
| 新增、删除、排序节点 | 未支持，无对应接口 |
| 按有效多角色和范围解析审批人 | 已支持 |
| 提交时保存审批人员快照 | 已支持 |
| 流程版本发布 | 未支持 |

下一阶段采用“轻量可配置顺序审批”，不建设通用 BPM：

1. 角色管理页面补齐新增、编辑和停用；
2. 流程模板支持草稿、发布、停用和不可变版本；
3. 节点支持新增、编辑、删除、排序和启停；
4. 增加岗位负责人、组织负责人等角色自动推导规则；
5. 合同提交时绑定已发布流程版本；现有成员快照机制保持不变；
6. 系统管理员继续可以处理全部当前节点，但必须记录原角色成员和实际操作人。

配置完成后，日常新增角色、组合已有权限、调整顺序审批模板和节点角色不再需要开发。以下事项仍需开发：新增权限编码及其鉴权点、接入新的审批业务对象、增加新的条件运算或审批动作、并行分支等新引擎能力。

## 线上初始化

云效常规发布只执行 `prisma migrate deploy`，不会运行包含演示企业、合作伙伴和账号的完整 `seed.ts`。默认审批流因此必须通过系统数据迁移初始化，不能依赖 `--seed`。

迁移 `20260728090000_initialize_default_approval_flows` 采用以下规则：

- 按合同类型幂等创建采购、销售和双边三条默认流程；
- 只补充缺失的流程和节点，不覆盖管理员已调整的流程或启停状态；
- 优先使用已有业务主管、风控经理和总经理测试账号；
- 对应账号不存在时使用现有有效 `ADMIN` 或 `APPROVER` 作为默认审批人；
- Prisma 影子库或全新空库没有用户时只创建三条流程模板、暂不创建节点；首次 `--seed` 会在创建测试账号后补齐节点；
- 正式使用前，管理员仍须在审批配置页核对实际审批人。

迁移 `20260728180000_role_based_approval_workflow` 完成角色会签升级：

- 预置 `BUSINESS_MANAGER`、`RISK_MANAGER`、`GENERAL_MANAGER` 三个审批角色并授予合同查看、审批权限；
- 把旧节点固定审批人加入对应角色，保留已有流程可用性；
- 节点改为保存 `roleId`、`approvalMode` 和 `scopeType`；
- 业务主管默认按合同部门解析，风控经理和总经理默认按合同企业解析；
- 审批任务增加角色名称、角色编码和审批方式快照字段。

## 统一访问控制接入

- 合同列表、详情、附件、保存、提交、审批、撤回、作废和删除均调用统一权限与数据范围服务。
- 外部企业合同范围以其 `Company.partnerId` 匹配合同卖方、买方或签约主体，不按创建人过滤。
- 系统管理员拥有全部数据范围，可处理所有当前节点；外部企业账号禁止授予系统管理员。
- 审批附件和合同附件只能在所属合同范围校验通过后访问。

详细规则见[角色权限与数据范围](./角色权限与数据范围.md)。
