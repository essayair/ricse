# 生产管理模块设计

## 1. 设计目标

以库存批次为核心实现轻量生产闭环，同时支持自营和委外：

```text
ProductionRecipe
  → ProductionTask
    → ProductionTaskInput
      → ProductionMaterialAllocation → 原料 InventoryLot
    → ProductionCompletion → 产成品 InventoryLot
```

生产方案是标准比例，生产任务在创建时复制投入快照；历史任务不依赖方案后续变化。原料批次分配保存预占、领用、耗用和退回累计量，完工单过账后与产成品库存批次一对一关联。

## 2. 数据模型

| 模型 | 主要职责 |
|---|---|
| `ProductionRecipe` | 库存主体、产出物料、基准产量、目标收率、偏差及质量规则 |
| `ProductionRecipeInput` | 基准投入物料、主辅包装角色、数量和单位 |
| `ProductionTask` | 自营/委外任务、仓库流向、计划与实际产量、状态和需求来源 |
| `ProductionTaskInput` | 创建任务时固化的计划用量及预占/领用/耗用/退回汇总 |
| `ProductionMaterialAllocation` | 任务投入行与原料库存批次之间的批次级执行关系 |
| `ProductionCompletion` | 分次完工、质量结论、入库过账及产成品批次来源 |

`InventoryLot.businessInboundId` 调整为可空，同时增加唯一的 `productionCompletionId`。库存批次必须来源于业务入库或生产完工之一，当前由服务层保证该异或关系。

## 3. 状态机

生产任务：

```text
DRAFT → RELEASED → MATERIAL_PREPARED → IN_PROGRESS
  └→ CANCELLED       └→ CANCELLED         ├→ PENDING_QC
                                             ├→ PARTIAL_COMPLETED
                                             └→ COMPLETED → CLOSED
```

完工申报：

```text
PENDING_QC → READY_TO_POST → POSTED
           ├→ REWORK
           └→ SCRAPPED
```

无质检要求的完工申报直接进入 `READY_TO_POST`。返工和报废不计入有效累计完工量，报废不形成库存。

## 4. 数量与事务规则

- 任务计划投入 = 方案标准投入 × 任务计划产量 ÷ 方案基准产量，保存三位小数。
- 同一任务投入物料不能重复；投入和产出不能使用同一物料 ID。
- 预占不改变 `InventoryLot.availableQuantity`，但库存总览的可承诺量同时扣除生产预占和销售预占。
- 领料事务同时扣减原料库存、更新分配记录、更新投入行、写 `PRODUCTION_ISSUE` 台账和推进任务状态。
- 退料事务恢复原库存批次，写 `PRODUCTION_RETURN` 台账。
- 完工入库事务创建产成品库存批次、写 `PRODUCTION_INBOUND` 台账、更新完工单和任务累计量。
- 实际收率 = 累计合格入库数量 ÷ 主料实际耗用数量；辅料和包装物不进入收率分母。
- 累计有效完工不得超过计划产量加允许偏差。
- 关闭任务前必须消除“已领 - 已耗 - 已退”余额。

## 5. API

### 生产方案

| 方法 | 路径 | 权限 | 用途 |
|---|---|---|---|
| `POST` | `/production/recipes` | `production.manage` | 创建方案 |
| `GET` | `/production/recipes` | `production.view` | 查询方案 |
| `GET` | `/production/recipes/:id` | `production.view` | 方案详情 |
| `PATCH` | `/production/recipes/:id` | `production.manage` | 更新/停用方案 |

### 生产任务

| 方法 | 路径 | 权限 | 用途 |
|---|---|---|---|
| `POST` | `/production/tasks` | `production.manage` | 创建任务草稿 |
| `GET` | `/production/tasks` | `production.view` | 任务列表与汇总 |
| `GET` | `/production/tasks/:id` | `production.view` | 任务完整详情 |
| `PATCH` | `/production/tasks/:id/release` | `production.manage` | 下达任务 |
| `GET` | `/production/tasks/:id/eligible-lots` | `production.view` | 候选原料批次 |
| `PATCH` | `/production/tasks/:id/reservations` | `production.manage` | 保存批次预占 |
| `POST` | `/production/tasks/:id/issue` | `production.post` | 领料过账 |
| `POST` | `/production/tasks/:id/consume` | `production.manage` | 记录实际耗用 |
| `POST` | `/production/tasks/:id/return` | `production.post` | 余料退回 |
| `POST` | `/production/tasks/:id/completions` | `production.manage` | 分次完工申报 |
| `PATCH` | `/production/completions/:id/quality` | 生产管理或质量管理 | 确认质量结论 |
| `POST` | `/production/completions/:id/post` | `production.post` | 完工入库过账 |
| `PATCH` | `/production/tasks/:id/close` | `production.manage` | 关闭任务 |
| `PATCH` | `/production/tasks/:id/cancel` | `production.manage` | 取消未领料任务 |
| `GET` | `/production/traceability` | `production.view` | 产成品批次追溯 |

## 6. 主数据与服务生态

委外加工方使用 `ServiceOrganization.organizationType = PROCESSING_PROVIDER`，仍通过 `partnerId` 关联供应商合作伙伴。专业档案用于加工能力和准入筛选，交易及后续应付仍引用统一合作伙伴主体。

## 7. 权限和范围

迁移预置 `production.view/manage/post` 与 `PRODUCTION_MANAGER` 角色。生产库存批次的可见范围从 `ProductionCompletion.task` 继承，不再假设所有库存批次都必有 `BusinessInbound`。

- 管理员或 `ALL` 范围：全部生产数据。
- 内部普通范围：本人创建任务，以及账号所属企业映射库存主体的任务。
- 外部企业：本企业作为库存主体的任务，或本企业服务生态档案作为加工方的委外任务。

列表、详情、候选原料批次、质量确认、完工入库和追溯使用同一任务范围。

## 8. 后续扩展点

- 销售执行批次按缺口自动生成生产建议或生产任务；
- 工序路线、工位、班组与工序报工；
- 独立生产质检任务及检测报告附件；
- 生产退库、完工入库冲销及审批；
- 加工费应付、材料成本、费用分摊和产成品批次成本；
- 委外发料运输和加工方库存状态；
- 生产任务附件、工艺文件和完工凭证。
