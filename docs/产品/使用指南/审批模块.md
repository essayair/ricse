# 审批流程 — 使用指南

> ✅ Iteration 4 已完成（2026-07-16）

## 功能概述

系统按合同类型使用固定顺序的多级审批链。系统管理员负责配置流程状态、审批人和采购金额门槛；合同提交后，审批任务按节点顺序依次流转，并完整保留每一轮审批记录。

## 前置条件

- 已完成组织架构和用户配置
- 审批人账号状态为「启用」，角色为审批员或管理员
- 合同处于「草稿」状态，且合同信息完整

线上发布执行数据库迁移时会幂等初始化采购、销售和双边合同三条默认审批流。若尚未维护业务主管、风控经理和总经理账号，系统先使用现有有效管理员作为默认审批人；正式提交合同前，管理员应在本页改为实际审批人员。

## 一、配置审批流程

1. 使用系统管理员账号登录。
2. 从左侧一级菜单进入「系统管理 → 审批流程」。
3. 找到采购合同、销售合同或双边合同审批流。
4. 可进行以下配置：
   - 启用或停用整条审批流程；
   - 为每个节点选择固定审批人；
   - 启用或停用单个审批节点；
   - 设置采购合同的总经理审批金额门槛。

系统管理菜单及审批配置接口仅对 `ADMIN` 角色开放。审批员和普通用户不能查看或修改配置。

### 当前配置边界

当前无需开发即可配置：

- 启用、停用采购、销售和双边合同审批流程；
- 修改现有节点审批人；
- 启用、停用现有节点；
- 修改采购合同总经理审批金额门槛。

当前尚不能在页面配置：

- 新建审批流程；
- 新增、删除或拖动调整审批节点；
- 按角色、部门负责人等规则动态确定审批人；
- 配置流程版本、会签、或签和并行分支。

上述缺口列入“角色与审批配置完善”迭代。完成后，日常新增顺序审批模板和调整节点不再需要修改代码；新增审批对象、条件算法、会签规则或审批动作仍属于开发事项。

## 二、当前默认审批链

| 合同类型 | 审批顺序 | 条件 |
|------|------|------|
| 采购合同 | 业务主管 → 风控经理 → 总经理 | 总经理节点仅在合同金额达到配置门槛时启用，默认门槛为 1,000,000 元 |
| 销售合同 | 业务主管 → 风控经理 | 固定两级审批 |
| 双边合同 | 业务主管 → 风控经理 → 总经理 | 固定三级审批 |

## 三、提交与处理审批

1. 业务人员在合同详情页点击「提交审批」。
2. 系统读取该合同类型当前启用的流程配置，生成新一轮审批任务。
3. 第一级任务进入「待处理」，后续节点进入「等待中」。
4. 当前节点审批人进入合同详情，填写审批意见并选择「通过」或「驳回」。
5. 通过后自动激活下一级；最后一级通过后，合同状态变为「已通过」。
6. 任一级驳回后，合同状态变为「已驳回」，本轮后续节点自动取消。

审批意见为必填项。普通审批员只有在被指定为当前节点审批人时才能操作；系统管理员可作为兜底角色处理任意当前待审批节点，但不能跳过节点顺序。

管理员代为处理时，审批记录同时保留原配置审批人和实际操作管理员，详情时间线会显示“由系统管理员代为处理”。

## 四、驳回后重新提交

1. 已驳回合同支持修改合同内容和附件。
2. 将合同恢复为「草稿」后再次提交审批。
3. 系统创建新的审批轮次，不覆盖上一轮记录。
4. 新一轮仍按提交时的最新流程配置依次流转。

## 五、状态说明

| 审批任务状态 | 说明 |
|------|------|
| WAITING | 等待前序节点完成 |
| PENDING | 当前审批人待处理 |
| APPROVED | 当前节点已通过 |
| REJECTED | 当前节点已驳回 |
| CANCELLED | 因驳回或重新提交而取消 |

## 六、常见问题

- 看不到「系统管理」：当前账号不是系统管理员。
- 审批流程页面为空：确认线上已经应用 `20260728090000_initialize_default_approval_flows` 数据迁移；普通发布不需要也不应重复执行完整演示数据 seed。
- 提交时提示流程未启用：管理员需启用对应合同类型的审批流。
- 审批按钮不可用：普通审批员不是当前节点的指定审批人；系统管理员不受该限制。
- 采购合同没有总经理节点：合同金额未达到当前配置门槛，或该节点已停用。
- 修改配置是否影响在途审批：已生成的审批任务保持原审批链；后续新提交或重新提交使用最新配置。

## 七、库存冲销审批

库存冲销采用独立的单级审核规则：

- 冲销申请提交后进入“待审批”，对应冲销数量立即占用原单可冲销额度。
- `APPROVER` 审批人和 `ADMIN` 系统管理员均可处理；系统管理员可以审批全部库存冲销单。
- 驳回时必须填写原因，驳回后立即释放预留额度。
- 审批通过后库存尚未变化，必须继续执行“冲销过账”才会生成反向库存台账。
- 后续可将库存冲销升级为系统管理中可配置的多节点审批流程。

## 八、审批权限与数据范围

- 审批资格由有效角色和当前节点共同决定，不能只依赖页面按钮显示。
- 合同节点由配置审批人处理，系统管理员可代办所有当前节点，系统记录配置审批人和实际操作人。
- 审批人查看合同及上下游信息时仍受其角色数据范围约束；系统管理员的数据范围为全部。
- 外部企业账号不能授予系统管理员角色，也不会因为能查看本企业合同而自动获得审批权限。
- 库存冲销审核读取当前有效的多角色授权，`APPROVER` 或 `ADMIN` 任一角色有效即可审核。

> 开发备注：当前合同审批配置页和配置接口仍按兼容主角色字段筛选 `APPROVER/ADMIN` 候选人，尚未完全读取新的多角色授权。正式开放配置前，应改为按有效角色及 `contract.approve` 权限筛选，并保留系统管理员兜底能力。

通用口径见[权限与数据范围规范](../权限与数据范围规范.md)。
