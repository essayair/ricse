# 审批流程 — 使用指南

> 角色会签版（2026-07-28）

## 功能概述

系统按合同类型使用顺序多级审批链。审批节点绑定审批角色，不再绑定某一个固定账号；合同提交时，系统根据节点人员范围解析该角色的有效成员并生成审批人快照。会签节点全部成员通过后才进入下一级，并完整保留每一轮、每一人的审批记录。

## 前置条件

- 已完成组织架构和用户配置
- 审批人账号状态为「启用」，并已获得节点绑定的审批角色
- 节点角色拥有 `contract.approve` 合同审批权限
- 用户角色授权的数据范围覆盖合同所属企业或业务部门
- 合同处于「草稿」状态，且合同信息完整

系统预置业务主管、风控经理和总经理三个审批角色。线上迁移会把原节点固定审批人加入对应角色，保证已有流程平滑升级；正式使用前，管理员仍应核对各角色成员及其企业、部门数据范围。

## 一、配置审批流程

1. 使用系统管理员账号登录。
2. 从左侧一级菜单进入「系统管理 → 审批流程」。
3. 找到采购合同、销售合同或双边合同审批流。
4. 可进行以下配置：
   - 启用或停用整条审批流程；
   - 为每个节点选择审批角色；
   - 设置审批方式：会签（全部通过）或或签（一人通过）；
   - 设置人员范围：合同业务部门、合同所属企业或全平台；
   - 启用或停用单个审批节点；
   - 设置采购合同的总经理审批金额门槛。

审批流程列表明确展示：合同类型、流程名称、流程状态、总经理审批金额门槛、审批节点数、最后更新时间和操作。

审批节点列表明确展示：审批顺序、节点名称、绑定审批角色、角色有效人数、审批方式、人员范围、启用条件和节点状态。

系统管理菜单及审批配置接口仅对 `ADMIN` 角色开放。审批员和普通用户不能查看或修改配置。

### 当前配置边界

当前无需开发即可配置：

- 启用、停用采购、销售和双边合同审批流程；
- 修改现有节点绑定角色；
- 配置会签或或签；
- 配置合同部门、合同企业或全平台人员范围；
- 启用、停用现有节点；
- 修改采购合同总经理审批金额门槛。

当前尚不能在页面配置：

- 新建审批流程；
- 新增、删除或拖动调整审批节点；
- 按岗位负责人、组织负责人等规则自动推导角色；
- 配置流程版本和并行分支。

上述缺口列入“角色与审批配置完善”迭代。完成后，日常新增顺序审批模板和调整节点不再需要修改代码；新增审批对象、条件算法、会签规则或审批动作仍属于开发事项。

## 二、当前默认审批链

| 合同类型 | 审批顺序 | 默认角色 | 默认方式与范围 | 条件 |
|------|------|------|------|------|
| 采购合同 | 业务主管 → 风控经理 → 总经理 | `BUSINESS_MANAGER` → `RISK_MANAGER` → `GENERAL_MANAGER` | 全部会签；业务主管按合同部门，其他按合同企业 | 总经理节点仅在合同金额达到配置门槛时启用，默认门槛为 1,000,000 元 |
| 销售合同 | 业务主管 → 风控经理 | `BUSINESS_MANAGER` → `RISK_MANAGER` | 全部会签；业务主管按合同部门，风控经理按合同企业 | 固定两级审批 |
| 双边合同 | 业务主管 → 风控经理 → 总经理 | `BUSINESS_MANAGER` → `RISK_MANAGER` → `GENERAL_MANAGER` | 全部会签；业务主管按合同部门，其他按合同企业 | 固定三级审批 |

## 三、提交与处理审批

1. 业务人员在合同详情页点击「提交审批」。
2. 系统读取当前流程、节点角色、审批方式和人员范围。
3. 系统解析角色的有效成员，将名单保存为本轮审批快照。
4. 第一级所有成员任务进入「待处理」，后续节点成员任务进入「等待中」。
5. 当前节点成员进入合同详情，填写审批意见并选择「通过」或「驳回」。
6. 会签节点所有成员通过，或或签节点任意成员通过后，自动激活下一级全部成员任务。
7. 最后一级满足通过条件后，合同状态变为「已通过」。
8. 任意成员驳回后，合同状态变为「已驳回」，本节点其他任务和后续节点自动取消。

审批意见为必填项。普通用户只有在提交时被解析为当前节点成员时才能操作。系统管理员可作为兜底处理当前节点；管理员通过时视为代办当前节点全部未处理成员，但不能跳过节点顺序。

管理员代办时，每条成员任务仍保留原审批人，同时记录实际操作管理员，详情时间线会显示“由系统管理员代为处理”。

## 四、驳回后重新提交

1. 已驳回合同支持修改合同内容和附件。
2. 将合同恢复为「草稿」后再次提交审批。
3. 系统创建新的审批轮次，不覆盖上一轮记录。
4. 新一轮仍按提交时的最新流程配置依次流转。

## 五、状态说明

| 审批任务状态 | 说明 |
|------|------|
| WAITING | 等待前序节点完成 |
| PENDING | 当前审批人待处理 |
| APPROVED | 当前节点已通过 |
| REJECTED | 当前节点已驳回 |
| CANCELLED | 因驳回或重新提交而取消 |

## 六、常见问题

- 看不到「系统管理」：当前账号不是系统管理员。
- 提交时提示流程未启用：管理员需启用对应合同类型的审批流。
- 提交时提示节点没有有效人员：给节点角色配置有效用户，并检查用户角色的数据范围是否覆盖合同部门或企业。
- 审批按钮不可用：当前用户不在本轮节点成员快照中，或其账号、角色授权已经失效；系统管理员不受该限制。
- 采购合同没有总经理节点：合同金额未达到当前配置门槛，或该节点已停用。
- 修改角色成员是否影响在途审批：不影响。本轮使用提交时的成员快照；后续新提交或重新提交使用最新成员。
- 审批流程页面为空：确认线上已经应用默认流程迁移及 `20260728180000_role_based_approval_workflow` 角色会签迁移。

## 七、库存冲销审批

库存冲销采用独立的单级审核规则：

- 冲销申请提交后进入“待审批”，对应冲销数量立即占用原单可冲销额度。
- `APPROVER` 审批人和 `ADMIN` 系统管理员均可处理；系统管理员可以审批全部库存冲销单。
- 驳回时必须填写原因，驳回后立即释放预留额度。
- 审批通过后库存尚未变化，必须继续执行“冲销过账”才会生成反向库存台账。
- 后续可将库存冲销升级为系统管理中可配置的多节点审批流程。

## 八、审批权限与数据范围

- 审批资格由有效角色、节点人员范围、提交时成员快照和 `contract.approve` 权限共同决定，不能只依赖页面按钮显示。
- 合同节点由角色成员处理；系统管理员可代办所有当前节点，系统记录原成员和实际操作人。
- 审批人查看合同及上下游信息时仍受其角色数据范围约束；系统管理员的数据范围为全部。
- 外部企业账号不能授予系统管理员角色，也不会因为能查看本企业合同而自动获得审批权限。
- 库存冲销审核读取当前有效的多角色授权，`APPROVER` 或 `ADMIN` 任一角色有效即可审核。

通用口径见[权限与数据范围规范](../权限与数据范围规范.md)。
