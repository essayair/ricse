# 关于本指南

本指南是 RICSE 平台各业务模块使用说明的**综合合订本**，覆盖从基础资料准备到合同、执行、物流、现场作业、库存、生产和内容运营的完整操作路径。

- **适用对象**：运营管理员、采销业务员、物流运营、现场地磅质检人员、仓储库管、生产管理员、财务人员及系统管理员。
- **内容基准**：截至 2026-09-08 平台已实际上线的功能。文中标注「未开放」的部分为菜单已存在但业务功能尚未建设，标注「示例数据」的部分为页面展示的非真实数据。
- **口径优先级**：本指南与各模块单独文档冲突时，以《业务单据关系与术语规范》和《权限与数据范围规范》为准。

> **阅读建议**：初次使用请按第 1、2、3 章建立整体认知，再按第 4 章准备基础资料，随后按实际岗位查阅对应业务章节。

# 第 1 章 平台概述与总体流程

## 1.1 平台定位

RICSE（Regional Industry Chain Service Ecosystem）是面向矿产（萤石等）大宗贸易的区域产业链服务生态运营管理平台，把**合同履约、物流执行、现场计量与质检、库存货权、轻量生产加工、对外内容运营**统一在一个系统中管理。

平台的核心设计原则：

1. **单据驱动**——每一次业务动作都形成可追溯的单据，不允许直接修改结果数据。
2. **上游继承**——下游单据的数量上限、参与企业和数据可见范围全部从上游单据继承，不重复维护。
3. **过账留痕**——库存的每一次增减都必须有对应的库存台账凭证，不存在"只改余额"的操作。
4. **快照固化**——单据生效时保存业务发生时的名称、重量、审批人等快照，后续修改主数据不影响历史凭证。

## 1.2 标准单据主链

```text
合同
  ↓ 1:N
合同执行批次（采购执行批次 / 销售执行批次）
  ↓ 1:N
供应商发货指令 / 销售发货通知单
  ↓ 1:N
物流运单（一车一趟一张）
  ↓
磅单 + 到货质检任务
  ↓
物流入库单 / 出库管理单
  ↓
业务入库单 / 销售出库单
  ↓
库存批次 + 库存台账
  ↓
结算单（尚未开放）
```

生产管理是一条并行支线，把已入库的原料批次转化为新的产成品批次：

```text
生产方案 → 生产任务 → 原料批次预占 → 领料 → 实际耗用 → 完工申报 → 质量确认 → 产成品库存批次
```

## 1.3 统一术语

| 业务含义 | 正式名称 | 不再使用 |

| 合同分批执行 | 合同执行批次（简称"执行批次"） | 订单、采购订单、销售订单 |
| 采购执行通知 | 供应商发货指令 | 采购提单、提货指令、发货单 |
| 销售执行通知 | 销售发货通知单 | 销售提单、提货单、提单 |
| 运输执行单据 | 物流运单 | 运输单、承运单 |
| 采购到货确认 | 物流入库单 | 到货单、物流收货单 |
| 销售离场确认 | 物流出库单 | 物流发货单 |
| 库存货权确认 | 业务入库单 / 销售出库单 | 正式入库单、业务出库提单 |

每个执行批次同时具有**名称**（业务人员填写，便于识别）和**编号**（系统生成，用于唯一定位）。下游单据必须同时展示两者。

# 第 2 章 登录与权限

## 2.1 登录

1. 在登录页输入**登录用户名**或**员工手机号**，以及账号密码。
2. 登录成功后进入 `/dashboard` 系统外壳，左侧菜单按当前账号可用功能动态展示。
3. 系统在每次业务接口请求中重新核对账号状态、有效角色、功能权限和数据范围——菜单可见不等于操作有效，后端会二次校验。

账号、员工或所属企业任一被停用时，登录、令牌刷新和已登录请求都会被拒绝；角色停用或授权过期后对应权限立即失效。

## 2.2 两个独立维度：功能权限与数据范围

平台的访问控制由两个互相独立的维度共同决定：

| 维度 | 回答的问题 | 示例 |
|---|---|---|
| **功能权限** | 用户**可以做什么** | 查看合同、新建执行批次、管理物流、审批合同 |
| **数据范围** | 用户**可以对哪些数据**执行这些操作 | 全部数据、本企业、指定企业、本部门、本人 |

**数据范围不会自动赋予功能权限。** 外部企业员工拥有"本企业全部关联数据"范围，并不代表自动获得修改、审批或删除能力。

一个账号可以同时拥有多个角色，可访问范围按有效授权合并；功能操作要求至少一个有效角色包含对应权限。

## 2.3 内部员工可配置的数据范围

- 本人创建数据
- 本部门
- 本部门及下级部门
- 本企业
- 指定企业
- 全部数据

## 2.4 外部企业账号

外部员工账号必须绑定 `EXTERNAL` 类型企业，且该企业必须关联唯一合作伙伴。外部账号的数据范围**固定**为"本企业全部关联数据"：

1. 本企业合作伙伴作为合同**卖方**；
2. 本企业合作伙伴作为合同**买方**；
3. 本企业合作伙伴作为合同**签约主体**；
4. 上述合同向下产生的**全部关联业务单据**。

这里的"全部"是企业级全部，不是平台级全部。同一外部企业的不同员工看到相同数据，不按创建人拆分。

**硬性约束**：

- 一个外部企业一期最多开通 **6 个**有效账号。
- 外部企业账号**不能**授予系统管理员角色。
- 外部企业未关联合作伙伴时，系统直接拒绝其访问业务数据，不会退化为本人范围或平台全量。
- 在外部企业专属只读视图完成前，**不应**向外部账号授予主数据管理、组织管理或用户账号管理权限。

## 2.5 预置岗位角色

| 业务域 | 预置角色 |
|---|---|
| 平台与经营管理 | 系统管理员、管理人员 |
| 采销执行 | 采销业务员 |
| 物流 | 物流运营 |
| 现场作业 | 地磅质检 |
| 仓储库存 | 仓储库管 |
| 生产加工 | 生产管理员 |
| 财务 | 财务结算 |
| 基础资料 | 主数据管理员、组织管理员 |
| 审批 | 业务主管、风控经理、总经理、审批人 |
| 基础协作 | 普通用户 |

角色可以组合授予。例如仓库负责人可同时获得"仓储库管"和"审批人"。**不要**通过把普通用户扩大到全模块管理权限来代替岗位角色。

## 2.6 管理员开通账号

系统管理员从两个入口开通员工账号：

1. 「组织数据 → 用户账号 → 新建」：依次选择企业和未开通账号的员工；
2. 「组织数据 → 员工管理 → 员工详情 → 开通账号」。

必填或需确认的项：

| 项 | 规则 |
|---|---|
| 员工手机号 | 11 位中国大陆手机号，员工范围内唯一，可作为登录凭据 |
| 登录用户名 | 默认带入员工手机号，可修改；字母或数字开头，支持字母、数字、点、下划线、短横线，3–50 位 |
| 登录密码 | 至少 6 位，需输入两次确认 |
| 初始角色 | 可在开通时选择；非系统管理员默认仅拥有所属企业数据范围 |

密码输入默认隐藏，可临时切换显示核对。后端只保存 bcrypt 哈希，不返回原始密码。管理员重置密码时同样需两次确认，重置后清除刷新令牌，原会话须重新登录。

员工姓名、手机号和邮箱以**员工档案**为准，登录用户名保持独立。停用员工会同步禁用账号并使会话失效；恢复员工后需管理员再单独启用账号。

# 第 3 章 导航与系统总览

## 3.1 侧边栏结构

侧边栏分为四组，组间以分隔线区分：

**业务运营管理**

- 采销管理：合同管理、执行管理、执行通知
- 物流管理：调度看板、运单管理、物流对账
- 库存管理：在库总览、入库单管理、出库单管理、库存冲销
- 生产管理：生产任务、生产方案、生产台账
- 质检影像：磅单管理、质检管理、监控录像
- 结算中心：应收管理、应付管理

**基础管理**

- 主数据管理：合作伙伴、服务生态、物料品类、仓库库位、车辆管理、价格基准、质检标准
- 组织数据：企业维护、部门管理、员工管理、用户账号、业务组

**内容与用户**

- 内容运营：资讯管理、供需信息、价格行情、官网咨询、数据源管理、采集与 AI
- 用户管理：个人用户

**系统**

- 系统管理：用户与权限、审批流程

菜单按账号权限动态显示。内容运营模块对系统管理员、内容运营角色或任一 `content.*` 权限持有者可见；系统管理模块仅对系统管理员可见。

## 3.2 系统总览首页

登录后的首页为「系统总览」，全部数据实时计算，**统计口径受当前账号数据范围限制**，页面顶部显示数据更新时间。

**待处理异常区**（有异常时以红色卡片突出）：汇总磅差异常、质检拒收和运单超时，可点击直达具体单据。无异常时显示绿色提示。

**关键指标卡**：

- 本月采购入库量（已过账口径，吨）
- 当前在途车辆（运输中运单数）
- 当前账面库存（吨）及有效库存批次数
- 待处理异常条数（磅差 / 质检拒收 / 运单超时分项）

**业务流转链路**：按执行批次 → 物流运输 → 过磅称重 → 到货质检 → 入库作业 → 出库作业顺序展示各环节待办数量，可点击跳转。无该模块查看权限时显示"无查看权限"。

**最近业务动态**：按时间倒序展示可见范围内的业务事件，可点击直达单据。

> 结算与监控模块尚未形成业务数据，首页明确说明不展示模拟数字。

# 第 4 章 基础资料准备（主数据管理）

主数据是全平台的基础档案中心。**所有业务单据都依赖主数据**，因此新环境上线的第一步是按本章顺序准备资料。

推荐准备顺序：合作伙伴 → 服务生态 → 物料分类与商品物料 → 质检标准 → 仓库库位 → 车辆与司机。

## 4.1 合作伙伴

合作伙伴是供应商、客户和内部签约主体的统一档案，一家企业**只建一份档案**。

### 4.1.1 新建

进入「主数据管理 → 合作伙伴 → 新建合作伙伴」。

**基本信息（必填）**

| 字段 | 说明 |
|---|---|
| 企业名称 | 完整法定名称，与营业执照一致 |
| 统一社会信用代码 | 18 位，与名称联合校验唯一性 |
| 合作伙伴角色 | 多选：供应商 / 客户，可同时勾选 |
| 单位性质 | 外部单位（编码 8 位数字自动生成）或内部企业（编码 6 位字母数字手动录入） |
| 合作伙伴编码 | 按单位性质自动确定格式，外部可切换手动指定 |

**补充信息（选填）**：简称/别名、搜索简码（拼音首字母）、法定代表人、联系人与电话、注册与办公地址、主要货源地、拟合作品种、授信额度、纳税人类型与发票类型、备注。

> **注意**：统一社会信用代码 + 企业名称必须全平台唯一，重复提交会被拒绝。

### 4.1.2 银行账户

在合作伙伴详情页切换到「银行账户」标签，可添加多个账户：开户名称、银行账号、开户行全称、联行号、账户类型（基本户/一般户）、是否默认。默认账户在结算时自动带出。

### 4.1.3 编辑限制

**创建后锁定，不可修改**：

| 字段 | 原因 |
|---|---|
| 合作伙伴编码 | 全平台唯一标识，合同/执行批次/结算均引用 |
| 统一社会信用代码 | 与编码、名称构成防重体系 |
| 内部/外部性质 | 决定编码规则体系 |

**可改但有限制**：企业名称允许修改（企业更名），但税号+名称联合唯一校验须通过；合作伙伴角色**仅允许追加，禁止移除**已有角色，防止执行中合同失去交易方向。

**可随时修改**：基本信息、工商登记、联系人与地址、税务发票、特殊资质、业务信息、授信额度、备注，以及影像附件的查看、删除和追加。

### 4.1.4 停用与黑名单

- 停用前系统自动检查是否存在**进行中的合同**（草稿/待审批/已通过/执行中），存在则拒绝停用。
- 停用后不可在新单据中被引用，已有历史单据不受影响，可随时重新启用。
- 加入黑名单需二次确认。

## 4.2 服务生态

服务生态用于维护**专业服务机构档案**。专业档案不重复建立企业主体，而是关联一条已存在的合作伙伴档案；该合作伙伴必须具备**供应商角色**，以便后续运费、检测费、仓储费进入应付结算。

入口：「主数据管理 → 服务生态」，分四类：

| 类型 | 维护内容 | 业务约束 |
|---|---|---|
| 物流承运商 | 道路运输许可证、资质有效期、运输方式、承运货物、服务区域、调度联系人、保险、结算方式 | 第三方物流运单**必须**从有效承运商中选择，不能自由填写 |
| 质检机构 | 机构资质、CMA、CNAS、支持物料、检测项目、服务区域、报告周期 | 合作方或第三方质检单必须从有效机构中选择 |
| 仓储与港口 | 运营类型、仓储能力、支持货物、服务区域、结算方式 | 新建或编辑**租赁仓库**时必须选择有效仓储服务商 |
| 加工服务商 | 加工能力、支持物料、服务范围、产能、资质、结算方式 | 委外生产任务**必须**选择有效加工服务商 |

同一合作伙伴可分别建立多类专业档案，但**同一专业类型只能有一条有效档案**。停用或黑名单档案不出现在新单据选择列表中，历史单据保留业务发生时的名称快照。

## 4.3 物料分类与商品物料

### 4.3.1 物料分类

先维护物料分类（支持两级），再在分类下建立物料档案。分类名称可按业务需要自由定义。

### 4.3.2 新建商品物料

进入「主数据管理 → 物料品类 → 新建商品物料」。建档已简化，**商品名称由系统自动拼接**，不手工填写。

| 字段 | 说明 |
|---|---|
| 商品分类 | 选择已维护的一级或二级分类 |
| 商品形态 | 精粉、原矿、块矿等 |
| 核心规格 | 指标 + 比较符 + 数值 + 单位，如 `CaF₂≥97%` |
| 包装方式 | 散装、吨袋、500kg 吨袋、1 吨吨袋等；可不带重量前缀直接选"吨袋" |
| 参考类型 | 默认"贸易商品（TRD）"，也可选原材料（RAW）、半成品（SFG）、产成品（FGD）；仅用于编码、统计和检索 |
| 计量单位 | 默认：吨 |
| **商品名称** | **只读**，按"所选分类名称 + 形态 + 核心规格"自动拼接，如"萤石精粉-CaF₂≥97%"；包装方式独立显示 |
| **物料编码** | **自动生成**：`TRD`/`RAW`/`SFG`/`FGD` 等前缀 + 6 位流水号 |
| 规格标准定义 | 独立常驻板块；第一行为核心规格，可追加水分、杂质、粒度等指标 |
| HS 编码 / 税务商品编码 | 报关与开票用，可选 |
| 质检模板 | 关联结构化质检模板，到货时按此解析检测指标 |
| 虚拟物料 | 委托加工成品/中间品，不参与实物库存 |

标准商品匹配、查重、标准编码和物料编码均由系统后台完成。

### 4.3.3 创建后的修改边界

创建后**分类、品名、形态、核心规格、包装和单位不可直接修改**，防止改变历史合同和库存中该商品的含义。可继续维护：状态、质检模板、HS/税务/内部编码、备注。需要加工后产成品时，使用「基于此物料创建产成品」快捷入口。

## 4.4 质检标准

入口：「主数据管理 → 质检标准」。依次维护三类可配置主数据：

| 类型 | 维护内容 |
|---|---|
| **检测指标** | 如 CaF₂、水分、SiO₂、粒度；维护编码、名称、符号、默认单位和精度 |
| **检测方法** | 如化学滴定法、XRF、烘干法、筛分法；维护方法编码、标准编号和版本 |
| **质检模板** | 按业务场景（采购/销售/通用）和物料分类，组合指标、判定符、标准值、拒收值及默认检测方法 |

- 指标与方法是**多对多**关系，可为指标指定默认方法；模板中每个指标只能选择已与其关联的方法。
- 物料可直接绑定一个启用中的模板；未绑定时系统按物料分类和采购/销售场景解析默认模板。
- 用户在某物料下选过检测方法后，系统下次优先带出该选择。
- 历史文本模板仅用于兼容显示，不再作为新业务的配置来源。

> **提示**：到货质检要按模板带出指标和阈值，因此**上线前必须至少维护一套质检模板**，否则质检报告录入时无法自动带出指标。

## 4.9 常见问题

**Q：一家企业可以同时是供应商和客户吗？**
A：可以。创建时同时勾选两个角色即可，系统内只有一份档案。

**Q：运输公司怎么建档？**
A：先建立为具有供应商角色的合作伙伴，再到「服务生态 → 物流承运商」创建专业档案。外协车辆从有效承运商中选择所属单位；内部车队车辆选"自有车辆"并关联内部主体。

**Q：合作伙伴编码可以修改吗？**
A：不可以。内部企业编码由管理员手工确定；外部单位编码由系统自动生成（8 位数字），如需手动指定，输入前系统会校验是否已存在。

**Q：物料停用后，历史合同怎么处理？**
A：停用仅影响新建单据，历史单据中引用的物料信息保持不变。

# 第 6 章 合同管理

合同是履约业务的上游依据，也是**企业数据范围的根单据**。

## 6.1 前置条件

- 已完成主数据配置（合作伙伴、物料等）
- 已启用对应合同类型的审批流程，并为所有启用节点配置有效审批人

## 6.2 创建与草稿

进入「采销管理 → 合同管理 → 新建合同」。

- 新建页第一次保存或提交时创建一份草稿，同一次新建请求具有唯一标识。**网络重试、后续保存和再次提交始终返回或更新同一份草稿，不会重复生成合同。**
- 修改表单后，通过返回、取消、侧边栏菜单或浏览器后退离开页面时，系统提示"保存草稿并离开 / 不保存并离开 / 继续填写"。选择保存时，即使主体、对手方或货物尚未填写完整，也会保存当前表单和待上传附件，再次编辑可恢复。
- **刷新或关闭浏览器标签页**受浏览器安全限制，只显示浏览器原生提醒，应先返回页面点击保存草稿。

**关键字段说明**

| 字段 | 说明 |
|---|---|
| 业务部门 | 新建时默认带出当前账号关联员工的所属部门，可在本企业部门范围内调整；用于匹配按部门配置的审批节点 |
| 外部合同号 | 填写纸质合同或其他系统的合同编号，便于跨载体对账；**不等同于**系统自动生成的合同编号 |
| 结算方式 | 可输入字段：既可选择按交货、预付、分期、月结等建议，也可直接录入合同约定原文 |
| 溢装/短装比例 | 统一默认 `10%`，保留显式配置 `0%` 的能力 |

> **统一规则**：所有包含"业务部门"字段的新建业务单据，前端默认显示发起人员工档案的所属部门，后端在未显式传值时再次以发起人部门兜底。

## 6.3 提交审批

点击「提交审批」时，系统按顺序执行：

1. 先保存合同；
2. 检查对应合同类型的审批流程、金额条件、节点角色和组织范围内角色成员是否有效；
3. 检查通过后上传附件，并按成员快照发起审批。

审批任务生成与合同进入「待审批」状态在**同一事务**中完成，任一环节失败都不会留下没有任务的待审批合同。

**失败处理**：审批流程未启用、节点或审批人配置不完整时，合同保留为草稿并提示"合同已保存为草稿，不会重复创建"。修复审批配置后可继续提交原草稿，无需重新新建。

历史草稿缺少业务部门时，系统优先使用创建人当前所属部门完成审批解析并在提交时补写；创建人未关联部门时，必须先编辑合同选择业务部门。

**撤回**：合同创建人或系统管理员可撤回待审批合同；撤回后未处理审批任务取消，合同回到草稿。

## 6.4 状态操作

「开始执行」「标记完成」「关闭合同」统一收纳在合同详情的**「合同状态操作」菜单**中，不作为直接按钮展示：

- 选择「开始执行」或「标记完成」后，系统展示本次状态变化的业务影响，操作人勾选确认后才能提交。
- 选择「关闭合同」后，系统提示关闭后不能继续生成下游单据，并要求**输入当前合同编号**完成确认。

二次确认仅用于防止误触，不扩大操作权限；状态操作仍受角色权限和状态机控制。

## 6.5 作废与删除

- 合同**不能直接删除**，必须先执行「作废」（草稿除外）。
- 草稿可由创建人或系统管理员直接软删除，不要求先作废。
- 待审批合同作废时，当前未处理及等待中的审批任务一并取消。
- **只有系统管理员**可以删除已作废合同；普通用户不显示删除入口，接口也会拒绝越权删除。
- 删除采用软删除，合同不再出现在业务列表，数据库审计记录仍保留。

## 6.6 履约进度

合同详情右侧的「履约进度」板块集中展示合同向下游的执行情况：

- 按**待执行、执行中、已执行**三个口径展示数量和金额；
- 根据有效执行批次状态自动计算总体履约百分比；
- 展示执行批次总数和已完成数量；
- 列出关联的采购/销售执行批次、金额和状态，点击可直达执行批次详情。

**计算口径**（实时计算，不人工填写）：

- 已完成执行批次 → 计入「已执行」
- 执行中的执行批次 → 计入「执行中」
- 合同总量/总额扣除上述两项后的余额 → 计入「待执行」（草稿和已确认批次属于待执行范围）
- 已取消执行批次**不占用**合同量，也不计入总体进度
- 合同关闭或完成后，总体进度显示为 100%
- **双边合同按采购端和销售端分别统计**，防止两端数据重复累计

## 6.7 操作记录

合同详情的「操作记录」板块记录合同创建、编辑、提交审批、撤回、状态变化、附件上传及删除等动作，每条显示实际操作人员、登录账号和操作时间，存在原因或备注时一并展示。

审批节点处理人和审批意见在**审批时间线**中单独展示；操作记录与审批记录共同构成完整追溯信息。合同软删除后操作记录仍保留。

## 6.8 权限与数据范围

- 查看、新建、修改、提交、审批、作废和删除分别受合同模块功能权限控制。
- 外部企业员工可查看本企业合作伙伴作为卖方、买方或签约主体的**全部合同**，不限创建人；尚未选定交易主体的未完成草稿也按所属外部企业共享。
- 合同附件使用与合同相同的企业范围，不能通过附件接口查看无权合同的文件。

# 第 7 章 审批流程

系统按合同类型使用**顺序多级审批链**。审批节点绑定**审批角色**而非固定账号；合同提交时，系统解析该角色的有效成员并生成审批人快照。

## 7.1 前置条件

- 已完成组织架构和用户配置
- 审批人账号状态为「启用」，并已获得节点绑定的审批角色
- 节点角色拥有 `contract.approve` 合同审批权限
- 用户角色授权的数据范围覆盖合同所属企业或业务部门
- 合同处于「草稿」状态且信息完整；按部门审批时必须能确定业务部门

系统预置**业务主管、风控经理、总经理**三个审批角色。

## 7.2 默认审批链

| 合同类型 | 审批顺序 | 默认方式与范围 | 条件 |
|---|---|---|---|
| 采购合同 | 业务主管 → 风控经理 → 总经理 | 全部会签；业务主管按合同部门，其他按合同企业 | 总经理节点仅在合同金额达到门槛时启用，**默认门槛 1,000,000 元** |
| 销售合同 | 业务主管 → 风控经理 | 全部会签；业务主管按合同部门，风控经理按合同企业 | 固定两级 |
| 双边合同 | 业务主管 → 风控经理 → 总经理 | 全部会签；业务主管按合同部门，其他按合同企业 | 固定三级 |

## 7.3 配置审批流程

使用系统管理员账号进入「系统管理 → 审批流程」。

**当前可配置**：

- 启用或停用整条审批流程（采购/销售/双边）
- 为每个节点选择审批角色
- 设置审批方式：**会签**（全部通过）或**或签**（一人通过）
- 设置人员范围：合同业务部门 / 合同所属企业 / 全平台
- 启用或停用单个审批节点
- 设置采购合同的总经理审批金额门槛

**当前尚不能在页面配置**（需开发介入）：

- 新建审批流程
- 新增、删除或拖动调整审批节点
- 按岗位负责人、组织负责人等规则自动推导角色
- 配置流程版本和并行分支

> 系统管理菜单及审批配置接口**仅对系统管理员开放**，审批员和普通用户不能查看或修改配置。

## 7.4 提交与处理

1. 业务人员在合同详情页点击「提交审批」。
2. 系统读取合同业务部门、当前流程、节点角色、审批方式和人员范围。
3. 解析角色的有效成员，将名单保存为**本轮审批快照**。
4. 第一级所有成员任务进入「待处理」，后续节点成员任务进入「等待中」。
5. 当前节点成员进入合同详情，**填写审批意见（必填）**并选择「通过」或「驳回」。
6. 会签节点全部成员通过、或或签节点任意成员通过后，自动激活下一级全部成员任务。或签同节点其他未操作成员显示"他人已审批"；任一成员驳回时，同节点其他成员显示"他人已驳回"。
7. 最后一级满足通过条件后，合同状态变为「已通过」。
8. 任意成员驳回后，合同状态变为「已驳回」，本节点其他任务和后续节点自动取消。

**管理员兜底**：系统管理员可处理当前节点，通过时视为代办本节点全部未处理成员，但**不能跳过节点顺序**。每条成员任务仍保留原审批人，同时记录实际操作管理员，详情时间线显示"由系统管理员代为处理"。

**成员变更不影响在途审批**：本轮使用提交时的成员快照，后续新提交或重新提交才使用最新成员。

## 7.5 驳回后重新提交

1. 已驳回合同支持修改内容和附件。
2. 将合同恢复为「草稿」后再次提交审批。
3. 系统创建**新的审批轮次**，不覆盖上一轮记录。
4. 新一轮按提交时的最新流程配置依次流转。

## 7.6 审批任务状态

| 状态 | 说明 |
|---|---|
| WAITING | 等待前序节点完成 |
| PENDING | 当前审批人待处理 |
| APPROVED | 当前节点已通过 |
| REJECTED | 当前节点已驳回 |
| OTHERS_APPROVED | 或签同节点已由他人审批 |
| OTHERS_REJECTED | 或签同节点已由他人驳回 |
| CANCELLED | 因驳回或重新提交而取消 |

## 7.7 库存冲销审批（独立规则）

库存冲销采用**单级审核**，不走合同审批链：

- 冲销申请提交后进入「待审批」，冲销数量立即占用原单可冲销额度。
- `APPROVER` 审批人和 `ADMIN` 系统管理员均可处理；管理员可审批全部冲销单。
- 驳回必须填写原因，驳回后立即释放预留额度。
- **审批通过后库存尚未变化**，必须继续执行「冲销过账」才会生成反向库存台账。

## 7.8 常见问题

- **看不到「系统管理」**：当前账号不是系统管理员。
- **提交时提示流程未启用**：管理员需启用对应合同类型的审批流。
- **提交时提示节点没有有效人员**：给节点角色配置有效用户，并检查其数据范围是否覆盖合同部门或企业。
- **提交时提示需要合同业务部门**：编辑合同并选择业务部门；历史草稿若创建人已关联部门，系统会自动补写。
- **审批按钮不可用**：当前用户不在本轮节点成员快照中，或账号/角色授权已失效；系统管理员不受此限制。
- **采购合同没有总经理节点**：合同金额未达当前配置门槛，或该节点已停用。

# 第 8 章 合同执行批次

执行批次是合同拆分后的具体业务执行单据，控制合同明细的累计执行数量。

## 8.1 前置条件

- 合同已审批通过，状态为「已通过」或「执行中」
- 合同至少包含一个有效行项

## 8.2 新建

可从以下入口进入：

- 「采销管理 → 执行管理 → 新建执行批次」
- 合同管理页顶部「新建执行批次」后选择合同
- 已通过或执行中合同的**列表行、详情页顶部或右侧履约进度**中点击「新建执行批次」，自动带入当前合同

操作步骤：

1. 选择状态为「已通过」或「执行中」的合同。
2. 填写执行批次名称。系统提供"合同标题 + 采购/销售执行批次"的建议名称，可修改。
3. 系统自动生成唯一执行批次编号，并带出合同明细、单价、交货地点和**剩余可执行数量**。
4. 填写本批次数量、计划履约日期、交货地点和备注。
5. 确认金额后点击「创建执行批次」。

**首次从「已通过」合同生成执行批次后，合同自动进入「执行中」状态。**

## 8.3 方向与数量控制

| 合同类型 | 可生成执行批次 |
|---|---|
| 采购合同 | 采购执行批次 |
| 销售合同 | 销售执行批次 |
| 双边合同 | 分别生成采购执行批次或销售执行批次 |

- 一个合同可生成多个执行批次，每条明细必须来自所选合同。
- 本批次数量必须大于 0。
- 同一方向所有**未取消**执行批次的累计数量不能超过合同数量。
- 已取消执行批次**不占用**合同数量，可重新建立批次。
- 双边合同的采购端和销售端分别统计剩余数量，互不占用。

## 8.4 状态流转

```text
草稿 → 已确认 → 执行中 → 已完成
  └→ 已取消 ←┘
```

| 状态 | 可执行操作 |
|---|---|
| 草稿 DRAFT | 修改、确认、取消、删除 |
| 已确认 CONFIRMED | 开始执行、取消；**可生成执行通知** |
| 执行中 DISPATCHED | 跟踪下游执行单据、完成执行批次 |
| 已完成 COMPLETED | 查看 |
| 已取消 CANCELLED | 查看、删除；数量重新释放 |

系统在开始执行时记录执行开始时间，完成时记录完成时间，**不允许跳过中间状态**。

> **重要**：执行批次「执行中」不代表车辆已发运。车辆运输状态以**物流运单**为准。

## 8.5 常见问题

- **找不到合同**：合同尚未审批通过，或已关闭/作废。
- **数量无法提交**：本批次数量超过该方向的剩余可执行数量。
- **执行批次不能删除**：仅草稿和已取消批次允许删除。
- **执行批次不能直接完成**：必须依次经过确认和开始执行。

# 第 9 章 执行通知

执行通知承接已确认的执行批次：采购方向生成「供应商发货指令」，销售方向生成「销售发货通知单」，并向下拆分物流运单。

## 9.1 创建规则

- 一个执行批次可拆分多张执行通知，**累计通知数量不得超过批次数量**。
- 采购执行批次只能生成供应商发货指令，编号格式 `PI-年月日-流水号`。
- 销售执行批次只能生成销售发货通知单，编号格式 `SD-年月日-流水号`。
- **销售常规出库必须选择发货仓库**；直拨业务可以不选择仓库。
- 起运地点和目的地点均为必填，可从有效仓库快捷选择（自动带入"仓库名称（地址）"），带入后仍可按实际作业地点修改。销售常规模式选择起运仓库时，该仓库同时作为正式发货仓库保存。
- **执行通知一期不设置审批**，由有权限的业务人员直接下达。
- 已取消通知释放占用数量；**已有有效物流运单的通知不能取消**。

## 9.2 操作流程

1. 进入「采销管理 → 执行通知 → 新建执行通知」。
2. 选择已确认或执行中的执行批次。
3. 填写本次通知数量、执行模式、计划日期、起运地点和目的地点。
4. 销售常规模式必须在起运地点选择仓库。
5. 创建后检查通知明细，点击「下达通知」。
6. 已下达通知可创建一张或多张物流运单。

**销售发货通知下达后，系统自动生成出库管理单并冻结库存**（详见第 14 章）。

## 9.3 状态流转

```text
草稿 → 已下达 → 执行中 → 已完成
  └→ 已取消 ←┘
```

- 第一张物流运单进入「在途」时，通知自动进入「执行中」。
- 所有有效物流运单签收后，通知才能完成。

# 第 10 章 物流运单与调度

物流运单是**车辆/车次级**运输单据，必须关联已下达或执行中的执行通知。一张运单对应一辆车的一个运输趟次。

## 10.1 单车建单

进入「物流管理 → 运单管理」，选择「单车建单」；也可从执行通知详情进入并自动带出通知。

1. **文字信息自动识别**（可选）：把微信、短信或调度文字粘贴到识别窗口并点击「识别并填入」。系统可识别通知号/批次号/合同号、车牌、司机、电话、承运单位、运输数量、起讫地和计划时间。**识别只回填表单，不自动创建。**
2. 选择已下达或执行中的执行通知。
3. 填写本车运输数量，**累计数量不得超过通知数量**。
4. 可在创建时选择车辆，也可先创建待发运运单，再到运单详情或调度看板分配车辆。
5. **自有运力**从启用的自有车辆中选择；**第三方承运**先选物流承运商，再从该承运商名下启用的外协车辆中选择。
6. 选择车辆后系统优先带入该车主驾；司机选择器把车辆关联司机排在前面，也可按姓名、手机号或服务商筛选同承运商其他司机。未建档的临时司机可手工填写。
7. 填写计划发运时间和预计到达时间，用于调度计划和超时判断。
8. **确认发运前必须具有车牌和司机信息**；第三方承运还必须填写承运单位。

运单编号格式：`WB-年月日-流水号`。

## 10.2 批量派车

- **一条车辆明细生成一张独立运单**；同一车辆执行多趟时，每趟单独一行并生成不同运单。
- 公共区域统一填写起运地、目的地、默认运输方式、承运商、计划时间和备注，可一键应用到全部车辆；每行仍可单独调整。
- 支持选择已维护车辆/司机，也支持填写临时车辆（必须填写车牌、司机姓名和联系电话，**不会**反向创建车辆主数据）。
- 支持粘贴"每车一行"的调度文字。多物料通知只识别车辆信息，数量需逐项核对。
- 页面按物料实时汇总通知数量、已建运单数量、本次分配数量和创建后剩余数量。
- **提示 vs 拦截**：车辆登记载重不足、同车同时间重复属于调度核对**提示**；数量越界、承运关系错误、车辆司机缺失和时间倒置会**直接阻止创建**。
- 一次批量提交最多创建 **100 张**运单。服务端整批复核，**要么全部成功、要么全部不创建**；重复点击或网络重试不会重复建单。

## 10.3 运输状态

```text
待发运 → 在途 → 已到达 → 已签收
  └→ 已取消
```

- 工作台把 `PENDING` 运单进一步区分为「待调度」（缺少车牌或司机）和「待发运」（资料完整）。
- 「待发运」阶段可修改车辆调度信息；**「在途」以后保留运输快照，不允许更换车辆**。
- 运单进入「在途」时，对应执行通知进入「执行中」。
- **采购运单确认发运进入「在途」时，系统自动生成「待到货」入库作业单**（详见第 13 章）。
- 运单确认到达时，系统自动生成**到货质检任务**（详见第 12 章）。

## 10.4 调度看板

进入「物流管理 → 调度看板」，按待调度、待发运、在途、已到达、已签收五列展示运单。

- 汇总有效运单、待调度、在途车辆、已签收和调度异常数量。
- 支持按运单、通知、批次、合同、车牌或司机搜索，可按采购/销售运输筛选。
- 运单卡片展示物料数量、运输方式、线路、计划时间及完整上游单据链。
- 可在卡片上直接确认发运、到达和签收；待调度运单进入详情补充车辆信息。
- **异常提示**：超过计划发运时间仍未发运、超过预计到达时间仍在途，或车辆司机资料缺失时显示异常，支持「只看异常」。

## 10.5 运单详情

- 顶部展示创建、发运、到达和签收进度，以及计划发运、预计到达、实际发运、实际到达和签收时间。
- 车辆选择器直接引用车辆主数据；**运输方式与车辆归属必须一致**，外协车辆必须属于当前所选物流承运商。
- 司机选择器引用独立司机档案。第三方运输只能选择当前承运商的司机；自有运力只能选择内部物流服务商维护的司机。
- 运单到达或签收后出现**「关联磅单」**板块，可直接创建或查看磅单。
- 运单到达后出现**「物流收货附件」**板块，按「签收单」「收货现场照片」「其他交接凭证」三行独立展示和上传。

**签收附件规则**：三类附件**合计至少存在一份**即可确认签收，不要求每类都上传。**已签收运单的收货附件保留为履约凭证，不允许删除。**

**小程序**：物流运单详情采用相同分类。现场照片可调用相机或相册；签收单和其他凭证还可从微信聊天文件中选择。支持查看附件、签收前删除误传附件，并在至少上传一份后直接确认签收。

# 第 11 章 磅单管理

磅单归集一辆车在**发货方、收货方**形成的多张完整称重凭证，并从中确定库存执行与结算共同采用的净重。

## 11.1 管理层级

```text
过磅任务（一条物流运单一个，车辆确定后自动生成）
└── 物流运单（一条任务信息）
    ├── 发货称重：第一张完整磅单、追加完整磅单……
    └── 收货称重：第一张完整磅单、追加完整磅单……
        每张完整磅单 └── 多条毛重/皮重记录
```

「过磅任务」列表按物流运单展示，**一辆车一行**。车辆/车牌确定后任务自动生成，因此尚未录入任何磅单时也能作为待办出现。

**录入时点**：发货称重可在运单待发运、在途、到达或签收阶段录入；**收货称重需在运单到达后**录入。

## 11.2 现场证据影像

- 节点包括：车牌与车头、货物与车厢、车辆上磅、地磅显示屏、空车状态、其他影像。
- 小程序选择节点后直接调用相机；Web 端允许上传第三方水印相机、外部影像或普通电脑文件。
- **计划重量只作为任务信息写入证据元数据，不冒充实际重量**；实际毛重、皮重以地磅显示屏照片和称重记录为准。
- 系统保留来源、节点、拍摄/上传时间、上传人、文件 SHA-256 和水印文本快照。

## 11.3 创建磅单

1. 进入「质检影像 → 磅单管理」，打开自动生成的过磅任务并点击「新增称重磅单」；也可从物流运单创建。
2. 选择物流运单。系统自动带出执行批次名称、运单编号、车牌、运输数量和采购/销售方向。
3. **结算重量口径默认「收货称重」，磅差容差默认 `0.5%`。**
4. 如改选发货重量、客户收货重量、第三方重量或手工确认重量，必须填写对应重量。
5. **至少上传一份**现场磅单照片、设备导出磅单或扫描件。支持 JPG、PNG、WEBP、PDF，单个文件**不超过 20 MB**。
6. 确认后系统生成 `PD-年月日-流水号` 格式的磅单编号。

系统自动带出车牌、司机、货物名称、规格型号、发货单位、收货单位及司磅员。操作人员需核对并补充**包/袋数**（散装填 `0`）。

**追加磅单**：同一运单允许在发货、收货两个节点分别维护多张完整磅单。每个节点第二张及以后属于追加磅单，**必须填写追加原因**；原磅单不会被覆盖。

## 11.4 称重与复磅

1. 磅单详情「新增称重记录」默认生成毛重、皮重两条基础录入行。**采购入场按「毛重 → 皮重」排列，销售出场按「皮重 → 毛重」排列。**
2. 每行填写重量、数据来源、称重时间和备注。首次称重时间默认取打开录入页时的系统时间，后续默认以上一次时间为基准随机增加 30–40 分钟（精确到秒）；所有默认时间均可手动修改，完整保存到秒。
3. **可分阶段保存**：只填写并保存当前已完成的称重，未填写重量的基础行不会提交；再次进入时系统继续提供尚未完成的称重。
4. 毛重和皮重均存在后，系统自动计算 `收货净重 = |有效毛重 − 有效皮重|`。
5. 需要复磅时点击「追加称重记录」，选择毛重或皮重继续录入。每条记录保留序次、来源、时间、操作人和备注，**不覆盖历史数据**。
6. 新增记录默认成为该类型的最新有效记录。如需采用其他结果，在记录表分别选择有效毛重和有效皮重，点击「保存有效毛重/皮重」。
7. 检查净重、磅差和结算重量无误后点击「完成称重」。

**完成称重前必须同时选择有效毛重和有效皮重，且当前结算口径必须有可用重量。完成后不能再追加复磅或更换有效记录。**

附件：待称重或称重中可删除；完成称重后作为业务凭证锁定，不可删除。

## 11.5 结算重量口径

| 口径 | 使用方式 |
|---|---|
| 收货称重 | **默认**；取本磅单有效毛重和皮重计算的净重 |
| 发货重量 | 输入发货环节确认重量 |
| 客户收货重量 | 输入客户签收确认重量 |
| 第三方重量 | 输入第三方计量机构确认重量 |
| 手工确认重量 | 输入争议协商或特殊流程最终确认重量 |

切换口径**不会删除**收货净重和其他重量。系统同时保留计划数量、收货净重、磅差、磅差率和最终结算重量。

## 11.6 选择结算入库磅单

1. 打开运单级「磅单信息」详情，核对发货、收货及追加的全部完整磅单。
2. **只有状态为「已复核」且存在有效净重**的磅单可选用。
3. 点击「选为结算入库磅单」后，系统把同一净重**同时同步给库存执行与结算**，不能分别选择两张。
4. 首张发货称重磅单复核后，系统在尚无选择时自动建立默认口径；后续收货或追加磅单**不会自动覆盖**。
5. 改选其他磅单**必须填写原因**。若相关入库/出库已过账，或出库已完成批次拣配，系统**禁止更换**。

## 11.7 状态与复核

```text
待称重 → 称重中 → 待复核 → 已复核
   └──────────────→ 已作废
```

- 新建后为「待称重」，新增任一称重记录后进入「称重中」。
- 毛重、皮重和结算重量完整后可完成称重，进入「待复核」。
- **收货净重相对运单计划数量的偏差超过容差时标记「磅差异常」。**
- 磅单进入「待复核」后，详情页顶部直接显示复核操作区。磅差异常时该区域以**红色边框**突出，同时展示磅差、偏差率和容差。
- **异常磅单复核必须填写偏差原因、核查过程和处理意见**，意见为空时按钮不可提交；正常磅单的复核意见可选。
- 已复核磅单不能修改结算口径或直接作废。

## 11.8 常见问题

- **创建收货磅单时看不到某张运单**：运单尚未到达（发货称重不受此限制）。
- **复磅会覆盖第一次数据吗**：不会。每次复磅新增记录，只改变默认选择的有效记录。
- **为什么不能完成称重**：检查是否已有有效毛重、有效皮重，以及所选结算口径是否存在对应重量。
- **附件选择后不能上传**：检查扩展名是否为 JPG/JPEG/PNG/WEBP/PDF，文件是否为空或超过 20 MB。

# 第 12 章 到货质检

物流运单确认到达后，系统**自动生成**一条「到货质检任务」。列表一行代表**一辆车的一次到货质检**，任务详情内可录入一家或多家检测机构的独立报告，并形成**一个**最终质检结论。

## 12.1 名称口径

| 名称 | 含义 |
|---|---|
| 到货质检任务 | 一次到货的完整质检业务容器，管理列表中的一行 |
| 机构检测报告 | 一家检测机构对一个样品出具的一份具体报告 |
| 最终质检结论 | 综合实际有效报告形成的**任务级**业务结论 |
| 执行口径报告 | 为入库扣水扣杂及结算提供具体数值的**一份**已确认报告 |

机构检测报告关联的是本次检测所依据的**磅单重量快照**，不会额外创建磅单。同一到货任务的多份报告通常关联同一张当前执行磅单，也允许选择该运单下其他已完成或已复核磅单。**系统不允许跨物流运单关联磅单。**

## 12.2 操作流程

1. 物流人员在运单详情**确认到达**，系统自动生成质检任务，初始状态「待取样」。
2. 进入「质检影像 → 质检管理」，打开对应任务；登记取样时间、取样人、取样方法和**计划报告数**。
3. 在 Web 端上传第三方水印相机/普通相机影像，或由已绑定后台账号的小程序用户在现场选择节点并调用相机拍摄。
4. 磅单完成称重或复核后，在「机构检测报告」板块点击「添加检测报告」。系统只列出该运单下的有效磅单，按「当前执行磅单 → 已复核发货磅单 → 其他有效磅单」顺序默认选择。随后按物料解析质检模板，带出指标、阈值及允许的检测方法。
5. 填写样品编号、检测机构、报告编号、检测时间和实测值，并上传该机构的检测报告附件。
6. 返回任务详情，对每份已出报告执行「确认报告有效」。
7. 至少存在一份有效报告后，**选择一份作为入库和结算的执行口径**，确认形成最终结论。

**计划报告数默认 1**，可按合同及风险要求调整为 2 份、3 份或更多。有效报告**少于**计划数量时，必须填写提前判定原因；系统会提示缺少平行检测对比的风险并要求二次确认。

## 12.3 状态说明

```text
待取样 → 待送检 → 检测中 → 待综合判定 → 已完成
                                   └→ 新增报告后待复判
任一阶段可进入异常处理中；作废后终止
```

机构报告自身有「已出报告、已确认、已作废」等状态。

> **关键规则**：确认机构报告只表示该份报告有效，**不会直接形成库存**。只有任务级最终结论为「合格」后，系统才会补齐入库作业依据。任务结论为**超标扣款、不合格（拒收）或待判定**时，只展示为异常或处理中，**不允许成为库存入账依据**。

## 12.4 附件与追溯

- 任务级现场影像按取样、混样、分样、封样和其他节点归档，保存来源、拍摄/上传时间、上传人、文件 SHA-256 和水印文本快照。
- 小程序拍摄来源标记为 `MINI_PROGRAM_CAPTURE`；Web 端可选第三方水印相机、系统导入、外部影像或普通上传。
- 外部水印照片原样保存，**不伪造其原始水印**。
- 每份机构报告可单独上传附件，支持 JPG/JPEG/PNG/WEBP/PDF，单个不超过 20 MB。附件在当前页面预览，不打开新标签页。
- 任务详情同时显示合同、执行批次、物流运单、磅单和入库作业单入口。
- 系统记录报告录入人、确认人、任务处理人、最终判定人、判定时间及版本。

## 12.5 权限

当前采用轻量权限：拥有**「质检管理」**权限的人员可完成取样录入、报告维护、报告确认和最终判定，不再拆分多个质检岗位角色。只有查看权限的人员可查看任务、报告和附件，但不能操作。

# 第 13 章 采购入库与库存形成

入库模块承接采购物流发运后的业务闭环。**无需人工新建入库单**——采购运单确认发运、进入在途时系统自动生成「待到货」入库作业单，同一张单持续跟踪到达、签收、过磅、质检、现场收货和库存入账。

## 13.1 前置条件

- 物流运单方向为**采购**，且已确认发运。
- 运单到达后才能进入现场过磅和质检节点。
- 正式确认收货和库存入账前，必须存在：
  - 一张**「已复核」磅单**；
  - 一张被选为最终验收依据的**「已确认且合格」质检结论**。
- 主数据中已维护启用状态的入库仓库。
- **「超标扣款」「不合格（拒收）」或「待判定」的货物不可入库**，也不能生成库存批次和台账。

## 13.2 自动生成规则

1. 采购运单确认发运、状态进入「在途」时，系统自动生成「待到货」入库作业单。
2. 运单确认到达时，系统再次检查并**幂等补生成**漏单。
3. 同一运单不存在其他未作废的入库作业单。
4. 后续磅单与质检单均关联并更新这张既有作业单，**不重复创建**。

系统初始带出运单、合同、执行批次、计划数量、物料、供应商、车牌及目标仓库；磅单、最终验收质检单、质量扣减和最终入库数量在后续作业中逐步补齐。

**最终入库数量优先取质检单的结算重量；质检单未单独给出时取磅单结算重量。**

## 13.3 上传收货附件

物流入库单处于「待入库」时，可在详情页上传现场照片、签收凭证或 PDF：

- 支持 JPG、PNG、WEBP、PDF；单个文件不超过 20 MB。
- 待入库状态支持查看、增加和删除；**确认收货后附件锁定，只允许查看**。

## 13.4 确认收货与入账

1. 核对物流、磅单、质检和附件，补齐**仓库、实际收货时间、收货人**后点击「确认收货」。
2. 已收货状态点击「生成业务入库并入账」。
3. 系统自动生成**业务入库单、库存批次**和一条**入库台账**，并增加可用库存。

服务端会在任务最终判定、验收依据绑定、确认收货和正式入账四个环节**重复校验**质检状态与结论。历史「超标扣款」待入库单或已收货单不能继续入账，应完成复检并重新形成任务级合格结论；无法修复的异常单再作废处理。

## 13.5 状态流转

```text
待到货 → 已到达待过磅 → 过磅处理中/待复核 → 已过磅待质检
→ 质检处理中/质检异常 → 合格待收货 → 已收货待入账 → 已入账
                                       └──作废────────→ 已作废
```

- **作业中**：由采购运单确认发运自动生成，通过细分阶段展示待到货、过磅、质检和合格待收货。
- **已收货**：现场收货已确认，可生成业务入库并入账。
- **已入账**：业务入库单、库存批次、库存台账已形成。
- **已作废**：不再参与后续业务；运单仍处于有效执行状态时，系统可补生成新的入库作业单重新完成验收。

## 13.6 库存查询（在库总览）

进入「库存管理 → 在库总览」可查看：

- 用户权限范围内的**总账面库存、待出库冻结、可用库存**，以及库存主体数、批次数、物料数和仓库数。
- **「主体及仓库库存汇总」**按"我方采购主体 + 实物仓库"逐行展示。平台总库存只作统计，**不合并不同主体的货权**。
- 每个批次的库存主体、业务入库单、物料、供应商、仓库、初始数量、账面数量、冻结数量、可用数量和质量结论。
- 库存台账中的业务类型、业务单号、数量变动和变动后余额。

**核算口径**：

```text
库存最小核算单位 = 主体 + 仓库 + 物料 + 批次
可用库存 = 账面库存 − 待出库冻结 − 生产预占
```

库存主体取**采购合同的"我方签约主体"**。同一主体可在多个仓库持有库存，同一仓库也可存放多个主体的库存；**销售出库只能冻结和选择与销售合同我方签约主体一致的库存批次**。

## 13.7 常见问题

- **没有自动生成入库作业单**：检查是否为采购运单且是否已确认发运；确认到达操作会再次补生成。
- **无法确认收货**：只有待入库状态可确认，且必须先补齐仓库、实际收货时间和收货人。
- **无法上传附件**：只有待入库状态允许增删附件。
- **无法生成库存**：必须先确认收货、验收依据必须已确认且合格，且一个物流入库单**只能入账一次**。

# 第 14 章 销售出库与库存扣减

## 14.1 自动生成规则

1. 销售发货通知处于**草稿**时，不冻结库存，也不生成出库管理单。
2. **下达**销售发货通知后，系统自动生成一张管理单：常规出库编号 `OOM-`，直拨发运编号 `DFM-`。
3. **常规模式**按发货仓库和物料冻结当前可用库存。库存不足**不会阻止下达**，而是显示已冻结数量和库存缺口。
4. **直拨模式**不经过我方仓库，**不冻结或扣减我方库存**；占位单用于跟踪物流、磅单、质检和签收。
5. 常规模式创建物流运单后，系统自动在管理单下生成一条**车次出库作业**；一张通知可对应多辆车。

## 14.2 操作流程

### 14.2.1 下达通知并检查冻结

1. 创建销售执行批次和销售发货通知，常规模式**必须选择发货仓库**。
2. 将通知从「草稿」下达。
3. 进入「库存管理 → 出库单管理」，应看到自动生成的 `OOM-` 出库管理单。
4. 核对通知数量、待出库冻结、库存缺口和物料明细。
5. 打开「在库总览」，确认**账面库存不变、待出库冻结增加、可用库存相应减少**。
6. 后续有新库存入账时，可在管理单点击「刷新库存预留」。

### 14.2.2 创建物流和磅单

1. 从销售发货通知创建一张或多张物流运单；每张运单自动形成 `OWO-` 车次作业。
2. 进入磅单新建页，可先选择销售发货通知筛选车次，再选择具体运单。
3. 在**「发货称重」**节点创建我方出库磅单，**默认先皮重、后毛重**；完成称重、附件和复核。客户收货后可在「收货称重」节点补录客户磅单。
4. 待称重或称重中的磅单可在详情「关联业务 → 调整运单」修改；**复核后锁定**。
5. 质检单不是出库必填项；如果创建，出库管理单会随磅单展示质检编号和结论。

### 14.2.3 拣配和差异处理

1. 磅单复核后，管理单车次显示「拣配库存」。
2. 进入车次作业，选择运单当前「入出库有效」的已复核发货磅单，按**先进先出自动分配**，或手工调整批次。
3. **分配合计必须等于该磅单有效净重**；若需改选整张磅单，先在运单详情填写原因并完成选用变更。
4. 实际重量在容差内时，保存后进入「待放行」。
5. 超出容差时进入「待差异处理」：
   - **短装**：选择「剩余后续补发」或「本车差额关闭」；
   - **溢装**：选择「确认溢装并按实际出库」；
   - 所有处理都必须**填写原因**。

### 14.2.4 确认放行

点击「确认放行」后，系统在一次事务中完成：

- 按实际重量生成**销售出库单**；
- 按选择批次**扣减库存并写负数台账**；
- 更新出库管理单累计实际数量；
- 将物流运单更新为**在途**并记录实际发运时间；
- 将销售发货通知更新为**执行中**。

> **已正式出库的数据不能删除或修改数量，错误必须通过库存冲销处理**（见第 15 章）。

### 14.2.5 直拨发运

1. 创建销售直拨通知并下达，在「出库单管理」看到 `DFM-` 直拨发运管理单。
2. 页面显示「直拨，不经过我方仓库」，冻结数量和库存缺口均不适用。
3. 创建关联通知的物流运单后，管理单自动展示车牌、运单状态、磅单、质检单和签收进度。
4. 当前版本**不在直拨管理单中生成我方入库、出库、库存批次或库存台账**；上下游通知绑定和独立结算口径留待后续完善。

## 14.3 出库状态说明

| 状态 | 含义 |
|---|---|
| 待物流安排 | 通知已下达，尚无物流运单 |
| 库存不足 | 通知计划数量尚未完全冻结 |
| 待出库称重 | 已有车次，尚无已复核磅单 |
| 待批次拣配 | 磅单已复核，尚未完成库存分配 |
| 待差异处理 | 实际重量超过容差或通知剩余额度 |
| 待放行 | 所有前置条件已满足 |
| 部分出库 | 已有车辆放行，还有剩余任务 |
| 已完成 | 通知和全部车次履约完成 |
| 直拨待物流/待发运/运输中/待完成 | 按直拨运单的创建、发运、运输和签收状态计算 |

## 14.4 关键口径

```text
账面库存：仓库实际尚未出库的数量
待出库冻结：已下达销售通知占用但尚未正式扣减的数量
可用库存：账面库存 − 待出库冻结 − 生产预占
```

- **冻结不产生库存台账**，放行后才扣减账面库存。
- 通知计划、运单计划、冻结数量和实际出库**分别保存**，实际称重不会覆盖上游计划。
- **库存不足不能通过差异确认绕过，也不允许生成负库存。**

## 14.5 常见问题

- **看不到管理单**：确认通知已下达；常规模式还必须选择发货仓库。
- **看不到车次**：确认物流运单关联的是该销售发货通知。
- **看不到「拣配库存」**：出库磅单必须已复核且运单仍待发运。
- **库存缺口一直存在**：先确认新库存已正式入账，再点击「刷新库存预留」。
- **无法放行**：检查磅单、差异处理、批次分配和物理库存是否全部满足。

# 第 15 章 库存冲销

库存冲销用于纠正**已经入账**的业务入库或销售出库。系统**不删除、不修改**原库存台账，而是创建冲销单，经审批后在原库存批次生成方向相反的台账。

## 15.1 冲销与作废的区别

| 场景 | 处理方式 |
|---|---|
| 业务单据尚未入账 | **作废原单**，不生成库存冲销 |
| 业务入库已形成库存 | 创建**入库冲销单**，减少原批次库存 |
| 销售出库已扣减库存 | 创建**出库冲销单**，恢复原出库使用的库存批次 |

已入账的原单**不得删除或直接修改数量**。

## 15.2 入库冲销

入库冲销减少原业务入库批次的初始数量和当前可用数量。可冲销数量取以下两者的**较小值**：

```text
原业务入库数量 − 已冲销及审批中预留数量
当前库存批次可用数量
```

**示例**：业务入库 100 吨，已销售出库 30 吨，批次剩余 70 吨 → 当前最多只能冲销 70 吨。若需冲销全部入库，应**先冲销相关销售出库**。

## 15.3 出库冲销

出库冲销严格按原销售出库明细恢复库存：

```text
原销售出库：
  批次A −20 吨
  批次B −10 吨

本次冲销 15 吨：
  批次A +10 吨
  批次B +5 吨
```

**系统不允许把恢复数量增加到其他库存批次。** 每个批次累计冲销量不能超过该批次原销售出库数量。

## 15.4 操作流程

1. 进入「库存管理 → 库存冲销 → 新建冲销单」。
2. 选择「入库冲销」或「出库冲销」。
3. 从可冲销列表选择原业务入库单或销售出库单。
4. 按原库存批次填写本次冲销数量，也可填写最大可冲销量。
5. 填写冲销原因和备注，创建冲销单。
6. **草稿状态**可上传业务撤销说明、纠错凭证、现场照片或 PDF；提交审批后附件锁定。
7. 申请人在详情页点击「提交审批」。
8. 系统管理员或审批人审核，可通过或驳回（**驳回原因必填**）。
9. 审批通过后点击**「冲销过账」**。
10. 系统再次校验累计冲销量和实时库存，通过后生成反向台账并更新原单状态。

> **重要**：审批通过后库存尚未变化，**必须执行「冲销过账」**才真正生效。

## 15.5 状态流转

```text
草稿 → 待审批 → 审批通过 → 已过账
  │       └──> 已驳回
  └──> 已取消
```

原业务入库单和销售出库单按累计冲销结果变为「已入账」「部分冲销」或「已冲销」。

## 15.6 库存台账方向

| 冲销类型 | 库存台账 | 批次处理 |
|---|---|---|
| 入库冲销 | 负数 | 减少原批次初始数量和可用数量 |
| 出库冲销 | 正数 | 恢复原销售出库使用的批次可用数量 |

冲销过账、批次余额更新、原单状态更新和台账创建在**同一个数据库事务**中完成，任一步失败整体回滚。

## 15.7 注意事项

- 审批中的冲销数量会被**预留**，防止重复申请超出原单数量。
- **已过账冲销单不能直接撤回**；如冲销本身有误，应通过新的受控业务进行纠正。
- 已进入结算的原单，后续结算模块需同步生成结算调整记录。

# 第 16 章 生产管理

生产管理把库存中的原材料按生产方案转化为新的产成品库存，支持**自营生产**和**委外加工**。系统完整保留「生产方案 → 生产任务 → 原料库存批次 → 实际耗用 → 完工申报 → 质量确认 → 产成品库存批次」的追溯链。

> 一期定位是大宗贸易平台中的**轻量生产执行管理**，不建设工序级 MES、设备联网、班组排班和复杂成本核算。

## 16.1 前置条件

1. 在「主数据管理 → 物料品类」分别维护投入物料和产出物料。**加工前后物料含义发生变化时必须使用不同物料编码。**
2. 在「主数据管理 → 仓库库位」维护原料仓库和成品仓库。
3. 维护内部库存主体。库存始终按「主体 + 仓库 + 物料 + 批次」独立核算。
4. 委外加工时，先把加工企业维护为具有供应商角色的合作伙伴，再在「服务生态 → 加工服务商」建立专业档案。
5. 给相关员工授予生产管理员、仓储库管或质量岗位权限。

## 16.2 建立生产方案

进入「生产管理 → 生产方案 → 新建生产方案」：

| 字段 | 说明 |
|---|---|
| 方案名称 | 业务人员可识别的名称 |
| 库存主体 | 该方案适用的内部货权主体 |
| 产出物料 | 加工后形成库存的物料编码 |
| 基准产量 | 标准投料比例对应的产出基数 |
| 标准投入 | 每个基准产量需要的主料、辅料和包装物数量 |
| 目标收率 | 用于分析计划和实际收率，**不直接改变库存** |
| 产量允许偏差 | 控制累计完工申报的最大数量 |
| 质量控制 | 勾选后，完工申报**必须确认合格**才能入库 |
| 工艺/质量要求 | 任务详情中的作业参考说明 |

**换算示例**：基准产量 100 吨、主料标准投入 108 吨 → 新建计划产量 200 吨的任务时，系统自动生成 216 吨计划主料。

方案被任务引用后，**库存主体、产出物料和基准产量锁定**；仍可维护名称、投料标准、工艺质量说明和启停状态，修改仅影响后续新任务。

## 16.3 创建并下达生产任务

进入「生产管理 → 生产任务 → 新建生产任务」：

1. 选择生产方案，系统自动带出库存主体、产出物料和计划投入。
2. 选择**自营生产**或**委外加工**；委外时必须选择有效加工服务商。
3. 选择原料仓库、成品仓库，填写计划产量、负责人和计划时间。
4. 可记录销售需求单号作为来源参考。
5. 保存后任务为「草稿」；复核无误后进入详情点击「下达任务」。

**任务下达不会立即扣减库存**，而是开放原料批次预占。

## 16.4 原料批次预占与领料

在任务详情「原料批次预占」区域：

1. 系统仅展示与任务**库存主体、原料仓库和投入物料一致**的可用库存批次。
2. 可点击「按入库顺序分配」，也可手工填写各批次预占数量。
3. 全部投入物料达到计划用量后，任务进入「待领料」。
4. 点击「确认领料」后，系统**原子扣减**原料库存并写入「生产领料」库存台账；任务进入「加工中」。

> **生产预占与销售待出库冻结共同占用库存可用量。** 在库总览分别展示销售预占和生产预占，避免同一库存被重复使用。

## 16.5 记录耗用与退料

领料后，在每个原料批次行内记录**实际耗用**。已领但未耗用的数量可退回原库存批次，系统恢复库存并生成「生产退料」台账。

**任务关闭前，所有已领数量必须已经耗用或退回。**

## 16.6 完工、质检与入库

1. 至少记录一次实际投料耗用后，才能点击「完工申报」。
2. 一项任务可分多次完工，每次形成独立完工单。
3. 需要质检时，具有生产管理或质量管理权限的人员选择「合格、返工、报废」。**返工或报废必须填写原因。**
4. 合格完工单进入「待入库」，点击「生产入库」后生成新的产成品库存批次和生产入库台账。
5. 累计合格入库量达到任务计划产量后，任务进入「已完工」。余料处理完成后关闭任务。

**每次完工入库独立形成一个产成品库存批次**，以便后续销售出库、质量和成本追溯。

## 16.7 状态流转

```text
草稿 → 已下达 → 待领料 → 加工中
                         ├→ 待质检 → 待入库 → 部分完工/已完工 → 已关闭
                         ├→ 返工 → 加工中
                         └→ 报废（不形成库存）
```

- 草稿、已下达和待领料且尚未领料的任务可以取消。
- **已领料或开始加工后不能直接取消**，应处理耗用、退料和完工结果。
- 只有质量合格的完工申报可以生产入库。
- **完工入库是库存过账动作，不是普通状态修改。**

## 16.8 自营与委外口径

| 项目 | 自营生产 | 委外加工 |
|---|---|---|
| 执行主体 | 内部生产人员 | 服务生态中的加工服务商 |
| 原料货权 | 始终属于任务库存主体 | 发往加工方后**仍属于**任务库存主体 |
| 库存处理 | 领料扣减原料批次，完工增加产成品批次 | 委外发料同样进入在制台账，完工回库增加产成品批次 |
| 加工费 | 可不填 | 可记录加工费单价，后续结算中心引用 |

## 16.9 生产台账

「生产管理 → 生产台账」以**已入库产成品批次**为入口，反查生产任务、库存主体、加工方以及实际投入的原料库存批次。支持按完工单、生产任务、产成品或库存批次搜索。

## 16.10 权限

| 权限 | 能力 |
|---|---|
| `production.view` | 查看生产方案、任务和生产台账 |
| `production.manage` | 维护方案、创建/下达任务、预占、耗用、完工和质量确认 |
| `production.post` | 生产领料、退料和完工入库**过账** |

系统预置「生产管理员」角色。仓储库管可查看任务并进行库存过账，质量岗位可查看任务并按其质量权限参与确认。**外部加工企业仅能查看分配给本企业加工服务档案的委外任务。**

## 16.11 一期边界

当前**不包含**：工序路线、设备/工位、班次报工、BOM 多版本审批、领料单打印、加工费应付单自动生成、原辅料及制造费用成本归集、生产退库冲销、质检任务模块自动关联。

# 第 17 章 内容运营中心

「内容运营」是资讯、供需、价格、咨询、数据源、采集和 AI 能力的**唯一管理入口**，服务于产业链平台官网、氟萤直上小程序和数字大屏。

菜单对系统管理员、内容运营角色或持有任一 `content.*` 权限的账号可见。

## 17.1 资讯管理

**状态流转**

- 人工维护：`草稿 DRAFT → 已发布 PUBLISHED → 已下线 OFFLINE`
- 自动采集：`采集并去重 → 已发布 PUBLISHED → 已下线 OFFLINE`

**规则**

- 只有**已发布且已到达发布时间**的资讯可由官网和小程序读取。
- 生意社自动采集资讯在标题、正文、来源链接和发布时间解析成功并完成**三层去重**（链接、外部编号、标题）后直接发布，不经人工审核；运营人员仍可编辑或下线。
- 采集内容保留数据源、原文链接、来源发布时间、采集时间和去重标识，**人工编辑不得破坏追溯字段**。
- 下线不删除历史数据；重新发布记录操作人和时间。
- 删除仅用于草稿或已驳回内容，受 `content.article.delete` 权限控制。
- 官网、小程序和后台列表统一按 `publishAt` **倒序**；自动发布资讯的 `publishAt` 采用**原文发布时间**，保证来源最新资讯排在最前。

可维护栏目、封面上传和标签，配置在页面内完成，不额外增加菜单层级。

## 17.2 供需信息

**状态流转**：`待审核 PENDING → 已发布 PUBLISHED / 已驳回 REJECTED → 已下线 OFFLINE`

- 用户提交默认**待审核**。
- **公开接口不返回联系人、手机号、微信 OpenID 等敏感信息。**
- 驳回必须填写原因；平台运营人员可直接创建草稿或发布。
- 用户供需提交与微信 OpenID 绑定。

## 17.3 价格行情

维护产品类型、地区规格、产品价格、区域均价和历史趋势。这是平台的**真实行情数据入口**（区别于主数据中的"价格基准"示例页面）。

数据来源包括：

| 来源 | 说明 |
|---|---|
| 手工录入 | 运营人员直接新增产品类型和价格 |
| Excel 导入 | 通过「数据源管理」上传行情表，进入异步导入队列 |
| 百川行情采集 | `MARKET_SYNC` 任务，**需配置直连凭据** |
| 国际氢氟酸行情 | `HF_MARKET_SYNC`，每日检查公开月度摘要，按"月份+区域+来源"幂等入库 |
| 萤石区域趋势 | `FLUORSPAR_TREND_SYNC`，每日采集华中、华东、北方年度序列，统一按美元/吨展示 |

**Excel 表头**支持：产品编码、产品名称、业务日期、地区、市场名称、价格、单位、涨跌、备注。

## 17.4 官网咨询

**状态流转**：`待处理 NEW → 跟进中 FOLLOWING → 已完成 COMPLETED / 无效 INVALID`

- 跟进过程保留处理人、处理时间和备注。
- 列表可按姓名、电话、企业或留言搜索，按状态筛选。
- 咨询提交接口有限流并记录来源页面信息。

## 17.5 数据源管理

管理 Excel 数据、外部数据源、导入记录和最近有效数据，可启停单个数据源。

**当前产业资讯的唯一来源是生意社萤石情报**（`pid=318`）。GDELT、Fluorspar.com 资讯源和上海有色网 RSS 均已停止调度，配置和历史执行记录仅作审计保留。

**采集合规约束**：

- 自动采集器只允许访问固定的列表页及其公开详情页；重定向也必须保持在该域名和路径白名单内。
- 透明客户端标识、单并发顺序访问、详情间隔 3 秒、每次默认第一页最多 20 条。
- **若来源返回安全检查页面则停止并记录异常，不执行 Cookie 挑战或浏览器伪装。**
- 不访问登录或付费内容。页面结构异常时整次任务失败，**不发布不完整内容**。

## 17.6 采集与 AI

**任务状态**：`待执行 PENDING → 执行中 RUNNING → 成功 SUCCEEDED / 部分成功 PARTIAL / 失败 FAILED / 已取消 CANCELLED`

- 同一数据源、同一业务日期的任务**必须幂等**。
- 生意社资讯按北京时间每天 `08:00`、`12:00`、`17:00` 自动采集，也支持 Worker 启动时和后台手工触发。
- 任务结果直接展示抓取、新增并发布、重复、行业过滤及来源错误数量；抓取成功但无新内容时明确显示"本次没有新增资讯"。
- 失败按**退避策略重试**，超过上限进入人工处理。
- **查询端优先返回最近一次成功数据，采集失败不清空有效数据。**

**AI 清洗**：`AI_CLEAN` 任务调用 DeepSeek 对资讯标题和正文进行清洗，由独立 `content-worker` 进程执行。

> ⚠️ **配置依赖**：百川行情采集需配置 `BAIINFO_*` 直连凭据（不再回退旧行情服务），AI 清洗需配置 `DEEPSEEK_API_KEY`。未配置时对应任务会明确失败并在任务列表显示原因，**但不影响合同、库存、审批和物流等核心业务**——内容采集运行在与交易 API 隔离的独立进程中。

## 17.7 内容运营权限

| 权限 | 说明 |
|---|---|
| `content.article.view` | 查看资讯 |
| `content.article.manage` | 新增、编辑资讯和栏目 |
| `content.article.publish` | 审核、发布、驳回和下线资讯 |
| `content.article.delete` | 删除草稿或已驳回资讯 |
| `content.supply-demand.view` | 查看供需信息及联系方式 |
| `content.supply-demand.review` | 审核、驳回、发布、下架 |
| `content.price.view` | 查看价格与数据源 |
| `content.price.manage` | 维护产品价格与类型 |
| `content.contact.view` | 查看官网咨询 |
| `content.contact.manage` | 分配、跟进和关闭咨询 |
| `content.datasource.manage` | 上传数据和维护数据源 |
| `content.collection.manage` | 执行、暂停、重试采集与 AI 任务 |

# 第 18 章 用户管理中心与小程序工作台

「用户管理中心」面向官网、小程序及未来平台中的**个人用户**，承接个人身份、微信登录资料、已验证手机号和后台企业账号关联。

## 18.1 与现有账号体系的边界

| 体系 | 面向对象 |
|---|---|
| 用户管理中心 → 个人用户 | 平台**外部个人用户**（官网访客、小程序用户） |
| 组织数据 → 员工 / 用户账号 | RICSE **内部员工**及获得后台访问权限的外部企业员工 |
| 主数据 → 合作伙伴 | **企业、机构**等业务主体 |

**个人用户与后台账号不合并为一条数据**，通过受控的一对一关联建立移动端企业身份。手机号只用于检索和人工核对，**不根据相同手机号自动合并、关联或覆盖数据**。

## 18.2 个人用户管理

- 「用户管理 → 个人用户」提供真实小程序用户列表、详情、检索、状态筛选和关联状态筛选。
- 小程序用户完成微信登录后自动建立个人用户档案，保存 OpenID、UnionID、昵称、头像、来源、注册时间和最近登录时间。
- 用户可在小程序主动授权手机号；**系统只接受微信服务端换取的手机号**并记录验证时间。
- 列表中的 OpenID **默认脱敏**，运营人员可用完整 OpenID 搜索定位但页面不完整展示。

## 18.3 关联后台账号

运营管理员可选择现有的**有效企业后台账号**进行关联、重新关联和解除关联。

**关联规则**：

1. 后台账号仍在「组织数据」中创建，必须关联有效企业和员工档案。
2. **一个个人用户同一时间只能关联一个后台账号，一个后台账号也只能关联一个个人用户。**
3. 关联**不创建新账号、不占用额外企业账号名额、不授予新角色**。
4. 企业权限**实时继承**后台账号已有的角色、权限和数据范围。
5. 外部企业用户继续限定在本企业关联业务数据范围内。
6. 用户名、员工手机号、微信验证手机号三者独立保存。
7. 关联、重新关联和解除关联均保留操作人、时间、目标账号及备注等审计记录。

后台「组织数据 → 用户账号」显示小程序关联状态，可跳转个人用户管理。

## 18.4 小程序企业工作台

已关联且有效的用户可进入小程序「企业工作台」：

- 查看待审批数量、合同数量和执行中合同数量。
- 提供合同待审批、已审批列表及合同审批详情，**支持填写审批意见后同意或驳回**。
- 移动审批直接复用后台合同状态机、节点分配、或签/会签、管理员审批和并发校验，**不单独复制审批规则**。
- 根据关联后台账号的实时权限，开放合同、执行批次、执行通知、物流运单、磅单信息、质检任务和库存批次查询入口。**第二阶段这些业务查询统一保持只读。**
- 移动业务查询直接调用后台既有业务服务，继续执行功能权限、企业范围及来源单据数据范围校验。

**停用联动**：个人用户被禁用，或关联的后台账号、员工、企业被禁用时，不开放企业工作台。

## 18.5 小程序导航规则

- 未登录或已微信登录但**尚未关联**有效后台账号时，底部保持四项：`首页｜资讯｜行情｜我的`。
- 仅当服务端返回 `workspaceEnabled=true` 时，底部显示五项：`首页｜资讯｜工作台｜行情｜我的`。
- 「我的」页面始终保留「我的工作台」入口：未登录时提示微信登录；已登录未关联时提示联系企业管理员并可刷新；关联账号失效时显示停用提示；有效关联时直接进入工作台。
- AI 助手不占用底部导航，改为首页快捷入口；资讯和行情继续服务所有用户。
- 关联、解除关联、账号停用或重新登录后，小程序重新获取服务端账号上下文并即时刷新底部导航；**本地缓存仅用于首屏显示，不作为授权依据**。
- 通过历史路径直接打开企业工作台时仍执行服务端校验，未开通用户返回「我的」页面。

# 第 19 章 系统管理

「系统管理」菜单及其接口**仅对系统管理员开放**。

## 19.1 用户与权限

进入「系统管理 → 用户与权限」，包含三部分能力：

# 附录 C 常见问题速查

## C.1 登录与权限

| 现象 | 排查方向 |
|---|---|
| 登录成功但看不到某个菜单 | 账号角色没有该模块功能权限，或角色已停用/过期 |
| 能进入模块但找不到某张单据 | 该单据不在当前授权数据范围内，或其上游合同与当前企业无关联 |
| 外部员工能看到同事创建的单据 | 正常。外部数据范围**按企业共享**，不按创建人拆分 |
| 外部员工不能审批或修改 | 企业级数据范围只决定**可见数据**，操作仍需角色包含相应权限 |
| 无法开通员工账号 | 检查员工是否已关联其他账号、用户名是否重复或不符格式、两次密码是否一致 |

## C.2 合同与审批

| 现象 | 排查方向 |
|---|---|
| 提交审批后合同仍是草稿 | 审批流程未启用，或节点角色无有效成员。修复配置后可继续提交原草稿 |
| 提示"需要合同业务部门" | 编辑合同选择业务部门；创建人未关联部门时必须手动选择 |
| 审批按钮不可用 | 当前用户不在本轮节点成员快照中，或账号/角色授权已失效 |
| 采购合同没有总经理节点 | 合同金额未达配置门槛（默认 100 万元），或该节点已停用 |
| 合同无法删除 | 合同必须先作废；且只有系统管理员可以删除已作废合同 |
| 审批流程页面为空 | 确认线上已应用默认流程迁移及角色会签迁移 |

## C.3 执行与物流

| 现象 | 排查方向 |
|---|---|
| 新建执行批次时找不到合同 | 合同尚未审批通过，或已关闭/作废 |
| 执行批次数量无法提交 | 超过该方向的剩余可执行数量 |
| 执行批次不能直接完成 | 必须依次经过"确认"和"开始执行" |
| 执行通知不能取消 | 已有有效物流运单的通知不能取消 |
| 批量派车被拒绝 | 数量越界、承运关系错误、车辆司机缺失或时间倒置会直接阻止创建 |
| 运单不能更换车辆 | 「在途」以后保留运输快照，只有「待发运」阶段可修改 |

## C.4 现场作业

| 现象 | 排查方向 |
|---|---|
| 创建收货磅单时看不到某张运单 | 运单尚未到达（发货称重不受此限制） |
| 不能完成称重 | 检查是否已有有效毛重、有效皮重，以及所选结算口径是否有对应重量 |
| 磅单附件上传失败 | 检查是否为 JPG/JPEG/PNG/WEBP/PDF，文件是否为空或超过 20 MB |
| 不能更换结算入库磅单 | 相关入库/出库已过账，或出库已完成批次拣配 |
| 质检报告确认后仍不能入库 | 单份报告确认只表示报告有效；必须形成**任务级"合格"最终结论** |

## C.5 库存

| 现象 | 排查方向 |
|---|---|
| 没有自动生成入库作业单 | 检查是否为采购运单且已确认发运；确认到达会再次补生成 |
| 无法确认收货 | 必须先补齐仓库、实际收货时间和收货人 |
| 无法生成库存 | 必须先确认收货，验收依据必须已确认且合格，且一个入库单只能入账一次 |
| 看不到出库管理单 | 确认销售发货通知已下达；常规模式还必须选择发货仓库 |
| 看不到「拣配库存」 | 出库磅单必须已复核且运单仍待发运 |
| 库存缺口一直存在 | 先确认新库存已正式入账，再点击「刷新库存预留」 |
| 已出库数据填错了 | 不能删除或改数量，必须通过**库存冲销**处理 |
| 冲销审批通过了但库存没变 | 审批通过后必须再执行**「冲销过账」** |

## C.6 生产

| 现象 | 排查方向 |
|---|---|
| 原料批次预占列表为空 | 只展示与任务**库存主体、原料仓库和投入物料一致**的可用批次 |
| 任务不能取消 | 已领料或开始加工后不能直接取消，须处理耗用、退料和完工结果 |
| 完工单不能入库 | 只有质量确认为「合格」的完工申报可以生产入库 |
| 任务不能关闭 | 所有已领数量必须已经耗用或退回 |

| 主数据只读视图 | 外部企业专属主数据和组织数据只读视图**尚未完成**，字段级敏感信息脱敏也未完成 |
| 授权限制 | 在上述视图完成前，**不应**向外部账号授予主数据管理、组织管理或用户账号管理权限 |
| 账号数量 | 一个外部企业一期最多 6 个有效账号 |
| 角色限制 | 外部企业账号不能授予系统管理员角色 |
| 服务商门户 | 承运商、质检机构等作为**非签约参与方**的数据可见范围尚未设计，需另行建立参与方映射和敏感字段权限 |

## D.5 外部依赖配置

以下功能依赖第三方凭据，未配置时会明确失败，**但不影响合同、库存、审批和物流等核心业务**（内容采集运行在独立进程中）：

| 功能 | 依赖配置 | 未配置时的表现 |
|---|---|---|
| 百川行情采集 | `BAIINFO_USERNAME` / `BAIINFO_PASSWORD` / `BAIINFO_AUTH` / `BAIINFO_COOKIE` | `MARKET_SYNC` 任务持续失败，提示"百川行情直连凭据尚未配置" |
| 资讯 AI 清洗 | `DEEPSEEK_API_KEY` / `DEEPSEEK_BASE_URL` / `DEEPSEEK_MODEL` | `AI_CLEAN` 任务失败 |
| 小程序微信登录 | `WX_APPID` / `WX_SECRET` | 登录时提示"微信登录尚未配置" |
| 小程序会话令牌 | `WECHAT_TOKEN_SECRET` 或 `AUTH_TOKEN_SECRET` | 使用默认兜底密钥，**存在安全风险，生产环境必须配置** |

> **运维建议**：暂时不使用百川行情时，应在「内容运营 → 数据源管理」中将 `BAIINFO_FLUORITE` 数据源置为「停用」，避免任务持续重试并产生大量失败日志。

## D.6 生产管理一期边界

不包含：工序路线、设备/工位、班次报工、BOM 多版本审批、领料单打印、加工费应付单自动生成、原辅料及制造费用成本归集、生产退库冲销、质检任务模块自动关联。

## D.7 直拨业务边界

直拨发运当前仅生成 `DFM-` 占位单用于跟踪物流、磅单、质检和签收进度，**不生成我方入库、出库、库存批次或库存台账**。上下游通知绑定和独立结算口径留待后续完善。
