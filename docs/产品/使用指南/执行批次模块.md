# 合同执行批次管理 — 使用指南

> ✅ Iteration 5 第一版已完成（2026-07-17）

## 功能概述

合同执行批次是合同拆分后的具体业务执行单据，简称“执行批次”。系统从已审批合同分批建立采购执行批次或销售执行批次，控制合同明细的累计执行数量，并跟踪批次从草稿、确认、执行到完成的全过程。

## 前置条件

- 合同已经审批通过，状态为「已通过」或「执行中」
- 合同至少包含一个有效行项
- 当前用户已经登录系统

## 一、新建执行批次

1. 进入「采销管理 → 执行管理」，点击「新建执行批次」。
2. 选择状态为「已通过」或「执行中」的合同。
3. 填写执行批次名称。系统提供“合同标题 + 采购/销售执行批次”的建议名称，用户可以修改。
4. 系统自动生成唯一执行批次编号，并带出合同明细、单价、交货地点和剩余可执行数量。
5. 填写本批次数量、计划履约日期、交货地点和备注。
6. 确认执行批次金额后点击「创建执行批次」。

首次从「已通过」合同生成执行批次后，合同自动进入「执行中」状态。

## 二、合同与执行批次方向

| 合同类型 | 可生成执行批次 |
|------|------|
| 采购合同 | 采购执行批次 |
| 销售合同 | 销售执行批次 |
| 双边合同 | 分别生成采购执行批次或销售执行批次 |

双边合同的采购端和销售端分别统计剩余数量，互不占用。用户可根据实际采销履约节奏分批生成两端执行批次。

## 三、分批执行与数量控制

- 一个合同可以生成多个执行批次。
- 每条批次明细都必须来自所选合同。
- 本批次数量必须大于 0。
- 同一方向所有未取消执行批次的累计数量不能超过合同数量。
- 已取消执行批次不占用合同数量，可以重新建立批次。
- 新建页直接显示每条合同明细的合同数量和剩余可执行数量。

## 四、执行批次状态

```text
草稿 → 已确认 → 执行中 → 已完成
  └→ 已取消 ←┘
```

| 状态 | 可执行操作 |
|------|------|
| 草稿 DRAFT | 修改、确认、取消、删除 |
| 已确认 CONFIRMED | 开始执行、取消；可生成供应商发货指令或销售发货通知单 |
| 执行中 DISPATCHED | 跟踪下游执行单据、完成执行批次 |
| 已完成 COMPLETED | 查看 |
| 已取消 CANCELLED | 查看、删除；对应数量重新释放 |

系统在开始执行时记录执行开始时间，在完成执行批次时记录完成时间。不允许跳过中间状态。执行批次“执行中”不代表车辆已经发运，车辆运输状态以物流运单为准。

## 五、执行批次查询与详情

- 执行批次名称用于业务识别，执行批次编号用于唯一定位和追踪；二者同时保留。
- 列表支持按执行批次名称、执行批次编号、合同号、合同标题搜索。
- 支持采购/销售类型筛选和状态筛选。
- 详情页展示关联合同、我方主体、交易对手、批次明细、金额和履约时间。
- 草稿状态可以修改执行批次名称。
- 创建执行通知和物流运单时优先显示执行批次名称，同时显示编号和合同号供核对。
- 点击关联合同可返回合同详情。

## 六、常见问题

- 找不到合同：合同尚未审批通过，或已经关闭/作废。
- 数量无法提交：本批次数量超过该方向的剩余可执行数量。
- 双边合同为什么要选择执行批次类型：采购端与销售端执行节奏可能不同，系统按方向分别生成和统计。
- 执行批次不能删除：仅草稿和已取消执行批次允许删除。
- 执行批次不能直接完成：必须依次经过确认和开始执行。

## 七、权限与数据范围

- 浏览执行批次需要“执行查看”权限；创建、修改、状态流转和删除需要“执行管理”权限。
- 执行批次的数据范围继承关联合同，不单独按批次创建人确定。
- 外部企业员工可查看本企业参与合同下的全部执行批次，同企业员工范围一致。
- 合同选择、列表、详情和编辑接口使用同一范围，不能通过批次 ID 访问无权合同的数据。

通用口径见[权限与数据范围规范](../权限与数据范围规范.md)。
