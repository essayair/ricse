# 入库与库存模块使用指南

## 1. 功能概述

入库与库存模块承接采购物流发运后的业务闭环：采购运单确认发运、进入在途时，系统自动生成“待到货”入库作业单；同一张单持续跟踪运输到达、签收、过磅、质检、现场收货和库存入账。仓管补齐实际收货信息并确认收货后，再生成业务入库单、库存批次和库存台账。

## 2. 前置条件

- 物流运单方向为采购；确认发运后即可生成入库作业单。
- 运单到达后才能进入现场过磅和质检节点。
- 正式确认收货和库存入账前，必须存在一张“已复核”磅单以及质检任务最终采用的一张“已确认”检测报告。
- 主数据中已维护启用状态的入库仓库。
- 质检异常不再自动禁止入库；入库人员须核对异常实测值，填写人工接收原因并二次确认。最终报告未确认、磅单未复核或折干物料缺少有效水分值，仍不能确认收货。
- 当前版本没有“免检入库”路径。采购执行通知即使取消“到货后需要质检”，也只是不自动生成任务，不能免除最终报告校验；采购业务应保持该选项开启。

## 3. 标准操作流程

### 3.1 自动生成入库作业单

无需人工新建物流入库单：

1. 采购物流运单确认发运、状态进入“在途”时，系统自动生成“待到货”入库作业单。
2. 运单确认到达时，系统再次检查并补生成漏单。
3. 同一运单不存在其他未作废入库作业单。
4. 后续磅单与质检单均关联并更新这张既有作业单，不重复创建。

系统初始带出运单、合同、执行批次、计划数量、物料、供应商、车牌及目标仓库；磅单、最终验收质检单、质量扣减和最终入库数量在后续作业中逐步补齐。

同一到货质检任务可以存在一份或多份机构检测报告，但入库单的“质量验收依据”只同步任务形成最终质检结论时选定的执行口径报告，不重复展示其他机构报告。该报告无论结论为合格、超标扣款还是不合格，都同步报告编号、检测机构、实测指标、扣减信息和处理方案；同步质检依据不等待磅单复核，实际收货与入账仍按磅单和到货规则校验。质检报告结论与入库人工接收决定分开记录。扣款待确认、不合格或待人工判定都作为异常提示，不替入库人员做接收决定；若决定接收，必须记录原因和确认人。

入库实物数量取当前选定并复核的入库磅单净重；最终报告形成后，详情立即按物料计价口径预览入库计价数量，确认收货时冻结该数量。若物料设置为“按实测水分折干”，按最终报告实测水分计算；质检超标扣价另计金额，不当作库存扣重。折干物料缺少有效水分值时不能确认收货。

### 3.2 上传收货附件

物流入库单处于“待入库”时，可在详情页上传现场照片、签收凭证或 PDF：

- 支持 JPG、PNG、WEBP、PDF。
- 单个文件不超过 20MB。
- 待入库状态支持查看、增加和删除；确认收货后附件锁定，只允许查看。

### 3.3 确认收货与入账

打开待入库单时，Web 和小程序会默认带入已有资料，减少重复录入：

- 入库仓库：优先保留本单已保存的仓库，未填写时只取物流目的地关联的启用仓库；不误取起运仓库，也不默认选择仓库列表第一项。目的地不是系统仓库时需人工选择。
- 实际收货时间：优先保留本单已保存时间，其次取物流运单的签收时间；尚未签收时以实际到达时间作为可修改的参考，不使用计划时间或当前打开页面的时间。
- 收货人：显示当前操作人；确认收货时由服务端记录该账号姓名，不取通知联系人或仓库负责人，也不能在表单中冒填他人。
- 默认带入仅是待确认表单内容，仍可人工修改；点击保存或确认收货后才写入本单，不自动确认收货或增加库存。附件上传、删除引起的刷新不会覆盖尚未保存的人工修改；已收货、已入账的历史单据不重新套用上游资料。

1. 核对物流、磅单、质检指标和附件，补齐仓库、实际收货时间后点击“确认收货”。质检异常时应核对红色实测值并填写人工接收原因；Web 与小程序均二次确认。缺项或前序作业未完成时会提示具体原因。
2. 已收货状态点击“生成业务入库并入账”。
3. 系统自动生成业务入库单、库存批次和一条入库台账，并增加可用库存。

服务端在确认收货和正式入账时重复校验最终报告、入库磅单和计价数量。异常结论本身不拦截，但确认收货须留存人工接收原因、确认人和时间；历史已确认收货的异常单据保留既有事实。

该质量门禁只适用于采购入库形成库存。销售出库质检目前为选配节点，不作为销售车辆放行和库存扣减的强制条件。

## 4. 状态流转

```text
待到货 → 已到达待过磅 → 过磅处理中/待复核 → 已过磅待质检
→ 质检处理中 → 合格待收货／质检异常待人工确认 → 已收货待入账 → 已入账
                                       └──作废────────→ 已作废
```

- 作业中：由采购运单确认发运自动生成，通过细分阶段展示待到货、过磅、质检和待收货；异常仅提示并要求人工确认。
- 已收货：现场收货已确认，可生成业务入库并入账。
- 已入账：业务入库单、库存批次、库存台账已经形成。
- 已作废：不再参与后续业务；运单仍处于有效执行状态时，可由系统补生成新的入库作业单并重新完成验收。

## 5. 库存查询

进入“库存管理”可查看：

- 用户权限范围内的实物库存、结算数量、业务预占、可用实物、库存主体数、批次数、物料数和仓库数。总量仅作统计；不同计量单位、不同商品或不同计价口径的结算数量不直接合并，需查看商品明细。
- 可按业务单元（事业部）、仓库或库存主体切换统计维度；点击统计行后，下方商品明细与库存批次随之缩小范围。
- “商品库存明细”按商品、业务单元、库存主体、仓库及计价口径逐行展示商品名称、实物数量、结算数量、业务预占、可用实物及批次数。同一仓库中不同主体或不同商品分别列示，不合并货权。
- 库存批次列表突出商品名称与批次号，将业务单元和库存主体合并为业务归属，并列展示实物余额、结算数量、业务预占与可用实物；初始实物、销售/生产预占、供应商和来源单据作为补充信息显示。
- 库存台账中的业务类型、业务单号、实物数量与结算数量的变动及余额。不同计量单位不能合计，历史沿用的结算数量标记为待核对。

库存主体取采购合同的“我方签约主体”。同一个主体可以在多个仓库持有库存，同一个仓库也可以存放多个主体的库存；销售出库只能冻结和选择与销售合同我方签约主体一致的库存批次。

## 6. 常见问题

- 没有自动生成入库作业单：检查是否为采购运单且是否已经确认发运；确认到达操作还会再次补生成。
- 无法确认收货：只有待入库状态可以确认；须有启用仓库、实际收货时间、已复核磅单和最终报告，异常时还须填写人工接收原因。
- 无法上传附件：只有待入库状态允许增删附件。
- 无法生成库存：必须先确认收货、验收依据必须是任务最终采用的已确认报告，并且一个物流入库单只能入账一次。

## 7. 权限与数据范围

- 查看入库单、库存批次、库存台账和附件需要“库存查看”权限；创建、确认、作废、入账及附件增删需要“库存管理”权限。
- 物流入库单从采购运单继承合同企业范围，业务入库、库存批次和库存台账继续继承该来源。
- 外部企业员工可查看本企业参与采购合同形成的入库与库存数据，不限收货人或单据创建人。
- 库存总览和库存台账均在服务端过滤企业范围，汇总数字只统计用户可见批次。

通用口径见[权限与数据范围规范](../权限与数据范围规范.md)。
