# 物流运单与调度 — 使用指南

> ✅ Iteration 6 调度执行闭环完成（2026-07-18）

## 功能概述

物流运单是车辆/车次级运输单据，必须关联已下达或执行中的供应商发货指令或销售发货通知单。一个执行通知可以拆分多张物流运单。

## 创建与调度

1. 进入「物流管理 → 运单管理」，按实际场景选择「单车建单」或「批量派车」；也可直接从执行通知详情进入并自动带出通知。
2. 如已收到微信、短信或调度文字，可粘贴到“文字信息自动识别”窗口并点击“识别并填入”。系统可识别通知号/批次号/合同号、车牌、司机、电话、承运单位、运输数量、起讫地和计划时间；识别只回填表单，不自动创建。
3. 选择已下达或执行中的执行通知。
4. 填写本车运输数量，累计数量不得超过通知数量。
5. 可在创建时选择车辆，也可以先创建“待调度”运单，再到运单详情或调度看板补齐车辆与司机；资料齐备后自动显示为“待发运”。
6. 自有运力从启用的自有车辆中选择；第三方承运先选择物流承运商，再从该承运商名下启用的外协车辆中选择。
7. 选择车辆后系统优先带入该车关联的主驾；司机选择器将车辆关联司机排在前面，并允许继续按姓名、手机号或物流服务商模糊筛选同承运商其他司机。未建档的临时司机仍可手工填写。
8. 填写计划发运时间和预计到达时间，用于调度计划和超时判断。
9. 确认发运前必须具有车牌和司机信息；第三方承运还必须填写承运单位。

物流运单编号格式为 `WB-年月日-流水号`。

### 批量派车

- 一条车辆明细生成一张独立物流运单；同一车辆执行多趟时，每个趟次分别保留一行并生成不同运单。
- 公共区域统一填写起运地、目的地、默认运输方式、承运商、计划时间和备注，并可一键应用到全部车辆；每行仍可调整承运商、车辆、司机、时间及物料数量。
- 支持选择已维护车辆/司机，也支持填写临时车辆；临时车辆必须填写车牌、司机姓名和联系电话，不会自动反向创建车辆主数据。
- 支持粘贴“每车一行”的调度文字，按车牌、司机、手机号、数量和承运商生成车辆行。多物料通知只识别车辆信息，数量需逐项核对。
- 页面按物料实时汇总通知数量、已建运单数量、本次分配数量和创建后剩余数量。允许分批派车，但本次总量不得超过通知剩余可运输数量。
- 提交前提示车辆登记载重不足、同车同时间重复等风险；这些属于调度核对提示，数量越界、承运关系错误、车辆司机缺失和时间倒置会直接阻止创建。
- 一次批量提交最多创建 100 张运单。服务端整批复核数量和主数据关系，所有运单要么全部创建成功、要么全部不创建；重复点击或网络重试不会重复建单。
- 创建完成页展示本次全部运单，可逐张进入详情。每张运单继续独立进入过磅、质检、采购入库或销售出库和签收流程。

## 运输状态

```text
采购：待调度 → 待发运 → 在途 → 已到达待收货 → 已收货
销售：待调度 → 待发运 → 在途 → 已送达待客户签收 → 客户已签收
    └──────→ 已取消
```

- 数据库中的 `PENDING` 是发运前的技术状态，界面必须进一步区分：缺少车牌或司机为“待调度”，车牌和司机资料完整为“待发运”。两类数量互斥，合计等于发运前运单总数。
- “待调度”表示尚未完成车辆与司机安排；“待发运”表示调度已完成、等待车辆实际发车，二者不是同一阶段，也不重复计数。
- “待发运”阶段可以修改车辆调度信息。
- “在途”以后保留运输快照，不允许更换车辆。
- 运单进入“在途”时，对应执行通知进入“执行中”。
- 调度工作台的混合视图按待调度、待发运、在途、已到目的地、已完成交接五列展示；单张运单内按采购/销售显示具体文案。
- 在途运单的下一步：采购为“确认到达”，销售为“确认送达”；后续分别为“确认收货”和“确认客户签收”。

## 调度工作台

- 汇总有效运单、待调度、在途车辆、已完成交接和调度异常数量。
- 支持按运单、通知、批次、合同、车牌或司机搜索，并可按采购/销售运输筛选。
- 运单卡片展示物料数量、运输方式、线路、计划时间以及完整上游单据链。
- 可在卡片上直接确认发运、到达/送达和收货/客户签收；待调度运单进入详情补充车辆信息。
- 超过计划发运时间仍未发运、超过预计到达时间仍在途，或车辆司机资料缺失时，显示异常提示并支持“只看异常”。

## 运单详情

- 详情顶部展示运单创建、发运、到达和签收进度。
- 展示计划发运、预计到达、实际发运、实际到达和签收时间。
- 待发运阶段支持选择车辆、手工填写车牌司机，以及配置自营或第三方承运信息。
- 车辆选择器直接引用车辆主数据并带入车牌、默认司机和手机号；运单创建页和调度区提供“维护车辆”入口。运输方式与车辆归属必须一致，外协车辆必须属于当前所选物流承运商。
- 司机选择器引用独立司机档案并支持姓名、手机号、服务商和准驾车型模糊过滤。第三方运输只能选择当前承运商的司机；自有运力只能选择内部物流服务商维护的司机。
- 车辆与司机不是固定一对一关系：车辆档案可以关联一名主驾和多名副驾，运单上的 `driverId` 表示本车次实际司机。
- 状态变化后运输信息作为执行快照展示，便于后续磅单和物流对账追溯。
- 运单到达或签收后，详情出现“关联磅单”板块；尚无有效磅单时可从此直接创建，已有磅单时可查看称重和结算重量。
- 采购运单到达后显示“物流收货凭证”，包含收货签收单、收货现场照片和其他收货凭证；销售运单送达后显示“物流交付凭证”，包含客户签收单、送达现场照片和其他交付凭证。
- 三类凭证合计至少存在一份才能完成收货或客户签收确认，不要求每一类都上传。完成交接后凭证保留为履约记录，不允许删除。
- 小程序使用同一方向化文案和附件分类；混合任务列表使用“待交接确认/已完成交接”中性口径。

## 质检触发

- 执行通知创建时配置“到货/交付后需要质检”。采购默认勾选，销售默认不勾选，允许根据合同约定调整。
- 只有勾选的执行通知，所属运单到达或送达后才自动生成质检任务。

## 权限与数据范围

- 查看运单、调度看板和附件需要“物流查看”权限；创建、调度、状态流转及附件增删需要“物流管理”权限。
- 物流运单通过执行通知、执行批次继承合同企业范围，不按承运人或创建人单独放大范围。
- 外部企业员工可查看本企业参与合同下的运单；承运商未来作为非签约参与方开放时，必须另行设计参与方映射和敏感字段权限。
- 收货附件与运单使用相同范围，附件查看地址只能在通过运单范围校验后获取。

通用口径见[权限与数据范围规范](../权限与数据范围规范.md)。
