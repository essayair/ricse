# 物流运单与调度 — 使用指南

> ✅ Iteration 6 调度执行闭环完成（2026-07-18）

## 功能概述

物流运单是车辆/车次级运输单据，必须关联已下达或执行中的供应商发货指令或销售发货通知单。一个执行通知可以拆分多张物流运单。

## 创建与调度

1. 进入「物流管理 → 运单管理 → 新建物流运单」；也可从执行通知详情进入并自动带出通知。默认一行，需要多辆车或同车多趟时追加、复制明细，不再区分单车和批量入口。
2. 如已收到微信、短信或调度文字，可粘贴到“多行调度信息识别”窗口。支持一辆车的多行字段或每车一行的名单，识别车牌、司机、电话、承运单位、运输数量、起讫地和计划时间；识别只回填表单，不自动创建。
3. 选择已下达或执行中的执行通知。
4. 填写本车运输数量，累计数量不得超过通知数量。
5. 车辆、司机确定后才能建单，必须填写车牌、司机姓名和联系电话，创建后统一为“待发运”。尚未找车的需求保留在执行通知，不提前创建空运单。
6. 自有运力从启用的自有车辆中选择；第三方承运先选择本行物流承运商，再选择直接关联或通过有效车队关联的车辆、司机。承运商只需选择一次，选车、选司机不会覆盖它；内部企业的物流承运商也可以作为第三方承运方。
7. 移动端按“运输方式 → 第三方承运商（如适用）→ 车辆 → 司机”顺序填写。自有运力不重复要求选择内部组织，社会运力不限制车辆、司机归属；切换运输方式或承运商时清空原车辆、司机选择。
8. 司机通过“搜索并选择司机”按姓名、手机号、承运商或车队查找，明确选中后带出姓名及电话。搜索关键字不会写入姓名；选择“手工填写临时司机”才展开姓名、电话输入框。车辆关联的有效主驾可自动带出，不覆盖已由操作人确定的司机。待发运详情中具备主数据维护权限的用户可主动保存临时档案，未勾选时仅供本次运单使用。
9. 填写计划发运时间和预计到达时间，用于调度计划和超时判断。
10. 确认发运前必须具有车牌、司机姓名和联系电话；第三方承运还必须选择物流承运商。

移动端与 Web 端使用同一口径：进入小程序「工作台 → 执行通知 → 详情 → 新建物流运单」，可手工填一辆车，也可把每辆车一行的名单粘贴后生成多行；待发运运单详情仍可用文字识别修改运输信息。识别后核对主数据匹配、选定的物料、可选的计划参考数量和时间，再保存或创建；实际装车数量以磅单为准。

物流运单编号格式为 `WB-年月日-流水号`。

### 多车建单

- 一条车辆明细生成一张独立物流运单；同一车辆执行多趟时，每个趟次分别保留一行并生成不同运单。
- 公共区域填写起运地、目的地和统一备注；“批量设置（可选）”默认收起，仅在需要一次修改多行时展开。点击“应用到全部车辆”后才修改实际行数据；变更运输方式或承运商并需要清空现有车辆、司机时先二次确认，空日期不覆盖已有时间。每行仍可独立调整，新增行沿用上一行运输安排，不继承尚未应用的设置草稿。
- 支持选择已维护车辆/司机，也支持填写临时车辆和司机；临时资料必须填写车牌、司机姓名和联系电话，默认不会反向创建主数据。具备主数据维护权限并主动勾选“同时保存”后，才会写入所选运输组织的车辆或司机档案。
- 支持粘贴“每车一行”的调度文字，按车牌、司机、手机号、可选的计划数量和承运商生成车辆行。多物料通知只识别车辆信息；未填数量时需选定本车物料。
- 小程序与 Web 端均支持多行识别和批量创建；移动端入口位于执行通知详情，适合现场直接复制微信群或短信中的派车名单。识别到的档案车辆、司机和承运商优先匹配已有主数据，未匹配内容保留为临时信息并要求人工补全。
- 页面按物料展示通知剩余参考数量和本次填写的计划参考数量。逐车数量可留空；超出剩余参考数量时提示核对，但不阻止建单。实际装车、出入库和结算数量按后续业务磅单处理。
- 提交前提示车辆登记载重不足、同车同时间重复、计划参考数量超出通知剩余参考数量等风险；承运关系错误、车辆司机缺失和时间倒置仍会阻止创建。
- 一次批量提交最多创建 100 张运单。服务端整批复核主数据关系，所有运单要么全部创建成功、要么全部不创建；重复点击或网络重试不会重复建单。
- 创建完成页展示本次全部运单，可逐张进入详情。每张运单继续独立进入过磅、质检、采购入库或销售出库和签收流程。

## 运输状态

```text
采购：待发运 → 在途 → 已到达待收货 → 已收货
销售：待发运 → 在途 → 已送达待客户签收 → 客户已签收
    └──────→ 已取消
```

- 数据库中的 `PENDING` 统一表示“待发运”，不再按资料是否齐全拆分状态或待办。
- 历史缺少车辆或司机信息的运单仍显示在待发运中，并提示补齐运输信息；不删除、不自动取消，也不能绕过发运校验。
- “待发运”阶段可以修改车辆调度信息。
- “在途”以后保留运输快照，不允许更换车辆。
- 运单进入“在途”时，对应执行通知进入“执行中”。
- 调度工作台的混合视图按待发运、在途、已到目的地、已完成交接四列展示；单张运单内按采购/销售显示具体文案。
- 在途运单的下一步：采购为“确认到达”，销售为“确认送达”；后续分别为“确认收货”和“确认客户签收”。

## 调度工作台

- 汇总有效运单、待发运、在途车辆、已完成交接和调度异常数量。
- 支持按运单、通知、批次、合同、车牌或司机搜索，并可按采购/销售运输筛选。
- 运单卡片展示物料数量、运输方式、线路、计划时间以及完整上游单据链。
- 可在卡片上直接确认发运、到达/送达和收货/客户签收；历史缺资料运单提供“补齐运输信息”入口。
- 超过计划发运时间仍未发运、超过预计到达时间仍在途，或车辆司机资料缺失时，显示异常提示并支持“只看异常”。

## 运单详情

- 详情顶部展示运单创建、发运、到达和签收进度。
- 展示计划发运、预计到达、实际发运、实际到达和签收时间。
- 待发运阶段支持选择车辆、手工填写车牌司机，以及配置自营或第三方承运信息。
- 车辆选择器直接引用车辆主数据并带入车牌、默认司机和手机号；运单创建页和调度区提供“维护车辆”入口。运输方式与车辆归属必须一致，外协车辆必须属于当前所选物流承运商。
- 司机选择器引用独立司机档案并支持姓名、手机号、服务商和准驾车型模糊过滤。第三方运输只能选择当前承运商的司机；自有运力只能选择内部物流服务商维护的司机。
- 车辆与司机不是固定一对一关系：车辆档案可以关联一名主驾和多名副驾，运单上的 `driverId` 表示本车次实际司机。
- 状态变化后运输信息作为执行快照展示，便于后续磅单和物流对账追溯。
- 运单到达或签收后，详情出现“关联磅单”板块；尚无有效磅单时可从此直接创建，已有磅单时可查看称重和结算重量。
- 采购运单到达后显示“物流收货凭证”，包含收货签收单、收货现场照片和其他收货凭证；销售运单送达后显示“物流交付凭证”，包含客户签收单、送达现场照片和其他交付凭证。
- 三类凭证合计至少存在一份才能完成收货或客户签收确认，不要求每一类都上传。完成交接后凭证保留为履约记录，不允许删除。
- 小程序使用同一方向化文案和附件分类；混合任务列表使用“待交接确认/已完成交接”中性口径。
- 小程序从相册选择图片时按压缩图片上传，服务端以文件内容签名识别 JPG、PNG、WEBP 或 PDF，不依赖微信临时文件名和客户端 MIME；兼容 iPhone 截图常见的无扩展名 PNG。附件名称与查看/删除操作分行展示，长文件名不会把按钮挤出窄屏安全范围。

## 质检触发

- 执行通知创建时配置“到货/交付后需要质检”。采购默认勾选，销售默认不勾选。
- 只有勾选的执行通知，所属运单到达或送达后才自动生成质检任务。
- 采购货物形成库存前必须取得任务级最终“合格”结论；取消采购通知的质检选项只会停止自动建任务，不构成免检，当前版本也不能完成确认收货和库存入账，因此采购业务应保持勾选。
- 销售交付质检按合同或业务需要选配，不作为销售出库放行、库存扣减及客户签收的强制前置条件。

## 权限与数据范围

- 查看运单、调度看板和附件需要“物流查看”权限；创建、调度、状态流转及附件增删需要“物流管理”权限。
- 物流运单通过执行通知、执行批次继承合同企业范围，不按承运人或创建人单独放大范围。
- 外部企业员工可查看本企业参与合同下的运单；承运商未来作为非签约参与方开放时，必须另行设计参与方映射和敏感字段权限。
- 收货附件与运单使用相同范围，附件查看地址只能在通过运单范围校验后获取。

通用口径见[权限与数据范围规范](../权限与数据范围规范.md)。
