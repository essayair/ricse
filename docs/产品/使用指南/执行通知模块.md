# 执行通知管理 — 使用指南

> ✅ Iteration 6 第一版完成（2026-07-17）

## 功能概述

执行通知承接已确认的合同执行批次：采购方向生成“供应商发货指令”，销售方向生成“销售发货通知单”，并向下拆分物流运单。

## 创建规则

- 一个执行批次可以拆分多张执行通知，累计通知数量不得超过批次数量。
- 采购执行批次只能生成供应商发货指令，编号格式为 `PI-年月日-流水号`。
- 销售执行批次只能生成销售发货通知单，编号格式为 `SD-年月日-流水号`。
- 采购、销售的起运地点和目的地点都不强制选择仓库，可从仓库或合作伙伴地址快速带入，也可直接填写。选择采购目的仓或销售起运仓时，系统同时记录为库存操作仓库；未选择时，在实际入库或库存出库前补充确认。
- 起运地点和目的地点均为必填，可选择有效仓库、我方签约主体或当前供应商/客户的启用收发货地址快速填入，也可以由运营人员直接填写新地址。选择只是快捷来源，带入后仍可按实际装卸位置修改。
- 采购通知的起运地可选供应商地址，目的地可选我方主体地址或仓库；销售通知的起运地可选我方主体地址或仓库，目的地可选客户地址。选择采购目的仓或销售起运仓时，该仓库同时作为库存操作仓库保存。
- 从地址主数据选择后，系统按“省 + 市 + 区/县 + 详细地址”自动拼接成一条完整地址，并同步带出联系人、联系方式。单据只保存选中时的完整地址快照，不依赖后续主数据变化。
- 地址、联系人和联系方式按单据快照保存，主数据后续变更不追溯修改历史通知。具有主数据管理权限的运营人员可以在创建通知时新增合作伙伴地址并选用；没有该权限也不影响手工填写本次地址。
- 执行通知一期不设置审批，由有权限的业务人员直接下达。
- 已取消通知释放占用数量；已有有效物流运单的通知不能取消。

## 操作流程

1. 进入「采销管理 → 执行通知」，点击「新建执行通知」。
2. 选择已确认或执行中的合同执行批次。
3. 填写本次通知数量、执行模式、计划日期、起运地点和目的地点；可选择仓库、我方主体地址、当前合作伙伴收发货地址或直接填写。
4. 采购常规模式在目的地选择入库仓库；销售常规模式在起运地选择出库仓库。
5. 创建后检查通知明细，点击「下达通知」。
6. 已下达通知可以创建一张或多张物流运单。

## 状态

```text
草稿 → 已下达 → 执行中 → 已完成
  └→ 已取消 ←┘
```

第一张物流运单进入“在途”时，通知自动进入“执行中”。所有有效物流运单签收后，通知才能完成。

## 权限与数据范围

- 查看执行通知需要“执行查看”权限；创建、下达、完成、取消和删除需要“执行管理”权限。
- 执行通知通过执行批次继承合同企业范围，候选批次和通知详情执行相同校验。
- 外部企业员工可查看本企业参与合同下由其他员工创建的通知，不可查看无关企业通知。
- 草稿或已下达且尚未派车的通知允许在运营后台和小程序修改地址；已有物流运单后，应在具体运单上维护实际运输地址，避免上下游历史不一致。

通用口径见[权限与数据范围规范](../权限与数据范围规范.md)。
