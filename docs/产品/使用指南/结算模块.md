# 资金结算 — 使用指南

资金结算用于把已生效合同的业务金额转化为应收、应付，并记录实际收付款、预收预付与核销关系。

```text
销售合同 → 应收确认 → 出纳登记收款 → 业务认领 → 财务确认 → 核销 → 已结清
采购合同/执行批次 → 付款申请草稿 → 业务确认 → 财务提交审批 → 出纳创建付款单 → 财务确认 → 核销 → 已结清
```

## 菜单与口径

- **应收管理（二级）**：下设“应收款计划”和“收款单”。应收款计划回答“客户应该付多少钱”；收款单记录实际到账、业务认领和核销。
- **应付管理（二级）**：下设“付款申请单”和“付款单”。付款申请单承载业务准备、财务提交和审批；付款单记录实际付出的资金。
- **结算台账**：按合同、法律主体、业务单元和交易对手汇总合同金额、结算金额、收付款、核销、未结、预收预付及逾期情况。
- **结算单**回答“应该收付多少钱”；**资金流水**回答“实际收付了多少钱”；**核销**建立两者的对应关系。
- 运费仍在「物流管理 → 运费结算单」独立归集，不与采购货款混为同一张业务结算单。

## 前置条件

1. 合同已审批生效，状态为已审批、执行中、已完成或已关闭。
2. 合同已经维护我方签约主体、交易对手方和业务单元（事业部）。
3. 经办人具有 `settlement.view`；结算创建/确认、收款登记/认领、付款申请/审批/执行、资金确认和核销分别使用专项权限。
4. 正式结算前，业务人员仍需核对磅单、质检结论、入出库凭证和合同结算口径。

## 创建并确认结算单

1. 进入「资金结算 → 应收管理」或「应付管理」。
2. 点击“新建应收结算”或“新建应付结算”。
3. 选择合同。系统自动带出我方签约主体、交易对手方、业务单元、合同金额、累计结算、剩余可结算和预收预付参考余额。
4. 选择结算口径：
   - **执行批次结算**：可选择一个或多个草稿、已确认、执行中或已完成的有效执行批次，逐行确认数量、单价和结算加减项金额；已取消批次不可选择；
   - **合同阶段结算**：填写阶段名称，并按阶段比例或金额结算；
   - **合同最终结算**：系统按“合同金额－累计有效结算”自动计算；
   - **调整结算**：用于业务确认后的补充调整，必须填写原因。
5. 保存后状态为“草稿”；复核无误后在详情中点击“确认形成应收/应付”。
6. 确认后不能直接修改金额，只能继续收付款核销，或在尚未核销时作废。
7. 已确认、部分结清或已结清的结算单，可在详情点击“打印存档”，进入独立的 A4 结算单页面；核对后打印，由供应方、采购方按实际管理要求签字盖章并归档。

系统会校验合同和执行批次的累计已结金额、数量，阻止重复或超额结算。同一合同可按多个执行批次分次结算，也可进行合同阶段及最终结算。

### 打印与归档

- 打印单据标题为“业务确认及结算单”，展示供应方、采购方、合同及结算编号、业务单元、结算明细、加减项、金额大写、资金核销情况、系统确认信息和双方签章区。
- 采购应付结算中，交易对手方为供应方、我方签约主体为采购方；销售应收结算中，我方签约主体为供应方、交易对手方为采购方。
- 草稿尚未形成正式应收应付，已作废单据不再有效，二者均不能打印存档。
- 打印动作会写入结算单操作记录，管理员可查看打印操作人和时间；系统留痕不能代替双方按合同及公司制度完成的签字、盖章和档案保管。
- 单位联系地址、联系人和默认有效银行账户取自主数据。正式打印前应先补全并核对合作伙伴及内部主体资料。

### 结算加减项与到期日

- 结算金额按“结算原金额＋结算加减项”计算；正数增加结算金额，负数扣减结算金额。
- 加减项适用于质量扣款、升贴水、价格补差、溢短装金额调整和商务折扣等场景。金额不为 0 时必须填写调整原因。
- 执行批次结算在各批次明细中填写加减项；合同阶段、合同最终和调整结算在单头填写。
- 执行批次是否完成不作为结算申请的硬性前提。预付款、发货款、到货款和尾款可按合同约定在不同履约阶段发起；页面同时展示批次状态、批次数量、剩余可结算数量与金额，申请人应依据合同及当前业务凭证填写。
- 系统继续校验批次必须属于当前合同和采购/销售方向、批次未取消、数量与金额不超过剩余可结算值；是否实际付款由付款申请审批流程判断。
- 结算详情实时展示关联执行批次的当前状态，并可进入批次详情；付款申请审批人可从申请详情进入关联结算单，核对批次状态及结算明细后决定是否批准。
- 应付结算填写“约定付款到期日”，应收结算填写“约定收款到期日”。到期日当天仍属于履约期限，次日仍未核销才计入逾期未结。
- 到期日不同于实际收付款日期，也不同于银行承兑、信用证等票据的到期日期。

## 收款登记、认领和确认

1. 出纳进入「资金结算 → 收款管理」，点击“登记收款”。
2. 先选择实际到账的我方收款主体和银行账户；当时不能确定业务归属时，不必选择合同，但必须按银行流水填写实际付款方。
3. 选择支付方式：银行转账、银行承兑、商业承兑、信用证、融资支付、现金或其他。
4. 填写金额、发生日期、双方银行账户、银行流水号；票据类付款补充票据编号和到期日。
5. 上传银行回单；第三方代付必须填写实际付款方和代付原因。
6. 对应业务人员在详情中新增认领明细，选择销售合同，可进一步选择执行批次、款项类型和本次认领金额。一笔到账允许拆分认领到多个合同或批次。
7. 全部到账金额认领完成后，状态进入“待财务确认”；财务人员复核双方、金额、账户、认领明细和回单后点击“财务确认”。
8. 确认后才形成可核销余额；每个合同只能使用认领到该合同且已确认的金额，预收款可以早于结算单登记。

收款登记允许暂不关联合同，但必须固化我方法律主体、到账账户、实际付款方、金额和银行流水。合同、客户、业务单元及执行批次在认领时确定；我方收款主体必须与被认领合同的我方签约主体一致，避免资金串户。

## 应付管理和付款执行

1. 业务人员进入「资金结算 → 应付管理」，新建付款申请，选择“采购付款”或“销售客户退款/保证金退回”。采购付款可关联已确认应付结算单，预付款允许暂不选择结算单；客户退款必须选择原收款单。
2. 可直接选择合同，也可先按我方主体、交易对手或关键词筛选合同；系统展示合同剩余可计划金额。需要细分到具体履约时，再选择执行批次，批次选项同时展示状态。
3. 填写款项类型、申请金额、计划付款日、支付方式和付款用途；从主数据银行账户中选择我方付款账户和对方收款账户。账户户名、开户行、账号作为业务快照随单保存，详情页每行均可点击复制，便于录入企业网银。
4. 保存后是业务草稿，可修改、删除和补充附件。业务人员复核无误后点击“确认资料并交财务”；此动作不进入审批。
5. 财务人员复核付款资料，可退回业务修改，也可点击“提交审批”。只有财务提交后，系统才按照「系统管理 → 审批流程 → 付款申请」的启用节点生成审批任务。默认路径为“风控/财务经理 → 业务责任人 → 总经理”，其中业务责任人按付款申请所属业务单元匹配；管理员可调整节点角色、会签/或签、人员范围和启停状态。
6. 当前节点审批人批准后才进入下一级；任一节点驳回后申请退回，修改或补充依据后须重新完成业务确认和财务提交，并保留每轮审批记录。
7. 全部节点通过后，出纳可从付款申请详情点击“创建付款单”，也可在付款单列表点击“新建付款单”后选择已审批且尚未付清的付款申请。两种入口都进入同一个独立创建页面，不允许脱离付款申请登记付款。
8. 页面自动带出申请基本信息、计划付款账户和计划收款账户。上传图片或 PDF，或直接粘贴银行回单截图后，系统识别电子回单号、付款/收款户名、账号、开户行、金额、币种、付款时间和用途；识别结果必须人工核对，OCR 不代替出纳确认。
9. 实际账户与申请账户不同时，页面同时校验该账号是否属于同一企业的其他有效账户。正常换用同主体其他账户允许继续，但必须填写账户差异说明；账号已登记在其他企业名下时禁止提交。申请账户快照保持不变，付款单保存真实发生账户。
10. 一张付款申请允许分次创建多张付款单，系统展示申请金额、累计已付和剩余待付，并阻止超额付款、重复电子回单号以及付款账号、收款账号、金额和时间完全相同的疑似重复登记。
11. 付款凭证随付款单创建并归档，付款单进入“待财务确认”；会计确认实际付款事实后，普通采购付款才可用于应付核销，客户退款则同步占用原收款单的可退余额。
12. 实际收款方与合同交易对手不一致时，必须在申请阶段标记第三方收款并填写原因；创建付款单时不得绕过审批修改收款方。

付款申请由采销业务员或运营经理发起。审批通过或已创建付款单的申请可进入独立详情页执行“打印存档”；打印版按 A4 排版，包含合同与付款双方、申请金额及用途、银行账户、审批轨迹、附件目录和签字栏，每次发起打印均写入操作记录。草稿、审批中、已驳回和已作废申请不得作为正式归档件打印。

结算单、付款申请、收款单和付款单均从列表进入独立详情页，不再以窄弹窗承载完整信息。付款单创建因包含申请选择、凭证预览、OCR 识别、账户校验和人工核对，也使用独立页面；仅简单编辑、核销等短操作继续使用弹窗。

资金结算中的日期字段统一通过日期面板选择，点击字段或日历图标打开，选择后点击面板内“确认”写入；打开业务弹窗时不会自动弹出日期面板。付款依据、银行回单等附件上传或删除后，当前详情页保持打开，可继续上传、查看和执行下一步，直至用户主动关闭。

## 查看结算台账

1. 进入「资金结算 → 结算台账」。
2. 可按应收/应付、结算状态、合同编号、合同标题、法律主体、业务单元和交易对手筛选。
3. 台账展示合同金额、草稿金额、正式结算金额、结算加减项、实际收付款、已核销、未核销资金、预收预付、未结和逾期金额。
4. 台账只用于查询和追踪，不直接修改汇总数；发现差异时应回到应收/应付、收款/付款或核销记录修正源单据。

## 核销

1. 打开一张已确认或部分结清的结算单。
2. 点击“核销收款/付款”。
3. 系统只列出同一合同、同一法律主体、同一交易对手且仍有余额的资金流水。
4. 输入本次核销金额并确认。
5. 系统同步更新结算单已核销金额和资金流水已分配金额；支持部分核销、多次核销和一笔资金核销多张结算单。
6. 核销错误时，管理员在核销记录点击“撤销核销”并填写原因，系统同步恢复两边余额并保留完整痕迹。

核销金额不得超过结算单未结金额，也不得超过资金流水可用余额。结算金额全部核销后，状态自动变为“已结清”。

## 状态

| 状态 | 说明 |
|---|---|
| 草稿 | 可复核后确认，也可直接作废 |
| 待收付 | 已确认形成正式应收/应付，尚未核销 |
| 部分结清 | 已核销部分金额 |
| 已结清 | 结算金额已全部核销 |
| 已作废 | 不再参与汇总 |

## 数据权限和审计

- 结算单和资金流水继承关联合同的数据范围，同时受用户业务单元归属上限控制。
- 法律主体用于应收应付和收付款归属，业务单元用于经营责任与利润统计，两者分别保存。
- 管理员可通过单据详情审计入口查看创建、确认、打印存档、核销和作废等操作轨迹。
- 已有有效核销记录的结算单或资金流水不能直接作废；必须先撤销核销。
- 保证金、退款和保证金退回独立展示，不允许误核销贸易货款结算单。

## 当前版本边界

已实现：独立的应收、收款、应付、付款申请、付款和结算台账入口；执行批次/合同阶段/合同最终/调整结算；收款登记、业务认领和财务确认；付款申请、审批、付款凭证 OCR、计划/实际账户核对、分次付款、出纳执行和财务确认；实际收付款主体、第三方收付款原因、业务依据/银行回单；部分/全部核销、核销撤销及合同累计控制。

后续实现：从入出库、磅单和质检结果自动计算价差扣罚，发票管理、银行流水自动导入匹配、多级金额条件审批和财务凭证接口。

通用口径见[权限与数据范围规范](../权限与数据范围规范.md)。
