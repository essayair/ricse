# 原地交割方案

> 状态：暂缓，作为后续储备方案；不纳入本次双边直拨开发与发布，不代表现有功能。
> 创建日期：2026-11-10；修订日期：2026-11-11。

## 零、本次范围与阅读说明

- 用户于 2026-11-11 确认搁置原地交割。以下流程、模式、仓库类型与交割记录均为后续候选设计，不作为本次开发任务或上线验收项。
- 本次不开放原地交割入口，不新增第三方仓储类型，不将旧 `DIRECT` 通知自动改名、转换或补账。存量核查仍须按实际单据进行，不能把尚未开发的功能作为旧数据默认归宿。
- 后续重启评审时，销售交割优先沿用来源库存批次的实物数量与辅助数量比例扣减；跨批次逐项分配、清零时处理尾差，不再次按报告扣水。采购多张计量凭证的累计与备选关系、无车辆记录的领域模型及更正闭环仍须补充技术设计。
- 本次双边直拨的有效口径见[双边合同业务方案](./2026-11-10_双边合同业务方案.md)，与本储备方案冲突时不扩大本次范围。

## 一、定位

原地交割指货物存放在仓库中不发生移动，通过仓储方办理货权过户完成交付，不需要物流运输。

原地交割改变我方库存：采购原地交割形成我方库存，销售原地交割扣减我方库存。这一点与双边合同的直拨交付（不形成我方库存）不同。

## 二、适用范围

| 后续候选范围（均暂缓） | 后续仍需另行评审 |
|---|---|
| 单向采购合同：供应商在仓库中将货权过户给我方 | 双边合同原地交割（供应商过户给我方后，我方当场过户给客户） |
| 单向销售合同：我方在租赁或第三方仓库中的库存过户给客户 | 代保管：客户已购买但货物仍留在我方仓库 |

边界规则：

1. 交割仓库须在主数据中登记。仓库类型在“自有”“租赁”基础上增加“第三方仓储”，并关联仓储方。
2. 货物在我方自有仓库中，客户购买后未提走的，视为销售未执行；客户提货时按常规运输办理，运输组织方式选择“客户自提”。
3. 供应商自有场地不作为交割仓库；货物仍在供应商场地、尚未运出的，视为采购未执行。

## 三、执行模式

以下仅为后续执行模式规划，本次不据此调整单向合同菜单或枚举展示：

| 执行模式 | 采购合同、销售合同 | 双边合同 |
|---|---|---|
| 常规运输 | 支持 | 支持（仓储中转） |
| 原地交割 | 暂缓，未来候选 | 暂缓，不纳入本次 |

## 四、业务流程

### 4.1 采购原地交割

```text
采购合同 → 采购执行批次 → 供应商发货指令（原地交割，选择交割仓库）
 → 交割记录（无车辆、无运输）
 → 登记计量依据、检测报告、货权转移凭证
 → 仓储库管交割确认 → 业务入库 → 交割仓库下的我方库存批次
 → 采购结算
```

### 4.2 销售原地交割

```text
销售合同 → 销售执行批次 → 销售发货通知单（原地交割，选择所在仓库）
 → 下达时预占库存
 → 交割记录（无车辆、无运输）
 → 登记交割数量依据、质量依据、货权转移凭证
 → 仓储库管交割确认 → 批次拣配与扣减 → 销售出库 → 销售交付确认
 → 销售结算
```

### 4.3 岗位分工

| 步骤 | 岗位 |
|---|---|
| 创建执行批次、执行通知 | 采销业务员 |
| 登记交割记录、计量依据、货权转移凭证 | 仓储库管 |
| 检测报告录入与最终结论 | 质检人员 |
| 交割确认 | 仓储库管 |
| 结算 | 结算人员 |

原地交割不经过物流运营，不进入调度看板、运费结算和司机小程序。

## 五、交割记录

1. 交割记录复用物流运单承载，运输方式为“原地交割”，页面统一称为“交割记录”。磅单、质检、入库作业、出库作业及结算沿用以运单为基础的现有流程。
2. 交割记录不填写车辆、司机，不产生运费。
3. 一次交割可包含大批量货物，不按车拆分；一张执行通知可分多次交割，每次交割一条记录。
4. 每条交割记录须上传货权转移凭证（仓储方出具的过户单、交割单或双方确认文件）。

## 六、数量与质量依据

### 6.1 采购

- 数量依据：仓储方出具的计量单或磅单，可为多张，也可为一张汇总计量单。
- 现有“采购入库只采用我方收货采信磅单”规则对原地交割作例外处理：采用仓储方计量依据，由仓储库管确认。
- 质量依据：交割时检测，或采用供应商、第三方检测报告。执行通知“是否需要质检”默认勾选。

### 6.2 销售

- 数量依据可选：现场复磅、仓储方计量单、库存账面数量。交割数量与预占数量的差异，沿用现有出库差异处理。
- 现有“出库须有已复核出库磅单”规则对原地交割作例外处理，允许按库存账面数量交割。
- 质量依据：默认沿用所交割库存批次已有的检测报告，也可现场重新检测。
- 库存扣减时，来源批次实物数量与辅助数量按原批次比例联动；重新检测仅作为交割或商业结算依据，不再次扣减原批次辅助数量。多批次分配须分别计算后汇总。
- 交割确认时同时完成销售交付确认，不再单独要求客户收货磅单和客户收货检测报告。

## 七、结算

- 采购结算以业务入库为数据来源，与常规采购一致。
- 销售结算以销售交付确认为数据来源，默认采用交割数量和交割时的质量依据，结算人员可改选。

## 八、异常与更正

| 情形 | 处理 |
|---|---|
| 交割确认前取消 | 作废交割记录，释放通知数量；销售交割同时释放库存预占 |
| 交割确认后更正 | 沿用库存冲销：采购走入库冲销，销售走出库冲销；前提条件与现有冲销规则一致 |

## 九、四流一致

原地交割的货物流依据为仓储方出具的货权转移凭证，交割确认前必须上传。合同、资金、发票的规则与常规采购、销售相同。

## 十、对现有规则的调整

| 现有规则 | 调整 |
|---|---|
| 任意合同的执行通知均可选择“直拨” | 单向合同改为“常规运输 / 原地交割”；“直拨交付”仅在双边合同下出现 |
| 仓库类型：自有、租赁 | 增加第三方仓储，关联仓储方 |
| 采购入库只采用我方收货采信磅单 | 原地交割采用仓储方计量依据 |
| 出库须有已复核出库磅单 | 原地交割允许按库存账面数量交割 |
| 运输方式：自有、第三方、社会运力 | 增加原地交割；同时增加供应商承运、客户自提（对单向和双边业务均开放） |

## 十一、存量数据

不能假定所有单向合同历史“直拨”均只有占位单或未影响库存；采购路径可能已生成入库相关记录。须结合运单、实际磅单、业务入出库、库存、部分冲销、结算、资金及发票逐条核查，本次不执行转换：

- 疑似原地交割且货物来自我方库存的，先列入人工核对；后续功能评审通过并取得具体操作授权后再决定是否补办，不能自动补出库；
- 其余按历史数据只读保留。

## 十二、后续恢复开发时的候选顺序（本次不执行）

1. 执行模式调整与存量数据核查。
2. 仓库类型增加第三方仓储。
3. 交割记录（运输方式“原地交割”），排除调度看板、运费结算、司机小程序。
4. 采购原地交割：仓储方计量依据、交割确认、业务入库。
5. 销售原地交割：账面数量交割、交割确认、出库扣减与销售交付确认联动。
