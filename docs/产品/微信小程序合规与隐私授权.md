# 微信小程序合规与隐私授权

## 一、适用范围

本规范适用于“氟萤直上”微信小程序的微信身份登录、手机号授权、企业账号关联以及现场业务功能。

当前协议版本：

- 《用户服务协议》：`2026.09.17`
- 《隐私政策》：`2026.09.17`

## 二、手机号授权流程

1. 用户点击头像“登录”、“登录并查看”或“验证手机号”时，系统先打开显式的手机号快捷登录授权窗口。窗口采用覆盖整页遮罩、贴底全宽、仅顶部圆角的原生式底部面板，并覆盖自定义 Tab 栏。
2. 授权窗口说明手机号的收集方式、使用目的和用途，并在下方提供可打开全文的《用户服务协议》和《隐私政策》。登录后仍保留两份协议的长期查看入口。
3. 同意项默认不勾选；用户未主动勾选时，系统只显示提示，不得渲染可调用微信 `getPhoneNumber` 能力的确认按钮。
4. 自定义窗口提供可见的“微信手机号快捷登录”按钮，并在按钮下方紧邻展示协议勾选项；用户主动勾选并再次点击该按钮后，才会唤起微信原生手机号授权窗口。不得使用覆盖整个页面或卡片的透明手机号授权按钮。
5. 用户拒绝微信手机号授权时，不创建已验证手机号，不保留本次临时登录状态。
6. 授权成功后，RICSE 保存手机号、手机号验证时间、两份协议版本和同意时间。
7. 协议发生实质更新时，应升级版本号；用户再次授权手机号时需重新阅读和主动勾选。

## 三、手机号用途

手机号仅用于：

- 微信用户身份校验；
- 匹配或辅助关联企业运营管理后台账号；
- 保障账号安全；
- 提供与用户主动使用功能相关的必要服务联系。

不得默认用于无关营销，不读取用户通讯录，不得绕过微信官方接口获取手机号。

## 四、产品与技术约束

- 前端同意状态只用于控制交互，后端仍必须校验 `accepted=true` 和协议版本。
- 合规留痕保存于 `WechatIdentity.serviceAgreementVersion`、`privacyPolicyVersion` 和 `consentedAt`。
- 《用户服务协议》和《隐私政策》在登录后仍应长期保留可访问入口。
- 微信公众平台后台还需要配置并发布《小程序用户隐私保护指引》，其收集信息类型和用途应与小程序页面保持一致。
- 微信返回手机号授权失败时，前端应区分“用户取消”和“隐私保护指引未生效”，显示可理解的反馈并记录原始 `errMsg` 供排查。
- 每次提审前，应使用全新微信用户或清除本地缓存，确认点击登录后弹出授权窗口、同意项默认未勾选、协议可打开、拒绝授权不会登录、勾选后点击真实按钮才能唤起微信授权。
