# 物流合同与运费结算产品方案

> 2026-10-22 确认口径。本轮在既有 MVP 上迭代；不改变物流合同菜单名称，不将找车强制绑定长期合同。

## 1. 模块分工

| 模块 | 管理内容 |
|---|---|
| 物流合同 | 双方签约主体、适用事业部、运价及合作条款 |
| 物流运单 | 车辆司机、货物、路线、发货与签收事实 |
| 物流结算单（菜单：运费结算单） | 选用计费磅单、确认计费数量和本次结算单价 |
| 付款申请单 / 付款单 | 申请审批、实际付款、凭证和运费核销 |

实际车队、司机可先安排运输，结算前补齐有效承运方。合同相对方、实际运力、收款方及开票关系必须如实记录；本轮不新增代开票税费或三方分账引擎。

## 2. 三类数量口径

| 方向 | 库存与货款 | 运费 |
|---|---|---|
| 采购 | 选择结算入库磅单；最终采购货款取实际入库过账数量，不再另选货款磅单 | 新建界面默认选收货净重；合同参考口径仍按约定的发货、收货或结算入库磅单核对 |
| 销售 | 我方发货磅单用于真实出库；销售货款可按双方确认的客户收货磅单，也可约定采用我方发货磅单 | 新建界面默认选收货净重；合同参考口径仍按约定的发货、收货或当前货款磅单核对 |
| 双方确认重量 | 不替代原始磅单，不反向改库存或货款 | 至少有一张有效磅单作为运输依据，填写确认重量和原因，提交前上传确认凭据 |

- 物流不自动取较小重量；操作人员根据约定明确选用，保留选择人、时间及快照。
- 一张运单至少需要一张已复核且净重大于零的有效磅单，不要求两端磅单齐全。
- 最终采购货款按入库过账，不妨碍此前按合同或批次申请预付款、阶段款。
- 销售客户磅单未取得时，可先编制物流结算草稿；按物流约定采用我方发货磅单时可明确选用，不强制等待货款结算。
- 销售改选货款依据不能回写已出库数量；出库已过账或完成拣配时仍不允许直接改我方出库依据。

## 3. 物流合同

### 3.1 页面与字段

创建、编辑为独立页面，分区风格与其他业务单据一致。

1. 内部管理信息：适用业务单元（事业部），默认全部，可指定一个或多个。
2. 合同基本信息：合同名称、我方签约主体（内部合作伙伴）、承运方、承运方后的外部合同号、签订/生效/到期日期。
3. 运价约定：计价方式、默认计量依据、运价行；路线两端同时留空表示不限路线。
4. 付款与其他约定：付款条件、货损保险、装卸等待等文本约定。
5. 合同附件：图片或 PDF，单个不超过20MB。草稿可暂缺，启用前必须上传。
6. 保存后自动生成系统编号、创建人、创建时间；不可手填。

“全部事业部”表示合同可适用于现有及后续新事业部，不代表获得其他事业部业务数据权限。指定事业部必须在操作人可维护范围内。

### 3.2 运价与生命周期

- 草稿可编辑；启用前要求合同名称、有效内部签约主体、有效承运方、合同附件及至少一条运价。
- 生效后合同基础信息和原运价锁定；可追加附件，不可删除原附件。
- 合同可终止，保留历史。终止前实际发货且在有效期内的运输仍能按历史约定匹配运价。
- 运价按实际发货日匹配，历史缺失发货时间时才使用签收日兼容。
- 精确路线优先于不限路线；同优先级匹配多份合同时由人员明确选择，不静默取第一份。
- 付款主体的代付变更不自动改换货主签订的物流合同。
- 本轮继续沿用“草稿→启用→终止”的人工确认，不新增一条物流合同审批工作流；未来可按需要接入统一审批。

## 4. 物流结算

### 4.1 编制

进入页面默认展示当前权限范围内全部已签收、尚未进入有效物流结算的运单，无需先选日期。开始/结束日期均为可选筛选项，可只填写一端，结束日期包含全天；点击“重置”恢复全部未结算范围。支持运单、车牌、货物、企业关键词过滤。不填日期仍可保存草稿，结算周期由所选运单的最早、最晚签收日期自动生成。

一张单据对应同一业务货主、同一事业部、同一结算承运方。多辆车、多执行批次可以合并，前提是上述归属一致。

可结算运单列表将“发货净重（吨）”“收货净重（吨）”分为两列，附磅单编号。双端重量不同时，较低的一侧用主题蓝色字体及“较低”文字提示；相同时不突出。新勾选运单默认选择收货磅单，缺少收货有效磅单时使用发货磅单，只有一张时选用该张，不自动按较低值计费。先勾选运单，再通过重量旁的单选框切换；下方计费磅单、重量及预览金额同步更新。一个节点有多张有效磅单时默认使用最新一张，也可在下方磅单选项中选择具体编号，列表显示实际选中磅单的净重。

列表中的“发货 / 签收时间”位于最后一列，两端净重紧邻展示，方便比较及选用。

切换合同运价不覆盖人员已经选择的磅单。不同于合同参考口径或使用双方确认重量，仍需填写重量依据说明。上述收货默认仅用于新建结算，不重新计算或覆盖已有结算快照，不改变库存及货款磅单。

### 4.2 付款主体

- 业务货主从贸易合同带出并保留。
- 本次付款主体默认业务货主，以“修改”按钮进入调整，不能直接覆盖原货主字段。
- 更换为其他有效内部企业必须填写原因；与物流合同我方签约主体不一致时明确提示，复核人员核对付款安排及依据。
- 付款申请引用物流结算确认的付款主体、承运方和事业部，不在付款阶段绕过原审批任意换主体。
- 本轮不将代付自动解释为货权转移或成本跨公司分摊。

### 4.3 运输与金额明细

一车一行保存快照：运单、车牌、货物名称及规格、发收货时间、发收货净重、选用磅单及毛皮净重、计价方式、计费数量、合同单价、本次单价、含税金额、调整原因。

- 元/吨：选定的计费重量 × 本次单价。
- 元/车次：一张一车一趟运单按1车次 × 单价，不再乘吨数。
- 物理净重与计费数量分开保存，双方确认重量或按车次时不混淆。
- 毛重通常含车辆，仅作核对；新合同不默认提供毛重计费，历史毛重合同保留计算兼容。
- 金额逐行使用十进制定点运算保留2位，再合计；数量保留3位。
- 新建时所选计费磅单不同于合同参考口径或手工确认重量需说明，保存后的草稿更换计费依据始终需填写调整原因；提交、复核均检查所选磅单状态及版本。
- 采购入库过账数量可能已包含质检扣重；物流引用的是所选磅单的物理净重，不直接将干基/扣重数量当作运费重量。

### 4.4 调价及留痕

合同单价不变，草稿中可调整本次单价。每次修改保存前值、后值、原因、操作人及时间。初次编制即覆盖合同价也保存调整历史。

合同详情下方称“结算记录”，展示引用该合同的可见结算、运单、计费数量、原价、实际价、金额、状态及调整历史。它是关联查询，不是重复维护的另一套台账。作废记录保留但不算有效结算。

### 4.5 状态和资金联动

草稿 → 提交复核 → 已复核 → 付款申请 → 审批 → 付款单 → 财务确认 → 运费核销。

已提交、未复核可退回草稿。复核后不能直接改价、改量或换付款主体。已有有效付款申请或核销记录时，不能直接作废；先处理关联资金流程。作废后运单回到未结算范围，原单及调整历史保留。

## 5. 权限与端侧

- 物流合同查看/维护沿用现有权限点，合同按适用事业部共享。
- 结算必须全部关联运单都在当前操作权限范围，不能因其中一车可见而泄露其他业务单元。
- 共享合同下的结算记录仍检查结算查看权限和数据范围。
- Web 负责合同档案、物流结算及财务制单；小程序同步采购/销售磅单用途选择、查看和更正原因。
- 外部企业账号不参与内部物流合同和运费财务管理。
