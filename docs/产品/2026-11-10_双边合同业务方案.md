> 创建日期：2026-11-10；修订日期：2026-11-12。
> 本次修订以 2026-11-11 用户确认口径为准：至少一张有效磅单和一份有效检测报告；销售交付确认联动采购完成；两向交付数量一致；交付与结算依据分离；允许撤销重做；原地交割暂缓。

## 一、定位与适用范围

### 1.1 定位

双边合同是我方作为中间贸易主体，同时向上游供应商采购、向下游客户销售的一笔采销关联贸易的管理单据。系统中保留一份双边合同，在其下分别生成采购执行批次和销售执行批次。

线下法律关系是两份独立合同：我方与供应商的采购合同、我方与客户的销售合同。系统中的双边合同不替代这两份法律合同，而是将二者作为一笔贸易统一管理。

### 1.2 本期范围

| 本期支持 | 本期不支持，后续通过采销关联能力扩展 |
|---|---|
| 一个上游供应商、一个下游客户（一采一销），可分多个执行批次、多车履约 | 一采多销、多采一销、多采多销 |
| 同一份双边合同内的采购与销售配对 | 两份独立采购合同与销售合同之间的配对 |
| 一个我方签约主体 | 采购、销售由不同内部主体签约（内部交易） |
| 直拨交付、仓储中转两种履约方式，可在同一合同内并存 | 加工后交付、第三方代储、港口交货 |
| 每辆车一种物料、一份合同 | 多合同拼车 |
| — | 上游、下游与我方三方共同签订的合同 |
| — | 原地交割（货物在仓库中不移动，仅办理货权过户） |

### 1.3 基本原则

1. 直拨交付采用“一趟运输、一次销售交付确认、两向业务单据、先销售后采购结算且两向数量一致”；仓储中转仍为采购入库和销售出库两段流程。
2. 直拨交付不形成我方仓库可用库存，不参与库存预占、拣配和扣减。
3. 实物凭证（运单、磅单、检测报告、签收凭证）只保留一套，由采购、销售两个方向共同引用；与交易对方相关的单据（合同附件、结算单、资金单据、发票）按方向各自独立。
4. 发货侧与收货侧原始数据分别保留，任何一方的数据不覆盖另一方；数量、质量差异在结算中处理，不通过修改磅单或制造库存损耗处理。
5. 采购、销售业务最终完成至少有一张已复核有效磅单和一份已确认有效检测报告，不要求发货侧、收货侧各一份。此要求不是创建运单或确认发运的上传前置，也不将普通销售出库放行改为必须重新检测。
6. 直拨以销售交付确认为主动作：销售采用的磅单、报告和数量同步用于该车采购业务入库及销售出库，采购交付不再单独确认。采购、销售交付数量一致，但各自最终商业结算数量、金额允许不同。
7. 原地交割为后续储备方案，本次不开发、不开放入口、不实施相关仓库类型扩充或历史数据转换，见[暂缓方案](./2026-11-10_原地交割方案.md)。

## 二、合同

### 2.1 合同信息

双边合同分上游（采购方向）、下游（销售方向）两栏录入，延续采购红色系、销售蓝色系的方向配色规范。

| 信息 | 采购方向 | 销售方向 | 说明 |
|---|---|---|---|
| 交易对手方 | 上游供应商 | 下游客户 | 现有 |
| 外部合同号 | 采购合同号 | 销售合同号 | 由一个字段拆分为两个 |
| 签订日期 | 采购合同签订日期 | 销售合同签订日期 | 由一个字段拆分为两个 |
| 价格条款 | 采购方向价格条款 | 销售方向价格条款 | 现有，见 2.3 |
| 合同附件 | 采购合同 | 销售合同 | 分别上传，见 2.2 |
| 我方签约主体、业务单元、税率 | 两个方向共用 | 两个方向共用 | 现有 |
| 交付质量要求与最终判定 | 两个方向共用 | 两个方向共用 | 本次业务要求一致，不分别生成相互冲突的交付结论 |
| 收付款约定 | 采购付款约定 | 销售收款约定 | 按方向保存合同原文或快照，不能把上游付款条件当作下游收款条件；不增加自动触发付款能力 |

### 2.2 合同附件

附件按类别管理：

| 类别 | 适用 |
|---|---|
| 采购合同 | 采购合同、双边合同 |
| 销售合同 | 销售合同、双边合同 |
| 其他 | 补充协议、报价单等，所有合同类型 |

规则：

- 双边合同提交审批时，须至少包含一份采购合同和一份销售合同附件；缺少任一类别时，提示缺少的具体类别。
- 采购合同、销售合同上传附件时，按合同类型自动归类，提交校验规则不变。
- 附件按方向使用：采购结算、付款申请、进项发票关联采购合同附件；销售结算、收款、销项发票关联销售合同附件。
- 已提交审批或已生效的合同，附件作为审批凭证保持不变，存量附件不要求补充分类；草稿和已驳回合同重新提交前，须完成附件分类。

### 2.3 价格条款

采购方向与销售方向使用同一定价类型（固定价格或按 CaF₂ 品位分档计价）。两个方向分别维护价格表及合同明确约定的商务扣价条款，并分别确认“元/度”计价口径；共同交付验收要求与最终质检判定只维护一套。用于商务扣价的水分上限、回收率等条款不得反向产生两套交付数量或改写原始报告。在此基础上补充以下能力：

1. **复制档位**：销售方向价格表可一键复制采购方向的品位区间与价格，复制后按销售合同修改。
2. **规格一致性提示**：两个方向选择的规格（碎屑、统矿）不一致时，提示经办人确认，不强制拦截。
3. **采销差价对照表**：合同详情与审批页面按两个方向全部档位边界划分品位区间，逐区间列示采购价、销售价（元/度，不含税）和差价；销售价低于采购价的区间标红提示。表下注明“未计入选矿回收率扣价和水分条件”。固定价格合同直接列示两向单价及差价。

### 2.4 交货条款

直拨交付时，采购合同的交货地点应约定为“买方指定地点”或写明客户收货地址。合同录入时对双边合同给出该项提示，作为货物流一致性的合同依据（见第七节）。

### 2.5 物料、数量口径与价格的关系

- 物料的计价数量口径分为实物数量 `PHYSICAL` 与按实测水分折干 `DRY_MATTER`。创建合同时从物料带入并按行固化，已执行合同不因物料后续修改而静默改变口径。
- 当前代码中普通固定价计算读取物料口径，品位分档计算优先读取合同价格规则快照；开发时须保留存量有效快照，并明确新合同的带入和校验，不得统一覆盖历史合同。
- 两向直拨交付共用一个已确认的数量口径：实物数量取交付采用磅单净重；折干数量取该净重 ×（1－交付采用报告水分÷100）。实物计价时辅助计价数量等于实物数量；折干时必须有有效水分实测值，缺失应定位到报告指标，不得默认为零。
- 定价类型决定单价算法，不决定是否折干：固定价为结算数量 × 本方向单价；品位分档按本方向规则计算吨价后再乘结算数量。结算仍按第六节独立选定商业依据。
- 新合同若两向价格规则中的数量口径与共同交付口径不一致，必须显式展示并由经办人按纸质合同确认；不能暗中取一侧替代另一侧。存量冲突进入人工核对，不自动批量改写。
- 数量、金额精度及舍入沿用系统现行统一规则；两向交付复制同一计算快照，不能各自舍入后产生尾差。

## 三、履约方式

| 履约方式 | 实物路径 | 库存处理 |
|---|---|---|
| 直拨交付 | 供应商 → 客户 | 生成采购业务入库与销售出库，不形成我方仓库可用库存 |
| 仓储中转 | 供应商 → 我方仓库 → 客户 | 沿用现有常规入库、库存预占、拣配与出库扣减 |

- 履约方式在执行通知上选择，不在合同上固定；同一份双边合同可同时存在直拨和仓储中转的执行通知。
- 合同审批不确定履约方式。合同审批通过后，由采销业务员选择入口决定：在双边合同详情使用“新建直拨执行”即为直拨，按常规方式建立执行批次与通知即为仓储中转。普通执行通知页面不提供直拨选项。
- 本次双边合同提供“常规运输 / 直拨交付”。原地交割暂缓，不能将单向合同旧“直拨”直接改名为尚未实现的原地交割；存量处理见 11.3。

## 四、直拨执行流程

### 4.1 总体流程

```text
双边合同审批生效
 → 新建直拨执行：采购执行批次 + 销售执行批次，配对生成供应商发货指令 + 销售发货通知单
 → 物流运单（一车一单，同时关联两张配对通知）
 → 供应商处装车：可登记发货磅单、发货报告 → 确认发运
 → 客户处到货：确认送达、上传签收凭证，可登记收货磅单、收货报告
 → 归集质检任务：至少一份有效报告，选定交付报告并形成最终结论
 → 销售交付确认（直拨，仓储库管）：选定有效磅单、报告与数量
 → 同一事务生成采购业务入库 + 销售出库，完成该车销售交付并同步完成采购交付
 → 采购结算、销售结算分别办理
 → 付款、收款、发票、核销分别办理
 → 执行通知、执行批次完成 → 合同关闭
```

### 4.2 单据关系

| 单据 | 份数 | 说明 |
|---|---|---|
| 双边合同 | 一份 | 管理单据 |
| 采购合同附件 / 销售合同附件 | 各一套 | 两份法律合同 |
| 采购执行批次 / 销售执行批次 | 各一份 | 分别统计两向履约进度 |
| 供应商发货指令 / 销售发货通知单 | 各一张，互相配对 | 同时创建、同时下达，数量与地址一致 |
| 物流运单 | 一车一张 | 同时关联两张配对通知，不重复派车 |
| 磅单、检测报告、签收凭证 | 共用证据集合 | 至少一张有效磅单、一份有效报告和必要签收凭证；有两侧资料时分别保留，不要求两侧齐全 |
| 采购业务入库 / 销售出库 | 各一张，成对生成 | 记录两向交付事实，不形成可用库存 |
| 采购结算单 / 销售结算单 | 各自独立 | 销售先结算；采购的磅单、报告、数量跟随同车已审批销售结算，金额各自计算 |
| 付款单 / 收款单、进项发票 / 销项发票 | 各自独立 | 分别与本方向交易对手方往来 |

### 4.3 按岗位的操作步骤

**① 采销业务员：合同**

新建双边合同，分两栏填写上下游信息、两个合同号和签订日期，分别上传采购合同和销售合同附件，填写两向价格条款，提交审批。

**② 采销业务员：新建直拨执行**

在双边合同详情中使用“新建直拨执行”，在一个页面内完成：

- 选择货物行，填写本次数量（页面显示采购、销售两向批次的剩余可通知数量，本次数量不超过二者较小值）；
- 计划日期；
- 起运地（从供应商地址中选择）、目的地（从客户地址中选择）及现场联系人；
- 运输组织方式（见 4.5）。

提交后，系统生成或选用采购、销售执行批次，配对生成供应商发货指令和销售发货通知单并下达。两张通知同时创建，任一失败则全部不生成。供应商发货指令可打印或外发给供应商。

**③ 物流运营：派车**

在直拨通知下单车或批量创建物流运单。运单标识“直拨”，显示供应商至客户的路线及发货人、收货人、运输委托方。供应商承运或客户自提时，只登记车牌和司机，不进入运费结算。

**④ 发货（供应商处）**

有任务操作权限的现场人员通过小程序上传供应商发货磅单，登记重量，标记为发货侧、合作方单据；有供应商检测报告的一并上传。确认发运后运单进入在途。发运沿用车辆、司机调度校验，不要求此时具备磅单或报告，也不要求完成确认前必须补齐发货侧资料，只校验最终至少一张有效磅单和一份有效报告。

**⑤ 到货（客户处）**

有任务操作权限的人员确认送达，上传签收凭证及现场影像；有客户收货磅单则登记为收货侧。直拨运单送达时幂等生成或补齐交付质检任务，已有任务不重复创建，不受执行通知自动质检选项影响。任务允许关联发货侧或收货侧已确认报告，可由客户、供应商、第三方或我方提供；报告环节与提供方分别记录，不限制必须为收货侧。已有有效报告可引用，不强制重新检测。

运单状态进入“已签收，待交付确认”。

**⑥ 仓储库管：直拨交付确认**

见 4.4。

**⑦ 结算人员：两向结算**

已完成交付确认的车次同时进入“采购待结算”和“销售待结算”，分别办理，见第六节。

**⑧ 财务：资金与发票**

付款、收款、发票沿用现有流程，并执行第七节的双边合同专项校验。

**⑨ 完成与关闭**

每车销售交付成功，同步完成该车采购交付并更新两向履约数量；采购不再重复操作。执行通知、执行批次按各自全部有效车次和剩余履约任务汇总完成，取消仅释放占用，不算已交付数量，剩余计划按现有差额关闭规则处理，不能一车完成就结束整个批次。交付完成与结算、收付款结清分别统计，不以“两向已结清”代替交付进度。合同按现有关闭规则办理。

### 4.4 直拨交付确认

**负责岗位**：仓储库管（库存管理人员，`inventory.manage` 权限）。

运单详情新增“直拨交付”页签，主操作为“确认销售交付并同步采购”，包含以下内容：

1. **资料检查**：分别显示发货侧、收货侧证据，但完成门槛为至少一张有效磅单、一份有效报告和必要签收凭证，不以两侧齐全为条件。有效报告须关联本车或符合现有同合同、供应商、事业部约束的共享报告；不要求每车重新检测。
2. **交付依据**：分别选择交付磅单和交付报告。只有一份有效资料时自动带入，确认摘要显示来源；多张同侧磅单须先按既有规则选定“采信磅单”，候选不能用已作废、未复核或非采信凭证。自动生成的空白占位磅单不计入有效资料数量，也不能因此强制补另一侧。报告可选发货侧或收货侧，最终判定采用所选报告。磅单默认取与所选报告同一侧的采信磅单；允许磅单与水分报告来自不同环节，但须选择原因“磅单协商”或“只有一方出质检单”，原因写入交付快照，确认摘要明示跨侧组合。
3. **两侧对比与数量**：两侧均有数据时展示净重、水分、品位及差异；缺失侧显示“未提供”，不得按零计算。按选定依据和 2.5 计算共同交付实物数量、辅助数量，并显示“采购业务入库＝销售出库”。差异首期提示，不增加强制数值阈值；已有质量异常处理仍须显式确认、留痕，不能因共用报告被静默判为合格。
4. **确认摘要**：展示所选凭证、来源、数量口径、计算值、共同质量结论、差异说明及将生成的两向单据。确认后在同一数据库事务内完成：
   - 生成采购业务入库、销售出库，使用同一组数量与证据快照；
   - 完成该车销售交付并同步完成采购交付；
   - 更新配对通知及两向批次履约进度；
   - 将交付状态置为“已确认”，运输状态保留“已签收”，页面组合显示“已交付”。

**运营经理复核**：仓储库管判断差异超出业务允许范围时，可填写说明并提交运营经理复核；是否提交由仓储库管判断，系统不强制。复核通过后按同一快照完成确认，驳回退回修改。复核中不能绕过复核直接确认；修改采用依据、数量、报告指标后原复核结果失效，须撤回复核并重新提交。

**批量确认**：同一张通知下资料齐全、未提交复核的车次可批量确认，每车分别生成单据，任一车失败不影响其他车次，结果逐车反馈。

**防重复与重确认**：同一车次同一时点只允许一组有效交付确认及配对业务单据。重复提交、并发确认、确认与取消并发均须校验当前版本，不重复生成、不留下半套单据。撤销后允许重新确认，生成新版本并保留原确认、撤销和重新确认记录，不覆盖历史快照。

### 4.5 运输组织方式

| 方式 | 运单 | 我方运费结算 |
|---|---|---|
| 我方组织（自有、第三方、社会运力） | 我方创建并调度 | 有，沿用物流合同与运费结算 |
| 供应商承运（运费含在到货价中） | 登记供应商提供的车辆与司机 | 无 |
| 客户自提 | 登记客户车辆与司机 | 无 |

运单运输方式在现有“自有、第三方、社会运力”基础上增加“供应商承运”“客户自提”，并标记该车次不产生我方运费。两种方式同样对单向采购、销售业务开放，例如供应商送货至我方仓库、客户到我方仓库提货。

### 4.6 直拨业务入库与销售出库的口径

- 两张单据记录同一车货的两向交付事实，采用销售交付确认选定的同一磅单、同一报告与共同数量口径，实物数量和辅助数量分别一致。
- 实物数量为所选有效磅单净重，不取计划数量；折干辅助数量按所选报告水分计算，其他物料按其有效数量口径计算。不允许生成采购、销售两套不同的交付数量。
- 可用的两侧原始重量、水分、品位和差异说明分别保留；已确认版本固化采用凭证、指标、计算、确认人和时间。后补另一侧资料不会自动改写已确认单据。
- 不生成库存批次，不写可用库存，不能被其他销售或生产占用。
- 单据标记为“直拨”，与配对单据、运单、配对通知相互关联。
- 成对生成、成对冲销，不允许只存在其中一张。

### 4.7 页面与移动端交互约定

- Web：合同详情“新建直拨执行” → 配对批次/通知 → 共享运单详情“直拨交付” → 资料、采用依据、两侧对比、共同数量 → 确认摘要。采购和销售详情均跳转同一车次，不重复展示两个待办要求分别处理。
- 批次选择显式区分“选择已有采购/销售批次”和“新建配对批次”；已有批次须为同合同、同物料、正确方向及有效状态。新建批次沿用确认规则，不能跳过确认直接下达通知。
- 地址支持选择仓库或合作伙伴地址快速带入，也允许人工填写；不能将“从供应商/客户地址选择”做成唯一方式。
- 小程序同步提供现场上传、有效依据选择、数量预览、交付确认、复核退回处理和取消/撤销入口，按钮按现有业务权限及状态控制，不只更新 Web。
- 本次复用已关联后台账号及现有移动权限的操作人员；司机可以由获授权现场人员代录，不隐含新增面向任意外部司机的注册、登录或任务门户。
- 创建与发运阶段提示“磅单、报告可后补”；完成确认阶段逐项定位缺失项。多侧选择展示当前已选状态，异常提示紧邻相关字段，保留附件当前页预览。
- 运输状态与交付状态分开：签收后待确认、复核中、已确认、已撤销分别展示。取消保留原因和历史，不用删除运单代替取消。

## 五、异常处理

### 5.1 首期支持

| 情形 | 处理 | 前提 |
|---|---|---|
| 整车拒收、退回供应商 | 运单标记为“拒收退回”并填写原因、上传依据；两向均不生成出入库；释放两张配对通知的数量；采购方向登记质量异议，商务处理在线下进行 | 交付确认前 |
| 直拨转入库（客户拒收后卸入我方仓库，或改为入库） | 仅调整该车，保留原运输与单据链；转常规采购入库，完成我方收货计量、质量确认后形成库存；释放该车销售通知占用，采购数量只计算一次。实际转运到仓时建立可追溯的后续运输段，不能把客户签收地点静默改成我方仓库 | 交付确认前；不得整张修改含其他车次的通知；后续销售从库存重新安排 |
| 撤销交付确认 | 两向业务单据成对撤销，保留历史版本，恢复该车“已签收、待交付确认”，回退相应履约进度并停止旧版本结算候选；允许重新确认 | 先按 5.3 处理所有下游引用，不能仅检查正式结算 |
| 取消运单 | 未完成交付时，不限于发运前；按当前状态处理关联任务、保留事实记录并填写原因，释放配对通知数量。已完成交付须先撤销，再取消 | 无有效下游占用或已完成必要反向处理；已发生运输不删除历史证据 |
| 签收后资料长期不齐 | 在现有工作台待办持续显示；主动超期提醒的期限、接收岗位、去重和频率在技术设计中明确，不重复轰炸 | 不为缺少另一侧资料创建无效待办；仅提示真正缺少的最低有效依据 |

### 5.2 后续扩展

- 部分接收、部分退回。
- 运输途中货损、灭失的责任认定与赔付首期在线下办理；系统保留运输、证据与处理原因，按 5.3 清理引用后办理异常取消，不伪造正常签收或交付。

### 5.3 下游引用与取消、撤销顺序

| 当前关联 | 操作前处理 |
|---|---|
| 质检/磅单等未完成现场任务、交付复核中 | 取消或撤回复核、关闭待办并保留已发生证据；共享检测报告只解除该车关联，不删除其他车次仍在使用的报告 |
| 结算草稿、已提交但未完成的结算或付款申请 | 先撤回、作废或按现有流程解除引用，释放数量/金额占用；不能留有效草稿引用已撤销交付 |
| 已确认结算、已核销资金、已分摊发票 | 先依次办理可用的撤销核销、撤销分摊、结算作废等反向操作；涉及实际资金退回、已开票更正或现有系统不支持的反向流程时，列明阻断项并先人工收尾，不直接取消 |
| 两向均无有效下游引用 | 原子撤销配对业务单据及交付确认，按新版本重新确认或取消 |

直拨采购结算跟随同车销售结算，作废顺序为先采购、后销售：存在有效跟随采购结算的车次，销售结算不能作废。

资金流水与历史发票不能因取消交付而自动删除。合同级预付款、其他车次收付款不得无差别回退；只处理本次拟撤销交付实际占用的关联。所有取消、撤销、复核、重确认均记录操作人、时间、原因与版本。

## 六、结算

本平台本期直拨业务约定进出结算数量一致：向客户结算多少，就向供应商结算多少。此为当前业务规则，不泛指所有贸易场景的会计处理。因此：

1. 采购、销售分别生成独立结算单，分别形成应付、应收。
2. **先销售、后采购**。同一车的销售结算审批确认（形成应收）后，才能创建该车的采购结算。销售结算尚未编制、仍为草稿或审批中时，采购结算可以预览试算，但不能保存，并提示“请先完成销售结算审批”。
3. **销售结算依据**：默认采用直拨交付确认时的磅单与检测报告，可以改选，改选按现有规则触发结算审批。销售可按现有规则办理协商数量、逐车调整或整单数量调整。
4. **采购结算全部跟随销售结算的数量依据**：磅单、检测报告（水分、品位）、结算数量（含销售侧的协商数量）均与同车销售结算一致，采购侧不能改选磅单或报告，不能单独协商数量，也不能单独调整总干基。销售结算做过整单数量调整的，采购结算须选择相同车辆并按相同最终数量调整。
5. **金额不跟随**：采购按采购方向价格表（品位分档时采用销售结算所用报告的品位）计价；单价调整、人工加减金额、整单金额调整由两向各自办理并按现有规则审批。
6. 采购、销售两向计价重量口径不一致的，不能自动结算，须先核对合同。
7. 采购结算的数据来源由“已过账采购入库”扩展为“直拨采购业务入库及同车已审批销售结算”。
8. 结算固化交付确认版本、跟随的销售结算行、合同价格规则和调整明细。销售结算或来源资料变化后，采购结算在确认、审批时重新核对，不一致即拦截；旧交付版本撤销后不得继续作为新结算候选。
9. 本节规则仅适用于直拨。双边合同的仓储中转仍按常规采购入库、销售出库分别结算。

## 七、四流一致

双边合同涉及两笔独立交易，每笔交易须各自实现合同流、货物流、资金流、发票流一致。

| 流 | 采购方向（供应商 → 我方） | 销售方向（我方 → 客户） |
|---|---|---|
| 合同流 | 采购合同附件、采购合同号 | 销售合同附件、销售合同号 |
| 货物流 | 供应商发货指令、采购业务入库 | 销售发货通知单、销售出库 |
| 资金流 | 我方付款给供应商 | 客户付款给我方 |
| 发票流 | 供应商开具给我方签约主体 | 我方签约主体开具给客户 |

### 7.1 货物流

直拨交付中实物不经过我方，须通过以下依据证明“供应商按我方指令交货、我方向客户交付”：

1. 采购合同约定交货地点为买方指定地点或客户收货地址；
2. 供应商发货指令载明收货单位和收货地址；
3. 物流运单载明发货人、收货人和运输委托方；
4. 客户签收凭证；
5. 运费由我方承担时，运费的合同、付款、发票与承运方、我方付款主体一致，沿用物流合同与运费结算规则。

### 7.2 资金流

- 正常采购货款支付给上游供应商，正常销售货款来自下游客户；此处限定正常货款方向，不将退货退款、原款退回等有原单关联的反向业务一并禁止。
- 禁止下游客户直接向上游供应商付款，禁止上下游货款相互抵扣后支付差额。
- 双边合同的付款申请中，第三方收款对象为同一合同的下游客户时拦截；收款认领中，付款方为同一合同的上游供应商时拦截。
- 现有付款凭证户名、收款主体与签约主体一致性校验继续适用。
- 退款、更正与撤销按对应原业务关联和既有反向流程办理，不得借“反向流程”伪装无依据的第三方代收付；本次不新增自动资金清算能力。

### 7.3 发票流

- 进项发票开票方为供应商、收票方为我方签约主体，对应采购结算单；销项发票开票方为我方签约主体、收票方为客户，对应销售结算单。现有发票分摊的开票方、收票方一致性校验继续适用。
- 进项、销项发票的货物名称和规格应一致，不一致时提示。
- 各方向发票数量与本方向结算数量核对。直拨采购结算数量跟随同车已审批销售结算，两向最终结算数量一致；发货与收货原始计量差异保留，不以改写原始凭证消除差异。仓储中转按各自出入库及结算流程核对，不套用直拨等量规则。

### 7.4 四流核对视图

双边合同详情新增“四流核对”，采购、销售两栏并列，逐车或逐批次展示：

- 合同：两份附件、两个合同号是否齐全，采购合同交货地点是否已约定；
- 货物：发货指令、运单当事方、签收凭证、两向业务单据是否齐全；
- 资金：收付款对象是否为本方向交易对手方，是否存在代付或抵扣；
- 发票：开票方与收票方、品名、数量是否与本方向结算单一致；
- 两向对照：直拨交付业务单据数量一致，采购结算数量跟随销售结算数量；商业结算可以不同于共同交付数量，但采购、销售之间不能各自另定数量。两向价格和金额分别计算，分次开票进度单独核对。

核对视图中的补充核对项首期仅提示、留痕，不新增统一阻断；不覆盖其他章节已经明确的门禁。合同分类附件必填、至少一张有效磅单与一份有效报告、有效证据关联、配对单据原子一致、已有资金/发票主体校验及明确的代付/抵扣拦截仍执行。四流视图不代表已完成税务认定或自动生成会计凭证。

## 八、信息展示与对外单据

| 单据或端 | 展示 | 不展示 |
|---|---|---|
| 供应商发货指令（对外） | 收货单位、收货地址、现场联系人、物料、数量 | 销售价格 |
| 送货单（对外） | 发货单位、物料、数量 | 采购价格 |
| 司机小程序 | 装货地、卸货地、联系人、待上传单据 | 价格 |
| 系统内部 | 按合同数据范围展示两向信息 | — |

外部账号不能因关联同一双边合同就读取全部商务资料：供应商仅查看采购方向价格、合同附件及资金信息，客户仅查看销售方向对应信息；共享物流和证据按完成本方业务所必需的字段开放。其他类附件须明确可见方向，未明确分类时不得默认同时对外公开。司机如已有合法任务身份，仅查看分配的趟次、地点、联系人及必要证据，不展示价格、银行资料或其他车次。

上述隔离必须同时落实到列表、详情、候选接口、附件预览/下载、打印、导出和小程序，不能只隐藏前端字段。内部账号继续受业务单元归属、角色操作权限和数据范围交集约束；不得为了直拨操作直接授予外部账号全局主数据或库存管理权限。

## 九、对现有规则的调整

| 现有规则 | 调整 |
|---|---|
| 常规采购入库采用现场确认的入库计量与质量依据 | 常规库存流程不借本次改动重做；直拨使用销售交付确认同一组依据、同一实物及辅助数量，联动完成该车采购 |
| 是否自动生成质检任务与最终完成门槛混用 | 通用自动质检选项默认勾选；关闭仅影响自动建任务，不免除采购、销售最终完成至少一份有效报告的要求。已有报告可关联，不强制重复检测；直拨送达一律幂等补齐归集任务 |
| 结算改用非我方侧磅单或检测报告触发结算审批 | 直拨车次改选任一侧不触发审批 |
| 直拨销售发货通知单仅生成过程跟踪占位单 | 改为配对通知、直拨交付确认及成对业务单据 |
| 一张物流运单只关联一张执行通知 | 直拨运单同时关联配对的两张通知 |
| 合同一个外部合同号、一个签订日期、附件不分类 | 按第二节调整 |
| 存量单向合同也有“直拨” | 新双边配对直拨与历史 DIRECT 语义分开，单向历史保留并核查，不自动改名或转换为原地交割 |

## 十、对现有采购、销售业务的影响

单向采购、单向销售的库存处理主链保留；最低有效依据、任务开关和候选报告等共用行为须按已确认口径一起校验，不宣称共用功能完全无变化。涉及影响如下：

| 改动 | 对单向业务的影响 | 处理方式 |
|---|---|---|
| 执行模式调整 | 原地交割本次不开放；新配对直拨仅适用于双边合同 | 单向历史 DIRECT 保持原义并按 11.3 核查，不批量转换；新单不再借用历史占位模式 |
| 合同附件分类 | 按合同类型自动归类，提交校验不变 | 单向合同的存量“其他”类附件视为本方向合同附件，结算、付款等页面照常带出 |
| 合同号、签订日期 | 无 | 现有字段继续表示本合同的合同号和签订日期；仅为双边合同新增销售方向合同号和签订日期 |
| 运输方式增加供应商承运、客户自提 | 新增可选项 | 两种方式不进入运费结算 |
| 质检自动生成默认勾选，与有效依据要求分离 | 最终完成至少一份有效报告，可引用已有发货或收货报告；普通销售库存放行不强制新增检测 | 存量无任务可补建归集任务并关联报告，不能用取消勾选绕过最终质量依据；复用水分、品位等校验 |
| 采购结算数据来源扩展 | 计算逻辑不变 | 涉及共用结算代码，须以现有采购结算用例回归验证 |
| 直拨改选结算依据不触发审批 | 无 | 仅免除直拨侧别改选本身，不免除质量异常、协商调整等现有处理 |
| 资金拦截、发票品名检查、四流核对 | 无 | 仅对双边合同生效 |

**库存统计隔离**：直拨采购业务入库与销售出库不形成库存，但现有业务入库会生成库存批次，销售出库明细必须关联库存批次。为避免直拨单据进入库存总览、库存台账、库存双数量、工作台统计和库存冲销，直拨业务单据建议使用独立数据表存储，仅在结算、四流核对和合同履约统计中汇总；如复用现有表，须逐一排查全部库存类查询。具体方式在技术设计评审时确定。

## 十一、现状与实施顺序

### 11.1 现状

2026-11-12 接续补充：库存管理新增“直拨进出”只读列表，按交付版本成对展示采购业务入库与销售出库，支持搜索、日期/状态、分页和有效数量汇总；运单列表新增“待直拨交付确认”筛选，与移动待办共用条件。直拨磅单发货单位为上游供应商、收货单位为下游客户，两侧采信不套用我方库存；移动交付同步默认同侧与跨侧原因。具体操作见《双边直拨模块》使用指南。

同日后续完善（本地未提交、未部署）：交付快照冻结发货/收货两侧采信磅单、有效检测报告及差异，Web 和小程序展示；合同交易方可直接作为合作方检测机构；直拨与常规批次、通知、运单共用日期流水编号；采购结算选择销售整单调整对应的完整车组后自动带入总数量，不允许改选依据或自行分摊。历史快照及编号不批量重写。

### 11.2 实施顺序

1. **合同**：附件分类与提交校验；两向合同号、签订日期；采销差价对照表、复制档位、规格一致性提示、交货地点提示。
2. **直拨执行**：配对批次/通知、共享运单、至少一张有效磅单与一份有效报告、共同交付数量快照、销售联动采购完成；Web 与小程序同步实现并校验权限。
3. **异常闭环**：整车拒收、单车转入库、下游引用处理、成对撤销与版本化重新确认、取消并发保护、待办恢复；不能只上线正常确认而缺少纠错入口。
4. **结算**：销售结算默认采用交付依据，可选择两侧商业依据；采购跟随已审批销售，同车组的整单数量调整自动带入；结算快照关联交付版本，金额按各方向价格计算。
5. **权限与四流**：方向级字段/附件隔离、资金代付与抵扣拦截、发票品名检查、核对视图；权限作为各接口基础要求，不延后到发布后补做。

数据结构与接口见[双边直拨模块设计](../技术/模块设计/双边直拨模块.md)，本地操作见[双边直拨使用指南](./使用指南/双边直拨模块.md)。本次已同步旧直拨说明，不代表线上已更新。

本地实现边界：新配对执行的运输方式在后续创建共享运单时选择；业务入库/销售出库为独立直拨业务单据，不进入常规仓储入出库表。普通采购入库仍使用既有我方收货依据门禁，本次不扩展为自动接受唯一对方磅单。四流视图只做内部核对提示，不代替税务认定和会计凭证。

### 11.3 存量数据与发布边界

- 不假定所有历史 DIRECT 均为“未影响库存的占位单”。同时核查单向、双边通知的实际运单、入库、出库、库存、结算、资金和发票引用；历史已过账数据禁止按新模式自动补生成配对单据。
- 新配对流程须有明确标识与关系，不能仅凭 `mode = DIRECT` 识别；旧双边未配对车次保留旧关联并列入人工核对。
- 只读核查 SQL 须先评审：计划数量与实际磅单数量分列；入库、出库分别预聚合再连接以避免 SUM 重复；覆盖部分冲销后的有效余额、软删除、目的仓库和双边历史通知。临时脚本未经修订验证，不作为迁移依据。
- 发布不自动执行生产补账、删除或转换，不修改内容资讯等无关数据。旧审批中/执行中合同保留有效快照；新增校验不得通过读取最新物料或空默认值重算旧单据。
- 常规库存、物流结算、工作台、打印、统计查询须同时识别运输签收与交付确认，直拨单据不混入仓库库存。原地交割不随本次发布。

### 11.4 开发验收清单

| 场景 | 验收结果 |
|---|---|
| 仅发货侧或仅收货侧有有效磅单、报告 | 满足最低资料要求即可选用，不强制补另一侧；所选组合缺水分/品位等必要指标时准确提示 |
| 一侧磅单、另一侧报告；共享报告关联多车 | 明确各自来源，每车数量取本车磅单，不把报告当重量来源；两向使用同一组交付依据 |
| 同侧多张磅单、报告作废或未确认 | 仅有效采信磅单及有效报告可用，候选、详情和确认接口规则一致 |
| 物料实物/折干、固定价/品位价 | 交付双数量正确，两个方向交付数量完全一致；两向金额各自计算，缺指标不默认取零 |
| 销售确认与多车汇总 | 一次完成该车采购和销售；其他车不被提前完成，交付与资金结清独立展示 |
| 并发、重复提交、事务失败 | 最多一组有效单据，无半套单据、重复数量和重复待办 |
| 撤销、重确认、取消 | 下游占用先处理，恢复进度；新版本可确认，旧快照与证据历史保留 |
| 多车中一车转入库或整车拒收 | 仅处理该车，其他车和配对通知有效数量正确；采购不重复计量，销售占用正确释放 |
| 两向商业依据与协商调整 | 销售选择商业依据和数量；采购跟随销售已审批结果，两向数量相同、金额可不同；销售整单调量时采购须选相同车组及总量，不回写共同交付快照 |
| 外部供应商、客户及移动账号 | 各方向字段、附件、下载打印均隔离；无权请求不能靠直接访问接口绕过 |
| 普通采购、销售、仓储中转及物流结算回归 | 不破坏现场库存流程、现有价税和付款审批；任务开关不能绕过最终报告要求 |
| 历史 DIRECT、合同与物料变更 | 不自动转换、不补造库存、不静默重算；原地交割无新增入口 |

## 十二、待财务、税务确认事项

1. 直拨交付货物流依据中必须具备的材料，例如签收凭证是否须载明我方名称。
2. 直拨两向业务单据使用同一次交付确认和共同交付日期；是否还需独立财务记账日期，以及进项、销项发票开具时间允许的间隔，由财务、税务确认。
3. 运费包含在到货价中与我方另行支付运费两种情形的票据要求。
4. 直拨业务的成本与收入确认时点。

上述事项不改变已确认的共同交付数量与系统确认动作；未确认前不自动形成会计凭证、税务申报数据或推定合规结论。
