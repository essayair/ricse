# 矿产供应链运营管理系统
## 01 系统管理员 · 主数据管理

---

## 角色定位

系统管理员负责全平台基础档案的配置与维护。本角色是系统正式运行的**前提条件**，所有业务模块（采销、物流、库存、质检、地磅等）的下拉选项、权限控制、数据口径均依赖主数据的准确配置。

> **在整体业务链中的位置**：主数据管理无上游业务依赖，是所有业务流的"地基"。配置质量直接影响全链路数据准确性、权限安全性与统计口径一致性。

---

## 业务链位置

```
【主数据管理】
       ↓ 支撑
采销业务员 · 物流运营 · 仓储库管 · 现场一线 · 财务结算 · 运营管理者
```

**上游任务流**：无业务前置依赖，由系统管理员在系统上线前完成初始配置，并在业务运营中持续维护更新。

**下游影响**：
- 采销业务员：引用往来单位/物料/价格创建合同
- 物流运营：引用车辆、承运商（往来单位 CARRIER）创建运单
- 仓储库管：引用仓库库位信息管理库存
- 财务结算：引用往来单位银行账户进行资金结算
- 全体角色：用户权限决定每个人的菜单可见范围和数据访问边界

## 核心功能模块

### 1. 往来单位管理（合作伙伴 / BP）
**优先级：P0**

往来单位是系统中所有交易对手的统一档案，采用 **BP（Business Partner）模式**：一家企业只存一份档案，通过角色标签区分它在不同业务中的身份。

| 功能 | 说明 |
|------|------|
| 统一档案 | 企业名称、统一社会信用代码、法人、联系方式、注册地址、经营地址 |
| 多角色标签 | 同一企业可同时具备：**供应商**（SUPPLIER）/ **客户**（CUSTOMER）/ **承运商**（CARRIER）/ **内部企业**（INTERNAL） |
| 编码规则 | 内部企业：4 位字母数字，手工录入；外部企业：6 位纯数字，系统自动生成（可切换手动） |
| 唯一性校验 | 统一社会信用代码 + 企业名称联合唯一，防止重复建档 |
| 银行账户 | 一个往来单位可绑定多个银行账户（区分基本户/一般户），支持设置默认结算账户 |
| 货源地 | 供应商可标注货源地（如金华、武义、福建），用于物料采购溯源 |
| 授信管理 | 可配置授信额度，用于合同/结算预警 |
| 状态管理 | 有效（ACTIVE）/ 停用（INACTIVE）/ 黑名单（BLACKLIST），停用后不可在新单据中引用 |

**角色说明**：

| 角色 | 英文 | 典型场景 |
|------|------|---------|
| 供应商 | SUPPLIER | 萤石矿企、原料提供方 |
| 客户 | CUSTOMER | 钢厂、氟化工企业等下游买家 |
| 承运商 | CARRIER | 物流车队、运输公司 |
| 内部企业 | INTERNAL | 集团子公司、分公司、内部业务主体 |

> **示例**：武义氟化工科技有限公司既向我方供应萤石原料，也向我方购买精制萤石粉，则同时勾选 SUPPLIER + CUSTOMER。

> **运维注意**：往来单位变更（如开票信息、联系方式）应及时更新；已生效历史单据不受影响，新单据引用最新版本。停用前需确认无进行中的合同。

### 2. 物料管理
**优先级：P0**

| 功能 | 说明 |
|------|------|
| 分类管理 | 支持两级分类（如"萤石粉 > CaF₂≥97%"），分类树可扩展 |
| 基础信息 | 物料编码（MT-xxxxxx）、品名、品级/等级（CaF₂含量）、计量单位、规格（粒度）、产地、包装方式 |
| 品级区分 | 同一品名按等级细分（如萤石粉分 97%、95%），单独建档管理 |
| 状态管理 | 有效 / 停用，停用后不可在新单据中引用 |

**萤石物料示例**：

| 品名 | 分类 | 品级 | 单位 | 规格 |
|------|------|------|------|------|
| 萤石粉 | 萤石粉 | CaF₂≥97% | TON | -200目 |
| 萤石粉 | 萤石粉 | CaF₂≥95% | TON | -200目 |
| 萤石块矿 | 萤石块矿 | CaF₂≥85% | TON | 散装 |
| 萤石砂 | 萤石砂 | CaF₂≥90% | TON | 散装 |

### 3. 仓库管理
**优先级：P0**

| 功能 | 说明 |
|------|------|
| 仓库基本信息 | 仓库编码（WH-xxx）、名称、类型（自有仓 / 租赁仓）、地址、仓管员及联系方式 |
| 关联往来单位 | 租赁仓库关联租赁方（往来单位），记录产权归属 |
| 状态管理 | 有效 / 停用 |

---

### 4. 车辆管理
**优先级：P0**

| 功能 | 说明 |
|------|------|
| 车辆档案 | 车牌号（唯一）、车型（自卸车 / 罐车 / 挂车）、品牌型号、核定载重 |
| 归属管理 | 自有车辆 / 外协车辆（外协车辆关联承运商往来单位） |
| 驾驶员信息 | 姓名、联系电话 |
| 状态管理 | 运营中（ACTIVE）/ 维修中（MAINTENANCE）/ 已退役（RETIRED） |

---

### 5. 价格管理
**优先级：P1（后续行情模块实现）**

暂缓，一期优先走通合同主线。价格基准将在行情模块独立实现，支持按物料维护参考价、历史价回溯、区域差异价。

---

### 6. 组织架构管理
**优先级：P1**

| 功能 | 说明 |
|------|------|
| 公司主体 | 关联内部企业（往来单位 INTERNAL），记录我方签约主体 |
| 部门 / 业务组 | 归属业务部门，用于报表统计 |
| 利润中心 | 支持移库核算场景 |
| 树形层级 | 无限层级，支持灵活扩展 |

---

### 7. 用户与权限管理
**优先级：P1**

| 功能 | 说明 |
|------|------|
| 用户账号 | 创建/停用系统用户，关联员工信息 |
| 角色配置 | 按岗位定义角色（采销业务员/物流运营/财务/现场一线等） |
| 菜单/按钮权限 | 控制各角色可见菜单与可操作按钮 |
| 数据权限 | 按部门维度控制数据可见性 |

---

### 8. 审批流程配置
**优先级：P1**

| 功能 | 说明 |
|------|------|
| 审批链配置 | 按单据类型（合同/付款申请/入库单等）配置审批节点 |
| 审批人设置 | 支持固定审批人和按岗位动态指定 |
| 抄送配置 | 关键单据审批时自动抄送相关人员 |

## 配置优先顺序（系统上线前）

**第一批（上线前必须就绪）**：
1. 内部企业档案（往来单位 INTERNAL）— 合同主体
2. 外部往来单位（供应商/客户）— 采销合同依赖
3. 物料分类 + 物料档案 — 所有业务单据依赖
4. 仓库档案 — 库存管理依赖
5. 车辆档案 — 物流运单依赖

**第二批（上线同期配置）**：
6. 组织架构与部门
7. 用户账号与角色权限
8. 审批流程配置

**第三批（稳定运行后接入）**：
9. 价格基准（行情模块）
10. OCR 识别工具

---

## 注意事项

- 主数据变更须记录版本历史，**已生效单据不随主数据变更而改变**，新单据始终引用最新版本
- 往来单位停用前，需确认无未完成的合同执行中
- 同一家企业**只建一份往来单位档案**，通过角色勾选区分供应商/客户身份，避免重复建档
- 内部企业（INTERNAL）档案由系统管理员手工维护编码，编码一经生效不得修改
- 外部往来单位编码由系统自动生成（6位数字），如需手动指定需先检查数据库是否已存在
