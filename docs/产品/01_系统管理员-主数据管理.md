# 区域产业链服务生态运营管理平台
## 01 系统管理员 · 主数据管理

---

## 角色定位

系统管理员负责全平台基础档案的配置与维护。本角色是系统正式运行的**前提条件**，所有业务模块（采销、物流、库存、质检、地磅等）的下拉选项、权限控制、数据口径均依赖主数据的准确配置。

> **在整体业务链中的位置**：主数据管理无上游业务依赖，是所有业务流的"地基"。配置质量直接影响全链路数据准确性、权限安全性与统计口径一致性。

> **岗位拆分**：平台全部配置和授权使用 `ADMIN`（系统管理员）；日常合作伙伴、服务生态、物料、仓库、车辆维护可授予 `MASTER_DATA_ADMIN`（主数据管理员）；企业、部门、员工和业务组维护可授予 `ORGANIZATION_ADMIN`（组织管理员）。

---

## 业务链位置

```
【主数据管理】
       ↓ 支撑
采销业务员 · 物流运营 · 仓储库管 · 现场一线 · 财务结算 · 运营管理者
```

**上游任务流**：无业务前置依赖，由系统管理员在系统上线前完成初始配置，并在业务运营中持续维护更新。

**下游影响**：
- 采销业务员：引用合作伙伴 / 物料 / 价格创建合同
- 物流运营：引用车辆、合作伙伴（承运服务方）创建运单
- 仓储库管：引用仓库库位信息管理库存
- 财务结算：引用合作伙伴银行账户进行资金结算
- 全体角色：用户权限决定每个人的菜单可见范围和数据访问边界

## 核心功能模块

### 1. 合作伙伴管理（合作伙伴 / BP）
**优先级：P0**

合作伙伴是系统中所有交易对手的统一档案，采用 **BP（Business Partner）模式**：一家企业只存一份档案，通过合作伙伴角色区分它在不同业务中的身份。

| 功能 | 说明 |
|------|------|
| 统一档案 | 企业名称、统一社会信用代码、法人、联系方式、注册地址、经营地址 |
| 合作伙伴角色 | 同一企业可同时具备：**供应商**（SUPPLIER）/ **客户**（CUSTOMER） |
| 内外部性质 | 创建时选择「外部单位」或「内部企业」，决定编码规则 |
| 编码规则 | 内部企业：6 位字母数字，手工录入；外部单位：8 位纯数字，系统自动生成（可切换手动） |
| 唯一性校验 | 统一社会信用代码 + 企业名称联合唯一，防止重复建档 |
| 银行账户 | 一个合作伙伴可绑定多个银行账户（区分基本户/一般户），支持设置默认结算账户 |
| 主要货源地 | 供应商可标注货源地，用于物料采购溯源 |
| 授信管理 | 可配置授信额度，用于合同 / 结算预警 |
| 状态管理 | 有效（ACTIVE）/ 停用（INACTIVE）/ 黑名单（BLACKLIST），停用后不可在新单据中引用 |

**合作伙伴角色说明**：

| 合作伙伴角色 | 英文 | 说明 |
|------|------|------|
| 供应商 | SUPPLIER | 向我方提供原材料或商品的外部企业 |
| 客户 | CUSTOMER | 向我方采购商品或服务的外部企业 |

> **说明**：运输公司、银行、技术服务公司等是合作伙伴的**业务属性**（体现在经营范围、主营业务字段），不作为独立角色。一家企业可同时勾选供应商和客户（如既是原材料供应方，又购买我方产品）。

> **内部企业**：集团子公司、分公司等内部主体，作为合同签约方使用。创建时选择「内部企业」，与外部单位在编码体系上区分。

> **运维注意**：合作伙伴变更（如开票信息、联系方式）应及时更新；已生效历史单据不受影响，新单据引用最新版本。停用前需确认无进行中的合同。

#### 1.1 服务生态

物流承运商、质检机构、仓储与港口服务商作为合作伙伴的专业扩展档案维护，不重复建立企业主体。外部服务机构关联的合作伙伴必须具备“供应商”合作伙伴角色。

| 服务类型 | 主要维护内容 | 业务用途 |
|---|---|---|
| 物流承运商 | 运输许可证、运输方式、服务区域、调度联系人、保险 | 第三方物流运单选择与运费应付 |
| 质检机构 | CMA/CNAS、检测范围、支持物料、报告周期 | 合作方及第三方质检单选择与检测费应付 |
| 仓储与港口 | 运营类型、仓储能力、支持货物、服务区域 | 租赁仓库运营方选择与仓储费应付 |

业务单据保存合作伙伴 ID，同时保存业务发生时的名称快照；专业档案停用后不允许在新单据中选择，但不影响历史单据。

#### 1.2 字段编辑权限

合作伙伴档案创建后，部分字段锁定、部分可修改。设计原则如下：

**终身不可修改（创建时确定后锁定）**

| 字段 | 原因 |
|------|------|
| 合作伙伴编码 `code` | 全平台唯一标识，合同/执行批次/结算均引用，修改导致历史单据关联断裂 |
| 统一社会信用代码 `taxId` | 与编码、名称构成防重体系，修改破坏唯一性校验 |
| 内部/外部性质 `isInternal` | 决定编码规则体系，创建时锁定 |

**可修改但有限制**

| 字段 | 限制 |
|------|------|
| 企业名称 `name` | 允许修改（企业更名场景），但 `taxId + name` 联合唯一校验须通过 |
| 角色 `roles` | 允许追加角色，禁止移除已有角色（防止执行中合同失去交易方向） |

**运营数据 — 可随时修改**

`shortName` `shortCode` `contactPerson` `contactPhone` `province` `city` `address` `bizAddress` `sourceRegion` `legalPerson` `legalPersonType` `legalIdCard` `controller` `controllerTitle` `controllerPhone` `orgType` `category` `regNo` `estDate` `regCapital` `regCurrency` `revenueScale` `corpType` `industry` `groupName` `isParent` `relatedPartyType` `taxType` `taxRating` `invoiceType` `licenseType` `licenseExpiry` `mainBiz` `bizScope` `tradingGoods` `equityStructure` `intro` `creditLimit` `remark`

**状态变更 — 有前置校验**

| 操作 | 校验 |
|------|------|
| 停用 | 确认无进行中的合同 |
| 加入黑名单 | 二次确认弹窗 |

### 2. 物料管理
**优先级：P0**

| 功能 | 说明 |
|------|------|
| 分类管理 | 支持两级分类树，分类可按业务需要自由定义 |
| 基础信息 | 物料编码（MATxxxx 自动生成）、品名、计量单位、包装方式、产地 |
| 规格指标 | 动态指标行（指标名称 / ≥≤= / 数值 / 单位），可按行业标准定义多项质量指标 |
| 虚拟物料 | 支持标记为虚拟物料（委托加工品、中间品），不参与实物库存管理 |
| 商品编码 | 可关联 HS 编码（海关报关）、税务商品编码（增值税发票） |
| 质检模板 | 关联质检指标模板，入库时自动触发对应质检任务 |
| 状态管理 | 有效 / 停用，停用后不可在新单据中引用 |

#### 2.1 物料分类维护

- **入口**：主数据管理 → 物料品类 → 分类管理
- **分类结构**：固定为两级，一级分类为物料大类，二级分类用于进一步细分；不允许创建第三级
- **创建顺序**：先创建一级分类，再在对应一级分类行内添加二级分类
- **显示顺序**：同级分类按排序号升序显示，排序号相同时按名称排序
- **名称校验**：同一上级分类下名称不可重复，不同上级分类下允许使用相同名称
- **删除控制**：存在下级分类时不能删除一级分类；已被物料档案引用的分类不能删除
- **引用方式**：创建或编辑物料时，从已维护的分类树中选择物料大类或二级分类

### 7. 用户与权限管理
**优先级：P1**

| 功能 | 说明 |
|------|------|
| 用户账号 | 创建/停用系统用户，关联员工和所属企业；外部企业一期最多 6 个有效账号 |
| 多角色配置 | 一个账号可分配多个角色，角色定义菜单、资源和操作权限 |
| 用户角色授权 | 数据范围配置在每一项用户角色授权上，不固定写在角色模板中 |
| 内部数据范围 | 支持全部、本企业、指定企业、部门、部门及下级、本人 |
| 外部企业范围 | 强制锁定为所属企业全部关联数据，不允许切换到其他企业或全平台 |
| 安全约束 | 外部企业不能授予系统管理员；系统必须保留至少一个有效系统管理员 |

新建员工时可填写所属企业、所属部门、姓名、手机号、岗位、邮箱和员工状态，其中企业、部门、姓名和手机号必填；手机号必须为 11 位中国大陆手机号，可在员工详情中修改，并通过接口校验和数据库唯一索引双重防止重复。开通用户账号时，系统默认将员工手机号带入登录用户名输入框，管理员可在提交前修改。手机号属于员工档案，登录用户名属于用户账号，两者独立保存，均可作为登录凭据。登录密码和确认密码仍须显式填写。用户名以字母或数字开头，可包含点、下划线和短横线，长度 3-50 位；密码至少 6 位且两次输入一致。

## 配置优先顺序（系统上线前）

**第一批（上线前必须就绪）**：
1. 内部企业档案 — 合同签约主体
2. 外部合作伙伴（供应商 / 客户）— 采销合同依赖
3. 物料分类 + 物料档案 — 所有业务单据依赖
4. 仓库档案 — 库存管理依赖
5. 车辆档案 — 物流运单依赖

**第二批（上线同期配置）**：
6. 组织架构与部门
7. 用户账号与角色权限
8. 在独立一级菜单「系统管理 → 审批流程」中配置合同审批链

**第三批（稳定运行后接入）**：
9. 价格基准（行情模块）
10. OCR 识别工具

## 注意事项

- 主数据变更须记录版本历史，**已生效单据不随主数据变更而改变**，新单据始终引用最新版本
- 合作伙伴停用前，需确认无未完成的合同执行中
- 同一家企业**只建一份合作伙伴档案**，通过合作伙伴角色勾选区分供应商/客户身份，避免重复建档
- 内部企业档案由系统管理员手工维护编码，编码一经生效不得修改
- 外部合作伙伴编码由系统自动生成（8位数字），如需手动指定需先检查是否已存在
- 审批流程不属于主数据二级菜单，仅系统管理员可在「系统管理」中查看和配置

## 用户、角色与数据权限

系统管理员在「系统管理 → 用户与权限」中维护角色权限和用户授权：

- 一个账号可以拥有多个角色；
- 角色决定用户可以执行的功能操作；
- 选择角色后可逐项配置权限，也可使用“全选全部权限”一次选中所有权限，再次点击取消全选；修改后需保存权限；
- 日常新增、编辑或停用角色应由管理员配置；当前后端接口已支持，前端管理入口列入下一阶段；
- 新增一种系统权限仍需开发接口鉴权和前端控制，不能仅通过页面填写权限名称实现；
- 数据范围配置在用户的每一项角色授权上；
- 内部员工可配置全部数据、本企业、指定企业、部门或本人数据范围；
- 外部企业员工的数据范围固定为“本企业全部关联数据”，不能授权其他企业；
- 外部企业的全部关联数据包括本企业作为买方、卖方或签约方的合同，以及合同向下关联的业务单据；
- 同一外部企业员工共享企业级业务范围，不限于本人创建的数据；
- 一个外部企业一期最多开通 6 个有效账号；
- 功能权限与数据范围分别计算：“能看到本企业全部关联数据”不等于自动获得修改、审批或删除权限；
- 合同、执行、物流、磅单、质检、出入库、库存、冲销及其附件已经接入统一范围；
- 结算、发票和收付款后续开发时继续沿合同或出入库来源单继承企业范围。

完整产品口径见[权限与数据范围规范](./权限与数据范围规范.md)，技术实现见[角色权限与数据范围设计](../技术/模块设计/角色权限与数据范围.md)。
