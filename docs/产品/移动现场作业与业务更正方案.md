# 移动现场作业与业务更正方案

## 一、目标

RICSE 小程序工作台定位为现场作业中心，覆盖物流、过磅、质检、入库和出库岗位的日常执行工作。Web 端负责计划、配置、批量处理和综合管理；小程序负责现场待办、拍照取证、业务确认、异常处理和快速查询。两端共用同一套权限、数据范围、状态流转和业务校验规则。

## 二、端侧分工

| 端 | 主要职责 |
| --- | --- |
| Web 运营管理后台 | 主数据、合同与执行计划、批量调度、库存分配、流程配置、综合查询、异常调整 |
| 微信小程序 | 物流发运与到达、现场签收、过磅、取样质检、收货入库、出库放行、附件影像和异常上报 |
| 两端共同能力 | 详情查询、草稿、允许状态下的编辑、撤回或作废、操作记录和状态跟踪 |

## 三、移动工作台交互

工作台以“我的待办”为第一入口，按照账号权限动态显示待调度、待发运、在途、待到达、待签收、待过磅、待复核、待取样、待判定、待入库、待入账、待出库、差异待处理和待放行。点击待办必须直接进入相应状态的数据集合，不再先打开全部记录。

现场页面遵循以下规则：

1. 自动带出当前员工、部门、企业和操作时间。
2. 车辆、司机、承运商、仓库和质检机构支持选择与搜索。
3. 页面只突出当前阶段最主要的操作，关键按钮固定在操作卡片末尾。
4. 不可操作时显示阻塞原因，不只隐藏按钮。
5. 保存和上传操作防重复提交；不可逆操作必须二次确认。
6. 状态、角色和业务结果统一显示中文，不向用户暴露内部代码。
7. 图片和文件显示上传进度，失败后可重试；未提交内容应尽量保留。

## 四、岗位闭环

### 物流

待调度 → 选择车辆、司机和承运商 → 确认发运 → 运输在途 → 确认到达 → 上传签收资料 → 确认签收。采购运单确认发运时自动生成待入库作业单，到达时再次幂等检查；到达后自动生成质检任务。

### 过磅

待过磅 → 创建发货或收货磅单 → 拍摄现场证据 → 录入可追加的毛重和皮重 → 选择有效称重 → 上传磅单 → 完成称重 → 复核 → 选择执行磅单。执行磅单作为入出库和结算重量口径，变更时必须校验下游影响。

### 质检

待取样 → 登记取样 → 拍摄取样、混样、分样和封样证据 → 选择检测机构与关联磅单 → 按物料质检模板填写指标 → 添加并上传检测报告 → 确认报告 → 选择判定依据 → 形成最终结论。

### 入库

待入库 → 跟踪到货、签收、过磅和质检 → 选择仓库 → 填写收货人和备注 → 上传入库凭证 → 确认收货 → 确认库存主体与数量 → 库存入账 → 生成业务入库单、库存批次和台账。

### 出库

待出库 → 查看或调整库存批次分配 → 装车和出库过磅 → 上传出库凭证 → 处理超装或短装差异 → 确认出库并放行 → 扣减库存 → 物流运单进入在途。

## 五、填错后的处理规则

| 数据阶段 | 处理方式 |
| --- | --- |
| 草稿或未确认 | 允许直接修改、删除和更换附件 |
| 已确认且下游未开始 | 撤回确认，填写原因后恢复可编辑，再次提交 |
| 下游已开始但未入账 | 发起更正，提示受影响单据；失效原执行口径并要求下游重新确认 |
| 已影响库存或结算 | 禁止覆盖原记录，使用冲销、反向单据或差异调整 |

附件在未确认阶段可以增删；进入下游后只能标记无效并上传替代附件；入账或结算后只允许追加补充凭证。所有修改、撤回、更正、作废和冲销均记录操作人、时间、原因、修改前后值及来源端。

## 六、统一实现原则

后端是状态机和权限的唯一规则来源。Web 与小程序调用相同业务服务，不分别实现业务判断。详情接口逐步统一返回当前阶段、阻塞原因、允许操作和下一步提示；前端根据这些能力渲染操作，避免只依赖写死的状态判断。

所有写操作使用现有业务操作日志记录；后续引入单据版本号和幂等键，防止多人覆盖和重复提交。外部企业账号继续受企业数据范围约束，绑定小程序身份不会扩大原后台账号权限。

## 七、迭代顺序

1. 第一阶段：补齐物流发运、到达、签收、精准待办、状态中文化、入出库附件和现场闭环。
2. 第二阶段：补齐未确认数据修改、删除、附件替换及统一操作记录展示。
3. 第三阶段：实现撤回确认、更正申请、下游影响提示和已入账后的冲销衔接。
4. 第四阶段：增加微信待办提醒、弱网草稿、图片水印、扫码识别和异常协同。

## 八、当前开发落地情况

本轮已完成第一阶段闭环及第二阶段的基础更正能力：

1. 工作台将物流待办拆分为待发运、运输中和待签收，并分别进入准确的数据集合。
2. 小程序可完成车辆、司机、承运商调度，确认发运、到达、签收和取消；销售常规出库未完成时会明确阻止提前发运。
3. 小程序可创建磅单、追加并选用毛重/皮重、上传与删除附件、完成称重、复核、选用执行磅单；填错磅单采用“作废并重新创建”，保留原始记录。
4. 小程序可登记取样、添加多机构检测报告、上传与删除报告附件、确认报告和形成最终结论；填错报告采用作废后重建。
5. 小程序可上传、查看和删除未确认的入出库现场凭证，处理出库差异，并完成收货、库存入账和出库放行；页面直接显示前序阻塞原因。
6. Web 质检详情补充现场影像删除、报告附件删除和填错报告作废；Web 与移动详情均展示业务操作记录。
7. 已确认且下游尚未开始的统一撤回，以及跨单据更正和已入账冲销，仍按第三阶段继续建设，不允许当前页面直接覆盖历史数据。
