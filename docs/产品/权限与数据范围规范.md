# 权限与数据范围规范

> 本文档是 RICSE 用户授权、内部员工数据范围和外部企业账号隔离的产品统一口径。各岗位说明、使用指南与本文冲突时，以本文及《技术/模块设计/角色权限与数据范围》为准。

## 一、两个独立维度

RICSE 的访问控制由“功能权限”和“数据范围”共同决定：

| 维度 | 回答的问题 | 示例 |
|------|------------|------|
| 功能权限 | 用户可以做什么 | 查看合同、新建执行批次、管理物流、审批合同 |
| 数据范围 | 用户可以对哪些数据执行这些操作 | 全部数据、本企业、指定企业、部门、本人 |

数据范围不会自动赋予功能权限。外部企业员工拥有“本企业全部关联数据”范围，并不代表自动获得修改、审批或删除权限；具体操作仍由其有效角色决定。

当一个用户拥有多个角色且各角色数据范围不同时，必须在同一角色授权内同时判断“目标权限”和“目标数据范围”。例如用户在玉门业务单元拥有审批权限、在龙游业务单元仅有查看权限时，不得把龙游查看范围与玉门审批权限组合后允许审批龙游合同。

## 二、用户与角色

- 一个账号可以同时拥有多个角色。
- 角色包含一组 `资源.操作` 功能权限。
- 系统管理员在“系统管理 → 用户与权限 → 角色权限”中配置角色权限；权限支持逐项勾选，也支持全选全部权限，再次点击全选项可取消全部选择。
- 角色是可配置项：目标形态支持管理员新增、编辑、停用角色，并为角色组合已有权限；日常新增角色不应修改代码。
- 权限项是开发控制项：新增 `资源.操作` 权限时，必须同时开发接口鉴权、菜单/按钮控制和测试，不能由管理员随意填写权限编码。
- 数据范围配置在“用户—角色授权”关系上，同一用户的不同角色可以使用不同范围。
- 系统保留主角色字段兼容旧功能，新鉴权以当前有效的多角色授权为准。
- 系统管理员拥有全部功能权限和全部数据范围，并可处理所有当前合同审批节点。
- 外部企业账号不能授予系统管理员角色。

### 预置岗位角色

平台按当前业务链预置以下岗位模板：

| 业务域 | 预置角色 |
|---|---|
| 平台与经营管理 | 系统管理员 |
| 采销执行 | 采销业务员 |
| 物流 | 物流运营 |
| 现场作业 | 地磅质检 |
| 仓储库存 | 仓储库管 |
| 生产加工 | 生产管理员 |
| 财务 | 财务结算 |
| 基础资料 | 主数据管理员、组织管理员 |
| 审批 | 运营经理、风控/财务经理、业务责任人、总经理 |
| 基础协作 | 基础查看 |

角色可以组合授予。例如承担采销与物流工作的员工可以同时获得“采销业务员”和“物流运营”。系统管理员为独占角色，不与其他角色叠加。不要通过给普通用户扩大到全模块管理权限来代替岗位角色；“管理人员”“审批人”两个泛化角色已经删除。

## 三、内部员工数据范围

内部员工的角色授权可以配置以下范围：

- 本人创建数据；
- 本部门；
- 本部门及下级部门；
- 本企业；
- 指定企业；
- 全部数据。

业务单元功能落地后增加：

- 本业务单元；
- 指定业务单元；
- 本业务单元及下级单元。

一个账号可以归属多个业务单元并设置一个默认业务单元；每个角色分别配置其适用业务单元。业务单元承担经营责任，原则上对应利润中心；员工行政归属仍由业务部门维护。

用户具有多个有效角色时，可访问范围按有效授权合并；功能操作仍要求至少一个有效角色包含对应权限。

内部普通账号的有效业务单元归属是经营业务数据访问的最高边界。角色范围不能突破该边界：`ALL` 表示该用户已加入的全部有效业务单元，`COMPANY`、`SPECIFIED_COMPANIES`、部门和本人范围也必须再与有效业务单元归属取交集。用户没有有效业务单元归属时，默认不能访问合同及其下游经营数据。系统管理员不受该边界限制；外部企业账号不配置内部业务单元，继续按合作伙伴参与关系隔离；资讯、系统配置和公共字典等非业务单元资源按各自权限规则处理。

统一计算公式为：

```text
最终范围 = 并集（每个拥有目标功能权限的角色范围 ∩ 用户有效业务单元归属）
```

## 四、外部企业员工数据范围

外部员工账号必须绑定 `EXTERNAL` 类型企业，该企业必须通过 `partnerId` 关联唯一合作伙伴。

外部账号的数据范围固定为“本企业全部关联数据”：

1. 本企业合作伙伴作为合同卖方；
2. 本企业合作伙伴作为合同买方；
3. 本企业合作伙伴作为合同签约主体；
4. 上述合同向下产生的全部关联业务单据。

这里的“全部”是企业级全部，不是平台级全部。同一外部企业的不同员工看到相同的企业关联业务数据，不限于本人创建；其他外部企业和无关交易的数据不可见。

外部企业未关联合作伙伴时，系统拒绝其访问业务数据，不能退化为平台全量或本人数据。

试运行阶段外部账号采用业务权限白名单，仅按协作需要开放合同、物流、磅单、质检和出入库等业务权限；不开放主数据管理、组织管理、任何系统管理权限和内部合同审批角色。业务表单所需的基础选项通过受限候选接口提供，不因此开放全量主数据和组织数据。

## 五、业务菜单与操作入口

- 用户拥有模块查看权限时显示对应普通业务菜单、列表和详情；
- 没有新增、修改、删除、确认、作废、审批、过账等操作权限时，隐藏相应操作入口；
- 页面隐藏只改善使用体验，不替代后端鉴权；所有写接口必须再次校验功能权限、数据范围和单据状态；
- 菜单、列表、详情、统计、附件、导出和候选单据必须使用一致的数据范围；
- 外部账号不显示主数据、组织数据和系统管理菜单。

## 六、企业范围继承链

业务单据不重复维护一套容易失真的“可见企业”字段，而是沿已确认的来源单据继承合同参与方范围：

```text
合同
  → 合同执行批次
  → 供应商发货指令 / 销售发货通知单
  → 物流运单
  → 磅单
  → 质检单
  → 物流入库单 / 物流出库单
  → 业务入库单 / 销售出库单
  → 库存批次 / 库存台账 / 库存冲销
```

列表、候选单据、详情、创建、修改、状态流转以及附件查看、上传、删除均使用同一范围校验。直接修改 URL 或单据 ID 不能绕过企业隔离。

结算单、发票、收付款模块后续开发时，必须从合同或对应出入库来源单继承相同范围，不得仅按创建人过滤外部企业数据。

## 七、账号和高风险操作

- 一个外部企业一期最多开通 6 个有效账号。
- 外部企业授权范围由系统锁定，管理员不能将其改为全平台或其他企业。
- 合同不能直接删除，必须先作废；只有系统管理员可以删除已作废合同。
- 合同默认采用“运营经理 → 风控/财务经理 → 业务责任人 → 总经理”四级审批；第 1、3 级按合同业务单元匹配，第 2、4 级为全平台范围。提交时固化成员快照，系统管理员可以兜底处理当前节点并记录原审批成员和实际操作人。
- 库存冲销审批只允许拥有 `inventory.review` 权限的角色或系统管理员处理。
- 附件与所属业务单据使用完全相同的数据范围，不能通过附件地址跨企业查看。

## 八、当前落地范围

已接入统一功能权限和数据范围：

- 合同及合同附件；
- 合同执行批次、执行通知；
- 物流运单及收货附件；
- 磅单、质检单及影像附件；
- 物流入库、销售出库及附件；
- 库存批次、库存台账、库存冲销及冲销附件；
- 生产方案、生产任务、原料批次预占、完工入库和生产台账；
- 合作伙伴、物料、仓库、车辆和服务生态的查看与管理接口；
- 企业、部门、员工、业务组和用户账号接口；
- 系统管理中的角色、权限、用户授权和数据范围配置。

结算中心当前为后续建设模块，其页面和数据接口接入时必须遵循本文。

### 尚待收口

- 角色创建和编辑后端接口已具备，管理页面尚未提供新增、编辑和停用入口；
- 生产环境仍需根据真实岗位清理历史叠加授权，并为每个业务单元明确配置运营经理和业务责任人；
- 主数据和组织数据当前仍以内部运营维护为主，外部企业专属只读视图和字段脱敏尚未完成；
- 在外部企业专属视图完成前，不应向外部账号授予主数据管理、组织管理或用户账号管理权限。

## 九、验收口径

- 同一外部企业的两名员工能看到相同的企业关联单据。
- 外部员工能看到他人创建、但本企业参与合同所产生的下游单据。
- 外部员工不能看到本企业未参与合同及其下游单据。
- 只有查看权限时能浏览但不能修改；只有数据范围而无模块权限时不能访问模块。
- 附件、候选单据接口和详情接口的结果与列表范围一致。
- 外部企业缺少合作伙伴绑定时，业务访问明确失败。
- 系统管理员不受业务数据范围限制，并可执行明确开放的管理员兜底操作。
- 内部普通账号即使角色范围配置为全部数据，也只能访问其有效归属业务单元的数据。
- 审批候选人必须同时满足节点角色、角色范围和合同业务单元归属，`ALL` 不能绕过业务单元归属。
- 外部账号启用前确认未获得主数据管理、组织管理和系统管理权限。

业务单元、角色范围绑定计算及动态审批的完整目标方案见[业务单元与权限审批优化方案](./业务单元与权限审批优化方案.md)。
