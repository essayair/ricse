# 司机与车辆统一建档

## 入口与概念

主数据管理 → 运力管理 → 新建司机与车辆。司机、车辆两个列表的创建入口指向同一页；物流承运商下的“新增司机”也进入此页，并带入承运商。

页面由上方司机信息、下方车辆信息组成。`Driver`和`Vehicle`仍是两套独立主数据，通过`VehicleDriver`建立主/副驾关联，不合并身份、不强制一对一。

每个区域支持“新建、选择已有、暂不填写”。另一侧完全空白时可以独立保存；若已填写部分资料，则必须补齐该侧基础必填项，或清空/选择“暂不填写”，不会静默丢弃未完成内容。

| 本次司机 | 本次车辆 | 保存结果 |
|---|---|---|
| 新建 | 不填 | 一份独立司机档案 |
| 不填 | 新建 | 一份独立车辆档案 |
| 新建 | 新建 | 两份档案，自动关联 |
| 新建 | 已有 | 新司机追加关联已有车辆 |
| 已有 | 新建 | 新车辆关联已有司机 |
| 已有 | 已有 | 建立关联；重复选择同一关系不重复插入 |

已有车辆存在主驾时保留原主驾，新关联司机为副驾；没有主驾时自动成为主驾。不覆盖原档案字段，也不删除其他司机关联。后续需要调整主/副驾，可在车辆编辑页维护。

## 基础校验与附件

- 新司机：姓名、11位有效手机号必填；身份证、驾驶证号选填，填写后继续执行全平台有效档案唯一校验。至少上传一份驾驶证、身份证等证件资料。
- 新车辆：完整车牌、车辆类型、核定载重必填，车牌唯一、载重大于0。至少上传一份行驶证等车辆资料。
- 每侧最多6份待上传附件；图片或PDF，单份不超过20MB，服务端再次检查真实文件格式。司机与车辆附件各自归属，不能混放。
- 已有档案不因本次迭代统一补录，也不要求为了关联重复上传；可以在同页选择新资料，保存时追加到已有档案。
- 档案详情和车辆编辑页可上传、当前页预览、替换资料。至少保留一份，替换时先上传新附件、再删除旧附件。
- 承运商仍可不选，社会运力可独立建档。已指定承运商的司机/车辆继续遵守现有归属一致性校验，不能借统一建档绕过业务规则。
- 选中司机已有承运商且本次新车辆尚未选归属时，默认带入对应承运商；车辆已有选择不会被覆盖，请在保存前核对。

司机、车辆和附件元数据在同一数据库事务内保存；任一侧失败全部回滚，并补偿清理已经上传的存储文件，避免仅创建司机、车辆失败的半套数据。

## 文字识别

在顶部粘贴一组微信、短信或文档文字，点击“识别并填入”。采用本地规则，不调用收费OCR或把个人信息发送到第三方。

可识别司机姓名、手机号、身份证/驾驶证、准驾车型、有效期、车牌、车型、品牌、核定载重、皮重、车主和承运商等常见标签。支持公斤到吨转换、全角标点和车牌字母规范化。推荐格式：

```text
司机：张三，手机号：13800138000，准驾车型：A2
车牌：甘A12345，车型：半挂车，核定载重：32吨，皮重：15吨
```

手机号或车牌精确匹配已有可用档案时，自动切换为“选择已有”并提示，不覆盖原信息；不自动创建承运商。发现多个无标签手机号、多个车牌时提示核对或拆分，不随意取第一条。未识别字段仍需手工补充，附件仍需上传，最终以用户核对保存为准。

## 权限与兼容

新建、关联、资料上传/删除使用`master_data.manage`；查看及附件预览使用`master_data.view`，文件路径还会核对档案归属。沿用现有内部主数据维护授权，不扩大外部企业账号权限。

原有车辆新建地址跳转新入口；司机字段快捷编辑、车辆编辑、车队分组及物流调度引用继续保留。司机/车辆后续修改不反写历史运单快照。此页是后台主数据建档，不把现场临时填写的司机姓名或车牌快照等同于正式建档。

## 车队成员管理

运力管理切换到“车队”，点击“成员管理”后在居中窗口内操作，不再把成员面板打开在列表下方。司机和车辆分别搜索、选择和加入；车辆候选不继承外部车辆列表的筛选条件。已有成员从候选中排除，每次操作后更新成员和列表数量，搜索条件保留。

仅主数据管理权限可加入或移出成员；查看权限只读。停用车队不能新加入成员，但可以移出已有成员。候选仅包含启用且未删除的司机/车辆；重复提交被锁定，并发重复加入返回明确提示。移出需二次确认，只解除车队分组，不删除司机/车辆档案，也不修改历史运单。
