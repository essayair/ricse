# 业务单据关系与术语规范

> 本文档是 RICSE 业务单据名称和上下游关系的统一口径。其他产品、技术和使用指南文档与本文冲突时，以本文为准。
>
> 单据访问权限和外部企业数据隔离统一遵循[权限与数据范围规范](./权限与数据范围规范.md)。

## 一、统一术语

| 业务方向 | 正式名称 | 不再使用的名称 |
|------|------|------|
| 合同分批执行 | **合同执行批次**（简称“执行批次”） | 订单、采购订单、销售订单 |
| 采购执行通知 | **供应商发货指令** | 采购提货指令、采购提单、发货单 |
| 销售执行通知 | **销售发货通知单** | 销售提单、销售提货单、提单 |
| 运输执行单据 | **物流运单** | 运输单、物流运输单、承运单 |
| 采购到货确认 | **物流入库单** | 到货单、物流收货单 |
| 销售离场确认 | **物流出库单** | 物流发货单 |
| 库存货权确认 | **业务入库单 / 销售出库单** | 正式入库单、业务出库提单 |
| 生产转换执行 | **生产任务 / 完工申报** | 加工订单、生产订单 |

合同执行批次按业务方向分为“采购执行批次”和“销售执行批次”。“销售发货通知单”是销售侧的业务执行通知，不等同于海运提单（Bill of Lading）；系统界面和文档中不再单独使用“订单”或“提单”指代上述业务单据。

每个合同执行批次同时具有“执行批次名称”和“执行批次编号”：名称由业务人员填写，用于快速识别实际履约批次；编号由系统自动生成，用于唯一定位、搜索和单据追溯。下游单据不得仅显示名称而隐藏编号。

为兼容现有数据和接口，程序内部暂时保留 `Order`、`OrderLineItem` 和 `/orders` 等技术标识；这些标识不作为用户界面和业务文档名称。

## 二、标准单据主链

```text
合同
  ↓ 1:N
合同执行批次（采购执行批次 / 销售执行批次）
  ↓ 1:N
供应商发货指令 / 销售发货通知单
  ↓ 1:N
物流运单（车辆/车次）
  ↓
磅单 + 质检单
  ↓
物流入库单 / 物流出库单
  ↓
业务入库单 / 销售出库单
  ↓
结算单
  ↓
发票 / 付款 / 收款
```

## 三、单据职责与关联

| 单据 | 职责 | 上游 | 主要下游 |
|------|------|------|------|
| 合同 | 法律和商务约定，确定主体、数量上限、价格及结算规则 | 审批流程 | 合同执行批次 |
| 合同执行批次 | 合同拆分后的具体业务执行单据，确定本批次方向、数量、日期和地点 | 合同 | 供应商发货指令/销售发货通知单 |
| 供应商发货指令 | 通知供应商执行一批采购交货 | 采购执行批次 | 物流运单 |
| 销售发货通知单 | 通知仓库/物流执行一批销售发货并形成通知级库存冻结 | 销售执行批次 | 出库管理单、物流运单 |
| 物流运单 | 记录承运商、车辆、司机、起讫地和运输状态 | 供应商发货指令/销售发货通知单 | 磅单、物流出入库单 |
| 磅单 | 按发货/收货节点记录完整称重凭证；一张凭证内部可有多次毛重/皮重及有效记录，同节点也可按原因追加整张凭证 | 物流运单 | 出入库、结算 |
| 到货质检任务 | 物流到达后自动生成；一条任务归集同一到货车辆的一份或多份机构检测报告，并形成唯一最终质检结论 | 物流运单、磅单 | 业务入库、结算 |
| 机构检测报告 | 任务下的具体检测凭证；一份对应一个样品、一家机构及一套指标和附件 | 到货质检任务、磅单 | 最终质检结论 |
| 出库管理单/车次出库作业 | 汇总通知级冻结、多车任务，并确认单车实际离场 | 销售发货通知、运单、磅单 | 销售出库单 |
| 业务入/出库单 | 确认货权和库存增减 | 物流单、质检单 | 库存、结算 |
| 结算单 | 汇总实际履约数量、价格、质量扣款和费用 | 合同及执行单据 | 发票、收付款 |
| 生产任务 | 按方案把原料库存批次转化为产成品库存批次，支持自营和委外 | 生产方案、可选销售需求 | 完工申报、产成品库存 |
| 完工申报 | 记录一次产出数量、质量结论和生产入库结果 | 生产任务、实际原料耗用 | 产成品库存批次 |

## 四、采购、销售和双边业务

### 采购业务

```text
采购合同 → 采购执行批次 → 供应商发货指令 → 物流运单
→ 物流入库作业单（发运时生成，并汇总磅单/质检）→ 业务入库单 → 采购结算单
```

### 销售业务

```text
销售合同 → 销售执行批次 → 销售发货通知单 → 自动出库管理单/待出库冻结
→ 物流运单/车次出库作业 → 出库磅单 → 销售出库单 → 客户签收 → 销售结算单
```

### 双边业务

系统保留一份双边合同，并在其下分别生成采购执行批次和销售执行批次：

```text
双边合同
├─ 采购执行批次 → 供应商发货指令 → 采购入库链
└─ 销售执行批次 → 销售发货通知单 → 销售出库链
```

采购端和销售端分别统计数量与履约进度，通过同一双边合同实现采销匹配。

## 五、状态边界

- 执行批次状态中的“执行中”表示执行批次已经进入下游执行，不代表某辆车已经发运。
- 实际运输状态只在物流运单中表达：待发运 → 在途 → 已到达 → 已签收。
- 合同审批通过后可以创建执行批次；首次创建执行批次后合同进入执行中。
- 执行批次确认后才可生成供应商发货指令或销售发货通知单。
- 一个执行批次允许拆分成多张供应商发货指令或销售发货通知单，一张执行通知允许拆分成多张物流运单。
- 执行通知一期不审批；销售常规出库必须选择发货仓库，直拨模式可以不选择仓库。
- 执行通知下达后才能创建物流运单；物流运单确认发运前必须完成车辆和司机调度。
- 结算单应引用实际执行数据，不直接以执行批次计划数量作为最终结算数量。
- 一张物流运单形成一条运单级磅单信息，向下承载发货称重和收货称重；每个节点可追加多张完整磅单，追加必须说明原因，原磅单和选用历史不得覆盖。从全部已复核磅单中统一选择一张“结算入库磅单”，库存执行与结算共同采用该口径。
- 一张物流运单确认到达后自动生成一条到货质检任务；任务列表一车一行，详情内可追加一份或多份机构检测报告。默认计划3份，实际至少1份；少于计划数形成结论时必须说明原因并二次确认。
- 采购运单确认发运、进入在途时自动生成一张“待到货”入库作业单，到达时幂等补生成；同一运单不得重复生成有效作业单。有效入库磅单确定净重基数；任务级最终质检结论确定质量结果，所选执行口径报告提供扣水扣杂数值。单份机构报告确认不直接入库，只有任务最终结论为合格时才补齐验收依据。超标扣款、熔断和待判定均不可直接入库。
- 物流入库单确认现场收货，业务入库单确认货权并形成库存；业务入库过账时同步生成库存批次和入库台账，不得只改库存余额而缺少变动凭证。
- 库存主体取采购合同的我方签约主体，仓库表示实物存放位置；库存最小核算口径为“主体 + 仓库 + 物料 + 批次”，总库存仅作统计。
- 销售发货通知草稿不冻结库存；下达后自动生成出库管理单和待出库冻结。冻结不改变账面库存，库存总览按“账面、待出库冻结、可用”分别展示。
- 一张通知对应一张出库管理单并允许多张物流运单；每张运单自动形成车次出库作业，磅单必须直接关联具体运单并由系统向上归集。
- 销售常规出库必须在车辆放行前完成出库磅单复核、库存批次拣配和差异处理；确认放行同步生成销售出库、扣减库存、写负数台账并将物流运单置为在途。
- 已入账业务不得删除或直接修改库存数量。业务入库冲销减少原入库批次，销售出库冲销恢复原销售出库使用的批次；冲销必须形成独立冲销单、审批记录和反向库存台账。
- 冲销允许分次进行，但审批中、审批通过和已过账数量累计不得超过原业务数量；原业务单状态按累计结果标记为部分冲销或已冲销。
- 生产方案定义标准投入产出比例；生产任务创建时固化用料快照。任务下达后生产预占与销售预占共同占用可用库存，领料、退料和完工入库必须生成独立库存台账。
- 一项生产任务允许多次完工；每次质量合格并入库的完工申报形成一个独立产成品库存批次，并保留到实际原料库存批次的追溯关系。

## 六、数据范围继承

- 合同是企业关联范围的根单据，以卖方、买方和签约主体确定直接参与方。
- 执行批次、执行通知、物流运单、磅单、质检单、出入库、库存和库存冲销沿上游关系继承合同参与方范围。
- 同一外部企业的员工共享该企业全部关联单据，不按创建人拆分。
- 列表、详情、候选单据和附件必须使用相同范围，禁止只过滤列表而放开详情或附件。
- 后续结算、发票和收付款数据继续沿合同或对应出入库来源继承。
