# 业务单据关系与术语规范

> 本文档是 RICSE 业务单据名称和上下游关系的统一口径。其他产品、技术和使用指南文档与本文冲突时，以本文为准。
>
> 单据访问权限和外部企业数据隔离统一遵循[权限与数据范围规范](./权限与数据范围规范.md)。
>
> 2026-11-11 修订：配对直拨、销售联动采购、两向独立结算及方向隔离已在本地实现，尚未部署；原地交割暂缓。具体实现与待验收范围以双边合同方案第十一节为准。

## 一、统一术语

| 业务方向 | 正式名称 | 不再使用的名称 |
|------|------|------|
| 合同分批执行 | **合同执行批次**（简称“执行批次”） | 订单、采购订单、销售订单 |
| 采购执行通知 | **供应商发货指令** | 采购提货指令、采购提单、发货单 |
| 销售执行通知 | **销售发货通知单** | 销售提单、销售提货单、提单 |
| 运输执行单据 | **物流运单** | 运输单、物流运输单、承运单 |
| 采购到货确认 | **物流入库单** | 到货单、物流收货单 |
| 销售离场确认 | **物流出库单** | 物流发货单 |
| 库存货权确认 | **业务入库单 / 销售出库单** | 正式入库单、业务出库提单 |
| 生产转换执行 | **生产任务 / 完工申报** | 加工订单、生产订单 |

合同执行批次按业务方向分为“采购执行批次”和“销售执行批次”。“销售发货通知单”是销售侧的业务执行通知，不等同于海运提单（Bill of Lading）；系统界面和文档中不再单独使用“订单”或“提单”指代上述业务单据。

每个合同执行批次同时具有“执行批次名称”和“执行批次编号”：名称由业务人员填写，用于快速识别实际履约批次；编号由系统自动生成，用于唯一定位、搜索和单据追溯。下游单据不得仅显示名称而隐藏编号。

为兼容现有数据和接口，程序内部暂时保留 `Order`、`OrderLineItem` 和 `/orders` 等技术标识；这些标识不作为用户界面和业务文档名称。

## 二、标准单据主链

```text
合同
  ↓ 1:N
合同执行批次（采购执行批次 / 销售执行批次）
  ↓ 1:N
供应商发货指令 / 销售发货通知单
  ↓ 1:N
物流运单（车辆/车次）
  ↓
磅单 + 质检单
  ↓
物流入库单 / 物流出库单
  ↓
业务入库单 / 销售出库单
  ↓
结算单
  ↓
发票 / 付款 / 收款
```

## 三、单据职责与关联

| 单据 | 职责 | 上游 | 主要下游 |
|------|------|------|------|
| 合同 | 法律和商务约定，确定主体、数量上限、价格及结算规则 | 审批流程 | 合同执行批次 |
| 合同执行批次 | 合同拆分后的具体业务执行单据，确定本批次方向、数量、日期和地点 | 合同 | 供应商发货指令/销售发货通知单 |
| 供应商发货指令 | 通知供应商执行一批采购交货 | 采购执行批次 | 物流运单 |
| 销售发货通知单 | 通知仓库/物流执行一批销售发货；常规库存出库形成通知级冻结，直拨不冻结库存 | 销售执行批次 | 出库管理单、物流运单 |
| 物流运单 | 记录承运商、车辆、司机、起讫地和运输状态 | 供应商发货指令/销售发货通知单 | 磅单、物流出入库单 |
| 磅单 | 按发货/收货节点记录完整称重凭证；一张凭证内部可有多次毛重/皮重及有效记录，同节点也可按原因追加整张凭证 | 物流运单 | 出入库、结算 |
| 质检任务 | 归集同一车次的一份或多份有效报告，形成采用依据与最终结论；自动生成开关不等于免除最终报告要求，直拨送达幂等补齐任务 | 物流运单、磅单 | 业务入/出库、结算 |
| 机构检测报告 | 任务下的具体检测凭证；一份对应一个样品、一家机构及一套指标和附件 | 到货质检任务、磅单 | 最终质检结论 |
| 出库管理单/车次出库作业 | 汇总通知级冻结、多车任务，并确认单车实际离场 | 销售发货通知、运单、磅单 | 销售出库单 |
| 业务入/出库单 | 确认业务交付；常规仓储业务形成库存增减，直拨配对业务单据不形成库存 | 物流单、质检单 | 库存（仅仓储业务）、结算 |
| 结算单 | 汇总实际履约数量、价格、质量扣款和费用 | 合同及执行单据 | 发票、收付款 |
| 生产任务 | 按方案把原料库存批次转化为产成品库存批次，支持自营和委外 | 生产方案、可选销售需求 | 完工申报、产成品库存 |
| 完工申报 | 记录一次产出数量、质量结论和生产入库结果 | 生产任务、实际原料耗用 | 产成品库存批次 |

## 四、采购、销售和双边业务

### 采购业务

```text
采购合同 → 采购执行批次 → 供应商发货指令 → 物流运单
→ 物流入库作业单（发运时生成，并汇总磅单/质检）→ 业务入库单 → 采购结算单
```

### 销售业务

```text
销售合同 → 销售执行批次 → 销售发货通知单 → 自动出库管理单/待出库冻结
→ 物流运单/车次出库作业 → 出库磅单 → 销售出库单 → 客户签收 → 销售结算单
```

### 双边业务

系统保留一份双边合同，并在其下分别生成采购执行批次和销售执行批次：

```text
双边合同
├─ 采购执行批次 → 供应商发货指令 → 采购入库链
└─ 销售执行批次 → 销售发货通知单 → 销售出库链
```

采购端和销售端分别统计数量与履约进度，通过同一双边合同实现采销匹配。

双边合同限定一采一销，履约方式在执行通知上选择。仓储中转沿用上述采购入库链与销售出库链；直拨交付不经过我方仓库：

```text
双边合同
├─ 采购执行批次 → 供应商发货指令 ┐（配对）
└─ 销售执行批次 → 销售发货通知单 ┘
   → 物流运单（一车一单，关联两张配对通知）→ 至少一张有效磅单、一份有效报告及签收凭证
   → 销售交付确认 → 同步完成该车采购交付
   → 采购业务入库 + 销售出库（共用依据及数量，成对生成，不形成可用库存）
   → 采购结算单、销售结算单（各自独立）
```

直拨交付以销售采用依据为准，两向实物数量、辅助数量一致；两向商业结算可分别选择依据和协商调整，不能回写交付快照。完整口径见[双边合同业务方案](./2026-11-10_双边合同业务方案.md)（本地实现，未部署）。

原地交割（不移动货物，仅办理仓库货权过户）已暂缓，本次不开放、不替代历史直拨模式。仅保留[后续储备方案](./2026-11-10_原地交割方案.md)。

## 五、状态边界

- 执行批次状态中的“执行中”表示执行批次已经进入下游执行，不代表某辆车已经发运。
- 实际运输底层状态为 `PENDING → IN_TRANSIT → ARRIVED → SIGNED`；采购显示为“待发运 → 在途 → 已到达待收货 → 已收货”，销售显示为“待发运 → 在途 → 已送达待客户签收 → 客户已签收”。
- 直拨交付状态独立于运输状态，签收后可为待确认、复核中、已确认、已撤销；已确认页面可显示“已交付”，不通过替换 SIGNED 使物流、结算和待办漏数。确认与撤销更新该车两向履约，整批完成仍按全部任务汇总，结算结清单独统计。
- 合同审批通过后可以创建执行批次；首次创建执行批次后合同进入执行中。
- 执行批次确认后才可生成供应商发货指令或销售发货通知单。
- 一个执行批次允许拆分成多张供应商发货指令或销售发货通知单，一张执行通知允许单车或批量拆分成多张物流运单；批量派车只是一种录入方式，不增加新的单据层级，一辆车的一个运输趟次始终对应一张独立物流运单。
- 执行通知一期不审批；采购、销售的起运地点和目的地点均可从仓库或合作伙伴地址快速带入，也可直接填写，不以是否选择仓库限制通知创建和下达。若后续发生实际入库或库存出库，须在相应现场作业环节补充确认库存操作仓库。
- 执行通知下达后才能创建物流运单；物流运单确认发运前必须完成车辆和司机调度。
- 结算单应引用实际执行数据，不直接以执行批次计划数量作为最终结算数量。
- 一张物流运单形成一条运单级磅单信息，向下承载发货称重和收货称重；每个节点可追加多张完整磅单，追加必须说明原因，原磅单和选用历史不得覆盖。同侧多张先确认采信磅单。交付/出入库依据与商业结算依据分别选择，不能再概括为采购货款永远等于库存过账数量；物流运费在结算单独立选择。
- 采购、销售最终完成至少有一张已复核有效磅单和一份已确认有效检测报告，不要求两侧各一份；唯一有效资料可带入，多份须明确采用依据。该要求不提前到运单创建或发运，也不将普通销售库存放行改为必须新增发货检测。
- 目标方案中执行通知自动质检默认开启，关闭只影响自动创建任务，不免除最终有效报告要求；已有报告可关联，不强制再次检测。直拨送达幂等补齐归集任务，允许使用发货侧或收货侧有效报告，不强制收货侧。
- 质量最终判定、必要指标完整性与异常确认是独立要求：有报告不等于自动合格，异常处理沿用现有人工确认及留痕规则，不以“最终合格”作为所有采购场景唯一放行条件。折干须有有效水分，品位计价须有必要品位指标，不能取零代替缺失。
- 常规采购发运时生成待处理入库作业，到达时幂等补齐；同一运单不得重复生成有效作业。有效磅单确定净重，任务最终采用报告提供质量数据，即使异常也同步到验收依据，由有权限人员按既有规则处理。新双边配对直拨不生成仓库库存作业副作用，改由销售交付确认成对生成非库存业务单据。
- 常规物流入库单确认现场收货，业务入库过账形成库存批次及台账；直拨业务入库和销售出库只记录两向交付，不形成库存批次、预占或库存台账，不能伪造仓库或过账后再抵消。
- 库存主体取采购合同的我方签约主体，业务单元取合同的经营归属，仓库表示实物存放位置；库存最小核算口径为“业务单元 + 库存主体 + 仓库 + 物料 + 批次”，总库存仅作统计。
- 业务单元（事业部）是经营责任、利润和内部数据权限维度；我方签约主体是法律关系与货权维度。两者独立选择，不能用签约主体推导业务单元。
- 销售发货通知草稿不冻结库存；常规库存销售下达后生成出库管理单和待出库冻结。冻结不改变账面库存，库存总览按“账面、待出库冻结、可用”分别展示；直拨不冻结、不拣配、不扣减库存。
- 一张通知对应一张出库管理单并允许多张物流运单；每张运单自动形成车次出库作业，磅单必须直接关联具体运单并由系统向上归集。
- 销售常规出库必须在车辆放行前完成出库磅单复核、库存批次拣配和差异处理；确认放行同步生成销售出库、扣减库存、写负数台账并将物流运单置为在途。
- 已入账业务不得删除或直接修改库存数量。业务入库冲销减少原入库批次，销售出库冲销恢复原销售出库使用的批次；冲销必须形成独立冲销单、审批记录和反向库存台账。
- 冲销允许分次进行，但审批中、审批通过和已过账数量累计不得超过原业务数量；原业务单状态按累计结果标记为部分冲销或已冲销。
- 上述库存冲销针对真实库存业务；直拨采用业务单据成对撤销且保留历史版本，先处理有效结算、申请、资金及发票引用，再允许取消或重新确认。取消不只限于发运前，但不得删除已发生运输和证据、不得自动删除真实资金或发票。每车只允许一组有效交付版本。
- 生产方案定义标准投入产出比例；生产任务创建时固化用料快照。任务下达后生产预占与销售预占共同占用可用库存，领料、退料和完工入库必须生成独立库存台账。
- 一项生产任务允许多次完工；每次质量合格并入库的完工申报形成一个独立产成品库存批次，并保留到实际原料库存批次的追溯关系。

## 六、数据范围继承

- 合同是企业关联范围的根单据，以卖方、买方和签约主体确定直接参与方。
- 执行批次、执行通知、物流运单、磅单、质检单、出入库、库存和库存冲销沿上游关系继承合同参与方范围。
- 同一外部企业的员工共享该企业全部关联单据，不按创建人拆分。
- 列表、详情、候选单据和附件必须使用相同范围，禁止只过滤列表而放开详情或附件。
- 后续结算、发票和收付款数据继续沿合同或对应出入库来源继承。
- 双边合同的企业参与范围不等于全部字段可见：外部供应商只查看采购方向商务信息及附件，外部客户只查看销售方向对应信息；共享物流证据按必要字段开放。详情、候选、预览下载、打印、导出及小程序均须执行方向隔离，目标规则见双边方案第八节及权限规范。
