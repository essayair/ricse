# 合同基准水分与扣水结算规则

> 2026-11-13，按 CaF₂ 品位分档计价的合同迭代。采购、销售及双边合同均支持；不替换其他商品和旧合同的既有计量方式。

## 1. 业务口径

“免扣水分”不是质量合格上限，也不是实际干基。合同应分别明确：

| 项目 | 作用 |
| --- | --- |
| 扣水方式 | 全部实测水分折干，或仅扣超出基准的水分 |
| 基准水分（免扣水分） | 仅在超基准扣水方式下必填，未超过时不扣重量 |
| 质量水分上限 | 独立、可选的自动计价例外界限，超过后转人工处理；不能将免扣基准当作此界限 |
| 合同质量结算规则 | 独立记录合格、扣价、拒收等规则，仍参与质量处置判断；如配置了水分质量限制，同样独立生效 |

仅超过免扣基准本身不会触发分档计价异常，但不豁免明确约定的质量限制、品位越档、证据缺失或交付前置流程。

## 2. 数量公式

超基准扣水：

```text
扣水比例（百分点）＝max（实测水分－基准水分，0）
结算基准重量＝所选磅单净重×[1－扣水比例÷100]
```

全部水分折干：

```text
实际干基重量＝所选磅单净重×（1－实测水分÷100）
```

净重100吨，基准水分5%：

| 实测水分 | 扣水后结算基准重量 | 实际干基重量 |
| --- | ---: | ---: |
| 3% | 100.000吨 | 97.000吨 |
| 5% | 100.000吨 | 95.000吨 |
| 6.8% | 98.200吨 | 93.200吨 |
| 10% | 95.000吨 | 90.000吨 |

净重与实际水分保持原始事实，不改成“扣除基准后的水分”。实际干基与合同结算数量分别展示和留存。数量统一三位小数，金额继续按原价税、品位档位、回收率及质量扣价规则计算。

## 3. 操作说明

1. 新建合同，选择“按 CaF₂ 品位分档计价”。
2. 在计价重量中选择“按合同扣水后的净重”；如合同不扣水，则选择所选磅单净重。
3. 新建分档规则默认提供“仅扣超出基准的水分”，基准值不预填，必须按合同录入；可改为“按全部实测水分折干”。
4. 质量水分上限可留空表示不在价格规则中另设上限；质量结算规则中的要求仍需另行核对，不会自动删除。
5. 双边合同采购、销售价格条款分别配置；复制采购价格条款至销售时仍是整份规则复制，包括扣水方式和基准，需要核对下游合同。
6. 在结算页分别选磅单和报告，单车数量随所选净重、水分及合同扣水方式重算；批量切换同样使用本车合同规则。
7. 结算预览、明细、打印展示实际干基和结算数量，并在采用超基准扣水时说明基准与公式。

## 4. 库存、交付与结算边界

- 常规采购入库和销售出库的库存实物、辅助数量仍按现有物料及我方单据规则记录，不因商业免扣水分回写已过账库存。
- 双边直拨无仓库库存；新规则的直拨交付按下游合同扣水口径计算共同计价数量，采购业务入库与销售出库保持等量。
- 直拨销售结算可按既有规则选择磅单、报告和协商数量；采购结算继续跟随已确认/审批销售结算的所选依据和数量，金额按采购合同另算。不同采销扣水条件不能让采购单独重算并破坏两向数量一致。
- 改选水分报告、磅单及协商调整继续使用原权限、说明、占用和审批规则，免扣水分不等于自动完成交付或审批。

## 5. 兼容与存储

- 现有 JSON 价格快照增加 `moistureDeductionMode: ACTUAL | EXCESS`、`moistureBasePct`，无数据库表结构迁移。
- `EXCESS` 要求基准0≤值＜100；0合法。实测水分、证据缺失不得按0猜测。
- 未保存新模式的旧规则继续按原全部水分折干；原 `moistureMaxPct` 仍表示质量/人工例外上限。绝不把旧上限自动解释成免扣基准。
- 新增模式、基准随结算来源和直拨交付快照固化；旧规则不追加这些字段，避免来源签名无故变化。
- 不批量修改正在执行合同、历史交付、库存或结算。已审批合同若需改口径，应另行办理受控变更，不能靠修改模板追溯重算。
- 本阶段“待人工判定”的一般结算放行能力仍是独立待开发事项，本次不绕过质量异常校验。
