# 公司试运行人员岗位与系统操作分工

> 文档状态：试运行讨论稿
>
> 编制日期：2026年9月21日
>
> 适用范围：公司内部采购、销售及履约业务试运行
>
> 目的：将现有人员、公司岗位与RICSE系统角色对应起来，明确每个业务环节“谁负责、使用哪个功能、线上怎么操作、线下做什么、完成后交给谁”。

## 一、使用说明

### 1.1 公司岗位与系统角色不是一回事

- **公司岗位**表示员工在实际业务中的职责，例如运营经理、仓管专员、会计。
- **系统角色**决定账号能查看哪些数据、能执行哪些操作，例如采销业务员、物流运营、地磅质检。
- 一个人可以同时承担多个实际岗位，也可以组合多个系统角色；但应遵循最小授权原则，只授予完成工作所需权限。
- 系统权限还受“业务单元（事业部）”范围约束。同一角色在玉门、龙游等不同业务单元可以配置不同人员。

### 1.2 本文使用的系统角色

| 系统角色 | 主要功能 |
|---|---|
| 采销业务员 | 创建、编辑、提交合同，维护执行批次和执行通知 |
| 运营经理 | 审核合同资料完整性和履约条件，处理合同第一级审批 |
| 风控/财务经理 | 审核资金、账期、税务、结算和风险，处理合同第二级审批 |
| 业务责任人 | 对所属业务单元经营结果负责，处理合同第三级审批 |
| 总经理 | 处理合同最终审批 |
| 物流运营 | 物流询价资料、调度、运单、状态跟踪、收货凭证和运费结算单 |
| 地磅质检 | 磅单、称重记录、样品、检测报告、最终质检结论和影像 |
| 仓储库管 | 采购入库、销售出库、库存批次、库存台账和库存冲销申请 |
| 财务结算 | 业务结算、应收应付等财务功能；当前完整财务闭环尚待开发 |
| 基础查看 | 查看授权业务单元内的业务数据，不执行写操作 |

> 特别说明：当前“运营经理”角色主要是合同审批角色，不能代替“采销业务员”完成合同创建和执行；“仓储库管”不能代替“物流运营”创建运单；“地磅质检”同时覆盖过磅和质检两个现场模块。

### 2.1 需要避免的授权方式

- 不要因为员工需要查看数据就授予全部管理权限，查看需求优先使用岗位角色自带只读权限或基础查看角色。
- 不要把系统管理员分配给普通业务人员，系统管理员只用于系统配置和故障兜底。
- 不要让会计代替仓管完成现场收货和库存入账责任；会计可以核对，仓管对实物与库存操作负责。
- 不要让仓管使用他人账号创建运单；需要创建运单时，应给本人增加物流运营角色并保留操作记录。

## 三、功能模块前置流程清单

### 3.1 前置条件分类

- **业务准备项**：不一定由上一张业务单据触发，但必须先维护主数据、人员权限或基础配置。
- **业务补录**：外部已经发生并取得凭证后，再关联到系统内现有业务单据。
- **系统硬性前置**：缺少指定单据、状态或结果时，系统不允许继续操作。
- **系统自动生成**：达到前置节点后由系统自动生成任务或管理单，不需要再次手工新建。
- **系统结果数据**：由前序业务过账形成，只用于查询和统计，不允许手工编造结果。
- **选配流程**：根据合同或执行通知决定是否启用，不作为所有业务的统一强制条件。
- **待开发**：目前仍在线下处理，本表只明确未来应承接的前置数据。

### 3.2 各功能模块前置流程

| 功能模块/业务动作 | 前置类型 | 必须具备的前置流程或数据 | 如何进入/生成 | 缺少前置条件时 |
|---|---|---|---|---|
| 合同创建 | 业务准备项 | 已维护业务单元、业务部门、我方签约主体、合作伙伴、物料和员工账号权限 | 在合同管理中直接新建 | 缺少主数据时先补充维护；合同可保存草稿，但不能提交审批 |
| 合同审批 | 系统硬性前置 | 合同已保存、必填信息完整并已提交；审批流程启用且各节点已配置审批人员 | 提交合同后系统自动生成审批任务 | 保持草稿或提交失败；不能绕过审批直接生效 |
| 执行批次 | 系统硬性前置 | 合同已审批通过并处于可执行状态，且仍有待执行数量或金额 | 从合同详情创建 | 合同未生效或可执行余额不足时不能创建 |
| 执行通知 | 系统硬性前置 | 已存在执行批次，且本次通知数量不超过可执行余额 | 从执行批次创建并下达 | 不能脱离合同和执行批次单独下达 |
| 物流合同 | 业务准备项 | 已维护并启用物流承运商；路线、计价方式和价格资料已明确 | 在物流管理中单独维护 | 不影响运单创建，但运费结算无法自动匹配运价，需手工补价 |
| 物流运单创建 | 系统硬性前置 | 已下达或可执行的执行通知，且仍有可调度数量 | 从执行通知单车或批量创建 | 不允许脱离执行通知创建正式业务运单 |
| 车辆与司机调度 | 系统硬性前置 | 运单已创建；运输方式已确定 | 在运单中选择承运商、车辆和司机，也可录入临时车辆资料 | 车辆和司机资料不完整时不能完成调度或发运确认 |
| 采购发运、到达和收货 | 系统硬性前置 | 采购运单已调度；按“确认发运→确认到达→过磅/质检→确认收货”顺序推进 | 在物流调度或运单详情逐步操作 | 前一状态未完成时，不开放后一状态操作 |
| 销售发运、送达和签收 | 系统硬性前置 | 销售运单已调度；出库称重、拣配和放行已完成 | 在运单详情依次确认发运、送达和客户签收 | 未完成出库放行时不能按正常流程发运；缺少签收凭证时不能确认签收 |
| 采购我方收货磅单 | 系统自动生成 | 采购运单已确认到达 | 系统自动生成“我方收货称重”待过磅任务 | 不需手工重复创建；未到达前不生成现场收货称重任务 |
| 采购供应商发货磅单 | 业务补录 | 已有采购运单或可关联的执行通知，并取得供应商磅单 | 在同一磅单业务中手工追加外部有效磅单 | 可以暂不补录，但最终至少应保留一张有效磅单，并明确执行口径 |
| 销售我方发货磅单 | 系统自动生成 | 销售运单已确定车辆 | 系统自动生成“我方发货称重”待过磅任务 | 不需手工重复创建；未确定车辆前不生成车次称重任务 |
| 销售客户收货磅单 | 业务补录 | 已有销售运单，并取得客户收货磅单 | 在同一磅单业务中手工追加外部有效磅单 | 可以暂不补录；有多张磅单时必须选择库存/结算执行口径 |
| 磅单复核与执行口径 | 系统硬性前置 | 至少一张称重记录完整的有效磅单；毛重、皮重、时间和附件等信息已核对 | 在磅单详情复核，并从多张有效磅单中选择执行磅单 | 未复核或未选择执行磅单时，不能作为库存、结算和后续确认依据 |
| 质检任务 | 系统自动生成、选配流程 | 执行通知要求质检，且关联运单已到达现场 | 达到条件后系统自动生成质检任务 | 销售业务可按合同选配；采购入库按当前规则必须完成质量判定 |
| 取样与送检 | 系统硬性前置 | 质检任务已生成 | 在质检任务中逐行新增样品、拍照并登记送检信息 | 没有质检任务时不能形成可追溯样品；每份样品必须有独立编号 |
| 检测报告 | 系统硬性前置 | 已有质检任务及对应样品/检测机构，已取得检测结果 | 在样品或机构检测报告区域添加 | 无法脱离质检任务单独形成正式检测报告 |
| 最终质检结论 | 系统硬性前置 | 至少一份有效检测报告 | 选择执行报告并形成任务级结论 | 单份报告或少于计划份数时，必须填写原因并二次确认 |
| 采购入库管理单 | 系统自动生成 | 采购运单进入发运/在途流程，系统获得本次预计入库信息 | 系统提前生成待到货入库管理单，到达后持续补全 | 不需要仓管手工新建；未完成前置条件时保持待到货或待处理状态 |
| 采购确认收货 | 系统硬性前置 | 运单已到达；有效磅单已复核并选为执行口径；最终质检结论合格；仓库、收货时间和收货人完整 | 在入库单详情确认收货 | 页面提示缺少项，不允许无提示跳过或确认失败 |
| 采购入库过账 | 系统硬性前置 | 入库管理单已确认收货 | 由仓储库管生成业务入库并入账 | 未确认收货不能增加库存；过账后形成库存批次和台账 |
| 库存查询 | 系统结果数据 | 已存在期初库存或已过账的入库/出库记录 | 从库存总览、库存批次或台账查询 | 没有库存结果时只显示空数据，不生成虚构数字 |
| 销售出库管理单和库存冻结 | 系统自动生成 | 销售执行通知已下达 | 系统自动生成出库管理单；常规出库同步冻结待出库库存 | 通知未下达时不冻结库存；库存不足应显示缺口，不能伪造可用库存 |
| 销售拣配与放行 | 系统硬性前置 | 已有出库管理单、车次运单和已复核的我方发货磅单；存在可分配库存批次 | 在出库单中选择执行磅单、自动或手工分配批次并处理溢短装 | 未选择磅单、未分配批次或差异未处理时不能正常放行和扣减库存 |
| 库存冲销 | 系统硬性前置 | 已存在可冲销的已过账入库或出库记录，且未超过可冲销数量 | 发起冲销申请，审核后执行过账 | 不能直接删除已过账库存业务；超量或重复冲销不允许提交 |
| 运费结算单 | 系统硬性前置 | 运单已签收；已有结算执行磅单；该运单未被未作废的结算单占用 | 按结算周期选择候选运单创建 | 不满足条件的运单不进入候选；无运价合同时需手工补价 |
| 物流对账 | 待开发 | 原则上应基于运费结算单、承运商账单、发票和差异确认 | 后续版本建设 | 当前仍在线下完成，不应误认为已有完整线上闭环 |
| 采购/销售财务结算 | 待开发 | 原则上需合同、已过账入出库、执行磅单、质检结果、发票及收付款资料 | 后续从来源单据自动形成应收应付 | 当前沿用线下财务流程，并保留平台来源单号用于追溯 |
| 进销存专题报表 | 待开发 | 已有连续、完整的合同、执行、库存和结算数据，并明确统计口径 | 后续建设专题报表 | 当前使用库存总览、库存批次、台账及各业务列表查询，不展示虚构数据 |

> 核心顺序：合同审批通过后才能执行；执行通知下达后才能创建正式运单；采购入库必须有有效磅单和合格质检结论；销售出库必须完成有效称重、库存批次分配和放行；已过账业务通过冲销纠正，不能直接删除。

## 四、采购业务全流程与人员分工

### 4.1 流程总览

```text
商务合作与采购条件确认（线下）
  → 创建采购合同（线上）
  → 四级合同审批（线上）
  → 创建执行批次和执行通知（线上）
  → 物流询价与车辆落实（线下为主、线上建档）
  → 创建并调度运单（线上）
  → 发运及在途跟踪（线上+线下）
  → 到达、过磅、取样和质检（现场+线上留痕）
  → 仓管确认收货并入账（线上）
  → 运费结算/采购结算（部分线上，部分待开发）
```

### 4.2 业务动作拆解

| 顺序 | 业务环节 | 责任人 | 公司岗位 | 系统角色 | 线下执行 | 线上功能及操作 | 完成标志/下一环节 |
|---|---|---|---|---|---|---|---|
| 1 | 商务合作 | 陈飞祥/杨宇豪 | 业务责任人 | 业务责任人 | 与供应商确认品种、规格、数量、价格、交货、运输、付款和结算条件 | 必要时查看历史合同、库存和履约数据；本步骤不要求代替运营人员录单 | 商务条件确定并移交黄蕾建档 |

## 六、各功能板块操作说明

### 6.1 合同管理

**功能是什么**：记录采购、销售或双边合同，统一管理合同资料、附件、审批、执行状态和下游履约进度。

**怎么操作**：

1. 进入「采销管理→合同管理」；
2. 点击“新建合同”，选择合同类型；
3. 填写业务单元、业务部门、我方签约主体和交易对手方；
4. 填写物料、数量、价格、日期、结算方式等合同条款；
5. 上传合同原件或相关附件；
6. 可先保存草稿，确认完整后提交审批；
7. 审批通过后，从合同详情创建执行批次并跟踪履约进度。

### 6.2 合同审批

**功能是什么**：通过“运营经理→风控/财务经理→业务责任人→总经理”四级顺序审批控制合同风险。

**怎么操作**：

1. 审批人从小程序工作台或Web合同详情打开待审批合同；
2. 查看合同、附件及前序审批意见；
3. 填写审批意见；
4. 选择通过或驳回；
5. 或签节点由任一有效成员完成后进入下一级，其他成员显示“他人已审批/他人已驳回”。

### 6.3 执行管理

**功能是什么**：把合同拆分为可执行的业务批次，再通过执行通知安排某次具体采购发货或销售发货。

**怎么操作**：

1. 从已生效合同详情点击“新建执行批次”；
2. 填写批次名称、计划数量、金额和计划发货日期；
3. 进入执行通知，填写本次起运地、目的地、地址联系人、仓库、运输和质检要求；
4. 确认后下达通知；
5. 采购通知进入物流执行，销售通知同时生成出库管理单并冻结可用库存。

### 6.4 物流管理

**功能是什么**：管理承运商、车辆、司机、运单、运输状态、签收附件、物流合同和运费结算。

**怎么操作**：

1. 提前维护物流承运商、车辆和司机档案；
2. 从执行通知创建一张或批量创建多张运单；
3. 选择自有或第三方运输、承运商、车辆和司机；
4. 填写计划发运和预计到达时间；
5. 在调度看板依次更新发运、到达/送达、收货/客户签收状态；
6. 上传签收单、现场照片或其他交付凭证；
7. 已签收运单可进入运费结算单。

### 6.5 磅单管理

**功能是什么**：归集同一运单的发货和收货称重，记录毛重、皮重、净重和现场证据，并选择库存与结算执行口径。

**怎么操作**：

1. 从现场待办或「磅单管理」打开待过磅单；
2. 采购我方收货默认先毛重、后皮重；销售我方发货默认先皮重、后毛重；
3. 录入或追加称重记录、时间、人员等信息；
4. 上传磅单、地磅显示照片和现场附件；
5. 确认有效称重记录并复核磅单；
6. 多张有效磅单时明确选择库存和结算使用的同一张执行磅单，并记录改选原因。

### 6.6 质检管理

**功能是什么**：管理到货质检任务、取样、样品拆分、多机构检测报告和最终质量结论。

**怎么操作**：

1. 运单到达后打开自动生成的质检任务；
2. 新增一个或多个样品，填写样品编号、取样人、时间和送检机构；
3. 每个样品拍摄并上传照片；
4. 在对应机构下添加检测报告，填写检测指标、方法和实测值；
5. 上传正式质检单或检测报告；
6. 对有效报告进行对比，形成任务级最终结论；
7. 单份报告或报告少于计划数量时，填写原因并二次确认。

### 6.7 采购入库和库存

**功能是什么**：在采购货物完成物流、过磅和质检后确认收货，生成业务入库单、库存批次和库存台账。

**怎么操作**：

1. 采购运单发运后，系统自动生成待到货入库作业单，无需人工新建；
2. 仓管在「入库单管理」核对物流、磅单和最终合格质检结论；
3. 补齐仓库、实际收货时间和收货人；
4. 点击确认收货；
5. 再执行“生成业务入库并入账”；
6. 在库总览查看业务单元、库存主体、仓库、物料和批次的账面、冻结与可用数量。

### 6.8 销售出库

**功能是什么**：根据销售发货通知冻结库存，按实际出库重量选择库存批次，完成放行和库存扣减。

**怎么操作**：

1. 销售执行通知下达后，系统自动生成出库管理单并冻结库存；
2. 创建物流运单后，系统生成车次出库作业；
3. 完成我方发货过磅并复核磅单；
4. 仓管打开车次作业，选择执行磅单并自动或手工拣配库存批次；
5. 处理短装、溢装等差异；
6. 确认车辆放行，系统生成销售出库单、扣减库存并写入台账。

### 6.9 物流合同与运费结算

**功能是什么**：维护固定承运商的路线运价，并将已签收运单按周期归集为运费结算单。

**怎么操作**：

1. 在「物流管理→物流合同」维护承运商、合同有效期和路线单价；
2. 在「运费结算单」选择结算周期和候选已签收运单；
3. 系统按我方主体、承运商、路线及有效期自动匹配合同价；
4. 未匹配合同的临时运输手工填写单价；
5. 调整合同价必须填写原因；
6. 完成后提交、复核；错误单据通过作废重开处理。

> 当前状态：物流合同与运费结算单第一版已开放；物流对账汇总页面仍为占位，运费结算与财务应付的自动衔接尚待开发。

### 6.10 财务结算

**功能是什么**：未来承接采购应付、销售应收、发票、付款、收款和核销。

**当前操作**：完整闭环尚未开发。试运行期间仍在线下完成财务处理，但应在付款、收款、发票或对账资料中记录平台合同号、执行批次号、入出库单号和运费结算单号，为后续上线核对历史数据。

### 6.11 进销存查询与报表

**当前已具备**：

- 在库总览；
- 按业务单元、库存主体、仓库、物料和批次查看库存；
- 查看账面数量、冻结数量和可用数量；

## 七、线上与线下的统一边界

| 类型 | 必须在线下完成 | 必须在线上留痕 |
|---|---|---|
| 商务合同 | 谈判、资信判断、纸质签章 | 合同结构化信息、附件、审批意见和执行状态 |
| 物流 | 询价、与司机沟通、园区报备、现场交接 | 承运商、车辆司机、计划时间、运输状态、签收凭证 |
| 过磅 | 车辆上磅、读取地磅显示、现场复核 | 毛皮净重、称重时间、磅单附件、照片、复核与执行口径 |
| 取样质检 | 卸货、取样、分样、寄样、实验室检测 | 样品编号、取样照片、机构、指标结果、报告附件和最终结论 |
| 仓储 | 实物验收、装卸、库位安排、车辆放行 | 收货信息、入库过账、批次拣配、出库扣减和库存台账 |
| 财务 | 银行付款收款、发票原件、会计核算 | 当前记录关联业务单号；后续上线应收应付、发票和核销 |

统一原则：线下完成真实业务动作，线上记录责任人、时间、结果、附件和上下游单据关系。不得只在线下完成而不更新系统状态，也不得在真实动作尚未发生时提前点击完成。

## 八、交接规则和试运行要求

### 8.1 环节交接规则

- 商务条件确定后，由业务责任人将完整资料交给黄蕾创建合同。
- 合同审批完成后，由黄蕾创建执行批次和执行通知，并通知物流人员接单。
- 物流人员落实车辆后，必须在提货前完成车辆、司机和运单信息录入。
- 运单到达后，物流人员更新到达状态，过磅和质检人员从移动工作台接续处理。
- 磅单复核和最终质检合格后，系统向仓管展示可收货条件，仓管负责最终入库。
- 销售出库在车辆发运前完成出库称重、批次拣配和库存扣减。
- 财务核对使用平台来源单据，不重新维护一套无关联的业务台账。

### 8.2 试运行要求

1. 选择一笔真实采购和一笔真实销售业务完整实跑；
2. 每名责任人使用自己的账号操作，不共享账号；
3. 所有账号必须配置正确业务单元和最小岗位角色；
4. 现场优先使用小程序，资料维护和批量查询使用Web后台；
5. 发现错误先记录单据号、操作人、时间和截图，不直接重新创建重复单据；
6. 每天汇总阻断问题，每周复盘流程、权限、字段和交互问题；
7. 线下与线上结果不一致时，以真实业务凭证为核对依据，并通过编辑、作废、冲销等正规方式修正系统记录。
